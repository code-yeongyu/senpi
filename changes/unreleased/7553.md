## 2026-11-27 - Ensure judges a registered primary by its socket, not its pid (senpi#4769, oh-my-openagent#15003, senpi#7553)

### What changed

- `packages/coding-agent/src/modes/rpc/host-endpoint-serving.ts` (new): `probeEndpointServing` makes one bounded `get_protocol_info` probe of a public path and answers `absent` (no entry, or nothing listens), `unserved` (it accepted, then closed or reset the connection with no answer, or answered only `host_unavailable`), `held` (it accepted and stayed silent until the deadline) or `answered`. Win32 named pipes, abstract sockets and an entry that cannot be stat'ed read as `held`. The deadline goes through a `ProbeExpiry`, so tests drive it with a virtual clock (`_test.servingProbeExpiry`).
- `packages/coding-agent/src/modes/rpc/host-ensure-unanswered.ts` (new): `settleUnansweredGeneration` holds the branch `ensureHostLocked` runs for a registered generation whose pid is alive but which did not answer, and decides it on that one verdict. An `unserved` generation is stopped (`replace_unreachable`) and replaced when this process wrote its record, or when the writer is provably gone. A `held` or `answered` socket is still refused (`host_busy`, or `foreign_writer` for a record another live process wrote), and an `absent` one still leaves a foreign generation stranded beside a fresh start (#1936).
- `packages/coding-agent/src/modes/rpc/host-ensure-liveness.ts`: `refuseIfForeignHeld` takes the verdict instead of probing again. `publicEndpointAccepts` is gone. `writerGone` (new) reads the record's writer stamp: gone only when its pid is not live or names a process started at another time, never when the stamp or the identity is missing.
- `packages/coding-agent/src/modes/rpc/host-ensure.ts`: calls `settleUnansweredGeneration` where the branch was inline. Its own `probeSocketReachable` call (10 s) is replaced by the verdict.
- `packages/coding-agent/src/modes/rpc/host-ensure-start.ts`, `host-daemon-paths.ts`: a fresh (generation 0) start moves the existing `stderr.log` to `stderr.prev.log` (`HostDaemonPaths.previousStderrLog`) before opening its own, instead of truncating it.
- `packages/coding-agent/src/modes/rpc/host-ensure-types.ts`: `_test.servingProbeExpiry`.

### Why

- A device's primary supervisor (engine 2026.11.23) stayed alive for days with a listener that closed every connection unanswered, because it could not reach its host child. `host ensure` refused `foreign_writer`: it counted "a connection was accepted" as ownership, and only the process that wrote the registration may stop a host, but the recorded writer pid no longer existed. Nothing could heal the endpoint. Its listener kept the path, so no fresh generation could bind beside it, and the device had no primary engine until someone stopped the process by hand.
- The fresh start that finally replaced it truncated the daemon's `stderr.log`, and with it the supervisor's one line saying why the host was unreachable.

### Why an extension could not handle it

- Endpoint ownership, the ensure decision and the daemon log are rpc host lifecycle internals that run before any extension loads.

### Expected merge conflict zones

- LOW: `host-ensure.ts` `ensureHostLocked`, the `registered && pidMatches` branch (now one call).
- LOW: `host-ensure-start.ts`, the `stderr` open in `startHost`.

### Fixed
- `host ensure` no longer refuses forever to replace a registered host whose process is alive but whose socket accepts connections and then closes them unanswered (or answers only `host_unavailable`). When this process started that host, or the process that registered it no longer exists, the host is stopped and a fresh one is started. A host that holds the connection silent (busy) is still never replaced. A fresh start now keeps the previous daemon log as `stderr.prev.log` instead of truncating it ([#7553](https://github.com/code-yeongyu/senpi/pull/7553))
