## 2026-11-11 - A client can ask what an unload would do, and holds are counted per client (senpi#6443)

### What changed

- `packages/coding-agent/src/modes/rpc/session-unload.ts`: `unload_session { dryRun: true }` answers what the real call would do now and changes nothing. It returns before the effect ledger and before anything is interrupted: `outcome: "ready"` or `"refused"` with the reason, detail and action the real call would carry, plus `blockers` (every standing one, in the order the real call checks them) and `interruptible` (what this call would interrupt instead). A dry run that carries an `effectId` the session already recorded is answered from the ledger's own check, as the real call is: the recorded replay for the same payload, `effect_id_conflict` for another payload or another kind of effect.
- `packages/coding-agent/src/modes/rpc/session-router-attachments.ts`: `otherAttachments` excludes every connection of the CALLER'S CLIENT, not only the asking connection, so the `attached` refusal of `unload_session` and `release_session` counts other clients. A connection's declared name ends with its incarnation: it is forgotten at every release of the connection, a `detach_connection` as well as a drop, whatever the connection held and whether or not the host is draining.
- `packages/coding-agent/src/modes/rpc/session-router-routing.ts`: hands every `set_client_info` to the declaration module (`preDeclare` under the compact flag, `declareSessionless` for a declaration with no `sessionId`), which keeps a name only once the declaration was accepted; and reads `otherAttachments` from the attachments module.
- `packages/coding-agent/src/modes/rpc/session-router-context.ts`, `packages/coding-agent/src/modes/rpc/compact-socket-commands.ts`: the client each connection declared (`clientIds`). `compact-socket-commands.ts` keeps it for a declaration that ends at the host (`declareSessionless`, `preDeclare`), only after that declaration was accepted; within one incarnation a later declaration without `client_id` keeps the name.
- `packages/coding-agent/src/modes/rpc/compact-negotiation.ts`, `packages/coding-agent/src/modes/rpc/connection-handler.ts`, `packages/coding-agent/src/modes/rpc/session-router-open.ts`: a declaration that goes on to its session is kept by that session, when it accepts it, through the client-info port's new `setClientId`; `sessionDeclaration` refuses a declaration that carries `client_id` under a retired incarnation as `delegation_incarnation_stale`, capabilities or not. A session in a worker isolate has no such port: unload and release do not apply to it, so nothing reads a name there.
- `packages/coding-agent/src/modes/rpc/effect-ledger.ts`, `packages/coding-agent/src/modes/rpc/effect-answers.ts` (new), `packages/coding-agent/src/modes/rpc/effect-commands.ts`, `packages/coding-agent/src/modes/rpc/handlers-model.ts`: `EffectLedger.recorded` is `begin`'s own check for an id it already holds, without recording, and `recordedEffect` maps its conflict to the same refusal `beginEffect` gives. The response builders and those two moved, unchanged, from `effect-commands.ts` to `effect-answers.ts`, which brings `effect-commands.ts` back under the file-size ceiling.
- `packages/coding-agent/src/modes/rpc/rpc-client.ts`: `RpcClient.setClientInfo(width, capabilities?, clientId?)` can send the name; a bound client sends it with its `sessionId`, the form the router now records.
- `packages/coding-agent/src/modes/rpc/rpc-session-command-types.ts`, `rpc-host-command-types.ts`, `rpc-input-validation.ts`, `method-classes-schema-session.ts`, `method-classes-schema-host.ts`: the `client_id` and `dryRun` fields, their bounds and their schemas.
- `packages/coding-agent/src/modes/rpc/rpc-effect-answer-types.ts`, `host-capabilities.ts`, `packages/coding-agent/docs/rpc.md`: the dry run's answer shape and the capabilities `unload_session_dry_run` and `client_identity`.

### Why

- A client that must stop work of its own before it unloads (cancel child tasks, take queued input back, stop the run) could not ask whether the unload would be refused: it did that work first and learned only from the refusal, leaving the session running for nobody.
- A `list_sessions` row counts the asking client's own attachment, and the refusal counted per connection, so one client holding a session through two of its own connections was told another client held it.

### Why an extension could not handle it

- Both are the host's own attachment bookkeeping and refusal path.

### Expected merge conflict zones

- LOW: `otherAttachments` in `session-router-attachments.ts`, the `set_client_info` line in `admitted` (`session-router-routing.ts`), the blocker list in `session-unload.ts`, the capability list in `host-capabilities.ts`.

### Added

- `unload_session { dryRun: true }` answers what the unload would do now - `ready`, or the refusal it would give, with every standing blocker and what it would interrupt - and changes nothing. Holds are counted per client: a connection that sends `set_client_info { client_id }` is the same client as every other connection carrying that id, so a client's own second connection is never "another client" for the `attached` refusal. Capabilities `unload_session_dry_run` and `client_identity` ([#6453](https://github.com/code-yeongyu/senpi/pull/6453)).
