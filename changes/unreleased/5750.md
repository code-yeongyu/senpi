## 2026-11-04 - /resume of a session a live process holds asks to cancel or take over (senpi#5750, fixes #5744)

### What changed

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: `handleResumeSession` checks live foreign holders (`checkSessionHolders`) before `runtimeHost.switchSession`. With a holder, a selector names it (`pid N in "<folder>"`) and offers `Cancel` or `Take over (stop it there)`. Cancel returns `{ cancelled: true }` and switches nothing. Take over calls `stopSessionHolders`, which signals each holder and waits until the session is free, then resumes; a holder that does not exit in time leaves the resume refused. A failed lookup stays advisory: the pre-switch result drives the same `Unable to inspect session holders` warning after the switch.
- `packages/coding-agent/test/suite/regressions/5744-resume-refuses-held-session.test.ts` (new): a real holder process plus a real `InteractiveMode` resume, with both choices.
- `packages/coding-agent/test/suite/regressions/issue-2951-resume-warning.test.ts`: keeps only the lookup-error case. The live-holder case moved to the 5744 test because the warn-and-switch it pinned is replaced.

### Why

- The TUI switched onto a session a live process was running and only warned. The restored lifecycle then read that process's live run as `interrupted_run`, so the next input started a second run of the same session, re-sending the in-flight prompt while the other process was still running it. The RPC host already refused this (#2951).

### Why an extension could not handle it

- `/resume` and extension `ctx.switchSession` both go through the interactive controller's `handleResumeSession`. An extension cannot gate the built-in picker's switch.

### Expected merge conflict zones

- LOW: the head of `handleResumeSession` and its two post-switch warning sites; the `foreign-session-holders` import block.

## 2026-11-04 - Holder check and take-over for interactive resume (senpi#5750, fixes #5744)

### What changed

- `packages/coding-agent/src/core/foreign-session-holders.ts`: adds `checkSessionHolders` (one lookup whose failure is reported, not thrown), `stopSessionHolders` (SIGTERM each validated holder, then wait for the holder records to clear, 10 s default), `describeSessionHolders` (the shared `pid N in "<cwd>"` text) and `SESSION_HOLDER_LOOKUP_FAILED`. `sessionHolderWarning` uses the shared text.

### Why

- Interactive resume needs the holder set before it switches, and an explicit take-over path, so it never becomes a second writer.

### Why an extension could not handle it

- Holder records and their identity validation are core session-persistence state.

### Expected merge conflict zones

- LOW: the helpers between `foreignSessionHolders` and `sessionHolderWarning`.
