## 2026-11-02 - todo corrects near-canonical init shapes before validation (senpi#5332)

### What changed

- `normalize.ts`: `prepareTodoArguments` now rewrites six near-canonical `init` shapes before schema validation. Phase records nested inside `list[i].items` (or inside top-level `items` on an explicit `op: "init"`) are promoted to phases, and `{content}` item records become their string. A phase with tasks but no name gets a default name, an empty phase is dropped, a JSON-string `list` is parsed, stray strings in `list` are dropped, and an `op` with stray leading or trailing punctuation is trimmed to the known op; `rm`, `done`, `drop` and `start` are only corrected when the call names a `task` or `phase`, so a correction never turns into a bulk change. Each rewrite adds an `[auto-corrected]` notice under a reserved string key that is trusted only when `prepareTodoArguments` set it. A call no rule changes comes back as the same reference, and a rewrite that would leave `list` empty is abandoned.
- `tools/todo.ts`: `execute` strips the reserved key with `splitPreparedCorrections` and prepends its notices to the corrections.
- `prompt.ts`: the `init` row states that each `list` entry is one phase and that `items` holds only task strings.

### Why

- senpi#5332: schema validation runs before `execute`, so these shapes failed with `Validation failed for tool "todo"` and never reached the execute-time correction. A transcript scan found 78 such failures in 75 sessions, mostly from GLM and Kimi models.

### Why an extension could not handle it

- `prepareArguments` belongs to the tool definition this builtin registers; no extension hook sits between the provider stream and another tool's validation.

### Expected merge conflict zones

- LOW: `prepareTodoArguments` and the helper block in `normalize.ts`, the `execute` prologue in `tools/todo.ts`, and the `init` row in `prompt.ts`.

### Fixed
- The todo tool now accepts near-canonical `init` calls (phases nested inside `items`, nameless or empty phases, a JSON-string `list`, stray strings in `list`, an `op` with stray leading or trailing punctuation), corrects them, and reports each correction instead of failing validation ([#5336](https://github.com/code-yeongyu/senpi/pull/5336))
