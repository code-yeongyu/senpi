### Added
- `move_session` op `copy` (capability `move_session_copy`): copies a session into a new, writable session under a caller-chosen id, so work can go on from a session that is read-only here (moved away, or a revoked import) ([#5889](https://github.com/code-yeongyu/senpi/issues/5889)).

## 2026-11-05 - Copy a read-only session into a new session (senpi#5889)

### What changed

- `packages/coding-agent/src/core/session-move/copy.ts` (new): `copySessionAs` reads the source header's `cwd`, refuses
  the source's own id (`invalid_move_request`) and an id a session file in the target folder already carries
  (`move_target_occupied`), then writes the copy with `SessionManager.forkFrom(source, cwd, dir, { id })`, serialized per
  folder and id in this process.

### Why

- A revoked import or a session that moved away refuses every write, and a client had no RPC to keep working from it:
  `fork`/`clone` rebind the open session in place, and `forkFrom` was reachable only from the CLI.

### Why an extension could not handle it

- Session files and the move ownership fold are core; an extension cannot mint a session file the host's routing knows.

### Expected merge conflict zones

- None upstream: `core/session-move/` is fork-only.

## 2026-11-05 - move_session op copy (senpi#5889)

### What changed

- `packages/coding-agent/src/modes/rpc/session-move-request.ts` (new): the `move_session` request parser, moved out of
  `session-move-commands.ts` unchanged, plus op `copy` (`sessionPath`, plain `sessionId`, absolute `sessionDir?`).
- `packages/coding-agent/src/modes/rpc/session-move-commands.ts`: runs `copy` through `copySessionAs` (default folder:
  this host's session folder for the source's `cwd`) and passes `invalid_move_request` from the core through.
- `packages/coding-agent/src/modes/rpc/session-move-wire.ts`, `method-classes-schema-host.ts`, `host-capabilities.ts`:
  the `copy` op type and schema, and the advertised `move_session_copy` capability.
- `packages/coding-agent/docs/rpc.md`: the `copy` row and paragraph.

### Why

- omo-desktop-app#4049 offers "Copy to a new thread" on a sealed copy; the copy must be a new session under the new
  thread's id, with the open session left as it is.

### Why an extension could not handle it

- `move_session` and its capability list are the RPC host's own surface.

### Expected merge conflict zones

- LOW: the `move_session` union in `method-classes-schema-host.ts` and `session-move-wire.ts`, the capability list in
  `host-capabilities.ts`.
