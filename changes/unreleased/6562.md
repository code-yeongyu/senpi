## 2026-11-12 - A reclaim lock's live holder is judged by its start time before its boot instant (senpi#3152)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/lease-file.ts`: `reclaimLockState` judges a live holder pid by its process start time first; the boot instant decides only when the start time cannot be read.

### Why

- A wall-clock step moves the kernel's recorded boot instant, so a live holder whose record predates a step past the 120 s tolerance read as another boot to a process holding the moved instant, and its lock was broken (senpi#3152, review of #6530).

### Why an extension could not handle it

- The reclaim lock is the builtin terminal's own lease machinery.

### Expected merge conflict zones

- LOW: `reclaimLockState` in `lease-file.ts`.

## 2026-11-12 - The resident writer probe checks its gone set first and judges a live writer by its start time (senpi#3152)

### What changed

- `packages/coding-agent/src/modes/rpc/host-handover-resident-writer.ts`: the reopen watch's probe checks its `gone` set before any boot read, so a gone writer no longer re-reads the kernel record (a `sysctl` spawn on macOS) on every 250 ms poll; a live same-host writer is judged by its process start time first, the boot instant only when that cannot be read.

### Why

- Review LOWs on #6530 (senpi#3152): the extra kernel reads per poll, and a live writer recorded before a wall-clock step past the tolerance read as another boot.

### Why an extension could not handle it

- The RPC host handover is host internals.

### Expected merge conflict zones

- LOW: `residentWriterProbe`.
