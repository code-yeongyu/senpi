## 2026-11-07 - Cursor logins renew through the IDE refresh grant (senpi#6155)

### What changed

- `packages/ai/src/auth/oauth/cursor.ts`: a login session now renews with a `refresh_token` grant to `https://api2.cursor.sh/oauth/token` using the Cursor IDE's public OAuth client id, and reads the snake_case `access_token`/`refresh_token` response. A `200` response with `shouldLogout: true` throws `OAuthReauthorizationRequiredError("invalid_grant")`, so the credential pool disables the row as a verdict on the login instead of retrying it as transient.
- `packages/ai/src/auth/oauth/cursor.ts`: a dashboard user API key (stored refresh token starting with `crsr_`) still trades at `auth/exchange_user_api_key` with the previous Bearer exchange and camelCase response; login sessions never use that endpoint anymore.

### Why

- senpi#2919 (port of upstream oh-my-pi#14753): every Cursor refresh sent the session token to the API-key exchange, which answers "Invalid User API Key", so logins lapsed about 60 days after sign-in while staying listed as active.

### Why an extension could not handle it

- The Cursor OAuth flow is a bundled builtin in `packages/ai/src/auth/oauth/`; no extension hook owns the refresh grant, the token endpoint, or the reauthorization error mapping.

### Expected merge conflict zones

- LOW: `refreshCursorCredential` and the Cursor refresh tests in `packages/ai/test/cursor-oauth.test.ts`; MEDIUM if upstream reworks the Cursor OAuth flow (the client id and token endpoint are upstream's).
