## 2026-11-15 - sessionBound means the tool cannot run without the session's record (senpi#6749)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: the `ToolDefinition.sessionBound` doc states the rule. A tool is session-bound when it cannot run without the calling session's record: entries, active tools, system prompt options, goal, scheduled prompts or placement. A tool whose only tie to the session is a later wake (a background command's exit or a monitor event, i.e. late results) or device-local state keyed by the session's id is not. The terminal's background `bash` and `monitor` stay unbound.

### Why

- Review L1 of #6757 asked whether the terminal tools belong in the set. They run on a hand that has no session, and they read none of the record the session port carries. Their wakes are late results (H3, senpi#5778), and their manifest is a sidecar under the session dir, which the carried session does not provide.

### Why an extension could not handle it

- The field's contract is part of the extension API's tool definition.

- LOW: the `sessionBound` doc comment in `ToolDefinition`.
