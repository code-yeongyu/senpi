## 2026-11-15 - Every remote call names its loop session (senpi#6754)

### What changed

- `packages/agent/src/execution/remote-protocol.ts`: `RemoteInvoke.sessionId?` (the calling loop session's id; identity only, never the record).
- `packages/agent/src/execution/remote-executor.ts`: `HandCall.sessionId?` passes it to the scope.
- `packages/agent/src/execution/remote-tool-host.ts`: `RemoteSessionPort.sessionId()`; every invoke of a session with a port carries it.

### Why

- Tools on the hand that key by session (`monitor`'s `children` target) need the session's identity on every call, not only on calls that carry the session record (ruling for #6773).

### Why an extension could not handle it

- It is agent-core's wire.

### Expected merge conflict zones

- LOW: `RemoteInvoke`, `HandCall`, `invokeOf` in `createRemoteToolHost`.

## 2026-11-15 - The session port carries documents, wakes and relocation; hand-written entries reach clients (senpi#6754)

### What changed

- `packages/coding-agent/src/core/hand/session-state-effects.ts` (new): closed parsers for session documents (paths inside the session directory only), wakes and a relocation request.
- `packages/coding-agent/src/core/hand/session-effects.ts`: `SessionEffects` gains `documents`, `wakes`, `relocation`; duplicate names in an active-set change are refused and `applyActiveToolsChange` dedupes.
- `packages/coding-agent/src/core/session-wakes.ts` (new): `SessionWake` (`id`, `source`, `dueAt`, `everyMs?`, `prompt`, `createdAt`, `entry?`; no key material), `SessionWakeChange`, `SessionWakePort`.
- `packages/coding-agent/src/core/session-control-actions.ts`: `sessionWakes()` (undefined for a session in this process) and `callSessionControlActions`, `pi.session` for a runtime without a session: relocation and wakes answer from the call's carried session.
- `packages/coding-agent/src/core/agent-session.ts`: `appendCustomSessionEntry` appends a custom entry and emits `entry_appended`, as `pi.appendEntry` does (which now uses it).

### Why

- A hosted loop's goal, schedule and relocation tools run on the hand: their state stays with the loop's session, a wake never carries key material, and an entry a hand writes reaches attached clients (review L1/L3 on #6762).

### Why an extension could not handle it

- These are the session port's contract and the session's own write path.

### Expected merge conflict zones

- LOW: new files; `createSessionControlActions`; `getActiveToolNames` neighbourhood in `agent-session.ts`.
