## 2026-11-02 - Ctrl+J inserts a newline in macOS Terminal.app (code-yeongyu/oh-my-openagent#9796, PR #5538)

### What changed

- `packages/tui/src/terminal.ts`: `normalizeAppleTerminalLineFeedInput(data, env, platform)` maps a lone LF to the native Shift+Enter sequence in a local Terminal.app session (`darwin`, `TERM_PROGRAM=Apple_Terminal`, no `SSH_CONNECTION`/`SSH_CLIENT`/`SSH_TTY`); any other input or terminal is returned unchanged.
- `packages/tui/src/components/editor.ts`: `handleInput` applies it right after the Warp-on-WSL normalization, with the editor's injected terminal environment and platform.

### Why

- Terminal.app sends CR for Return and LF only for Ctrl+J. In legacy key mode a lone LF matches both `enter` and `ctrl+j`, and the editor checks submit before newline, so the documented Ctrl+J newline submitted the prompt. LF stays Enter elsewhere because some terminals send LF for Return.

### Why an extension could not handle it

- Input normalization runs inside the TUI editor before keybinding matching; extensions only see the submitted text.

### Expected merge conflict zones

- LOW: the normalizer block before `keyboardEnhancementEnabled` in `terminal.ts`; the first lines of `Editor.handleInput` and the `../terminal.ts` import in `editor.ts`.
