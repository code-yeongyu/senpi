## 2026-11-02 - Claude CLI login output is read as the CLI prints it (senpi#5360)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/claude-cli-auth.ts`: `SUCCESS_LINE` no longer anchors at line start, and `MANUAL_URL_LINE` also reads the OSC 8 hyperlink form of the copy-code URL.
- `packages/coding-agent/test/fixtures/claude-cli-auth/fake-claude.mjs`: prints `Login successful.` without a leading newline and the copy-code URL as an OSC 8 hyperlink, as Claude Code 2.1.306 does.

### Why

- Claude Code writes `Login successful.` on the line of its unterminated `Paste code here if prompted > ` prompt, so every successful login settled as `unexpected_exit` and was rolled back. It wraps the copy-code URL in OSC 8 even with `NO_COLOR=1`, so `onManualUrl` never fired.

### Why an extension could not handle it

- The parsing lives in the builtin extension's own module; only its source can change it.

### Expected merge conflict zones

- LOW: `claude-cli-auth.ts` pattern constants and the `onManualUrl` call in the stdout handler; `fake-claude.mjs` login output lines.
