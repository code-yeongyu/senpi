## 2026-11-02 - Admit resume candidates before transferring ownership (senpi#1473)

### What changed

- `packages/coding-agent/src/core/session-manager.ts`: `prepareOpen` asynchronously reads a non-persisting candidate, buffers migration and appends, and validates canonical identity, exact destination bytes and its write fence before committing under the existing host write grant. Preparation has no evictable blob backing; publication excludes local competing writes and freezes further candidate mutations. Same-file reconciliation checks the original write fence rather than adopting a later owner's fence.
- `packages/coding-agent/src/core/session-entry-file.ts`: asynchronous resume loading fingerprints the exact bytes it parses, including skipped malformed/blank lines, and records an unterminated final segment from that same read without a second transcript-sized buffer.
- `packages/coding-agent/src/core/session-resume-file.ts`: strict asynchronous staging, file sync, rename and directory sync report the publication boundary without changing ordinary rewrite behavior. The published transcript base captures its actual line-content fingerprint and file identity.
- `packages/coding-agent/src/core/session-manager.ts`, `packages/coding-agent/src/core/session-resume-file.ts` and `packages/coding-agent/src/core/session-write-recovery.ts`: acceptance terminates a valid final record even when the SDK stages no append; incomplete final bytes are atomically backed up before removal, retaining the existing recovery notice and subsequent-append behavior.
- `packages/coding-agent/src/core/session-write-reservation.ts`: a publication waits for earlier asynchronous header writes, excludes local writers through the existing reservation funnel, and stays visible to weak-writer grant reconciliation across awaits. Releasing it and reconciling the source happen in one synchronous segment before the commit promise settles.
- `packages/coding-agent/src/core/agent-session-runtime.ts`: cancellation precedes preparation, trust and factories. Resume constructs the actual SDK candidate before outgoing teardown, then commits, retires the source and promotes that candidate. Failed candidates release their own hold and manager. Busy same-file resumes cancel; accepted same-file resumes refresh around shutdown writes.
- `packages/coding-agent/src/core/agent-session.ts`: prepared sessions own local subscriptions, their tool-search service and manager, but not provider resources or MCP presentations keyed by their borrowed session ID. Promotion makes those resources owned; SDK rejection uses the same disposal contract.
- `packages/coding-agent/src/core/resume-preparation.ts`, `packages/coding-agent/src/core/agent-session-services.ts` and `packages/coding-agent/src/core/sdk.ts`: one preparation scope owns factory resources and constructed sessions, including failures before construction and after SDK return. Candidate construction uses private model runtimes and validates selected configuration-file revisions.
- `packages/coding-agent/src/core/agent-session-services.ts`: trust is fenced before asynchronous resource loading, or immediately after the candidate's own trust resolver returns its decision. Revocation during loading rejects the stale generation without rejecting a legitimate newly saved trust decision.
- `packages/coding-agent/src/core/model-runtime.ts`, `packages/coding-agent/src/core/runtime-credentials.ts` and `packages/coding-agent/src/core/auth-storage.ts`: private runtime forks copy provider and credential overlays while keeping settings listeners, concurrency controls and OAuth registrations independent from the outgoing/shared runtime.
- `packages/coding-agent/src/core/session-resume-conflict.ts`: typed recoverable refusals for changed targets and other failures while the outgoing runtime still owns its session.

### Why

- `packages/coding-agent/src/core/agent-session-runtime.ts`, `packages/coding-agent/src/core/agent-session.ts`, `packages/coding-agent/src/core/session-manager.ts` and `packages/coding-agent/src/core/session-resume-conflict.ts`: SDK admission can fail after construction. Tearing down the outgoing session first left an unusable runtime; ordinary destination opens also repaired or appended to files before admission. Same-ID candidate disposal could clear the still-live source's resources.
- `packages/coding-agent/src/core/model-runtime.ts`, `packages/coding-agent/src/core/runtime-credentials.ts`, `packages/coding-agent/src/core/auth-storage.ts`, `packages/coding-agent/src/core/agent-session-services.ts`, `packages/coding-agent/src/core/sdk.ts` and `packages/coding-agent/src/core/resume-preparation.ts`: mutating shared settings listeners or provider registrations during construction cannot be repaired by disposal alone; candidate state must remain private.
- `packages/coding-agent/src/core/session-resume-file.ts`, `packages/coding-agent/src/core/session-write-reservation.ts` and `packages/coding-agent/src/core/session-entry-file.ts`: partial appends can strand a source's leaf, separate parsing/fingerprint reads can describe different bytes, and unguarded asynchronous publication can overwrite another local writer or lose its host grant during an await.
- `packages/coding-agent/src/core/session-write-recovery.ts`: preserving preparation bytes must not lose the ordinary torn-tail backup and recovery notice when acceptance makes the target appendable.

### Why an extension could not handle it

- `packages/coding-agent/src/core/agent-session-runtime.ts`, `packages/coding-agent/src/core/agent-session.ts`, `packages/coding-agent/src/core/session-manager.ts` and `packages/coding-agent/src/core/session-resume-conflict.ts` own construction, persistence, resource lifetime and the acceptance boundary before extension startup.
- `packages/coding-agent/src/core/model-runtime.ts`, `packages/coding-agent/src/core/runtime-credentials.ts`, `packages/coding-agent/src/core/auth-storage.ts`, `packages/coding-agent/src/core/agent-session-services.ts`, `packages/coding-agent/src/core/sdk.ts`, `packages/coding-agent/src/core/resume-preparation.ts`, `packages/coding-agent/src/core/session-resume-file.ts`, `packages/coding-agent/src/core/session-entry-file.ts` and `packages/coding-agent/src/core/session-write-reservation.ts` own the factory's shared infrastructure and durable publication boundary.
- `packages/coding-agent/src/core/session-write-recovery.ts` owns the shared recovery notice for ordinary writes and accepted prepared publication.

### Expected merge conflict zones

- `packages/coding-agent/src/core/session-manager.ts`: constructor, persistence and static opening methods.
- `packages/coding-agent/src/core/agent-session-runtime.ts`: `switchSession`.
- `packages/coding-agent/src/core/agent-session.ts`: constructor, tool-search adoption, disposal and promotion.
- `packages/coding-agent/src/core/session-resume-conflict.ts`: the error class.
- `packages/coding-agent/src/core/model-runtime.ts`, `packages/coding-agent/src/core/runtime-credentials.ts` and `packages/coding-agent/src/core/auth-storage.ts`: private runtime/credential construction.
- `packages/coding-agent/src/core/agent-session-services.ts`, `packages/coding-agent/src/core/sdk.ts` and `packages/coding-agent/src/core/resume-preparation.ts`: factory resource ownership and admission setup.
- `packages/coding-agent/src/core/session-resume-file.ts`: asynchronous publication.
- `packages/coding-agent/src/core/session-entry-file.ts`: asynchronous load fingerprint capture.
- `packages/coding-agent/src/core/session-write-reservation.ts`: publication exclusion and live grant enumeration.
- `packages/coding-agent/src/core/session-write-recovery.ts`: recovery notice shared with asynchronous resume-tail backup.

## 2026-11-02 - Publish only admitted tool-search owners (senpi#1473)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/tool-search/service.ts`: provider-scope lookup names the live owner, rather than an async context retaining a retired service. Candidate adoption is private until activation; disposal removes only its own publication.
- `packages/coding-agent/src/core/extensions/builtin/tool-search/index.ts`: loading creates an extension-owned service without replacing the outgoing scope. Session startup or a sessionless runtime's first use publishes it.

### Why

- Preparing a replacement must not redirect live lookups or cause sessionless lookups to see two active owners.

### Why an extension could not handle it

- These are the builtin's own ownership registry and boot points.

### Expected merge conflict zones

- `packages/coding-agent/src/core/extensions/builtin/tool-search/service.ts`: service disposal, adoption and scoped lookup.
- `packages/coding-agent/src/core/extensions/builtin/tool-search/index.ts`: first-use boot and default factory.

## 2026-11-02 - Candidate loading leaves shared MCP state alone (senpi#1473)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`: shared-service observers and native-search gates activate on attach, not extension load. Unstarted generations do not shut down the shared service.

### Why

- A candidate may never start. Its loading must neither replace the outgoing native-search gate nor retain subscriptions on a shared MCP service.

### Why an extension could not handle it

- This is the MCP builtin's own initialization.

### Expected merge conflict zones

- `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`: attach setup and shutdown handler.
