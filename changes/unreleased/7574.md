## 2026-11-27 - The read path variants take an injected existence check (senpi#4565, senpi#7574)

### What changed

- `packages/coding-agent/src/core/tools/path-utils.ts`: `resolveReadPathWith(filePath, cwd, exists)` is `resolveReadPath` over an injected existence check; `resolveReadPath` keeps its synchronous one. The permission parser passes its prefetched path facts, so classifying a `read` call no longer stats the path on the host thread.

### Why

- The permission decision runs on the host thread for every tool call; a synchronous probe of a path on a mount that does not answer froze the host (senpi#4565).

### Why an extension could not handle it

- The read tool and the permission parser share this resolver; both must agree on the file a read opens.

### Expected merge conflict zones

- LOW: `path-utils.ts`, the head of `resolveReadPath`.

## 2026-11-27 - The open-free walk takes injected lstat/readlink; canonicalizePath is gated (senpi#4565, senpi#7574)

### What changed

- `packages/coding-agent/src/utils/paths.ts`: `realpathWithoutOpenWith` / `realpathWithoutOpenStrictWith` walk over an injected `OpenFreeWalkIo`; `realpathWithoutOpen` / `realpathWithoutOpenStrict` keep the synchronous calls inline in their own bodies, so the no-sync audits still see every caller that makes them. `canonicalizePath` answers a path under an unmounted macOS automount verbatim and `canonicalizePathStrict` refuses it (`EAUTOMOUNT`) before `realpathSync.native`.

### Why

- The permission decision and the monitor registration resolve caller paths on the host thread; they now walk over facts fetched off it (senpi#4565). `canonicalizePath` is reached with a session's cwd.

### Why an extension could not handle it

- The walker and `canonicalizePath` are shared utilities called from core and builtin code.

### Expected merge conflict zones

- LOW: `paths.ts`, `resolveWithoutOpen`'s signature and the two canonicalize helpers.
