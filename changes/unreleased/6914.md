## 2026-11-18 - A terminal that attaches to a host-held session applies its command line (senpi#6914)

### What changed

- `packages/coding-agent/src/cli/held-session-attach.ts` (new): `heldSessionAttachPlan(parsed, { autoResizeImages })` turns the command line of an attaching start into an `AttachStartup`. The first prompt carries the `@file` text and images before the first message, and the other messages follow. `--provider/--model` or `--model <provider>/<id>[:<thinking>]` becomes the model, and `--thinking` the level. A model pattern, or a model without a provider, refuses the start. So does every flag that configures the process running a session (`UNAPPLIED_FLAGS`: `--system-prompt`, `--append-system-prompt`, `--api-key`, `--models`, the tool flags, `--tool-runtime`, the extension, skill, prompt-template, theme and context-file flags, `--name`, `--offline`, `--approve`/`--no-approve`, `--verbose`, `--grok-neo`, `-` (stdin)), plus any unknown or extension flag. The refusal names each one, since the host already runs the session with its own configuration.

### Why

- senpi#6911 L1: the attach path of senpi#6909 dropped the prompts, `--model`, `--thinking`, `--use-theme` and `--tui-mode` without a word.

### Why an extension could not handle it

- Startup admission runs before any extension loads.

### Expected merge conflict zones

- None: new file.

## 2026-11-18 - The attaching start passes its command line; both ends must be a terminal (senpi#6914)

### What changed

- `packages/coding-agent/src/main.ts`: `admitOrExit(sessionFile, appMode, attach?)` takes the command line (`HeldSessionAttach`) from `createSessionManager`. An attach admission builds the plan (a refusal exits 1 with a notice) and runs `runAttachedTui` with the socket, session, `tuiMode`, `theme` and `startup`. Without the context (a rebind), it never attaches. `canAsk` now also requires stdout to be a terminal.

### Why

- senpi#6911 L1 and L4: the command line reaches the attached session, and `omo --session X > log` keeps the exit-76 refusal instead of failing in the attached view's terminal check.

### Why an extension could not handle it

- Mode dispatch happens in `main.ts` before extensions load.

### Expected merge conflict zones

- LOW: `admitOrExit`, `openSessionOrExit` and the top of `createSessionManager`.

## 2026-11-18 - hostAttachSocket refuses an unproven holder (senpi#6914)

### What changed

- `packages/coding-agent/src/core/foreign-session-holders.ts`: `hostAttachSocket` returns nothing when any holder is `unproven`, so the "could not be verified" refusal applies, as it does for take-over.

### Why

- senpi#6911 L3: a stale or reused-pid host record led to a failed dial (exit 1) where the clear refusal used to be.

### Why an extension could not handle it

- Holder records are core session ownership.

### Expected merge conflict zones

- LOW: `hostAttachSocket`.

## 2026-11-18 - The attached TUI applies a start's model, thinking and prompts (senpi#6914)

### What changed

- `packages/coding-agent/src/modes/interactive/attach-startup.ts` (new): `applyAttachStartup(request, sessionId, startup)` sends `set_model` with `scope: "session"` (only this session's model, as a local `--model`; the device's saved default stays), then `set_thinking_level`, then each prompt as `prompt` with `streamingBehavior: "followUp"`. A host refusal rejects, so the prompts never run on a model the session refused.
- `packages/coding-agent/src/modes/interactive/attach.ts`: `connect(address, ref, startup?)` applies the startup once the history is shown.
- `packages/coding-agent/src/modes/interactive/run-attached-tui.ts`: takes `startup` and passes it to `connect`.

### Why

- senpi#6911 L1: a terminal start's command line becomes the attached session's own commands.

### Why an extension could not handle it

- The attached TUI loads no extensions.

### Expected merge conflict zones

- LOW: the end of `connect()` in `attach.ts`; the options of `runAttachedTui`.
