## 2026-11-10 - A continuation that resumes after the run settled is an active run (senpi#6345)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: new `_beginActiveRun()`, the one place that enters the active-run bracket `isStreaming` reports (turn admission, queued-input ages, `_isAgentRunActive`). `_promptAgent()` uses it in place of its inline copy.
- `packages/coding-agent/src/core/agent-session.ts`: `_continueAgentAfterCurrentRun()` calls `_beginActiveRun()` before it continues the agent. The continued run's `agent_end` settles the bracket through `_emitAgentSettled()` as usual, and a continuation that starts no run closes the bracket it opened. The `runBoundedRetryContinuation` call moved, unchanged, into the new `_runContinuation()`.

### Why

- An extension-triggered compaction (the built-in context-reduction handoff calls `ctx.compact()`) aborts the active run, which settles, and then resumes the queued messages through `_continueAgentAfterCurrentRun()`. That path never re-entered the bracket, so `isStreaming` stayed `false` while the agent visibly worked.
- As a result, Esc did not interrupt the continuation, and a double Esc opened `/tree`. Typed input took the idle path: it rendered as a plain bubble instead of a `Steering:` row, and it waited on the session-work barrier until the continuation ended (senpi#6345).

### Why an extension could not handle it

- The active-run bracket and the continuation choke point are private to `AgentSession`. A TUI-side guess would leave RPC `get_state`, `currentTurnId` and prompt admission wrong.

### Expected merge conflict zones

- LOW: the bracket lines in `_promptAgent()`, and the `runBoundedRetryContinuation` call that moved into `_runContinuation()`.
