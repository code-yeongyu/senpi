## 2026-11-14 - The registry preflight tests set their own ref (senpi#6690)

### What changed

- `scripts/registry-preflight.test.mjs`: the stub environment strips `GITHUB_ACTIONS` and `GITHUB_REF`, so no spawned `release.mjs`/`publish.mjs` inherits the runner's pair. `runRelease` sets the pair per case: a live run from `refs/heads/main` by default (the registry preflight sits behind the live-run ref guard), and a new case dispatches `refs/pull/6532/merge` and asserts the refusal before the suite, any tag and any push, with the unknown-name preflight not what stopped it. The `publish.mjs` case keeps the explicit pair it already set.

### Why

- The two `release.mjs registry preflight` cases inherited the CI job's `GITHUB_REF`, so on every pull-request run the senpi#6645 ref guard stopped `release.mjs` before the registry preflight the cases test (senpi#6690); main's own run was green only because its ref is `refs/heads/main`.

### Why an extension could not handle it

- Release tooling tests; extensions do not run in them.
