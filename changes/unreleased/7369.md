## 2026-11-22 - An empty print run fails with a usage error (senpi#3521)

### What changed

- `packages/coding-agent/src/main.ts`: print and JSON launches prepare input after applying typed extension flags. If there is no prompt, stdin, `@file` content or later message, they report a usage error and exit 1 before starting the model runtime or creating the agent session.

### Why

- `senpi -p` with nothing to send exited 0 without output, so a caller could not tell it from a quiet success.

### Why an extension could not handle it

- Argument handling and mode dispatch happen in the CLI entry before extensions run.

### Expected merge conflict zones

- LOW: the launch-input preparation in `main.ts`.

## 2026-11-22 - Validate print input before model startup (senpi#3521)

### What changed

- `packages/coding-agent/src/core/agent-session-services.ts`: let print and JSON launches validate input after loading resources and applying typed flags, before starting the model runtime. Other launches still load resources and models in parallel.

### Why

- An empty invocation does not need to resolve or admit a model to report a usage error.

### Why an extension could not handle it

- The CLI owns input preparation; the services bootstrap owns model startup.

### Expected merge conflict zones

- LOW: resource and model startup in `packages/coding-agent/src/core/agent-session-services.ts`.

## 2026-11-22 - `hasPrintInput` for the empty print check (senpi#3521)

### What changed

- `packages/coding-agent/src/cli/initial-message.ts`: new `hasPrintInput(initial, laterMessages)`, true for a prompt, piped stdin, `@file` text or images, or a later message.

### Why

- `main.ts` uses it to refuse a print run that has nothing to send instead of exiting 0 silently.

### Why an extension could not handle it

- It is part of CLI argument handling.

### Expected merge conflict zones

- LOW: the end of `cli/initial-message.ts`.
