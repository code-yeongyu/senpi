## 2026-10-29 - Disposed sessions do not settle pending input releases (senpi#4670)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_settleInputRelease` returns immediately after disposal, before restoring holds or emitting release events.

### Why

- `packages/coding-agent/src/core/agent-session.ts`: an extension command can replace its held session before the old prompt's `finally` settles the release. That settlement must not write through the disposed session manager or invoke its stale extension runner.

### Why an extension could not handle it

- `packages/coding-agent/src/core/agent-session.ts`: core owns the prompt finalizer and its pending release, after the replacing command has already relinquished the old session.

### Expected merge conflict zones

- LOW: the initial guard in `_settleInputRelease` in `packages/coding-agent/src/core/agent-session.ts`.
