## 2026-11-23 - Tool-search default: first-party Anthropic endpoint only, Mythos included (senpi#7257)

### What changed

- `packages/ai/src/utils/prompt-cache-ttl.ts`: the default `supportsToolReferences` gate also accepts versioned `claude-mythos-*` ids and the exact `claude-mythos-preview` alias, and now requires the first-party endpoint (`isAnthropicApiBaseUrl(model.baseUrl)`) as well as the `anthropic` provider id. Explicit compat overrides still win. Kept in lockstep with the coding-agent native tool-search gate.

### Why

- Anthropic lists tool search for the Mythos line, but the default matched only `opus|sonnet|fable`, so Mythos sessions ran without native tool search unless a compat override was set.
- The provider id alone does not identify Anthropic's API: a gateway configured under the `anthropic` id kept the id and inherited the default, so it received tool-reference blocks it may reject. The base URL now decides, as it already does for web search and gzip bodies.

### Why an extension could not handle it

- This is the shared default that every caller reads; an extension can set a per-model override but cannot correct the default for all sessions.

### Expected merge conflict zones

- LOW: the first line and model-id match of `defaultSupportsToolReferences`.

## 2026-11-23 - Native tool-search default: first-party Anthropic endpoint only, Mythos included (senpi#7257)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/tool-search/native-support.ts`: the default gate also accepts versioned `claude-mythos-*` ids and the exact `claude-mythos-preview` alias, and now requires `isAnthropicApiBaseUrl(model.baseUrl)` as well as the `anthropic` provider id. `AnthropicToolSearchModel` therefore carries `baseUrl` (every runtime caller already passes a full `Model`). Explicit compat overrides still win. Kept in step with pi-ai's `supportsToolReferences` default; a parity matrix in the native tool-search contract test fails if only one of the two gates is reverted.

### Why

- Anthropic lists tool search for the Mythos line, but the default matched only `opus|sonnet|fable`.
- A gateway configured under the `anthropic` provider id kept the id and got the server tool injected, which such endpoints reject with a 400 that disables native search for the session.

### Why an extension could not handle it

- This is the shared default that every caller reads; an extension can set a per-model override but cannot correct the default for all sessions.

### Expected merge conflict zones

- LOW: `AnthropicToolSearchModel` and the first line of `defaultSupportsToolSearch`.
