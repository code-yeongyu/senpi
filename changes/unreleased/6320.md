## 2026-11-10 - Rotation locks record their owner; only a dead owner's stale lock is cleared (senpi#2981)

### What changed

- `packages/coding-agent/src/core/log-file-rotation.ts`: the rotation lock file now records its owner as `<pid>:<nonce>` when it is taken. `clearStaleLock` never clears a stale lock whose owner process is still alive (a paused holder, not a crashed one), re-reads the owner before removing a dead owner's lock, and locks written by older releases (no owner recorded) keep the previous staleness-only removal. Rotation cleanup only removes the lock this process took, so a fresh lock taken by another process is never removed.

### Why

- Two writers could clear the same stale lock at once, and one of them could then remove a fresh lock a third writer had just taken, so two rotations ran together and one rotated generation was lost (senpi#2981 item 1).

### Why an extension could not handle it

- Log rotation is core file handling shared by the engine host, CLI, and desktop host; no extension API owns the lock file or the rotation path.

### Expected merge conflict zones

- LOW: `clearStaleLock` and the `finally` cleanup in `rotateLogIfNeeded` only; the lock acquisition and rename paths are unchanged.

## 2026-11-10 - A paused MCP file sink is noted once per outage, not once per retry window (senpi#2981)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/mcp/log.ts`: the ring-buffer note after a file-sink write failure now reads "file sink paused after write failure; retrying" and is pushed once per outage (cleared on the next successful write) instead of once per retry window.

### Why

- The sink only pauses for `LOG_SINK_RETRY_MS`, so "disabled" misstated its state, and with an unwritable directory the line repeated about every 5 s, bounded only by the ring size (senpi#2981 item 3).

### Why an extension could not handle it

- The MCP file sink and its ring buffer live in this builtin's logger; no extension API observes or rewrites its write-failure path.

### Expected merge conflict zones

- LOW: the `catch` in `#writeFile` only; the redaction and rotation paths are unchanged.

## 2026-11-10 - The config-reload log status says `paused`, not `disabled` (senpi#2981)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/config-reload/log.ts`: `ConfigReloadLogStatus.disabled` is renamed to `paused`, documented as the retry-window pause after a write failure. No production code reads the field; only tests did, and all of them are updated.

### Why

- `disabled` misstated the state: the sink only pauses for `LOG_SINK_RETRY_MS` and then retries on its own (senpi#2981 item 4).

### Why an extension could not handle it

- The config-reload logger is this builtin's own sink; no extension API owns its status shape.

### Expected merge conflict zones

- LOW: the `ConfigReloadLogStatus` interface and its two return sites only.
