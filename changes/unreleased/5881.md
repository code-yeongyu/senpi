## 2026-11-05 - One shared request-auth composition step and the direct egress (custody CK2, senpi#5881)

### What changed

- `packages/coding-agent/src/core/egress/compose-request-auth.ts` (new): `composeRequestAuth(base, definition, resolveField)` resolves the configured headers field by field (`header:<name>`, in declaration order, one at a time) through an injected resolver, merges them over the credential's own headers, requires a credential header when there is no base auth, and composes `Authorization: Bearer <key>` for `authHeader` with the unchanged "authHeader requires a resolved API key" error. `configValueFieldResolver` is today's configuration-value resolution (reference authority checked first, same error descriptions). `SecretField` names a secret position in a provider definition.
- `packages/coding-agent/src/core/egress/direct.ts` (new): `createDirectEgress({ streamFn })` returns a `ModelEgress` whose `stream` is the given function itself and whose `routeFor` answers `direct` / `fused` / served now.
- `packages/coding-agent/src/core/provider-api-key-auth.ts`: the api-key, ambient-only OAuth and ambient-auth resolvers compose through `composeRequestAuth`; `withConfiguredAuth` moved into it.
- `packages/coding-agent/src/core/provider-composer.ts`: the extension OAuth `toAuth` composes through `composeRequestAuth`.

### Why

A hosted brain must compose request auth from secrets released by sealed custody, without a second copy of the composition rules (#5831). One step with an injected field resolver serves both: local paths pass today's configuration-value resolution, and the sealed egress will pass a custody lease. Behavior is unchanged; Z1 goldens recorded before the extraction pin composed values, header order, sources, env and error strings.

### Why an extension could not handle it

Request-auth composition runs inside the provider composer and the api-key auth adapters, below every extension hook; an extension cannot replace how core composes a provider's own auth.

### Expected merge conflict zones

- LOW: the `resolve` bodies of `composeApiKeyAuth`, `ambientOnlyAuth` and `ambientApiKeyAuth` and the removed `withConfiguredAuth` in `provider-api-key-auth.ts`; `composeOAuthAuth.toAuth` and the import block in `provider-composer.ts`.
