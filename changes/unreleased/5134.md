## 2026-10-31 - The Claude Code child never inherits bare mode (senpi#5132)

### What changed

- `auth-environment.ts`: `withoutBareMode` drops `CLAUDE_CODE_SIMPLE` (case-insensitively) from an environment; `stripManagedAuthEnvironment` applies it, so every `claude auth *` spawn built by `buildClaudeCliEnvironment` and every managed lane loses it.
- `auth-attempt.ts`: `createAttemptMessages` applies it to the final `options.env` of every turn, the one point the ambient, oauth-slots, config-dir and claude-cli lanes all pass through.
- `availability.ts`: the ambient `claude auth status` probe spawns with an explicit environment (`AmbientProbeOptions.environment`, default `process.env`) without it; `spawnProbe` receives that environment.

### Why

- With `CLAUDE_CODE_SIMPLE` set (Claude Code's `--bare` mode), Claude Code authenticates only with `ANTHROPIC_API_KEY` or an `apiKeyHelper` and never reads the OAuth login. A host or parent session in bare mode therefore made every subscription turn fail with `Not logged in` (reported as a rejected OAuth token), and made the ambient probe report the provider as unconfigured.

### Why an extension could not handle it

- The subprocess environment is built inside this builtin's auth lane and probe; no extension hook sees it.

### Expected merge conflict zones

- `auth-environment.ts`: the new helper above `hasRequestOauthToken` and the return of `stripManagedAuthEnvironment`.
- `auth-attempt.ts`: the `CLAUDE_CODE_DISABLE_AUTO_MEMORY` line in `createAttemptMessages`.
- `availability.ts`: `AmbientProbeOptions` and the spawn in `probeAmbientClaudeAuthStatus`.
