## 2026-11-16 - Release Linux jobs can run on Boat self-hosted runners behind an off-by-default flag (senpi#6850)

### What changed

- `.github/workflows/publish-npm.yml`: a new `boat_run_label` dispatch input (default empty). The forced-suite jobs `prepare`, `forced-rest` and `forced-shard` run on `[self-hosted, boat-large, <boat_run_label>]` only when the repository variable `RELEASE_BOAT_ENABLED` is `true`, the event is `workflow_dispatch` and the label is not empty; otherwise they resolve to `ubuntu-latest` exactly as before. The label is passed to `native-prebuilds.yml`. A new GitHub-hosted `boat-watchdog` job (only `actions: write`, `contents: read`) runs under the same condition: when a Boat job waits 10 minutes for a runner it dispatches the workflow again with the same inputs, an empty label and an empty `sha` pinned to the run's commit, then cancels the run. The `release` job, which holds the push token and publishes through npm trusted publishing, does not change.
- `.github/workflows/build-binaries.yml`: the same `boat_run_label` input and condition for the `build` job only (a tag push always builds on `ubuntu-latest`), and its own `boat-watchdog` job. Every GitHub Release job, the npm dispatch and the smoke matrix do not change.
- `.github/workflows/native-prebuilds.yml`: a `boat_run_label` `workflow_call` input (default empty). A Linux build row runs on the Boat label under the same condition; every other caller and event keeps the row's own runner.
- `.github/agent/skills/release-publish/SKILL.md`: a "Boat runners" section covering what moves, what never moves, how the external dispatcher starts the runners, and the fallback (never re-run jobs of a Boat run; dispatch again with an empty label). It also notes that Boat-built prebuilds and the Rust cache outlive the run.

### Why

- Release Linux jobs spend most of their wall time in the hosted runner queue (a sampled forced cut: 8 suite jobs each waited 39-43 min for about 15 min of work). Ephemeral self-hosted runners in Boat sandboxes, started per run by an external dispatcher, skip that queue without any runner registration credential in this repository.

### Why an extension could not handle it

- These are the repository's own release workflows.

### Expected merge conflict zones

- LOW: the `workflow_dispatch` inputs of `publish-npm.yml` and `build-binaries.yml`, and the `runs-on` lines of the moved jobs.

## 2026-11-16 - Boat runner fallback watchdog and runs-on evaluation (senpi#6850)

### What changed

- `scripts/boat-watchdog.mjs` (new): the `boat-watchdog` jobs' script. It lists the run's jobs every 30 s. When a job labelled with the run's `boat_run_label` has been queued for `QUEUE_LIMIT_SECONDS` (600), it re-dispatches the workflow with the same inputs and an empty label, then cancels the run. It stops once `DONE_JOB` has started. After `MAX_LIST_FAILURES` (10) consecutive failed job listings it fails, rather than holding the run and its concurrency group open.
- `scripts/release-boat-runner.test.mjs` (new): evaluates every job's `runs-on` in every workflow over each event, label and variable value, and proves five things:
  - Flag off, a non-dispatch event or an empty label keeps today's runner.
  - Exactly the listed jobs move.
  - The release, publish and GitHub Release jobs never mention Boat.
  - A pull request never reaches a self-hosted runner.
  - The watchdog's condition, permissions, dispatch-before-cancel order and decision table hold.
- `scripts/workflow-text.test-support.mjs`: `evaluateExpression` also evaluates `format()`, `toJSON()` and `fromJSON()`.
- `scripts/ci-platform-scope.test.mjs`: a Boat row's `runs-on` counts as the row's own `matrix.runner` on a pull request.

### Why

- The Boat runner switch must provably change nothing while it is off and never reach a pull request. A hosted fallback must exist for runners that never come online.

### Why an extension could not handle it

- These are the repository's own release scripts and their tests.

### Expected merge conflict zones

- LOW: the tokenizer and `primary()` of `scripts/workflow-text.test-support.mjs`.
