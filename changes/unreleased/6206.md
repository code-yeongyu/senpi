## 2026-11-08 - Delegated-origin work asks on a session with no client-named mode (senpi#6206)

### What changed

- `packages/coding-agent/src/core/turn-origin.ts` (new): a turn's origin (`local`, `delegated`, `engine`) is assigned at its starting record, and a `delegated_origin` custom entry records that a remote device drove the session.
- `packages/coding-agent/src/core/permission-decision.ts` (new): the per-decision preset rule (client-named, then live parent, then delegated default or recorded mode, then host default).
- `packages/coding-agent/src/core/agent-session.ts`: `connectionOrigin` on prompt and queued input; each user message is marked with its turn origin, and the run start and user-message start set the current origin.
- `packages/coding-agent/src/core/sdk.ts`: `createAgentSession` binds the per-decision rule, so SDK-created and in-process child sessions get it.
- `packages/coding-agent/src/core/agent-session-runtime.ts`: `permissionPresetSource: "host_default"` on the launch profile; a host-default preset is never marked as a client's choice, and naming a preset clears the marker.
- `packages/coding-agent/src/core/permission-mode.ts`: `bindPermissionDecision`, `clientNamedPreset` and `withClientPreset`.

### Why

- A session a remote device drove with no named approval mode ran every tool call on the host's default, so nothing the remote device started ever asked (remote approval-mode work, tracked privately).

### Why an extension could not handle it

- Which connection started a turn is known only to the RPC record handlers and the session's input queue, and children are created by the core session factory.

### Expected merge conflict zones

- LOW: `_handleAgentEvent` (the `agent_start` and user `message_start` branch), `_enqueuePreparedInput` and the user-message construction in `prompt()` of `AgentSession`.
- LOW: the end of `createAgentSession`.

## 2026-11-08 - The preset is read per decision through the core override (senpi#6206)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/permission-system/preset-registry.ts`: `registerDecisionPresetOverride` / `readDecisionPresetOverride`.
- `packages/coding-agent/src/core/extensions/builtin/permission-system/index.ts`: the preset the rules load from is the override when the core sets one; an invalid `--permission-preset` keeps refusing every call (#2617).

### Why

- The delegated default and child inheritance decide per gated call, from state only the core has (remote approval-mode work, tracked privately).

### Why an extension could not handle it

- This is the builtin permission extension itself; the override is how the core feeds it.

### Expected merge conflict zones

- LOW: `loadPermissionRules` and `followPresetFlag`.

## 2026-11-08 - RPC input carries its connection's origin (senpi#6206)

### What changed

- `packages/coding-agent/src/modes/rpc/connection-roles.ts`: `isDelegated`.
- `packages/coding-agent/src/modes/rpc/connection-handler.ts`: `prompt`, `follow_up` and `compact` pass whether their connection is delegated; a delegated `compact` records the delegated origin.
- `packages/coding-agent/src/modes/rpc/client-input-handler.ts`: passes `connectionOrigin` into the session and records the delegated origin.
- `packages/coding-agent/src/modes/rpc/session-router-open-profile.ts`: a host-level preset folded into an open is marked `host_default`.
- `packages/coding-agent/src/modes/rpc/session-registry-attach.ts`, `worker-session-registry.ts`: an attach naming a preset clears the host-default marker.

### Why

- The delegated default needs the starting record's connection, and an embedder's host-level preset must not exempt a remote device's session (remote approval-mode work, tracked privately).

### Why an extension could not handle it

- Connection identity lives in the RPC host.

### Expected merge conflict zones

- LOW: the `prompt`, `follow_up` and `compact` cases of the connection handler.
