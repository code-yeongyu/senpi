### Fixed

- With two or more logins for one provider, an account whose credential the token endpoint refused (HTTP 401, `invalid_grant`, an expired, reused or invalidated refresh token, a revoked token, or a refusal the provider's own refresh decided, such as Kimi Code's 403) or whose token was revoked or invalidated server-side (with or without an HTTP status) is now blocked and the request moves to a sibling account before any output, instead of failing the request. A refresh that failed in the network (any socket, DNS or HTTP-client fault code, or statusless network wording) still retries the same account, and any other failed refresh, including a 401 that names a client or request fault (`invalid_client`, `unauthorized_client`, `invalid_request`, `unsupported_grant_type`, `invalid_scope`), never blocks one. ## 2026-10-30 - An auth failure of one pooled account fails over (senpi#2304, senpi#3037, senpi#5010)

### What changed

- `packages/coding-agent/src/core/credential-pool/classify.ts`: before any auth prose, a failed refresh (`ModelsError` code `oauth` in the cause chain) classifies as `failover` with `auth_error` only when its `OAuthTokenEndpointError` cause refused the credential (`isRefusedGrant`: the adapter's `credentialRefused`, any 401, a 400 naming `invalid_grant`, `refresh_token_*` or `token_revoked`, or a 403/404 whose OAuth code does; an OAuth code in `CLIENT_FAULT_CODES` outranks all of them). Any other failed refresh skips every blocking branch: it retries the same account when the first error code in its cause chain is in `NETWORK_FAULT_CODES`, or, with no code and no token-endpoint answer, when its text matches `NETWORK_TEXT`, and fails the request otherwise. A provider diagnostic in the auth category or with an auth token code (`token_revoked`, `token_invalidated`, ...; not `token_expired`) classifies as `failover` with `auth_error` unless a provider fault or a 429 takes precedence, including statusless network/timeout faults. `REVOKED_TOKEN_TEXT` joins `INVALID_KEY_TEXT` as the prose last resort under the same provider-fault guard, matching token revocation but not a session, page or request token, nor unrelated session invalidation.
- `packages/coding-agent/src/core/credential-pool/rotation-events.ts`: `rotationErrorFromEvent` attaches the event's whole provider diagnostic, not only its HTTP status.

### Why

- A refused refresh token (no status) and a statusless revoked-token frame classified as `fail_request`, so one dead account dead-ended a pool with healthy siblings, and a pinned dead account was selected on every request.

### Why an extension could not handle it

- Classification runs inside the core credential-pool engine that `ModelRuntime` drives; no extension hook sees the failure before it is classified.

### Expected merge conflict zones

- LOW: the auth branch of `classifyCredentialFailure` and the regex and code-set block above it in `classify.ts`; `rotationErrorFromEvent` in `rotation-events.ts`.

## 2026-10-31 - Token endpoint errors carry their OAuth code and refusal decision (senpi#5010)

### What changed

- `packages/ai/src/utils/oauth-refresh-error.ts`: `OAuthTokenEndpointError` takes an optional third argument and exposes `oauthError` (the body's OAuth `error` code) and `credentialRefused` (default `false`).

### Why

- The credential pool must tell a refused credential from a client fault or an unreadable page without reading adapter prose; an adapter that already decided the refusal had no way to say so.

### Why an extension could not handle it

- The error type is constructed inside the bundled OAuth adapters; an extension cannot attach facts to an error it does not throw.

### Expected merge conflict zones

- LOW: the `OAuthTokenEndpointError` class in `oauth-refresh-error.ts`.

## 2026-10-31 - Kimi Code's refused refresh says so on its error (senpi#5010)

### What changed

- `packages/ai/src/auth/oauth/kimi-coding.ts`: a refresh refused with 401, 403 or `invalid_grant` throws `OAuthTokenEndpointError` with `credentialRefused: true` and the body's `oauthError`; other failed refreshes carry `oauthError` only.
- `packages/ai/src/auth/oauth/radius.ts`: `OAuthResponseError` passes its OAuth code to the base class instead of declaring its own `oauthError` field.

### Why

- Kimi's refusal message has no OAuth JSON, so the credential pool stopped blocking a dead Kimi login and failing over to a sibling account (senpi#5010 review).

### Why an extension could not handle it

- The Kimi refresh runs inside the bundled OAuth adapter; no extension hook can annotate its error.

### Expected merge conflict zones

- LOW: the unauthorized branch of `refreshToken` in `kimi-coding.ts`; `OAuthResponseError` in `radius.ts`.
