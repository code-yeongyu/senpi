## 2026-11-26 - Identity protection for file effects and tool output (senpi#7528)

### What changed

- File operations authorize the filesystem object before consuming bytes. Shell and terminal capture, tool updates, results and errors mask private material while retaining public identifiers. Engine capability negotiation distinguishes guarded engines from older releases.

### Why

- A file operand can reach private material through an alias. A shell can produce sensitive output without naming an identity in its command. Neither case is decided by checking command text.

### Why an extension could not handle it

- The check must apply to both tool placements even in a session with extensions disabled.

### Expected merge conflict zones

- Tool dispatch, machine file effects, shell and terminal capture, and the native/fallback search adapters.

## 2026-11-26 - Guard reads used for edit baselines and output spill previews (senpi#7528)

### What changed

- `packages/coding-agent/src/core/tools/write.ts` and `packages/coding-agent/src/core/tools/output-accumulator.ts` read through the protected file handle rather than reopening a pathname.

### Why

- `packages/coding-agent/src/core/tools/write.ts` reads a baseline before writing; `packages/coding-agent/src/core/tools/output-accumulator.ts` reads preview bytes from a spill path. Both are file effects.

### Why an extension could not handle it

- Neither the open in `packages/coding-agent/src/core/tools/write.ts` nor the one in `packages/coding-agent/src/core/tools/output-accumulator.ts` is a separate tool invocation.

### Expected merge conflict zones

- Local baseline loading in `packages/coding-agent/src/core/tools/write.ts` and the tempfile reader in `packages/coding-agent/src/core/tools/output-accumulator.ts`.
