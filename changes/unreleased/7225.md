## Bundled skill resolves to a real file beside the executable (2026-11-22)

### What changed

- `index.ts`: `bundledSkillPath()` resolves the module-relative copy, then the shipped skill directory beside the executable (new `getImagegenSkillDir()` row in `config.ts`'s `ShippedAsset` table), then the embedded `type: "file"` import; a Bun locator (`/$bunfs/…`, `~BUN…`, `%7EBUN…`, via new `isBunVirtualPath()` in `config.ts`) is never returned. The miss notice now names both probed locations once. `registerImageGenExtension` takes an optional injectable environment so compiled-binary layout is testable from source runs.
- `core/bundled-resources.ts`: the read-permission root is `getImagegenSkillDir()` instead of the module-relative directory, so a compiled binary advertises the real sidecar root.
- `scripts/build-binaries.sh`: stages `dist/core/extensions/builtin/imagegen/skill/` to `skill/` beside each compiled binary, beside the theme and asset dirs.

### Why

- In a `bun build --compile` binary the embedded import resolves to `/$bunfs/root/SKILL-<hash>.md` (POSIX) or `B:\~BUN\root\…` (Windows): existsSync passes, descriptor-based readers get ENOENT, and no client or child process can open it. Clients list skills by path and offer to open them (senpi#3799), so the advertised path must be a real on-disk file — the same sidecar mechanism the codemode bun skill, themes, and interactive assets already use.

### Why an extension could not handle it

- The resolution order is part of this builtin's contribution itself: an external extension cannot replace what `resources_discover` advertises for the shipped skill, and cannot ship a real file beside the executable the way the release build must.

### Expected merge conflict zones

- LOW: resolution order lives in `index.ts`; the asset-table row and getter live in `config.ts`.
- LOW: one staging line pair in `scripts/build-binaries.sh`, covered by `scripts/build-binaries-staging.test.mjs`.

## Release staging ships the imagegen skill beside the binary (2026-11-22)

### What changed

- `scripts/build-binaries.sh`: the per-platform staging block copies `dist/core/extensions/builtin/imagegen/skill/` to `skill/` beside each compiled binary, next to the theme and asset directories. `scripts/build-binaries-staging.test.mjs` runs the real staging block and asserts `skill/SKILL.md` lands in the archive.

### Why

- A compiled binary's embedded `type: "file"` import resolves to a Bun locator (`/$bunfs/…`, `B:\~BUN\…`) that no descriptor-based reader or external process can open (senpi#3799). The runtime resolves the skill from the shipped directory beside the executable, so the build must stage it there.

### Why an extension could not handle it

- Release staging is repository build tooling: it runs before any runtime extension loads, and an extension cannot add files to a compiled binary's archive.

### Expected merge conflict zones

- LOW: one staging line pair inside the `# Copy shared files` block, shared with any other lane adding staged assets.

## Opaque subscription skill locations retain the loaded copy (2026-11-22)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/options.ts` passes the session identity to skill-catalog extraction.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/skill-locations.ts` owns the extracted root-table and legacy-location rewrite. A same-file Claude path remains usable; a missing or different Claude path uses an opaque session location. XML entities are decoded before path matching and encoded for the catalog.

### Why

- The old fallback exposed the literal agent directory. Unconditionally rewriting to the Claude directory instead would read a competing installation. The opaque location identifies the loaded file without relying on that link.

### Why an extension could not handle it

- This builtin owns the subscription prompt. An external extension cannot replace the path after this provider has extracted its skill catalog.

### Expected merge conflict zones

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/options.ts`: the skill append call.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/skill-locations.ts`: extracted from the former path helpers in options.ts.

## Resolve exact skill locations before host read authorization (2026-11-22)

### What changed

- `packages/coding-agent/src/core/agent-session.ts` supplies the live loaded-skill inventory to runtime bootstrap.
- `packages/coding-agent/src/core/runtime/bootstrap.ts` prepares the built-in read's arguments using that inventory and the current session identity.
- `packages/coding-agent/src/core/skill-read-paths.ts` derives opaque locations from the session and file root, resolves only exact loaded skill files, and rejects unknown locations. Preparation changes a detached execution argument, leaving the assistant transcript intact.

### Why

- `packages/coding-agent/src/core/agent-session.ts` owns the current loaded resources and session identity. Passing both lets the host read select the right copy even when names collide.
- The SDK's native Read is denied by the existing hook. Its streamed call reaches the host read, so `packages/coding-agent/src/core/runtime/bootstrap.ts` resolves the location before tool-call permissions and the executor's canonical filesystem policy.
- `packages/coding-agent/src/core/skill-read-paths.ts` rejects other-session aliases, unadvertised suffixes and traversal instead of remapping an arbitrary directory tree.

### Why an extension could not handle it

- The permission extension runs before the subscription extension's tool-call handlers. A late mutation would authorize the display path instead of the selected file. `packages/coding-agent/src/core/agent-session.ts` and `packages/coding-agent/src/core/runtime/bootstrap.ts` bind the existing argument-preparation seam before all permission hooks; `packages/coding-agent/src/core/skill-read-paths.ts` shares the location identity with the provider without global mapping state.

### Expected merge conflict zones

- `packages/coding-agent/src/core/agent-session.ts`: the runtime bootstrap options.
- `packages/coding-agent/src/core/runtime/bootstrap.ts`: default read-tool construction.
- `packages/coding-agent/src/core/skill-read-paths.ts`: new exact-file location contract.
