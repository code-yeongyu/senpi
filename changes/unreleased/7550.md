## 2026-11-27 - CI runs the equivalence recorder's leak guard (senpi#7550)

### What changed

- `.github/workflows/ci.yml`: the senpi-qa harness unit-test step also runs `.agents/skills/senpi-qa/scripts/lib/equivalence-record-guard.test.mjs`.

### Why

- The fused-equivalence recorder now refuses a host or a golden that would put host-private text into a public golden (a project-rules block, a home path); its tests must run on every PR so the guard cannot silently stop working.

### Why an extension could not handle it

- This is the CI workflow. Extensions do not run in it.

### Expected merge conflict zones

- LOW: the `node --test` line of the senpi-qa harness unit-test step in `.github/workflows/ci.yml`.

## 2026-11-27 - Context file names exported for the equivalence recorder's leak guard (senpi#7550)

### What changed

- `packages/coding-agent/src/core/context-files.ts`: `loadContextFileFromDir` probes `CONTEXT_FILE_NAMES` from the new `context-file-names.ts` instead of a local list; same names, same order, same behavior.

### Why

- The fused-equivalence recorder refuses a host where a context file sits at or above the sandbox temp dir, because the CLI would load it into a recorded, public golden. Reading the CLI's own list (in a file without the loader's imports) keeps the guard from ever checking fewer names than the CLI reads.

### Why an extension could not handle it

- Context-file discovery is core resource loading that runs before extensions; the names live only in this loader.

### Expected merge conflict zones

- LOW: the import block and the first lines of `loadContextFileFromDir` in `packages/coding-agent/src/core/context-files.ts`.
