## 2026-11-05 - Deleting a session removes its durable store (S21b b1, senpi#5991)

### What changed

- `packages/coding-agent/src/modes/interactive/components/session-selector.ts`: `deleteSessionFile(sessionPath, agentDir = getAgentDir())` removes the session's default durable store medium (`defaultSessionStoreMedium`, from the file's directory and header id) once the file is gone, next to its tool media. A medium it cannot remove is reported in `mediaError` like leftover media, and the status message says some of the session's data was not removed.

### Why

On Bun every entry of a session is also in its durable store; a deleted session must not leave its transcript in SQLite.

### Why an extension could not handle it

The selector's delete is core UI with no extension hook.

### Expected merge conflict zones

The media removal step inside `deleteSessionFile`, its signature, and the delete status message in `session-selector.ts`.

## 2026-11-05 - The durable store is the default session store on Bun (S21b b1, senpi#5991)

### What changed

- `packages/coding-agent/src/core/sdk.ts`: `createAgentSession` calls `bindDefaultSessionStore` once it settles the session manager; `CreateAgentSessionOptions.sessionStore: "jsonl"` is a test-only, in-process opt-out.
- New `session-store/default-binding.ts` (binds a persisted session on Bun), `session-store/default-store.lazy.ts` (the only path to `bun:sqlite`, loaded on Bun only) and `session-store/default-store.ts` (one medium and one epoch per session under `<agentDir>/session-store/<hash of the session directory's real path>/<id>` (`session-store/default-store-path.ts`, which has no SQLite and so also serves the Node delete path), so two projects using one session id never share a store: claim 0->1 when fresh, otherwise bind at the current epoch; a takeover raises the epoch and fences that session's stale peers).
- `packages/coding-agent/package.json`: depends on `@earendil-works/pi-storage-sqlite-bun` (published by senpi#5975). That package loads `bun:sqlite` only through a run-time import, so the Node session worker bundle, which inlines the lazy store import, has no static Bun built-in import.

### Why

Plan row S21b (senpi#5822), K6/K9: on Bun the session store is durable by default. Every session replacement (new, fork, branch, switch) builds its runtime through `createAgentSession`, so one call binds them all.

### Why an extension could not handle it

Session persistence is set up before extensions load.

### Expected merge conflict zones

`createAgentSession`'s session-manager setup and `CreateAgentSessionOptions` in `sdk.ts`.

### Fixed
- Processes that open a new store file at the same time no longer fail with "database is locked": the switch to WAL retries a busy lock, waiting on a timer rather than blocking the thread, until the busy timeout has passed (SQLite fails one of two concurrent switchers at once rather than waiting) ([#5991](https://github.com/code-yeongyu/senpi/pull/5991)).

## 2026-11-05 - Durable store errors and options are part of the public API (S21b b1, senpi#5991)

### What changed

- `packages/agent/src/index.ts` exports `DurableStoreError` and the `DurableStoreOptions`/`StoreWritePoint` types next to `SyncCommit`/`SyncCommitStore`.

### Why

The default session store on Bun (coding-agent) opens and fences a session's medium through these types and must recognize a fenced or stale write by its error class.

### Why an extension could not handle it

They are the agent package's own exports.

### Expected merge conflict zones

The durable store export block in `packages/agent/src/index.ts`.

## 2026-11-05 - coding-agent depends on the Bun SQLite durable store (S21b b1, senpi#5991)

### What changed

- `packages/coding-agent/package.json` depends on `@earendil-works/pi-storage-sqlite-bun` (lockstep version), published as `@code-yeongyu/senpi-storage-sqlite-bun` by senpi#5975.

### Why

On Bun, the default session store is that package's SQLite store (S21b, senpi#5822). It is loaded lazily and only on Bun, so Node never loads `bun:sqlite`.

### Why an extension could not handle it

Package dependencies are the package's own manifest.

### Expected merge conflict zones

The `dependencies` block of `packages/coding-agent/package.json`.
