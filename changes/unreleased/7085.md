## 2026-11-19 - open_session forkFrom forks a session instead of opening a blank one (senpi#7085, omo#13031)

### What changed

- `packages/coding-agent/src/modes/rpc/session-router-open-fork.ts` (new): `forkForOpen` resolves `open_session.forkFrom`, a durable id looked up in this host's own session folder (`findSessionFile`) or an absolute session file path. It writes the fork with `SessionManager.forkFrom` into this host's session folder for the open's folder (the id `durableSessionId` when given) and answers the open command that opens the fork's file, or a typed refusal: `fork_source_not_local` (no file here carries the id), `fork_source_not_found` (no readable session file at the path, or an ambiguous id), or `invalid_launch_profile` (`forkFrom` with `sessionPath`).
- `packages/coding-agent/src/modes/rpc/session-router-open.ts`: `open()` validates the request, forks, then opens the fork like any open by path. A refused fork opens nothing, and an open that fails after the fork was written removes the fork's file.
- `packages/coding-agent/src/modes/rpc/find-session.ts`: `findSessionFile` is exported, so `find_session` and the fork share one lookup.
- `packages/coding-agent/src/modes/rpc/custom-capability.ts`, `host-capabilities.ts`: the capability `open_session_fork`, advertised by every multi-session host.
- `packages/coding-agent/src/modes/rpc/rpc-host-command-types.ts`, `method-classes-schema-host.ts`: `forkFrom` on `open_session` only (not `claim_session`, not a move's import open).

### Why

- `open_session` ignored `forkFrom`, so a client that asked for a fork (omo's `thread_create { fork_from }`, on this device or another) got a plain new session with no history. omo refused every fork until the engine could do it.

### Why an extension could not handle it

- The open, its session file and the host's session folder belong to the RPC router and the session registry. An extension runs inside a session that is already open.

### Expected merge conflict zones

- LOW: `session-router-open.ts` `open()` head and catch block; `host-capabilities.ts` capability list; `method-classes-schema-host.ts` `open_session` schema line.

### Added
- `open_session` takes `forkFrom` (a durable id or session file path this host can read) and opens a fork of that session: a new session with its history, the source left untouched. A source the host cannot read is refused, `fork_source_not_local` or `fork_source_not_found`, and nothing is opened. Hosts advertise `open_session_fork` ([#7085](https://github.com/code-yeongyu/senpi/pull/7085))
