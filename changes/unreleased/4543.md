## 2026-10-28 - A macOS automount trigger path is never resolved (senpi#4543)

### What changed

- `packages/coding-agent/src/utils/paths.ts`: added `isBlockingAutomountPath()`, a string-only predicate that is true on darwin for the literal `/home` and for paths under `/home/` that are outside the current user's home directory, matched after normalization and case-folding because the default macOS filesystem ignores case; added `UnresolvableAutomountPathError` for callers that must fail closed.

### Why

- On macOS `/home` is an autofs trigger backed by the `auto_home` directory-service map. Bun resolves a path by `open(2)`-ing its components, so resolving such a path forces the automount; when the map is wedged the open never returns and the calling thread is parked, which on the engine loop stops the whole session. The promise form blocks identically, so a deadline race cannot bound it; only a decision taken before any syscall can.

### Why an extension could not handle it

- The resolution runs inside core path helpers that execute before every filesystem tool call; an extension cannot intercept them.

### Expected merge conflict zones

- LOW: a new exported helper appended next to the existing canonicalization helpers.

## 2026-10-28 - Filesystem canonicalization skips macOS automount triggers (senpi#4543)

### What changed

- `packages/coding-agent/src/core/tools/filesystem-policy.ts`: `canonicalizeFilesystemPath()` throws `UnresolvableAutomountPathError` when `isBlockingAutomountPath()` holds, instead of calling `realpath`. It fails closed rather than answering with the unresolved path, which would let a `/home` alias of a directory pass a containment check that its real `/Users` path fails.
- `packages/coding-agent/src/core/tools/file-mutation-queue.ts`: a mutation target under the trigger is refused with the same error instead of being keyed on an unresolved path.
- `packages/coding-agent/src/core/tools/grep/rg/enumerate.ts`: a search root under the trigger is reported as a missing path instead of being resolved and stat-ed.

### Why

- Both helpers run on the host loop before every read, list, grep, find, edit and write. A path under a wedged macOS `/home` automount trigger blocks their `realpath` call forever, and the existing resolution deadline cannot fire because the thread itself is blocked in `open(2)`.

### Why an extension could not handle it

- These are the core helpers every built-in filesystem tool funnels through; an extension sees the path only after they have already resolved it.

### Expected merge conflict zones

- LOW: one guard line each at the top of two small functions.

## 2026-10-28 - Nested AGENTS.md containment skips macOS automount triggers (senpi#4543)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/nested-agents-md/core/containment.ts`: `resolveAndContain()` denies containment when `isBlockingAutomountPath()` holds for the root or the target, instead of resolving them with `realpath`.

### Why

- Containment runs for every file the agent touches, so a path under a wedged macOS `/home` automount trigger blocked the session here as well.

### Why an extension could not handle it

- This is a built-in extension's own resolution step.

### Expected merge conflict zones

- LOW: fork-only extension file.
