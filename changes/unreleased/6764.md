## 2026-11-16 - A transient compaction failure no longer latches admission (senpi#6760)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: the two sites in `_checkCompaction` that arm `_blockedPostCompactionAssistant` after a failed automatic compaction now share `_failedCompactionLatchesAdmission()`. It exempts the new `transient-failure` rejection cause as well as `external-owner`, so after a transient summary failure the next send of any origin runs compaction again instead of throwing `RequiredCompactionError` with no attempt. `describeCompactionRejection` describes the new cause.

### Why

- A long-lived automated session hit `api_error: Network error or service unavailable` on its threshold compaction. The extension cancelled after its bounded retries, the session latched admission (#7921 case 6), and only a person's prompt releases that latch (#4161). Every automated send was then refused forever with the context above the threshold. The latch exists for deterministic insufficiency; a transient provider failure says nothing about the context.

### Why an extension could not handle it

- `packages/coding-agent/src/core/agent-session.ts`: the admission latch is private session state armed by core after an automatic compaction fails; an extension can only report why it rejected.

### Expected merge conflict zones

- LOW: `agent-session.ts`, the two latch-arming blocks in `_checkCompaction`, the new `_failedCompactionLatchesAdmission` beside `_isCompactionOnCooldown`, and `describeCompactionRejection`.

## 2026-11-16 - `CompactionRejectionCause` gains `transient-failure` (senpi#6760)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `CompactionRejectionCause` adds `"transient-failure"`: the summary request failed on a transient provider error after its bounded retries. An extension returns it from `session_before_compact` with `cancel: true`; it reaches `compaction_end` and rejected `session_compact` events like the other causes.

### Why

- The session must tell a failure that says nothing about the context from one that proves the context cannot be compacted. Only the latter may latch automatic admission.

### Why an extension could not handle it

- The cause is part of the public `session_before_compact` result contract that core reads.

### Expected merge conflict zones

- LOW: the `CompactionRejectionCause` union in `types.ts`.

## 2026-11-16 - The core route rejects a transient summary failure as `transient-failure` (senpi#6760)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/compaction/index.ts`: when the core-route summary generation fails and no deterministic recovery applies, a failure that `isRetryableSummaryAttempt` accepts is cancelled with `rejectionCause: "transient-failure"` (the reason text is unchanged).
- `packages/coding-agent/src/core/extensions/builtin/compaction/speculative.ts`: `isRetryableSummaryAttempt` is exported so the rejection and the in-request retry share one definition of a transient provider failure.

### Why

- The bare cancel was recorded as `cancelled-by-extension`, which the session answered by latching admission. The rejected `session_compact` event still records a circuit-breaker failure, so three consecutive transient rejections still cool automatic compaction down for 60 s.

### Why an extension could not handle it

- This is the builtin compaction extension's own policy.

### Expected merge conflict zones

- LOW: the generator-failure `catch` of the `session_before_compact` handler in `index.ts`; the `isRetryableSummaryAttempt` declaration in `speculative.ts`.
