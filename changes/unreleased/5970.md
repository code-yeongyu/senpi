## 2026-11-05 - Startup refuses or takes over a held session (senpi#5756)

### What changed

- `packages/coding-agent/src/main.ts`: `createSessionManager` selects the session through the former body (now `selectStartupSession`) and then runs `admitStartupSession` before anything writes to the session or a runtime starts on it; a refusal exits 1, a declined take-over exits 0. Prompting is offered only in interactive mode with a TTY on stdin.

### Why

The startup path still only warned (#2951/#2956) when another live process held the session, so a second run of the same session started (the startup path of #5744, which #5750 fixed for `/resume`).

### Why an extension could not handle it

Session selection and opening happen in `main.ts` before any extension is loaded.

### Expected merge conflict zones

- LOW: the head of `createSessionManager` in `main.ts` and the `session-opening.ts` import.

## 2026-11-05 - Startup admission for a held session (senpi#5756)

### What changed

- `packages/coding-agent/src/cli/session-opening.ts`: new `admitStartupSession(sessionFile, io)` returning `open`, `cancelled` or `refused`. It reuses `checkSessionHolders`, `describeSessionHolders`, `takeOverRefusal` and `stopSessionHolders`. Without a person to ask, or for a holder that cannot be stopped safely, it refuses and names the holder; otherwise it asks, stops the holder on take-over, and refuses if the session is still (or newly) held. A failed lookup stays advisory. `prepareSessionOpening` is unchanged.

### Why

senpi#5756: opening a held session at startup must never start a second writer.

### Why an extension could not handle it

It runs before the runtime and its extensions exist.

### Expected merge conflict zones

- LOW: the import block of `session-opening.ts`.

## 2026-11-05 - takeOverRefusal names the retry step (senpi#5756)

### What changed

- `packages/coding-agent/src/core/foreign-session-holders.ts`: `takeOverRefusal(holders, retry = "then /resume again")` takes the retry hint, so the startup refusal says to open the session again. `/resume` output is unchanged.

### Why

The startup refusal reuses the `/resume` refusal reasons.

### Why an extension could not handle it

Core helper shared by `/resume` and startup.

### Expected merge conflict zones

- LOW: the `takeOverRefusal` signature.
