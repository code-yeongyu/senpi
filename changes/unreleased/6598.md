## 2026-11-13 - A move bundle's listed paths are plain, and the sender refuses a name that cannot be listed before it seals (senpi#6571 and senpi#6445 reviews)

### What changed

- `packages/coding-agent/src/core/session-move/bundle.ts`: `hasIdleSegment`: a `.` or an empty segment under either separator. The manifest's parser refuses a listed path that has one, as it refuses an absolute path, a `..` segment and a path too deep. `MovePathNotPlainError` is the sender's refusal for a file whose bundle path the parser would refuse on those grounds.
- `packages/coding-agent/src/core/session-move/export.ts`: `assertMoveFits` also refuses a file whose path in the bundle leaves the bundle or has a `.` or an empty segment, and it now looks at each extension's sidecar as well as the resident blobs and the staged extension state (`sidecarSources` is what the export itself lists). It is asked where it was: before the export's own seal, for a session already sealed before a bundle is written, and by the `move` release before its seal.
- `packages/coding-agent/src/core/session-move/inline-bundle.ts`: the check of an inline file's name asks `hasIdleSegment` in place of its own copy of the rule. What that check refuses is unchanged.

### Why

- What classifies a listed file reads its path as text, and what moves it reads the disk. `files/extensions/./x/<id>.json` passed the parser, was not recognised as an extension's state file by the checks that read the text, and still landed as one.
- Off Windows a backslash is an ordinary character of a name, so a file named `a\.\b.json` is listed under a path with a `.` segment once both separators count. Refusing that only where a bundle is read would seal the session for a move no receiver takes. The same was true before this change of a name such as `a\..\b.json`.

### Why an extension could not handle it

- It is the session move's own bundle format and its own seal.

### Expected merge conflict zones

- LOW: `parseFile` and the error classes in `bundle.ts`; `assertMoveFits` and `copySidecars` in `export.ts`; `staysInBundle` in `inline-bundle.ts`.
