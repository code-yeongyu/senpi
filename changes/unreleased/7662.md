## 2026-11-28 - The extension loader's served-module table is exported for the bundle manifest (senpi#7662)

### What changed

- `packages/coding-agent/src/core/extensions/loader.ts`: `VIRTUAL_MODULES` is exported. Its entries are unchanged.

### Why

- The bundle build reads the compiled table's keys to write `extensionModules` into `dist/bundle/runtime-manifest.json`, so an embedder (oh-my-openagent's compiled binary) learns which modules the loader serves without parsing `loader.js`. senpi stops shipping that file once its exports point at the bundle.

### Why an extension could not handle it

- The table is the loader's own; only the loader module can expose it.

### Expected merge conflict zones

- LOW: the `VIRTUAL_MODULES` declaration line in `loader.ts`.

## 2026-11-28 - runtime-manifest.json lists the extension loader's served modules (senpi#7662)

### What changed

- `scripts/build-coding-agent-bundle.mjs`: `readExtensionModules()` imports the compiled `dist/core/extensions/loader.js` and returns the sorted keys of its `VIRTUAL_MODULES`; `writeRuntimeManifest` writes them as `extensionModules` beside `buildId` and `externals`.
- `scripts/build-coding-agent-bundle.test.mjs`: the built manifest's `extensionModules` must equal the compiled loader's table keys.

### Why

- oh-my-openagent parsed the installed `loader.js` for this set. That parse refuses the `...SENPI_SUBPATH_MODULES` spread added in senpi#7657, and the file goes away when the per-file tree stops shipping.

### Why an extension could not handle it

- The manifest is a build artifact.

### Expected merge conflict zones

- LOW: `writeRuntimeManifest` in `build-coding-agent-bundle.mjs`.
