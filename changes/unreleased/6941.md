## 2026-11-18 - Session lists include stores registered in the shared session index (senpi#6941, omo-desktop-app#8097)

### What changed

- `packages/coding-agent/src/core/shared-session-stores.ts` (new, fork-only): reads `<agentDir>/session-stores/*.json` (`{ "version": 1, "root": "<absolute path>" }`, one file per store, written by its owner) and returns each registered root's session directories. Malformed, relative or missing roots contribute nothing.
- `packages/coding-agent/src/core/session-manager.ts`: `SessionManager.list` in the default per-folder layout also lists registered-store sessions whose cwd matches the folder (same `sessionCwdMatcher`), deduplicated by path. `SessionManager.listAll` with the default root walks the registered store directories next to the project directories. An explicit custom session dir is unchanged.

### Why

- The OmO desktop keeps its sessions in its own store, so a running terminal's `/resume` never listed sessions created in the app (omo-desktop-app#8097). Nothing is cached between listings, so a session the app creates shows in the next list of an already running process.

### Why an extension could not handle it

- Session directory enumeration happens inside core `SessionManager.list()` / `listAll()` before any extension or selector hook sees a session.

### Expected merge conflict zones

- LOW: the import block and the tail of `SessionManager.list()`; the directory collection at the top of the default-root branch of `SessionManager.listAll()` in `session-manager.ts`.
