## 2026-11-05 - The durable store is the default session store on Bun (S21b b1, senpi#5982)

### What changed

- `packages/coding-agent/src/core/sdk.ts`: `createAgentSession` calls `bindDefaultSessionStore` once it settles the session manager; `CreateAgentSessionOptions.sessionStore: "jsonl"` is a test-only, in-process opt-out.
- New `session-store/default-binding.ts` (binds a persisted session on Bun), `session-store/default-store.lazy.ts` (the only path to `bun:sqlite`, loaded on Bun only) and `session-store/default-store.ts` (one medium and one epoch per session under `<agentDir>/session-store/<id>`: claim 0->1 when fresh, otherwise bind at the current epoch; a takeover raises the epoch and fences that session's stale peers).
- `packages/coding-agent/package.json`: depends on `@earendil-works/pi-storage-sqlite-bun` (published by senpi#5975).

### Why

Plan row S21b (senpi#5822), K6/K9: on Bun the session store is durable by default. Every session replacement (new, fork, branch, switch) builds its runtime through `createAgentSession`, so one call binds them all.

### Why an extension could not handle it

Session persistence is set up before extensions load.

### Expected merge conflict zones

`createAgentSession`'s session-manager setup and `CreateAgentSessionOptions` in `sdk.ts`.

## 2026-11-05 - Durable store errors and options are part of the public API (S21b b1, senpi#5982)

### What changed

- `packages/agent/src/index.ts` exports `DurableStoreError` and the `DurableStoreOptions`/`StoreWritePoint` types next to `SyncCommit`/`SyncCommitStore`.

### Why

The default session store on Bun (coding-agent) opens and fences a session's medium through these types and must recognize a fenced or stale write by its error class.

### Why an extension could not handle it

They are the agent package's own exports.

### Expected merge conflict zones

The durable store export block in `packages/agent/src/index.ts`.

## 2026-11-05 - coding-agent depends on the Bun SQLite durable store (S21b b1, senpi#5982)

### What changed

- `packages/coding-agent/package.json` depends on `@earendil-works/pi-storage-sqlite-bun` (lockstep version), published as `@code-yeongyu/senpi-storage-sqlite-bun` by senpi#5975.

### Why

On Bun, the default session store is that package's SQLite store (S21b, senpi#5822). It is loaded lazily and only on Bun, so Node never loads `bun:sqlite`.

### Why an extension could not handle it

Package dependencies are the package's own manifest.

### Expected merge conflict zones

The `dependencies` block of `packages/coding-agent/package.json`.
