## 2026-11-02 - auth check sees extension-registered providers (senpi#2191, PR #5530)

### What changed

- `packages/coding-agent/src/cli/auth-check.ts`: `createAuthCheckModelRuntime(credentials, options)` now takes `{ cwd, agentDir?, resourceLoaderOptions? }`, loads extensions through a `DefaultResourceLoader` (no skills, prompt templates, themes or context files), replays their provider registrations into the auth-check runtime with `replayExtensionProviderRegistrations`, and refreshes only those providers offline. The caller's credential store stays the runtime's only store.

### Why

- The runtime held only the built-in catalog, so a provider an extension registers (`anthropic-subscription`) answered `provider_not_found` while generations through it succeeded, and `--model <provider>/<id>` failed resolution with `invalid_state`.

### Why an extension could not handle it

- `auth check` runs before any session or extension binding exists; the runtime it builds is the CLI's own.

### Expected merge conflict zones

- LOW: the `createAuthCheckModelRuntime` body and the import block of `auth-check.ts`.

## 2026-11-02 - Extension provider replay is one shared function (senpi#2191, PR #5530)

### What changed

- `packages/coding-agent/src/core/agent-session-services.ts`: the loop in `createAgentSessionServices` that replays queued extension provider registrations (config and native, in call order) is extracted unchanged into the exported `replayExtensionProviderRegistrations(modelRuntime, extensionRuntime)`, which returns the registered provider ids and the per-extension error diagnostics. `createAgentSessionServices` calls it in the same place.

### Why

- `auth check` must register the same extension providers a session does without building full session services, which open a writable `auth.json` when the runtime's store is read-only.

### Why an extension could not handle it

- Provider registration replay is part of service construction in core.

### Expected merge conflict zones

- MEDIUM: the provider-replay block in `createAgentSessionServices` and the `./extensions/index.ts` type import.

## 2026-11-02 - auth commands receive the CLI's extension factories (senpi#2191, PR #5530)

### What changed

- `packages/coding-agent/src/main.ts`: `runAuthCommand(args, extensionFactories)` passes `main()`'s extension factories, the `--extension` paths and `--no-extensions` to `createAuthCheckModelRuntime`.

### Why

- The auth-check runtime must load the same builtin and inline extensions a generation loads to see their providers.

### Why an extension could not handle it

- `runAuthCommand` is dispatched from `main()` before any extension loads.

### Expected merge conflict zones

- LOW: the `runAuthCommand` signature, its `createAuthCheckModelRuntime` call, and the `runAuthCommand(args, ...)` call in `main()`.
