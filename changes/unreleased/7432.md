## 2026-11-24 - RPC device-code logins send the user code (senpi#7125)

### What changed

- `packages/coding-agent/src/modes/rpc/connection-handler.ts`: `startLogin`'s `onDeviceCode` emits `auth_login_url` with `userCode`, `intervalSeconds` and `expiresInSeconds` next to the verification URL.

### Why

- Over RPC a device-code login (ChatGPT Subscription's headless route, and every provider using `onDeviceCode`) could never finish: the client got the verification page but not the code the user must type there, and the login ended when the poll expired.

### Why an extension could not handle it

- The RPC login event stream is built in the connection handler; an extension cannot add fields to `auth_login_url`.

### Expected merge conflict zones

- LOW: the `onDeviceCode` callback in `startLogin`.

## 2026-11-24 - auth_login_url lists the device-code fields (senpi#7125)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: the `auth_login_url` event type gains optional `userCode`, `intervalSeconds` and `expiresInSeconds`.

### Why

- RPC device-code logins now carry the user code; the shared event type must describe it.

### Why an extension could not handle it

- The event union is declared in core and consumed by every mode.

### Expected merge conflict zones

- LOW: the `auth_login_url` member of the session event union.
