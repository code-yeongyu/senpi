## 2026-11-06 - Opt senpi and its children out of Windows EcoQoS throttling (senpi#6125)

### What changed

- `packages/coding-agent/src/cli.ts`, `packages/coding-agent/src/cli-main.ts`, `packages/coding-agent/src/bun/cli.ts`, `packages/coding-agent/src/rpc-entry.ts`: each entry imports `./windows-power-throttling-startup.ts` (fork-only) after the private descriptor table is captured and before the internal role dispatch. On Windows under Bun the process opts itself out of `ProcessPowerThrottling` execution-speed throttling and wraps `ChildProcess.prototype.spawn` and `Bun.spawn`, so every child it starts gets the same call right after its pid is known. Off Windows, on Node, or with `SENPI_KEEP_POWER_THROTTLING=1` nothing is loaded or patched.

### Why

- A launcher chain with no visible window makes Windows apply EcoQoS to senpi and every child, which then runs at 2-10% of a core. The policy is per process and not inherited, so both this process and each child need the call.

### Why an extension could not handle it

- Extensions load after the CLI has already started processes (the bun re-exec, workers), and the opt-out must also cover the tool child and RPC host processes, which never load extensions.

### Expected merge conflict zones

- LOW: the import block at the top of each entry file.

## 2026-11-06 - The Windows tool-child job also runs the EcoQoS opt-out tests (senpi#6125)

### What changed

- `.github/workflows/ci.yml`: the `tool-child-windows` job runs `src/core/windows-power-throttling.test.ts` and `src/core/windows-power-throttling.win32.test.ts` under Bun, and its executed-tests step requires the win32 file to have passed tests.

### Why

- The opt-out is only observable against the real kernel32, so the assertion that this process and spawned children read `ControlMask=EXECUTION_SPEED, StateMask=0` needs a Windows runner, and a skipped file must fail the job.

### Why an extension could not handle it

- CI workflow configuration, not runtime behaviour.

### Expected merge conflict zones

- LOW: the `tool-child-windows` test command line and its file loop.
