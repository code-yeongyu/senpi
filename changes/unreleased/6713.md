## 2026-11-15 - bash gets an executor seam for the session's device, off by default (senpi#6713)

### What changed

- `packages/coding-agent/src/core/tools/bash.ts`: `BashToolOptions.deviceMachine` and the `OMO_TOOLS_VIA_DAEMON` flag (default off). With `bash` named, the tool runs on the injected device machine; with no device it fails with `DeviceUnavailableError` and never runs locally. Slice 1a only: nothing supplies a device machine yet, so no call goes through the device daemon; the relay transport is slice 1b.

### Why

- Q's order that every tool call on a remote device go through that device's hands daemon. A probe showed remote sessions run their tools in-process on the device, so the tool executor needs a seam a relay transport can plug into.

### Why an extension could not handle it

- The executor is chosen inside the built-in tool's construction; an extension cannot swap the operation layer the built-in bash tool uses without this option.

### Expected merge conflict zones

- LOW: `BashToolOptions` and the operations choice in `createBashToolDefinition`.

### Added

- `OMO_TOOLS_VIA_DAEMON=bash` (off by default): an executor seam that runs the bash tool on the session's device, with a typed `DeviceUnavailableError` instead of a local run when no device is available. Slice 1a only: not yet via the device daemon; the relay transport is slice 1b (senpi#6713).
