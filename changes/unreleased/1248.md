## 2026-11-02 - Honor explicit Anthropic long-cache retention on compatible proxies (senpi#1248)

### What changed

- `packages/ai/src/api/anthropic-messages.ts`: the `getCacheControl` wire-level `cache_control.ttl` decision delegates to the shared `allowsAnthropicLongCacheRetention()` helper, so an explicit `compat.supportsLongCacheRetention` value is authoritative on any host while an unset value keeps the `api.anthropic.com` hostname inference. The file no longer imports `isAnthropicApiBaseUrl`.

### Why

- A model routed through an Anthropic-compatible proxy could explicitly declare one-hour cache support, but the wire path still required the native Anthropic hostname and silently omitted `ttl: "1h"`. Sharing one helper with the TTL resolver keeps the request TTL and the internal cache accounting from drifting.

### Why an extension could not handle it

- The cache-control object is serialized inside the private Anthropic Messages request builder before dispatch; no extension hook can rewrite that provider-wire field or keep it synchronized with the core TTL accounting.

### Expected merge conflict zones

- LOW: the prompt-cache helper import and the `ttl` expression in `getCacheControl` in `packages/ai/src/api/anthropic-messages.ts`.

## 2026-11-06 - The warm pre-flight accepts an opted-in Anthropic-compatible host (senpi#1248)

### What changed

- `packages/ai/src/api/warm-prompt-cache.ts`: the Anthropic branch returns `{ supported: false }` for a host only through the shared `supportsAnthropicCacheWarming()` predicate instead of its own `isAnthropicApiBaseUrl` check, and the model cast moved above the guard so one predicate owns both decisions.

### Why

- `warmPromptCache` refused every non-native `anthropic-messages` base URL, so an explicitly opted-in gateway got `supported: false` and the keep-alive stopped with `unsupported-model` even after the retention decision learned to honour `compat.supportsLongCacheRetention` (senpi#1248).

### Why an extension could not handle it

- The warm request is assembled inside the provider package and its SDK client is constructed there; an extension cannot rewrite the refusal or the base URL it dials.

### Expected merge conflict zones

- LOW: the Anthropic branch guard in `warmPromptCache`.

## 2026-11-02 - Shared tri-state Anthropic long-cache retention decision (senpi#1248)

### What changed

- `packages/ai/src/utils/prompt-cache-ttl.ts`: adds the exported `allowsAnthropicLongCacheRetention(model)` helper. An explicit `compat.supportsLongCacheRetention` of `true` or `false` wins on any host; only an unset flag falls back to `isAnthropicApiBaseUrl(model.baseUrl) && getAnthropicCompat(model).supportsLongCacheRetention` (which keeps the Fireworks carve-out). The `anthropic-messages` branch of `resolvePromptCacheLifetime()` uses it to pick the 3600 s vs 300 s TTL. `getAnthropicCompat` is unchanged.

### Why

- `compat.supportsLongCacheRetention` is a documented models.json field, but for `anthropic-messages` the one-hour TTL was additionally gated on the native hostname, so an explicit proxy opt-in did nothing. Only the `foreign host + true` case changes behavior.

### Why an extension could not handle it

- Extensions sit above the provider request and cache-accounting boundary; they cannot change the wire `cache_control.ttl` and the core `resolvePromptCacheLifetime()` result together.

### Expected merge conflict zones

- MEDIUM: the `anthropic-messages` branch of `resolvePromptCacheLifetime()`, now a helper call instead of an inline conjunction.
- LOW: the helper inserted just above `getAnthropicCompat`.

## 2026-11-06 - Shared tri-state warming eligibility for Anthropic hosts (senpi#1248)

### What changed

- `packages/ai/src/utils/prompt-cache-ttl.ts`: adds `supportsAnthropicCacheWarming(model)`. The native host always qualifies; a proxy qualifies only when its model entry asserts `compat.supportsLongCacheRetention: true`. It sits beside `allowsAnthropicLongCacheRetention` and neither reads the other's state.

### Why

- Warming a host that ignores `cache_control` sends a request for no benefit, while refusing a host that honours it leaves a real prompt cache cold (senpi#1248). An unset flag cannot tell a host that caches for five minutes without the one-hour option apart from one that ignores `cache_control`, so only an explicit assertion widens eligibility.

### Why an extension could not handle it

- Provider-host cache capability belongs to the shared cache matrix; extensions consume it.

### Expected merge conflict zones

- LOW: a helper inserted below `allowsAnthropicLongCacheRetention`.

## 2026-11-06 - Keep-alive warms an opted-in Anthropic-compatible gateway (senpi#1248)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/cache-keepalive/index.ts`: `isWarmSupportedModel` calls the shared `supportsAnthropicCacheWarming()` from `@earendil-works/pi-ai` instead of the local `isAnthropicApiBaseUrl(model.baseUrl)` check, and the import list drops `isAnthropicApiBaseUrl`.

### Why

- The hostname-only check kept every gateway seat cold, so a session on an Anthropic-compatible proxy whose model sets `compat.supportsLongCacheRetention: true` never got a refreshing ping even though its requests do carry `cache_control` (senpi#1248).

### Why an extension could not handle it

- The builtin is the caller.

### Expected merge conflict zones

- LOW: the `@earendil-works/pi-ai` import block and `isWarmSupportedModel`.
