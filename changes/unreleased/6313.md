## 2026-11-10 - A relayed peer-agent delivery runs under the receiving session's own preset (senpi#6305)

### What changed

- `turn-origin.ts`: a fourth turn origin, `peer`, for a turn opened by a relayed delivery from an agent on a remote device of the same account. `decidingTurnIsDelegated` is false for it, so the permission decision treats the turn as the session's own work (a client-named preset, a live parent, the host default) and never runs it above that preset.

## 2026-11-10 - admit_external_message marks an agent's relayed delivery as a peer turn (senpi#6305)

### What changed

- `admit-external-message-command.ts`: `deliveryTurnMark` returns `peer` only when the connection is delegated, its device is the delegation's principal (never anything the record says), and the sender is an `agent`. A steer still joins the running turn; every other delivery keeps the connection's origin, so a non-agent or sender-less delivery from a remote device still asks.
- `test/suite/regressions/6305-peer-delivery-receiver-preset.test.ts`: on a host whose default preset is `full-access`, an agent's delivery from a remote device's connection runs its gated call without asking, while an `external` sender and a delivery with no sender still ask.

### Fixed
- A message another agent sends from a device of the same account now runs under the receiving session's own permission preset instead of stopping on an approval nobody can answer on an unattended host. Remote prompts and deliveries from any other kind of sender still ask (senpi#6305).

## 2026-11-10 - A tool-owned permission request keeps autoApproveAsk (senpi#6305)

### What changed

- `parsers.ts`: `toolOwnedPermissionRequests` passes a tool's `autoApproveAsk` through instead of dropping it, so a tool can ask the system to approve an `ask` decision for a call while `allow` and `deny` rules still match its request (an omo reply to the peer that messaged the run, oh-my-openagent#12954). `ToolPermissionRequest` (`core/extensions/types.ts`) declares the field.
