## 2026-11-05 - executeTool() bodies run on the preflighted arguments (senpi#5880)

### What changed

- `packages/coding-agent/src/core/execute-tool-on-host.ts`: the host's body calls `tool.execute()` with `prepared.args` instead of the host's frozen copy, so the preflight-fact carry to that copy is gone (`noPreflightCarry`). New `unrecordableArguments()` names why the host cannot record the arguments as JSON.
- `packages/coding-agent/src/core/agent-session.ts`: `executeTool()` throws `ExecuteToolError("invalid_params", ...)` for such arguments before it enters the host.

### Why

senpi#5861: since senpi#5852 the body got the host's JSON copy, so object identity, `Date` values and the body's in-place edits were lost, and a hook's BigInt threw untyped. Z1 keeps the extension and tool-call experience unchanged; the host still records its JSON copy.

### Why an extension could not handle it

`executeTool()` is the session's own extension API method; an extension cannot change how the session runs it.

### Expected merge conflict zones

- LOW: `execute-tool-on-host.ts` body and host options; `agent-session.ts` `executeTool()` before `runExecuteToolOnHost()`.
