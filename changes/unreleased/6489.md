## 2026-11-12 - Project settings writes use a key allowlist (senpi#6489, fixes #6479)

### What changed

- `modes/rpc/project-setting-policy.ts` (new): `set_project_setting` writes keys from a fixed allowlist after validating each value against its declared type. Any other key, its removal included, is decided the way the same edit would be decided for that session (`permission-system/dispatch.ts` policy export, `core/permission-decision.ts` origin rule). It is refused with `project_setting_needs_permission` or `project_setting_denied` when that decision is not an allow.
- `rpc-error-types.ts`: the two new error codes. `docs/rpc.md`: the allowlist and the refusals.
- Tests: `test/rpc/project-setting-policy.test.ts` and `test/suite/regressions/6479-project-settings-key-allowlist.test.ts`.

### Must not break

Keys on the allowlist write exactly as before. Reads are unchanged. A key outside the allowlist gets the same decision for every caller in the same state.

## 2026-11-12 - A policy-only dispatch decision for project settings writes (senpi#6489, fixes #6479)

### What changed

- `dispatch.ts`: `decideDispatchPolicy` returns the decision a call would get now from the session's registered authorizer, without asking or recording an approval. It throws exactly where `authorizeToolDispatch` refuses before it asks: no authorizer, a retired one, or a policy that cannot decide.

### Why

- `set_project_setting` decides a key outside its allowlist like the same edit, through the session's own authorizer, with no prompt.

### Why an extension could not handle it

- This is the builtin permission extension's own dispatch module; the decision has to use its registered authorizer.

### Expected merge conflict zones

- LOW: the exports of `dispatch.ts`.

## 2026-11-12 - The preset a record's own decision uses (senpi#6489, fixes #6479)

### What changed

- `permission-decision.ts`: `recordDecisionPreset` gives the preset the record being handled must be decided on, by the delegated-default rule for that record's own origin (`recordIsDelegated`) instead of the session's current turn; `undefined` when the live preset applies.

### Why

- An RPC record that starts no turn (`set_project_setting`) must be decided for its own origin, not for whichever turn ran last.

### Why an extension could not handle it

- The origin rule and the live sessions it binds live in the core.

### Expected merge conflict zones

- LOW: `permission-decision.ts` exports.
