## 2026-11-01 - Shipped-dependency audit script with an exact exceptions list (senpi#5296, part of #2941)

### What changed

- `scripts/audit-production.mjs`: runs `npm audit --omit=dev` and fails on every moderate-or-worse advisory, naming the advisory, package, installed node and the dependents npm flags through it. An advisory passes only when `scripts/audit-exceptions.json` holds an unexpired entry for that exact GHSA id, package and installed node; expired entries fail, unmatched entries print as stale, and malformed audit output or exception entries fail closed.
- `scripts/audit-exceptions.json`: the committed exceptions list, empty.
- `scripts/audit-production.test.mjs`: covers exact-node waivers, expiry, stale entries, the severity threshold and the fail-closed parsing.

### Why

- `scripts/audit-production.mjs`: releases were published while the scheduled audit was red (#2941). The script carries the fail-closed evaluation from the closed #3887, without its node-forge exception, so both the release and the scheduled job share one verdict.

### Why an extension could not handle it

- The dependency audit runs in CI and release workflows before any runtime extension loads.

### Expected merge conflict zones

- LOW: `scripts/audit-production.mjs`, `scripts/audit-exceptions.json` and `scripts/audit-production.test.mjs` are new files.

## 2026-11-01 - Releases and the scheduled audit run the shipped-dependency audit gate (senpi#5296, part of #2941)

### What changed

- `.github/workflows/publish-npm.yml`: the release job runs `node scripts/audit-production.mjs` right after installing dependencies, so an unexcepted moderate-or-worse advisory in the shipped tree fails the job before anything is published.
- `.github/workflows/npm-audit.yml`: the scheduled audit runs the same script instead of `npm audit --omit=dev --audit-level=moderate`.
- `.github/agent/skills/release-publish/SKILL.md`: documents the gate and the exceptions file.

### Why

- `.github/workflows/publish-npm.yml`: the scheduled audit was red for weeks while releases still published (#2941); nothing in the release path read it.

### Why an extension could not handle it

- Release workflows run before any runtime extension loads.

### Expected merge conflict zones

- LOW: `.github/workflows/publish-npm.yml`: one new step after "Install dependencies".
- LOW: `.github/workflows/npm-audit.yml`: the audit step's command.
