### Changed
- A session started with `--model` now keeps that model: when it fails (a rate limit, an overload), the turn ends with that model's error instead of moving to another model in the fallback chain. Sessions started without `--model` keep model fallback as before ([#6524](https://github.com/code-yeongyu/senpi/issues/6524)).

### Fixed
- When model fallback moves a session to another model, or back, the model now reads a note saying which model is answering, so it no longer states its launch model while another model writes its replies ([#6524](https://github.com/code-yeongyu/senpi/issues/6524)).

## 2026-11-12 - Explicit launch model pins the session; fallback switches leave a context note (senpi#6524)

### What changed
- `packages/coding-agent/src/core/agent-session.ts` turns model fallback off for a session whose start event names `initialModelProvenance: "cli"` (an explicit `--model`), the same runtime override `--no-model-fallback` applies.
- `packages/coding-agent/src/core/model-switch-marker.ts` (new) builds a hidden `model_switch` custom message for each fallback switch and revert. The retry controller's `switchModel` callback queues it, and the session writes it right before the next request (the continuation choke point and the turn-start restore), so the model that answers reads it.

### Why
- A session launched on one model answered about a quarter of its turns from other models and kept stating its launch model (omo#13243). A model chosen at launch must answer or fail with its own error, and any switch must be readable by the model.

### Why an extension could not handle it
- The fallback decision and the request boundary both live in the session's retry path.

### Expected merge conflict zones
- `packages/coding-agent/src/core/agent-session.ts`: the `noModelFallback` computation in the constructor, the `switchModel` callback passed to `RetryFallbackController`, the turn-start `_maybeRestoreFallbackPrimary()` call and the `continueRun` callback of the scheduled continuation.
