## 2026-11-17 - PI_TUI_DEBUG render dumps stay in the TUI's own log directory (senpi#6871)

### What changed

- `packages/tui/src/tui.ts`: `PI_TUI_DEBUG=1` render dumps go to `path.join(this.logDirectory, "tui-render")`, created 0700, instead of `path.join(os.tmpdir(), "tui")`. Each dump keeps its 0600 mode.

### Why

- On Linux `os.tmpdir()` is `/tmp` for every user, so `<tmpdir>/tui` was one directory for the whole machine. Whoever created it first owned it: every other user's render then threw `EACCES` writing its dump, and the dumps (whole screen contents) sat in a directory other users could list. `logDirectory` is already where this TUI's crash and debug logs go (the user's agent directory).

### Why an extension could not handle it

- The dump is written from inside `TuiBase`'s render loop; no extension hook sees or redirects it.

### Expected merge conflict zones

- LOW: the `PI_TUI_DEBUG` block near the end of `doRender` in `packages/tui/src/tui.ts`, if upstream changes its dump directory or contents.
