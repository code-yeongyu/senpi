## 2026-11-03 - In-process ToolHost context (senpi#5657)

### What changed

- `packages/agent/src/agent-loop.ts`: passes `local: { context, assistantMessage }` to the ToolHost.
- `packages/agent/src/execution/tool-host.ts`: optional `ToolHostOptions.local`.
- `packages/agent/src/execution/tool-outcome-events.ts`: the module description is a file comment instead of the first function's JSDoc.
- `packages/agent/src/index.ts`: exports the coordinator, ledger, memory store, admission line and `withToolNameCorrection`.

### Why

The prepared pipeline (brain/hand split S18b) runs today's preparation steps in the loop's process and needs the loop's context and the issuing assistant message; a remote host never reads them.

### Why an extension could not handle it

The ToolHost seam's options are the agent loop's own contract.

### Expected merge conflict zones

`agent-loop.ts` at the ToolHost call; `src/index.ts` exports.

## 2026-11-03 - Opt-in prepared execution pipeline (senpi#5657)

### What changed

- `packages/coding-agent/src/core/execution/pipeline-prepared.ts` and `pipeline-prepared-batch.ts` are new: the prepared ToolHost and its per-batch coordinator/executor adapter.
- `packages/coding-agent/src/core/execution/pipeline-witness.ts`: with `SENPI_EXECUTION_PIPELINE` set, installs a receipt writer (unless a sink exists) and, for `prepared`, the prepared ToolHost.
- `packages/coding-agent/src/core/execution/executor.ts` and `executor-types.ts`: `ReleaseRequest.onUpdateFor(toolCall)`, so updates carry the prepared call.

### Why

Plan row S18b: the prepared pipeline (executor + coordinator) behind the ToolHost seam, off by default until its phase gate.

### Why an extension could not handle it

The session's ToolHost and receipt sink are bound by the session itself.

### Expected merge conflict zones

`pipeline-witness.ts`; `executor.ts` release body.
