## 2026-11-12 - The sweep before a move's import leaves a staging folder it cannot list (senpi#6570)

### What changed

- `packages/coding-agent/src/core/session-move/import-staging.ts`: `entriesOf`, with which the sweep before an import attempt lists `.move-staging` and each move's folder in it, answers no entries for a folder it cannot list, whatever the reason. It did so only for a folder that was gone and threw anything else.

### Why

- One staging folder of another move that could not be read (`EACCES`, `EPERM`) made every import into that session folder fail as `import_failed`, after the move was recorded as receiving (the review of senpi#6445). The sweep removes clutter, so a folder of another move must not decide what this import answers; the removals already left what they could not remove.

### Why an extension could not handle it

- The move core owns the import's staging.

### Expected merge conflict zones

- None upstream: `core/session-move/` is fork-only.
