## 2026-11-11 - A published socket secret survives a failed cleanup or directory fsync (senpi#6437)

### What changed

- `packages/coding-agent/src/modes/rpc/socket-transport.ts`: after `link()` publishes the candidate, the private `publishSocketSecretIfAbsent` returns `published` even when the directory fsync fails or this attempt's staging file cannot be removed. Each of those is reported as a process warning, `SENPI_RPC_SOCKET_SECRET_DIRECTORY_SYNC_FAILED` or `SENPI_RPC_SOCKET_SECRET_STAGING_LEFT_BEHIND`, with the path and cause in `detail`. When `link()` itself fails, the staging file is removed first and the `link()` error is reported, never a cleanup error after it.
- `packages/coding-agent/src/modes/rpc/socket-transport.ts`: when `link()` fails with `EPERM`, `ENOTSUP`, `EOPNOTSUPP` or `ENOSYS` (a filesystem without hard links), the publication throws `SocketSecretHardLinksUnsupportedError` with `reason: "hard_links_unsupported"`, the path, and the `link()` error as `cause`. There is no fallback to writing the final path, because this design never opens that path for writing.
- Tests: `test/suite/regressions/desktop-4199-socket-secret-publish-failures.test.ts` (new) injects each of those failures. `desktop-4199-socket-secret-staging-cleanup.test.ts` now injects a close failure that leaves the descriptor open.

### Why

- These are review findings on senpi#4369. A failed staging `unlink` in `finally` replaced a `published` result or the `link()` error. A directory fsync failure failed the process that had already won the race, so it returned an error while every other reader used its secret. On a filesystem without hard links the raw `link()` errno reached the caller with nothing naming the cause. The close-failure test closed the descriptor before throwing, so it never covered a close that leaves the descriptor open.

### Why an extension could not handle it

- The RPC host, its supervisor and the terminal control endpoint provision the secret before any extension loads.

### Expected merge conflict zones

- LOW: `publishSocketSecretIfAbsent` in `socket-transport.ts`.

### Fixed
- On POSIX, a process that publishes the RPC socket secret no longer fails when the directory fsync or the staging-file cleanup after the publication fails. Those failures are now warnings. A filesystem without hard links gets a typed refusal that names the cause ([#6437](https://github.com/code-yeongyu/senpi/pull/6437)).
