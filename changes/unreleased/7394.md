## 2026-11-23 - A status publish no longer rebuilds a released session's history (senpi#6682)

### What changed

- `packages/coding-agent/src/modes/rpc/effect-ledger.ts`: `latestSessionEffect` folds the newest well-formed `rpc_effect` / `rpc_client_message_admission` receipt through `sessionManager.reduceHistory` (module-level `latestEffectHistory` reducer) instead of scanning `getEntries()`; the `latestCache` WeakMap goes, and the parameter narrows to `{ sessionManager: Pick<SessionManager, "reduceHistory"> }`.
- `scripts/realm-census.json`: `latestCache` replaced by `latestEffectHistory` (constant).

### Why

- Every `session_status` publish called `getEntries()`, which on an idle session whose history was released (senpi#3519) rebuilt and kept the full-history view, re-reading the file on a trimmed mirror. Any `subscribe_sessions` subscriber undid the idle memory release.

### Why an extension could not handle it

- The status stream's last-effect provider is RPC host internals; no extension hook reads or replaces it.

### Expected merge conflict zones

- LOW: `effect-ledger.ts`, the block above `EffectLedger` (fork-only file).
