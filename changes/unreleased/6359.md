### Changed
- Every built-in system prompt now tells the model the codebase is its own ("This codebase is yours: what it is for and how it is built are your call, and you will keep building on it") and to change it the way its owner would: build on the code that already does the job instead of adding a parallel copy, fit new behavior into the structure that is there, leave no duplicate or dead code behind, and fix a defect in the code being changed instead of only noting it. The "smallest correct change wins: no refactors beside a focused fix" rule and its rewordings ("no drive-by refactors", "diagnose and fix minimally", "the best change is usually the smallest correct change") are removed from every core so the two cannot cancel each other; the request still sets the scope, and a problem outside the code being changed is still a follow-up for the summary ([#6358](https://github.com/code-yeongyu/senpi/issues/6358)).

## 2026-11-10 - The code is the model's own; the smallest-change rule is gone (senpi#6358)

### What changed

- `style.ts` (full and diet): the opening Style paragraph no longer says "Smallest correct change wins: no refactors beside a focused fix". It now states ownership ("This codebase is yours: what it is for and how it is built are your call, and you will keep building on it") and what the owner does: build on the code that already does the job instead of adding a parallel copy, fit new behavior into the structure that is there, leave no duplicate or dead code behind; a defect in the code being changed is fixed now, one elsewhere is a follow-up for the summary. The kept constraints follow unchanged: no helpers or abstractions for hypothetical needs, no defensive checks inside trusted code, trust framework guarantees, validate only at system boundaries, targeted edit over file rewrite.
- `intent-gate.ts` (full and diet): the change-ask route reads "diagnose and fix at the cause, at exactly the asked scope - what fully satisfies an open-ended goal and nothing beyond it" (was "diagnose and fix minimally ... the smallest path that fully satisfies an open-ended goal").
- `verification.ts` (both claim-audit variants): "Fix failures your change caused and any that sit in the code you changed; note other pre-existing failures separately" (was "Fix only issues your changes caused; note pre-existing failures separately").
- Goldens: `test/suite/regressions/3483-prompt-goldens.json`, `test/suite/prompt-presets-native-baseline.json` (all 204 rows; `sourceCommit` kept as the suite asserts it) and the senpi-qa fused-equivalence goldens (darwin-arm64 and linux-x64) carry the new sentences; the goldens were derived by replacing exactly the changed sentences, and the 3483 byte-equality suite proves the derivation for the default prompt. E27's `prompt_cache_key` hashes the raw prompt and tool schemas (`packages/ai/src/api/openai-prompt-cache.ts`), so it is re-pinned from the harness's own actual value: linux-x64 from the EQ job on the PR, darwin-arm64 from a local `--compare --cases E27` run under the host pin. The six darwin-arm64 goldens E25-E30 also receive the senpi#6272 `tool.generate_image` insertion that senpi#6355 applied to the linux-x64 set only, so a macOS EQ run compares against the current prompt.

### Why

- Anthropic's Fable 5.2 prompting guide documents that a model with no ownership statement acts like a guest in someone else's repository: it bolts a new function on beside the existing one, leaves the duplicate, and only mentions a nearby defect. senpi#6314 kept the ownership sentence out and the smallest-change rule in; the repository owner ruled the reverse (senpi#6358): ownership in, smallest-change out, so neither cancels the other. "Fix minimally" and "fix only failures your change caused" were the same rule in other words and would have cancelled ownership on the most common ask (a bug fix) and on a pre-existing failure inside the changed code.

### Why an extension could not handle it

- The sentences are built inside the shared prompt builder.

### Expected merge conflict zones

- Fork-only files. The first Style paragraph in `style.ts`, the change-ask bullet in `intent-gate.ts`, the claim-audit sentence in `verification.ts`.

## 2026-11-10 - Every core owns the code; the smallest-change rule is gone (senpi#6358)

### What changed

- The ownership rule from `dynamic-prompt/changes.md` (same date) is stated in every core that carried the smallest-change rule, in that core's own register: Scope paragraph of `claude-fable-5-1.ts`, `claude-fable-5-2.ts`, `claude-opus-5.ts`, `claude-opus-5-5.ts`, `claude-sonnet-5-5.ts`, `claude-haiku-5-5.ts`, `kimi-k3.ts`, `kimi-k3-1.ts` and `deepseek-v4-1-flash.ts`; Style paragraph of `claude-fable-5.ts`, `grok-4.6.ts`, `grok-4.7.ts` and `gpt-5.5.ts`; "Pragmatism & Scope" of `gpt-5.6.ts` ("The best change is usually the smallest correct change ... A bug fix is not surrounding cleanup" is replaced); "Scope and Recovery" of `gpt-6-astra.ts` ("in the smallest correct change" is replaced). Kept in each: the request sets the scope, no helpers or abstractions for hypothetical needs, no defensive checks inside trusted code, validate only at system boundaries, the test-sizing and surgical-edit sentences.
- The same rule in other words is gone: `gpt-5.5.ts` "no drive-by refactors"; the change-ask route's "diagnose and fix minimally" in the Claude, Kimi and DeepSeek cores and `claude-fable-5.ts` (now "fix at the cause"); `grok-4.6.ts` / `grok-4.7.ts` "fix minimally from the error" (now "fix the error at its cause"), `grok-4.6.ts` "open-ended ones take the smallest path" (now "get what fully satisfies the goal and nothing beyond it"), `grok-4.7.ts` refactor route "make the smallest change" (now "make the change").
- Pre-existing problems: the Kimi K3 / K3.1 Scope lead and the DeepSeek Scope paragraph say a defect in the code being changed is fixed now and a problem elsewhere is a follow-up (was "a pre-existing bug ... is a follow-up ... unless the requested behavior cannot work without it"). Every core's claim-audit sentence reads "Fix failures your change caused and any that sit in the code you changed; note other pre-existing failures separately" (`grok-4.5.ts` in the orchestrator's voice, `gpt-6-astra.ts` with "report").
- `test/suite/prompt-presets-native-baseline.json`: all 204 hashes recaptured (every preset renders a changed sentence); `sourceCommit` unchanged as the generation suite asserts it.

### Why

- See `dynamic-prompt/changes.md` (senpi#6358): the owner's ruling reverses the senpi#6314 decision to leave the Fable 5.2 guide's ownership sentence out.

### Why an extension could not handle it

- These lines are the preset cores themselves.

### Expected merge conflict zones

- Fork-only files. The Scope / Style / Pragmatism paragraphs, the change-ask route bullet and the claim-audit sentence in each listed preset.
