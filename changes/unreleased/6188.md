## 2026-11-07 - The non-interactive project-trust context no longer imports the startup UI (senpi#6185)

### What changed

- `packages/coding-agent/src/cli/project-trust.ts`: `toExtensionMode` and the stderr notice move to the new `cli/project-trust-noninteractive.ts`, which also exports `createNonInteractiveProjectTrustContext` (selects and inputs resolve `undefined`, confirms `false`). `createProjectTrustContext` reuses them and keeps its interactive prompts.

### Why

- senpi#6185: the RPC workspace trust verbs (#6177) built their context through `cli/project-trust.ts`, whose static `cli/startup-ui.ts` import put `core/keybindings.ts`, `core/package-manager.ts` and `utils/child-process.ts` (`spawnSync`) on the RPC session path and turned `no-sync-in-session-path.test.ts` red. Those verbs only use a context with `hasUI: false`, which never prompts.

### Why an extension could not handle it

- This is the CLI's own trust-context factory used by core startup and the RPC host.

### Expected merge conflict zones

- LOW: the import block and `notify` of `createProjectTrustContext`.

## 2026-11-07 - An asynchronous project-trust resource scan for the RPC session path (senpi#6185)

### What changed

- `packages/coding-agent/src/core/trust-manager.ts`: adds `hasTrustRequiringProjectResourcesAsync`, the same walk as `hasTrustRequiringProjectResources` over `fs/promises` (with `projectCodemodeNamesExecutableAsync` and `projectAgentsSkillDirsAsync`); the codemode executable-settings path and parsing are shared helpers. The synchronous function is unchanged; `test/trust-manager.test.ts` asserts both agree on every case.

### Why

- senpi#6185: `get_project_trust` / `set_project_trust` ran the synchronous `existsSync`/`readFileSync` scan on the RPC session path, which the frozen no-sync baseline forbids.

### Why an extension could not handle it

- Project trust is core policy that the RPC host calls directly.

### Expected merge conflict zones

- LOW: `codemodeExecutableSettings` and the end of `hasTrustRequiringProjectResources`.
