## 2026-11-19 - an install of the same build replaces a serving host only once its install is gone (senpi#7088)

### What changed

- `packages/coding-agent/src/modes/rpc/host-install.ts`, `host-install-rule.ts`: a host's runtime root (`installPath`) and whether it still exists (`installPresent`); `installGoneReplaces` is the one rule every path asks.
- `packages/coding-agent/src/modes/rpc/host-core-gate.ts`, `host-handover-wire.ts`, `multi-session-host.ts`: `get_protocol_info` reports `installPath` and `installPresent`, read at each answer; the idle handover reads presence before each `begin_handover`.
- `packages/coding-agent/src/modes/rpc/host-decision.ts`: `host ensure --policy upgrade` hands over with `reason: "install_gone"` to a client of the same engine whose extension set covers the host's, when the host reports its install gone.
- `packages/coding-agent/src/modes/rpc/host-idle-handover.ts`: `already_current` only while the host's install is present.
- `packages/coding-agent/src/modes/rpc/host-handover-request.ts`: the CLI prints the named generation's `already_current` as a refusal (exit 3), never `handover_completed`.
- `packages/coding-agent/src/modes/rpc/host-protocol-info.ts`, `host-status.ts`, `host-status-all.ts`: the fields are parsed, and `host status` shows `binaryPath` and `installPresent`.

### Why

- senpi#7086: two installs of one build share a content-digest `runtimeBuildId`, so a host started from one install kept serving from it even after it was removed, and the CLI reported an idle handover that moved nothing as completed.

### Why an extension could not handle it

- Host identity, the ensure decision and the idle handover are the RPC host's own lifecycle.

### Expected merge conflict zones

- MEDIUM: the tail of `decideHostAction` in `host-decision.ts`; the same-build branch of `idleHandoverOutcome`.
- LOW: `withHostIdentity`, `HostCoreGate` construction and `dispatch`, the `HostStatusReport` fields.

### Fixed
- A socket host started from one install of a build is replaced by another install of the same build once its own install is removed (`host ensure`, or an idle handover at its next idle point); while it is present the host keeps serving, so two live installs never hand it back and forth. `host handoff --when idle` reports an `already_current` refusal instead of `handover_completed` when nothing moved, and `host status` shows `binaryPath` and `installPresent` ([#7088](https://github.com/code-yeongyu/senpi/pull/7088))
