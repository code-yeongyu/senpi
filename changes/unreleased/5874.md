### Added
- Remote dialogs (brain/hand split S26b): the `ui-dialog` nested plane (`UI_DIALOG_PLANE`, `askRemoteDialog`, `serveDialogPlane`). A dialog a tool raises on a hand is asked by the loop that owns the call. The hand keeps its timeout and abort, and the loop's dialog settles when the hand stops waiting or the call ends. An invoke now names the nested planes the session serves to it (`planes`, absent when none; `HandCall.planes`). KILL-DIALOG-01 and FAULT-DIALOG-01 conformance cases are registered and exported from `./conformance` ([#5874](https://github.com/code-yeongyu/senpi/pull/5874)).

### Added
- On a split session, a select, confirm or input dialog raised by a tool on the hand (a permission prompt, an MCP elicitation, a sign-in code) is answered where the session runs: by the attached client, or by another session or agent over RPC, with the first answer winning. A late answer is refused. A hand whose loop serves no dialog plane keeps today's behavior ([#5874](https://github.com/code-yeongyu/senpi/pull/5874)).

## 2026-11-05 - Remote dialogs on the hand link (S26b, senpi#5874)

### What changed

- `packages/agent/src/execution/remote-ui.ts` is new: the `ui-dialog` plane, its request and answer codec, `askRemoteDialog` (hand) and `serveDialogPlane` (loop).
- `packages/agent/src/execution/remote-protocol.ts`: `RemoteInvoke.planes` (optional, decoded fail-closed); `remote-link.ts` stamps it from the planes the session serves; `remote-executor.ts` passes it to `HandCall.planes`.
- `packages/agent/src/execution/testing/dialog-cases.ts`, `dialog-registry.ts` are new (KILL-DIALOG-01-SL/XM, FAULT-DIALOG-01); `hand-harness.ts` gains `planes`, `body` and `kill()`; `conformance/registry.ts` and `conformance/index.ts` register and export them; `packages/agent/src/index.ts` exports the dialog plane.

### Why

Brain/hand split S26b (C5.c, K2): a dialog on the hand must reach whoever can answer the session's dialogs.

### Why an extension could not handle it

The hand link and its nested planes are below the extension layer.

### Expected merge conflict zones

`conformance/registry.ts` tail (the registry chain S27a, S26b, S33, S35); the `execution/` export block of `src/index.ts`; `RemoteInvoke` in `remote-protocol.ts`; `dispatch` in `remote-link.ts`.

## 2026-11-05 - The hand's call port answers dialogs through the loop (S26b, senpi#5874)

### What changed

- `packages/coding-agent/src/core/extensions/ui-remote-dialog.ts` is new: `remoteDialogs` (the port's dialog half) and `serveDialog(runner)` (the loop side).
- `packages/coding-agent/src/core/extensions/ui-plane-data.ts` is new: the plain-data check, moved out of `ui-presentation.ts`.
- `packages/coding-agent/src/core/extensions/ui-presentation.ts`: `openPresentationPort(..., dialogs)` and `PresentationBroker.present(nested, planes, run)`. With the `ui-dialog` plane the port answers dialogs and is no longer presentation-only, so `hasUI` is true on the hand.

### Why

S26b (C5.c): a hand's permission prompt and other dialogs must be answerable where the session runs.

### Why an extension could not handle it

Which UI an extension's `ctx.ui` is during a hand call is decided by the hand's runtime.

### Expected merge conflict zones

`openPresentationPort` and `PresentationBroker.present` signatures in `ui-presentation.ts`.

## 2026-11-05 - A hand call carries the planes its loop serves (S26b, senpi#5874)

### What changed

- `packages/coding-agent/src/modes/rpc/runtime-factory-loopless.ts`: `execute(..., nested, planes)` passes the planes to the call's port; a file operation's port gets none.
- `packages/coding-agent/src/modes/rpc/remote-executor-scope.ts`: passes `HandCall.planes` through.

### Why

S26b: the hand must know at call start whether its loop serves dialogs.

### Why an extension could not handle it

The loopless runtime's call path is below the extension layer.

### Expected merge conflict zones

The `execute` signature of the loopless runtime.
