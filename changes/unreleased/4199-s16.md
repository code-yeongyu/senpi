## 2026-10-27 - Advertise the reservation launch capabilities and choose the launch route by them (desktop#4199)

### What changed

- `packages/coding-agent/src/modes/rpc/launch-capabilities.ts` (new): the capability names `socket_secret_reservation_v1` and `participant_lifetime_locks_v1`, what this build reports per platform (both on Windows, none elsewhere) and the probe answer for `--launch-capabilities --version`.
- `packages/coding-agent/src/modes/rpc/host-launch-reservation.ts`: `selectLaunchRoute` runs a selected command, wrapper included, with the probe and classifies its explicit answer. Both names select the reservation route; a version line or a list missing either name keeps the legacy route; any spawn failure, non-zero exit, deadline or other output is `launch_capability_unknown`. `offerSupervisorLaunch` takes the generation's expected roles.
- `packages/coding-agent/src/modes/rpc/host-ensure-start.ts`: on Windows, an explicit `--child-command` in `hostArgs` is probed before the owner's presence lock, the secret and the reservation; the generation expects the host role only when that command reports both capabilities.
- `packages/coding-agent/src/modes/rpc/host-lifecycle.ts`: a parent-admitted supervisor launches its host the legacy way (no locator, no offer, no claim wait) when the generation expects no host role, and otherwise probes an explicit child command before offering the role; a command that did not report both fails with `launch_capability_missing` before the spawn.
- `packages/coding-agent/src/modes/rpc/host-lifecycle-launch.ts`: adds the `launch_capability_missing` and `launch_capability_unknown` rejections.
- `packages/coding-agent/src/modes/rpc/endpoint-reservation-store.ts`: `expectedRoles` reads a generation's expected roles.

### Why

- Design section 5, "Mixed versions", final paragraph: the new parent-admitted route needs an explicit side-effect-free launch-capability result for the selected command naming both capabilities; an old runtime's recognized legacy or unsupported-capability result keeps the unchanged legacy route before any role offer; an execution/IO error is not a legacy result; no capability is inferred from a version, a spawn's success or a missed acknowledgement. The Revision 7 scope limits the reservation path to Windows public endpoints, and the POSIX lifetime locks are the conditional contract #4199 does not implement, so a POSIX build advertises neither capability.

### Why an extension could not handle it

- The probe is answered before the CLI loads anything, and route selection runs in the host launch path before extensions exist.

### Expected merge conflict zones

- `packages/coding-agent/src/modes/rpc/host-ensure-start.ts`: the start prologue and `reserveSupervisorLaunch`.
- `packages/coding-agent/src/modes/rpc/host-lifecycle.ts`: the host offer before `spawnHostChild` and `offerReservedHost`.
- `packages/coding-agent/src/modes/rpc/host-launch-reservation.ts`: `offerSupervisorLaunch`.

## 2026-10-27 - Answer the launch-capability probe before anything else runs (desktop#4199)

### What changed

- `packages/coding-agent/src/cli.ts`: answers `--launch-capabilities --version` with the launch-capability record before its `--version` fast path.
- `packages/coding-agent/src/main.ts`: `main()` answers the same probe first, for the compiled binary and direct `cli-main` runs.

### Why

- Design section 5, "Mixed versions": a launcher must get a side-effect-free launch-capability result from the selected command before it chooses the reservation route. Riding on `--version` keeps an old runtime's answer side-effect free too: it prints its version, which is its recognized legacy result.

### Why an extension could not handle it

- The answer must come before the engine, settings or extensions load.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/cli.ts` just before the `--version` fast path.
- LOW: `packages/coding-agent/src/main.ts` at the top of `main()`.

### Added

- A launcher can ask a runtime for its launch capabilities with `--launch-capabilities --version`. On Windows this build reports `socket_secret_reservation_v1` and `participant_lifetime_locks_v1`, and the host launch uses the reservation route only for a command that reports both; an older runtime keeps its legacy launch, and an unreadable answer fails the start (sisyphuslabs/omo-desktop-app#4199, design section 5 "Mixed versions").
