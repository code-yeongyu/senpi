## 2026-11-22 - Windows bash redirects to nul reach /dev/null instead of creating a nul file (senpi#3765)

### What changed

- `packages/coding-agent/src/core/tools/bash.ts`: `createLocalBashOperations` wraps `exec` on win32 to pass the command through `mapWindowsNulRedirects` (new fork-only `windows-nul-redirect.ts`), which rewrites an unquoted output-redirect target that is exactly `nul` to `/dev/null`. Other platforms and PowerShell are unchanged.

### Why

- Git Bash creates a literal `nul` file for a cmd.exe-style `2>nul`/`>nul`, which git cannot index, so later checkpoints failed on every turn.

### Why an extension could not handle it

- The local bash operations are built inside the core tool; a `spawnHook` is per-tool-instance user configuration and is not applied to `user_bash` or other callers of `createLocalBashOperations`.

### Expected merge conflict zones

- LOW: `createLocalBashOperations` in `bash.ts`.

### Fixed
- On Windows, a bash command that redirects to `nul` (`2>nul`, `>nul`, `&>nul`) no longer leaves a literal `nul` file in the working directory; the output is discarded as intended ([#3765](https://github.com/code-yeongyu/senpi/issues/3765))
