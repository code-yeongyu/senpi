## 2026-11-12 - A landing place that cannot be looked at is not free (senpi#6471)

### What changed

- `packages/coding-agent/src/core/session-move/landing-occupied.ts`: `landingFile` asks whether a name stands at the landing place with its own `nameStands` (an `lstat`), no longer with the shared existence helper. Only "nothing by that name" is `free`. A link counts as a name even when it leads nowhere, so it reads as `occupied`. Any other failure to look is thrown, and the step that asked fails.

### Why

- The shared existence helper answers "not there" for every failure to look. So a landing place that could not be inspected read as `free`: `prepare` readied a move that could not land, and the import went on to put the session's file at that name, replacing what stood there.
- `prepare` and the import ask this one function, so one change covers both steps.

### Why an extension could not handle it

- The landing check is engine state inside `prepare` and the import's commit; no extension runs there.

### Expected merge conflict zones

- LOW: the top of `landing-occupied.ts` (its imports and the lines above `landingFile`).

### Fixed

- A session move no longer treats a landing place it cannot inspect as free. A link at the landing file's name, including one that leads nowhere, now keeps the place (`move_target_occupied`), and any other failure to look fails `prepare` or the import with `move_failed` instead of letting the move land over what stands there.
