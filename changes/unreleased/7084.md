## 2026-11-19 - session_stop: one stop for everything a session owns (oh-my-openagent#14390, senpi#7084)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: new `session_stop` event (`SessionStopEvent { requestedBy: "user" | "agent", signal }`), its handler result `SessionStopResult { stopped, failed }` with `SessionStopItem` / `SessionStopFailedItem`, the per-owner `SessionStopOwnerReport` and `SessionStopReport { owners }`, the `pi.on("session_stop", ...)` overload, and the optional `ExtensionContext.stopSession(requestedBy)`.
- `packages/coding-agent/src/core/extensions/runner.ts`: `ExtensionRunner.emitSessionStop(requestedBy)` runs every `session_stop` handler through `runSessionStopHandlers` (new `session-stop-emit.ts`) under the `session_shutdown` handler budget and reports a handler that throws, answers something that is not a report, or runs past the hard cap under `failed`; the extension context's `stopSession` calls it.
- `packages/coding-agent/src/core/extensions/index.ts`: re-exports the new `SessionStop*` types.
- `packages/coding-agent/src/core/extensions/event-placement.ts`: places `session_stop` as `split`.

### Why

A user who said "do this, then stop" still had a goal continuing, persistent monitors that came back after a restart, and children running: stopping took `/goal clear`, `kill_bash` per watch and `/tasks` separately, and nothing removed a persistent monitor's restore record. One event every owner answers lets one command stop everything, with a report of what stopped and what could not.

### Why an extension could not handle it

The work lives in several extensions (goal, terminal, and outside packages such as a task engine); only the runner can reach every loaded extension's handlers and bound each one, and the context capability that starts the stop is created by the runner.

### Expected merge conflict zones

- LOW: the `SessionMoveImportEvent` neighborhood, the `ExtensionEvent` union and the `on(...)` overload list in `types.ts`; the context object in `runner.ts` next to `registerRunBackgroundJob`; the type export list in `index.ts`.

## 2026-11-19 - Root exports for session_stop (oh-my-openagent#14390, senpi#7084)

### What changed

- `packages/coding-agent/src/index.ts`: exports `SessionStopEvent`, `SessionStopItem`, `SessionStopFailedItem`, `SessionStopResult`, `SessionStopOwnerReport` and `SessionStopReport` from the package root.

### Why

An extension package outside this repository answers `session_stop` with these shapes (the task engine cancels its children there).

### Why an extension could not handle it

The package root's export list is the public contract; an extension cannot add exports to it.

### Expected merge conflict zones

- LOW: the extension type export list in `index.ts`.

### Added
- `/stop all` and the `stop_session` tool stop everything a session owns for good: the goal is cleared, every monitor (persistent ones included) and background shell is killed and none is restored after a restart, and every extension answering the new `session_stop` event (for example a task engine's children) stops its work; the command prints what each owner stopped and what it could not ([#7084](https://github.com/code-yeongyu/senpi/pull/7084))
- Extension API: the `session_stop` event and `ctx.stopSession()`; each handler is bounded by the `session_shutdown` handler budget and a failing or hung one is reported under `failed` ([#7084](https://github.com/code-yeongyu/senpi/pull/7084))
