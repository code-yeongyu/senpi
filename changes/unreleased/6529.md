## 2026-11-12 - A pinned model's failure is a typed exhaustion (senpi#6524)

### What changed
- `packages/coding-agent/src/core/agent-session.ts`: `_reportPinnedModelFailure`, called when a run settles, emits `retry_fallback_exhausted` with `pinned: true` and the failing model when model fallback is off and the run ended on a failure fallback would have handled. The event type gains the optional `pinned` field.

### Why
- A pinned turn must end in a typed error naming the model and the cause (omo#13243, review of #6526); rate limits carry no typed `errorCause`.

### Why an extension could not handle it
- The settle edge and the fallback state are the session's.

### Expected merge conflict zones
- `packages/coding-agent/src/core/agent-session.ts`: the `retry_fallback_exhausted` member of the session event union, `_emitAgentSettled` before `_takeRunFallbackExhaustion()`, and the new `_reportPinnedModelFailure` next to `_emitFallbackExhausted`.

## 2026-11-12 - Print mode and TUI name a pinned model failure (senpi#6524)

### What changed
- `packages/coding-agent/src/modes/print-mode.ts` prints `Pinned model failed: <model> (...)` for a `retry_fallback_exhausted` with `pinned: true`; `packages/coding-agent/src/modes/interactive/interactive-mode.ts` titles its notice box `Pinned model failed`.

### Why
- So a pinned failure is not reported as a fallback chain that ran out.

### Why an extension could not handle it
- Both surfaces are built-in modes.

### Expected merge conflict zones
- The `retry_fallback_exhausted` branches in `print-mode.ts` and `interactive-mode.ts`.
