## 2026-11-12 - A pinned model's failure is a typed exhaustion (senpi#6524)

### What changed
- `packages/coding-agent/src/core/agent-session.ts`: `_reportPinnedModelFailure`, called when a run settles, emits `retry_fallback_exhausted` with `pinned: true` and the failing model when model fallback is off and the run ended on a failure fallback would have handled. The event type gains the optional `pinned` field.
- The hard-error class moves to `_isHardErrorFallbackClass`, so a non-retryable failure (a 400 `invalid_request`, `insufficient_quota`) is still classed as one on a pinned session, where `canTryFallback` is always false. `_isHardErrorFallbackEligible` keeps its old meaning (the class plus a usable candidate).
- The report reads the run's OWN last assistant reply (`_runLastAssistant`, set on each assistant message and read and cleared at the top of every settle, before any early return), so a run that settles with no reply of its own never re-reports an earlier turn's failure, including one kept by a run that settled while fallback was on.
- A pinned usage-limit failure sets `agent_settled.fallbackExhausted` exactly as a spent chain does: the goal monitor waits for the stated reset.

### Why
- A pinned turn must end in a typed error naming the model and the cause (omo#13243, review of #6526); rate limits carry no typed `errorCause`.

### Why an extension could not handle it
- The settle edge and the fallback state are the session's.

### Expected merge conflict zones
- `packages/coding-agent/src/core/agent-session.ts`: the `retry_fallback_exhausted` member of the session event union, `_emitAgentSettled` before `_takeRunFallbackExhaustion()`, and the new `_reportPinnedModelFailure` next to `_emitFallbackExhausted`.

## 2026-11-12 - Print mode names a pinned model failure (senpi#6524)

### What changed
- `packages/coding-agent/src/modes/print-mode.ts` prints `Pinned model failed: <model> (...)` for a `retry_fallback_exhausted` with `pinned: true`.

### Why
- So a pinned failure is not reported as a fallback chain that ran out.

### Why an extension could not handle it
- Print mode is a built-in mode.

### Expected merge conflict zones
- The `retry_fallback_exhausted` branch of the event subscriber in `print-mode.ts`.

## 2026-11-12 - The TUI names a pinned model failure (senpi#6524)

### What changed
- `packages/coding-agent/src/modes/interactive/interactive-mode.ts` titles the notice box of a `retry_fallback_exhausted` with `pinned: true` `Pinned model failed · <model>`.

### Why
- So a pinned failure is not reported as a fallback chain that ran out.

### Why an extension could not handle it
- The notice box belongs to the built-in interactive mode.

### Expected merge conflict zones
- The `retry_fallback_exhausted` case in `interactive-mode.ts`.
