## 2026-11-08 - ask-user refuses escape residue in question text once (oh-my-openagent#12797)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/ask-user/escape-residue.ts` (new): `findEscapeResidue` finds `\uXXXX` escapes left in question, header and option text, both literal ones and ones whose backslash was dropped (`ub0b4`), with guards against hex-like ids and quoted code; `AskUserEscapeResidueError` is the typed tool error.
- `packages/coding-agent/src/core/extensions/builtin/ask-user/tool.ts`: before a card opens, a call whose text holds escape residue is refused once with `AskUserEscapeResidueError`, which asks the model to re-call with raw UTF-8 text. If the next call still holds residue, the card opens as written and the user gets a warning notice. `AskUserState.escapeResidueRefused` carries the one refusal.
- `packages/coding-agent/src/core/extensions/builtin/ask-user/extension.ts`, `packages/coding-agent/src/core/extensions/builtin/ask-user/resume.ts`: the new state field starts false and resets on `session_start` and `agent_end`.

### Why

- Models sometimes write non-ASCII tool-call text as `\uXXXX` escapes and drop the backslash, so a Korean card showed `ub0b4 Tailscale 쓰기` for `내 Tailscale 쓰기` (oh-my-openagent#12797). The JSON is valid, so parsing cannot catch it; only the text can.

### Why an extension could not handle it

- The check belongs to the ask-user builtin's own argument handling; it is a fork-only builtin, not an upstream path.

### Expected merge conflict zones

- LOW: `AskUserState` and the `execute` path just before `startQuestion` in `tool.ts`.
