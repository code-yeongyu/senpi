## 2026-11-27 - Embedders can retire a closed session without opening it (senpi#7577)

### What changed

- `packages/coding-agent/src/index.ts` exports `retireSession` and `SessionRetirement`.

### Why

- A controller can close a session after its last host has exited.

### Why an extension could not handle it

- No extension is running when a session exists only on disk.

### Expected merge conflict zones

- LOW: the named exports in `packages/coding-agent/src/index.ts`.

## 2026-11-27 - Host recovery respects session retirement (senpi#7577)

### What changed

- A final requested close records retirement. Handover, retained restart and ordinary opens skip retired sessions. Explicit `open_session.reopenRetired` can reopen one. `packages/coding-agent/src/modes/rpc/connection-handler.ts` returns live retirement from `get_state`; `find_session` and resident list rows also report it.

### Why

- Retained sessions could reappear after close without a caller requesting another turn.

### Why an extension could not handle it

- Successor hosts decide which transcripts to open before session extensions exist.

### Expected merge conflict zones

- The open command schema, host capability list, and `get_state` case in `packages/coding-agent/src/modes/rpc/connection-handler.ts`.

### Fixed
- Multi-session hosts no longer restore retired sessions automatically. Hosts advertise `session_retirement`; an explicit `open_session` with `reopenRetired: true` reopens one ([#7581](https://github.com/code-yeongyu/senpi/pull/7581)).
