## 2026-10-28 - Context usage after a model switch is not the previous model's count (oh-my-openagent#11684, senpi#4675)

### What changed

- `packages/ai/src/types.ts`: `StreamOptions.contextUsageNotBefore` (Unix ms) carries when the session switched to the request's model.

### Why

- Provider usage counts the context with the answering model's tokenizer. After a mid-session model switch the last usage came from the previous model, so the status line showed it against the new model's window (304K/500K where the new model counted about 172K), and compaction thresholds and request-time context checks read the same figure until the new model answered. Both switch directions were affected.

### Why an extension could not handle it

- The figure is derived inside the engine's own estimator and session accounting, which extensions only read through `ctx.getContextUsage()`; no hook can change which usage the core compaction gates and provider clamps trust.

### Expected merge conflict zones

- LOW: one optional field added to `StreamOptions` after `onProviderStreamEvent`.
