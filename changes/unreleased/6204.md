## 2026-11-08 - A client-named approval mode is echoed and survives a preset-less reopen (senpi#6204)

### What changed

- `packages/coding-agent/src/core/agent-session-runtime.ts`: `createAgentSessionRuntime` restores a client-named preset the session file recorded when the open names none; the constructor, `apply()` and `setPermissionPreset` bind the named preset to the live session (reported as `client`, persisted, and announced on a live change).
- `packages/coding-agent/src/core/permission-mode.ts` (new): the mode a session enforces (`permissionPreset`, `permissionPresetSource`, `permissionPresetStatus`, `effectivePermissionPreset`) and the `permission_mode` custom entry.

### Why

- A remote client could not confirm which approval mode a session enforces, and the mode it named was lost after a relay host restore (sisyphuslabs/omo-desktop-app#6189).

### Why an extension could not handle it

- The launch profile and the session file meet only in the runtime factory path; an extension loads after the flags are already computed.

### Expected merge conflict zones

- LOW: `createAgentSessionRuntime`, the constructor and `apply()` of `AgentSessionRuntime`.

## 2026-11-08 - `pi.sessionDialog`, the `audience` dialog option and `permission_preset_changed` (senpi#6204)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ExtensionUIDialogOptions.audience`, an optional `opts` on `editor`, and `ExtensionAPI.sessionDialog`.
- `packages/coding-agent/src/core/extensions/loader.ts`: wires `pi.sessionDialog` to the current UI context.
- `packages/coding-agent/src/core/extensions/session-dialog-api.ts` (new): the session-addressed dialog adapter.
- `packages/coding-agent/src/core/extensions/builtin/permission-system/settings.ts`: exports `resolvePermissionPreset`, sharing one preset order with `loadPermissionSettings`.

### Why

- A task runner forwarding a background child's permission prompt needs a dialog every attached client can answer (sisyphuslabs/omo-desktop-app#6189).

### Why an extension could not handle it

- Dialog targeting is decided by the RPC event writer from the raising connection; an extension cannot address a frame to the session.

### Expected merge conflict zones

- LOW: `ExtensionUIDialogOptions` and the `ExtensionAPI` block next to `getPermissionPreset`.
