## 2026-11-05 - A Node JSONL-hatch writer is fenced and imported by the durable store; diverged hatch files fork (S21b b3, senpi#6037)

### What changed

- `packages/coding-agent/src/core/session-holders.ts`, `session-holder-records.ts`: under `SENPI_SESSION_STORE=jsonl` on Node, the holder record carries `k9f2: true` and `liveHolders` reports it.
- `packages/coding-agent/src/core/session-store/hatch-fence.ts` and `durable-binding.ts`: `DurableSessionBinding.open` first calls the new `fenceHatchWriters` hook, which advances the file's write fence only when a live foreign holder carries `k9f2`, so the hatch writer's next write gets `SessionFencedError` while Bun holders keep warn-and-continue.
- `packages/coding-agent/src/core/session-store/hatch-marker.ts` and `session-manager.ts`: each Node hatch write (append, first flush, async header write, whole-file rewrite, forkFrom) records the file's size and mtime in `<file>.k9f2`, so a diverged hatch file forks on the next Bun open.
- `packages/coding-agent/src/core/session-store/durable-binding.ts`: the stale-projection repair and the reprojection on open fence a live hatch writer, then import what it wrote, before replacing the file; the repair writes the store's committed session.
- `packages/coding-agent/src/core/session-store/projection-file.ts`: the binding's projection-file helpers move here unchanged (`durable-binding.ts` re-exports the seam); `session-hold-errors.ts` gains the fence error text.

### Why

Plan row S21b (senpi#5822), K9.f: a developer running the Node JSONL hatch must not lose or fork history silently once the same session opens durably on Bun.

### Why an extension could not handle it

Session holding, write fencing and the durable binding are core session-store paths.

### Expected merge conflict zones

`DurableSessionBinding.open` and the repair path in `durable-binding.ts`; the write sites in `session-manager.ts`.
