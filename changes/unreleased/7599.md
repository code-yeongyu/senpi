## 2026-11-28 - Preserve live default extension shims across installations (#7597)

### What changed

- `packages/coding-agent/src/core/resource-loader.ts` keeps an existing generated shim when it targets a regular builtin module of the same name.
- `packages/coding-agent/src/core/generated-shim-banner.ts` recognizes the complete first-line sentence across brands and parses the single generated re-export.

### Why

- Distinct installations generate distinct absolute URLs for the same builtin. Replacing a live target on startup changes the shared file every time the other installation seeds it.

### Why an extension could not handle it

- Resource seeding writes the shared file before extensions load.

### Expected merge conflict zones

- `DefaultResourceLoader.ensureGlobalDefaultExtensions`, dead-target repair and generated shim recognition.

## 2026-11-28 - Serialize watcher-triggered session reloads (#7597)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/config-reload/index.ts` shares a reload queue across engine copies serving the same event loop. Parked sessions keep pending changes through reattachment.
- `packages/coding-agent/src/core/extensions/builtin/config-reload/generated-shim-filter.ts` filters generated re-exports using the same parser as resource seeding.

### Why

- One watched change could start a reload in every session at once. Cross-brand generated shims reached that path as user edits.

### Why an extension could not handle it

- This builtin owns the watcher's pending changes, admission decision and reload handoff.

### Expected merge conflict zones

- `flushPending`, session activity handlers and generated-shim filtering.
