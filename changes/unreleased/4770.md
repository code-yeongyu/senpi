## 2026-10-29 - Use Bun for no-emit type checking (senpi#4770)

### What changed

- The root `check` script runs `bun check --no-script --all -p` for `tsconfig.json` and `scripts/tsconfig.json`.

### Why

- Use the pinned Bun checker while preserving the checked projects and type-error failures. `--no-script` prevents dispatching the root `check` script recursively.

### Why an extension could not handle it

- Repository validation runs outside the extension runtime.

### Expected merge conflict zones

- LOW: the two type-check commands in the root `package.json` `check` script.

## 2026-10-29 - Use Bun in direct CI type checks (senpi#4770)

### What changed

- `.github/workflows/ci.yml` and `.github/workflows/read-summary-binary-parity.yml` use `bun check --no-script --all -p` with their existing gate-harness and root projects.

### Why

- CI and the root validation script should use the same checker without invoking package scripts.

### Why an extension could not handle it

- GitHub Actions runs these commands before the agent runtime starts.

### Expected merge conflict zones

- LOW: the direct type-check steps in `ci.yml` and `read-summary-binary-parity.yml`.
