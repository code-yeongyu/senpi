## 2026-11-03 - Session presence on a headless host's rows and opens (S34, senpi#5652)

### What changed

- `packages/coding-agent/src/modes/rpc/multi-session-host.ts`: `MultiSessionHostOptions.sessionPresence?: HeadlessPresence`, passed to the router as a session default. When absent (every host but a headless one with a presence binding) the host is unchanged.
- `packages/coding-agent/src/modes/rpc/session-router-types.ts`: `RpcHostSessionDefaults.sessionPresence?`.
- `packages/coding-agent/src/modes/rpc/session-router-open.ts`: the `open_session` answer carries `presence` when the host has one.
- `packages/coding-agent/src/modes/rpc/session-router-host-reads.ts`: each `list_sessions` row carries `presence` when the host has one.
- `packages/coding-agent/src/modes/rpc/rpc-host-response-types.ts`: `RpcSessionPresence` and the optional `presence` field on the `open_session` answer and the `list_sessions` row.

### Why

- A client that re-attaches to a headless session must see that its owning machine is offline and the session paused (C2, K7; senpi#5652).

### Why an extension could not handle it

- The `open_session` and `list_sessions` answers are RPC host internals that no extension reaches.

### Expected merge conflict zones

- LOW: one optional field each in the host options, the session defaults and the two response types; one spread line in the `open_session` answer and in `answerListSessions`.

## 2026-11-03 - Offline pause and exactly-once resume for the headless engine (S34, senpi#5652)

### What changed

- `packages/coding-agent/src/modes/headless/presence-ledger.ts` (new): durable `presence.pause` / `presence.resume` records and open-pause documents on a DurableStore, under the store's admission line; a resume deletes the open pause in the same commit, so it is applied exactly once.
- `packages/coding-agent/src/modes/headless/presence.ts` (new): `openHeadlessPresence`: machines going offline and online, per-session pauses (owner: every session; hand: the sessions whose tool calls run on it), the view, and `ready` gates; a restart recovers the open pauses.
- `packages/coding-agent/src/modes/headless/presence-gates.ts` (new): `gatePresence` wraps a session's `prepareRequest` (waits for the owner) and an explicit ToolHost (waits for the owner and the session's hands); a fused session has no ToolHost to wrap.
- `packages/coding-agent/src/modes/headless/headless-host.ts`: `HeadlessHostOptions.presence?: HeadlessPresenceBinding`; when set, each runtime is tracked and gated as it is created. No CLI flag sets it yet.
- `packages/coding-agent/src/modes/headless/testing/kill-presence.ts` (new): KILL-PRESENCE-01..04.

### Why

- C2 and K7: an offline owner or hand pauses the dependent work, reconnect resumes it exactly once, and other sessions keep running (senpi#5652).

### Why an extension could not handle it

- It gates the loop of every session a headless host creates and changes the host's answers.

### Expected merge conflict zones

- LOW: new files; the options type and `headlessHostOptions` in `headless-host.ts`.

## 2026-11-03 - Export the admission line type from the conformance entry (S34, senpi#5652)

### What changed

- `packages/agent/src/conformance/index.ts`: exports the `AdmissionLine` type, so a writer outside this package can take the store's single admission line.

### Why

- The headless engine's presence ledger shares the store's admission line (senpi#5652).

### Why an extension could not handle it

- It is this package's public type surface.

### Expected merge conflict zones

- LOW: one export line.
