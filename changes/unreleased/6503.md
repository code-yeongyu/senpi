## 2026-11-12 - Tool-argument decode reaches Record values, typeless unions and protocol-validated MCP schemas (senpi#6271)

### What changed

- `packages/ai/src/utils/validation.ts`: `decodeJsonEncodedStructures()` resolves an object key's schema through `patternProperties` as well as `properties`/`additionalProperties` (new `propertySchemaForKey()` helper), so a `Type.Record` value such as `{k: '["a"]'}` against `Record(String, Array(String))` decodes to `{k: ["a"]}` instead of validating as `['["a"]']`.
- `packages/ai/src/utils/validation.ts`: when a schema carries no top-level `type`, decoding recurses into the `anyOf`/`oneOf` members that accept the value's kind (new `decodeSchemasFor()` helper), so JSON text nested inside e.g. `Union([Array(Array(String)), Null])` is decoded.
- `packages/ai/src/utils/validation.ts`: `validateToolArguments()` runs the decode before the protocol-validator early return, so protocol-validated (modern MCP) schemas no longer keep the pre-#6266 behaviour for JSON-encoded arrays/objects.
- `packages/ai/test/validation.test.ts`: table-driven regression tests for all three shapes (senpi#6271); each failed before the fix for the intended reason and passes after it.
- Correction to the #6266 fragment: its sentence "including MCP tools whose schemas no extension owns" holds only for legacy MCP schemas. Protocol-validated modern MCP schemas returned from `validateToolArguments()` before the decode ran, so they kept the old behaviour until this PR.

### Why

- The #6266 review found three gaps in that fix's coverage: Record values live under `patternProperties` and were never recursed into; a typeless union's empty `getSchemaTypes()` stopped recursion after the outer string decoded; and `getToolArgumentValidator()` short-circuited before the decode. Each gap left a model-sent JSON string to be wrapped by `Value.Convert` into a one-element array that passed validation, so the tool ran with JSON text as its argument.

### Why an extension could not handle it

- Argument validation and conversion run in the shared core before any tool's `execute` sees the parameters; per-tool `prepareArguments` shims would have to repeat the fix for every array-typed parameter, including MCP tools whose schemas no extension owns (legacy MCP schemas) and protocol-validated modern MCP schemas alike.

### Expected merge conflict zones

- LOW: `decodeJsonEncodedStructures()` and the protocol-validator early return in `validateToolArguments()` in `packages/ai/src/utils/validation.ts`.
