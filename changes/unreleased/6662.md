## 2026-11-13 - Release workflow: per-ref queue off main, early off-main refusal, no tested_tree output (senpi#6662)

### What changed

- `.github/workflows/publish-npm.yml`: the workflow concurrency group is `release-main` for runs on main and `release-<ref>` for any other ref. Before, every ref shared one `release` group.
- `.github/workflows/publish-npm.yml`: the forced-suite `prepare` job runs the release job's own "Refuse a live release from any ref but main" step first. A force_tests dispatch off main that is not a dry run now stops before the matrix jobs.
- `scripts/release-forced-prepare.mjs`: the prepare job no longer writes `tested_tree`. Its outputs are `base_sha`, `tested_sha`, `version` and `bundle`, which supersedes the senpi#6642 entry's list.

### Why

- GitHub keeps one pending run per concurrency group, so a dry run queued on a branch could cancel a release pending on main.
- A live dispatch off main spent the whole test matrix before the release job refused it.
- No job or script read `tested_tree`.

### Why an extension could not handle it

- These are the repository's own release workflow and release scripts; no extension point reaches them.

### Expected merge conflict zones

- LOW: `.github/workflows/publish-npm.yml` (the concurrency block and the prepare job) and `scripts/release-forced-prepare.mjs` are fork-only.
