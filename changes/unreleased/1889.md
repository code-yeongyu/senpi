## 2026-11-22 - Auxiliary requests follow the session's model-fallback chain (senpi#1889)

### What changed

- `packages/coding-agent/src/core/internal-model-request.ts` (new): `streamInternalModel(runtime, model, context, options, config)` runs an auxiliary request on its model and, when the session's fallback policy has a chain for that model, moves the request to the chain's next rung on a failure that arrives before any committed output (`isCommittedRotationOutput`). It walks a request-local `RetryFallbackController` over the runtime's registry, with cooldowns kept per runtime and apart from the session's own controller, so the session's chat model never changes. A rung on another model gets none of the caller's resolved key, headers, extra body, env or effort, and runs through `runtime.streamSimple` with `maxRetries: 0`; the runtime resolves that model's auth for the session. An image request never moves to a text-only rung. Without a chain, or with `modelFallback` off, the caller's stream runs unchanged. Each move emits `internal_model_fallback` (`source`, `from`, `to`, `reason`, `chainKey`).
- `packages/coding-agent/src/core/agent-session.ts`: title generation, compaction and branch summaries stream through `_internalStreamFn(source)`, which wraps `agent.streamFunction` in `streamInternalModel` with the session's `SettingsManager` and emits the `internal_model_fallback` session event. `AgentSessionEvent` gains that event.

### Why

- Every auxiliary request ran only on its first model. When that model failed, the compaction, title, branch summary, `/btw` answer or `look_at` description failed, even though the session had a fallback chain the main turn would have used.
- The Codex quota admission, account-switch notices and session-account auxiliary auth that the original PR also carried are not part of this change: main covers them through the shared usage poller (senpi#3684), session-scoped auxiliary auth (senpi#3924), provider account failover events (senpi#2304) and headroom-aware account picking (omo#9234).

### Why an extension could not handle it

- Title generation, compaction and branch summaries are issued by `AgentSession` with its own stream function; no extension hook sees their failure before it reaches the caller.

### Expected merge conflict zones

- LOW: the `AgentSessionEvent` union (one added member), the three `streamFn` arguments for title, compaction and branch summary, and `_internalStreamFn` after `_buildSessionTitleBaseOptions`.

## 2026-11-22 - `/btw` follows the session's model-fallback chain (senpi#1889)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/btw/index.ts`: the side query streams through `streamInternalModel` with `ctx.sessionSettings`, and a move to another model shows a warning notice.

### Why

- A side query failed outright when its model failed, even with a fallback chain configured.

### Why an extension could not handle it

- This is the extension; the fallback walk is shared with core callers.

### Expected merge conflict zones

- LOW: the `streamFn` passed to `runSideQuery`.
