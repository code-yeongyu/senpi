## 2026-11-02 - Lookups outside a trimmed mirror parse the session file once per idle window (senpi#2596)

### What changed

- `packages/coding-agent/src/core/session-manager.ts`: `getEntry(id)` and `getBranch(fromId)` for an id outside a trimmed mirror read a held id index of one session-file parse (`persistedIndex`) instead of re-parsing the file on every call. The index is built on the first miss, kept across appends, rebuilt when the requested id left the mirror after it was taken (`trimmedIds`) or the session file changed, and released by `dropMaterializedCaches()`.
- `packages/coding-agent/src/core/session-persisted-index.ts` (new, fork-only): `indexPersistedEntries` builds the id index, first occurrence winning for duplicated ids.

### Why

- On a large compacted session every mirror miss cost a full JSON parse and its garbage, and several misses in one turn stacked the footprint before GC (senpi#2596).

### Why an extension could not handle it

- The lookup paths and the mirror trimming are private to `SessionManager`.

### Expected merge conflict zones

- MEDIUM: `getEntry`, `getBranch` and `dropMaterializedCaches` in `session-manager.ts`.
