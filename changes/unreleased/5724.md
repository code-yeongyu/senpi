## 2026-11-04 - Recovery stream failures are recognizable by their diagnostic (senpi#5723)

### What changed

- `packages/ai/src/tool-call-middleware/recovery-stream-failure.ts`: `isToolCallRecoveryStreamFailure(message)` answers whether `terminateRecoveryStreamForFailure` ended the message, keyed on the three diagnostic types it attaches (`text_tool_call_recovery_invalid_content_event`, `text_tool_call_recovery_collision`, `text_tool_call_recovery_invalid_native_event`), never on the error text. Exported from the package root.

### Why

- senpi#5723: the session's retry path needs to tell our own stream-recovery failures from model failures without matching prose.

### Why an extension could not handle it

- The diagnostic types are private to the recovery stream; only this module can name the full set.

### Expected merge conflict zones

- LOW: the new predicate above `terminateRecoveryStreamForFailure`; one export line in `packages/ai/src/index.ts`.

## 2026-11-04 - Tool-call recovery stream failures never switch models (senpi#5723)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_isHardErrorFallbackEligible` returns false for a message `isToolCallRecoveryStreamFailure` recognizes, so the turn ends with the error instead of walking the fallback chain. These failures were never same-model retryable and stay that way, so no retry replays text the stream already showed.

### Why

- senpi#5723: `Invalid assistant content event order` (and the collision and native-event-order failures) are defects in our own tool-call stream recovery. Their text matches no retryable or terminal pattern, the recovery strips the tool calls, so the hard-error path treated them as a model failure and moved the session to the next model in the chain, which hits the same recovery.

### Why an extension could not handle it

- The retry and fallback decision runs inside the session's `agent_end` handling; no extension hook sees it.

### Expected merge conflict zones

- LOW: the `@earendil-works/pi-ai` import list and the head of `_isHardErrorFallbackEligible` in `packages/coding-agent/src/core/agent-session.ts`.
