## 2026-11-22 - TUI-only control commands are deliberately excluded from the method-class table (senpi#6160)

### What changed

- `packages/coding-agent/src/modes/interactive/session-control-method-exclusions.ts` (new): `TUI_METHOD_CLASS_EXCLUSIONS`, the commands the TUI endpoint's `get_protocol_info.commands` lists that `RPC_METHOD_CLASS` deliberately does not classify, each with its recorded reason: `subscribe` is per-connection feed state under the `subscribe_sessions` rule (a forwarder serves the stream itself); the four presenter client records (`mcp_presenter_context`, `mcp_form_presented`, `mcp_form_response`, `mcp_form_sync`) are decided by the delegated-connection gate's `answer` grant outside the table (senpi#4249 R-1b); `mcp_presenter_secret_answer` is a sealed secret answer only a local presenter may give, never relayed.
- `packages/coding-agent/src/modes/interactive/session-control-commands.ts`: exports `TUI_CONTROL_COMMANDS` so the coverage test consumes the exact advertised list.
- `packages/coding-agent/test/rpc/tui-method-class-coverage.test.ts` (new): every advertised command is either classified in the table or excluded with a reason, and every exclusion is still advertised, absent from the table, and states a non-empty reason.

### Why

- senpi#6160: since #6159 the endpoint advertises the host's `method_classes` table, but its command list also names the six commands above, so a remote relay refused them as `method_unclassified` by omission rather than decision. `RPC_METHOD_CLASS` and its digest are unchanged (one table, one digest for both endpoint kinds), and `RPC_METHOD_CLASSES_VERSION` needs no bump because no class meaning changed.

### Why an extension could not handle it

- The endpoint's `commands` list and the shared table are core surfaces; an extension can neither classify records for a relay nor carry the engine-side exclusion record the test enforces.

### Expected merge conflict zones

- LOW: the `TUI_CONTROL_COMMANDS` export in `session-control-commands.ts`; the two new files have no overlap.
