## 2026-11-17 - A session the machine's multi-session host holds opens attached there (senpi#6909)

### What changed

- `packages/coding-agent/src/cli/session-opening.ts`: `StartupAdmission` gains `{ attach: HostAttachTarget }`. An interactive start (`canAsk`) that may attach (`canAttach`) of a session whose holders are all one multi-session host with a published `host_socket` is admitted as an attach to that socket and the session's durable id, instead of being refused. Everything else keeps the senpi#5756 admission unchanged.

### Why

- The OmO desktop runs its sessions on such a host. Refusing them in a terminal meant a running app and a terminal could never share a session live in either direction.

### Why an extension could not handle it

- Startup admission runs before any extension loads, and decides whether the in-process runtime opens the file at all.

### Expected merge conflict zones

- LOW: `admitStartupSession` and the `StartupAdmission` type.

## 2026-11-17 - Startup runs the attached TUI for a host-held session (senpi#6909)

### What changed

- `packages/coding-agent/src/main.ts`: `admitOrExit(sessionFile, appMode, canAttach = true)` runs `runAttachedTui` on the admitted socket and session, then exits, so the in-process runtime never opens the held file. `rebindSessionOrExit` passes `canAttach = false` (a rebind rewrites the file).

### Why

- Follows the senpi#6909 admission: the terminal follows the host's live session as one more client, so one writer remains.

### Why an extension could not handle it

- Mode dispatch happens in `main.ts` before extensions load.

### Expected merge conflict zones

- LOW: `admitOrExit` and `rebindSessionOrExit`.

## 2026-11-17 - hostAttachSocket names the one host that holds a session (senpi#6909)

### What changed

- `packages/coding-agent/src/core/foreign-session-holders.ts`: `hostAttachSocket(holders)` returns the public socket when every holder is a session of one multi-session host that published it; `sessionIdFromFile` is exported for the admission.

### Why

- Startup attaches to that host instead of refusing a session it holds.

### Why an extension could not handle it

- Holder records are core session ownership.

### Expected merge conflict zones

- LOW: next to `takeOverRefusal`.

## 2026-11-17 - The attached TUI shows the session's model live (senpi#6909)

### What changed

- `packages/coding-agent/src/modes/interactive/attach.ts`: the status line names the session's model from `get_state`, and a `model_changed` record updates it, so a switch another client of the session makes shows at once.

### Why

- With a terminal attached to a session the desktop also drives, a model switch in either must show in the other.

### Why an extension could not handle it

- The attached TUI loads no extensions.

### Expected merge conflict zones

- LOW: `record()` and `showStatus()` in `attach.ts`.
