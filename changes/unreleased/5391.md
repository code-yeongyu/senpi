## 2026-11-02 - gpt-6-astra core: terse, no Verification, tool list or file-operations block (senpi#5390)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/prompt-preset/gpt-6-astra.ts`: `## Verification` removed; `stop-checks` in `## Stop Goal` names the checks up front, runs them once and never re-verifies verified results. The tool list and `## File operations` leave the core (`## Tool Guidelines` stays). `## Writing` is codex's gpt-6-astra "Writing style" verbatim. `root-cause` opens `## Scope and Recovery`. Tool-bound rules carry `requiresTool` and render only when the session has the tool. Every other directive is restated tersely. o200k 4,355 -> 3,608 on a real first-turn tool set.

### Why

Q (2026-11-02) asked to replace the Astra prompt after comparing it with the Codex CLI request for the same model: drop the blocks that cost tokens without earning them, take Codex's writing section, and steer the model to diagnose root causes.

### Why an extension could not handle it

This is the preset's own core text.

### Expected merge conflict zones

`gpt-6-astra.ts` rule constants and `buildGpt6AstraCore`; the `gpt-6-astra:*` hashes in `test/suite/prompt-presets-native-baseline.json`.

## 2026-11-02 - Cores receive the tool guidelines without the tool list (senpi#5390)

### What changed

- `packages/coding-agent/src/core/dynamic-prompt/tool-section.ts`: `buildToolGuidelinesSection()` renders the `## Tool Guidelines` block alone; `buildToolSection()` uses it and renders the same bytes as before.
- `packages/coding-agent/src/core/dynamic-prompt/build.ts`: `DynamicPromptCoreContext.toolGuidelines` hands that block to `corePrompt` overrides.

### Why

The gpt-6-astra core drops the tool list and keeps the guidelines tools contribute.

### Why an extension could not handle it

The tool section is assembled by the builder before a `corePrompt` override runs.

### Expected merge conflict zones

`DynamicPromptCoreContext` and the `buildToolSection` tail.
