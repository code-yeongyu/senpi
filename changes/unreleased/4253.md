## 2026-10-25 - Command Code builtin provider (senpi#4253)

### What changed

- `packages/ai/src/providers/commandcode.ts` (new): `commandCodeProvider()` with `envApiKeyAuth` over `CMD_API_KEY` / `COMMANDCODE_API_KEY`, both wires registered (Anthropic Messages, OpenAI Chat Completions), a store-backed `refreshModels` that restores a cached catalog, honours the abort signal and keeps the baseline when `/models` fails, and a `getModels` that serves the shipped catalog until the plan's own list lands and then serves only that list.
- `packages/ai/src/providers/commandcode-config.ts` (new): `GET https://api.commandcode.ai/provider/v1/models` transport; strips the plan namespace (`commandcode-goat-plan/…`), keeps vendor-prefixed ids intact, maps `supported_endpoints` to a wire (skipping `/responses`-only rows), and merges baseline pricing, reasoning levels and modalities, marking ids the baseline does not know `cost.unknown` rather than free.
- `packages/ai/src/providers/commandcode.models.ts` (new, generated), `packages/ai/src/providers/data/commandcode.json` (new, generated), `packages/ai/src/providers/data/.manifest.json`: `bun run generate-models --strict` output; the manifest carries the new file hash.
- `packages/ai/src/providers/all.ts`: registers `commandCodeProvider()` in `builtinProviders()`.
- `packages/ai/scripts/generate-models.ts`: `processCommandCodeModels` maps models.dev `commandcode` rows by wire (`provider.npm`), cost, context/output caps, input modalities and reasoning-effort options.
- `packages/ai/src/types.ts`, `packages/ai/src/env-api-keys.ts`: `KnownProvider` and the env-key pair, `CMD_API_KEY` first.
- `packages/ai/README.md`: supported-provider row, environment-variable row, and the dynamic-provider paragraph.
- `packages/ai/src/providers/AGENTS.md`: adds `commandcode` to the on-disk provider list.
- `packages/coding-agent/src/core/provider-display-names.ts`, `packages/coding-agent/src/core/model-resolver.ts`, `packages/coding-agent/src/cli/args.ts`: display name, `DEFAULT_MODELS.commandcode = claude-sonnet-5-5`, and the env-var help line.

### Why

- senpi#1708 asks for Command Code as a first-class provider with model discovery rather than a hand-maintained custom entry, and omo's provider map derives builtins from the engine, so a `commandcode` builtin is what both consumers need.
- The provider serves two wires behind one key. Routing per model from the endpoint's own `supported_endpoints` (instead of guessing from ids) means a model the plan gains is selectable without a release, which is exactly the staleness #1708 reports.

### Why an extension could not handle it

- A provider id, its catalog and its wire routing are `packages/ai` registry surfaces: `builtinProviders()`, `KnownProvider` and the generated shard are compiled into the package, and no extension can add an id that `models.setProvider()` and the generated aggregator enumerate.

### Expected merge conflict zones

- LOW: `builtinProviders()` in `packages/ai/src/providers/all.ts` (one line) and `KnownProvider` in `packages/ai/src/types.ts`.
- LOW: `API_KEY_ENV_VARS` in `packages/ai/src/env-api-keys.ts` and the `DEFAULT_MODELS` tail in `packages/coding-agent/src/core/model-resolver.ts`.
- MEDIUM: `packages/ai/src/models.generated.ts` and `packages/ai/src/providers/data/.manifest.json` are regenerated on every catalog refresh; resolve by re-running `bun run generate-models --strict`, never by hand.

## 2026-10-25 - Command Code in the provider registry (senpi#4253)

### What changed

- `packages/ai/src/types.ts`: `KnownProvider` gains `commandcode`.
- `packages/ai/src/env-api-keys.ts`: `API_KEY_ENV_VARS.commandcode = ["CMD_API_KEY", "COMMANDCODE_API_KEY"]`.

### Why

- The provider id must exist in the registry for `getEnvApiKey`, provider-scoped auth resolution and `getBuiltinProvider` to reach the new factory.

### Why an extension could not handle it

- `KnownProvider` and the env-key table are compile-time package surfaces; extensions cannot extend them.

### Expected merge conflict zones

- LOW: the `KnownProvider` union and the `API_KEY_ENV_VARS` record.

## 2026-10-25 - Command Code catalog generation (senpi#4253)

### What changed

- `packages/ai/scripts/generate-models.ts`: `processCommandCodeModels` reads models.dev `commandcode`, keeps tool-capable non-deprecated rows, chooses `anthropic-messages` when the row's `provider.npm` is the Anthropic SDK and `openai-completions` otherwise, and maps cost, caps, modalities and reasoning-effort levels.

### Why

- The catalog has to be regenerable from the same feed as every other provider; a hand-owned shard would go stale between releases.

### Why an extension could not handle it

- Catalog generation runs at build time in the package script; no runtime extension can produce the committed shard or manifest.

### Expected merge conflict zones

- LOW: the `generateAllModels` dispatch list and the new function beside `processZaiModels`.

## 2026-10-25 - Command Code in the coding agent (senpi#4253)

### What changed

- `provider-display-names.ts`: `commandcode` renders as `Command Code`.
- `model-resolver.ts`: `DEFAULT_MODELS.commandcode = "claude-sonnet-5-5"`, so `--provider commandcode` without a model id resolves.

### Why

- An unlisted provider falls back to its raw id in `/model` and cannot resolve a default model from the provider name alone.

### Why an extension could not handle it

- Display names and default-model resolution run before extension loading.

### Expected merge conflict zones

- LOW: one entry in each record.

## 2026-10-25 - Document the Command Code key (senpi#4253)

### What changed

- `args.ts`: the help environment block lists `CMD_API_KEY` with `COMMANDCODE_API_KEY` as its alias.
