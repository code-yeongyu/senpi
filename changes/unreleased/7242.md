## 2026-11-22 - show_html_page reads images bounded and writes pages exclusively (senpi#7242)

### What changed

- `packages/coding-agent/src/extensions/html-render/images.ts`: every local image is read from its own file descriptor in bounded chunks, at most `MAX_IMAGE_BYTES + 1` bytes total, and refused as soon as the cap is exceeded; the stat-based pre-check and the unbounded whole-file read are gone. An unreadable path still lands in `missing`.
- `packages/coding-agent/src/extensions/html-render/tool.ts`: the page file is written as `<safeTitle>-<Date.now base36>-<random hex>.html` with flag `wx`, retrying on `EEXIST`, so two same-title pages written in the same millisecond no longer overwrite each other.

### Why

- The size check and the read were separate steps, so an image that grew after its stat was read whole into memory before the cap refused it (senpi#2840); and the millisecond-resolution filename with a default overwrite flag let concurrent same-title calls replace each other's files.

### Why an extension could not handle it

- The image inlining and the page file write are this extension's own implementation; the fd-bounded read and the exclusive write are its internal file handling.

### Expected merge conflict zones

- LOW: `readImageWithinLimit` and the read loop in `images.ts`; `writePageExclusively` and the filename construction in `tool.ts`.
