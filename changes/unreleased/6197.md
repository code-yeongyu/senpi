## 2026-11-08 - `contextFiles.globalPath` relocates the global context file (senpi#5567)

### What changed

- `packages/coding-agent/src/core/context-files.ts`: `ContextFileLimits` gains the additive optional `globalPath` (the settings object already spreads into `loadProjectContextFiles` at `resource-loader.ts`, and `Settings.contextFiles` is typed `ContextFileLimits`, so no loader or settings-manager change is needed). New `loadGlobalContextFile(agentDir, globalPath)` replaces the direct agent-dir probe for the user-scope entry: a blank/unset path keeps the agent-dir probe; a file path (leading `~` expanded, relative resolved against the process cwd) is read directly; a directory runs the same `AGENTS.override.md`/`AGENTS.md`/`AGENTS.MD`/`CLAUDE.md`/`CLAUDE.MD` candidate probe; a set-but-missing, unreadable, special-file, or candidate-less target falls back to the agent-dir probe without erroring. The loaded entry keeps `scope: "user"`, joins the existing `seenPaths` dedupe, and the untouched `applyContextFileLimits` budget applies identically.
- `packages/coding-agent/docs/settings.md`: `contextFiles.globalPath` table row. `packages/coding-agent/docs/usage.md`: Context Files bullet notes the override.

### Why

- Users whose standing instructions live outside the agent dir (e.g. `~/.agents/AGENTS.md`, shared across several agent CLIs) had to symlink or duplicate the file into `~/.senpi/agent`; the request asks for a configured path instead (senpi#5567).

### Why an extension could not handle it

- Context-file discovery is core startup loading consumed by the system-prompt builder before any extension event fires; an extension could only re-read and re-inject prompt text, not relocate the scoped user file the loader dedupes and budgets.

### Expected merge conflict zones

- LOW: `context-files.ts` `ContextFileLimits` and `loadProjectContextFiles`'s global-entry line (fork-only file; `loadContextFileFromDir` itself is unchanged).
