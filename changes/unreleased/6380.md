## 2026-11-11 — Claude account diagnostics survive summaries and legacy defaults are removed

### What changed
- `packages/coding-agent/src/core/credential-accounts.ts` preserves optional redacted provider message and HTTP status in stored account summaries and RPC.
- `packages/coding-agent/src/core/anthropic-legacy-sign-out.ts` replaces flat legacy subscription credentials with an empty account list, removes previously migrated default placeholders and their stale pin, and preserves genuine named CLI accounts.

### Why
- The provider response was discarded before clients could explain a rejected test. A legacy placeholder must not look like a separately saved account. Repeated migration remains idempotent.

### Why an extension could not handle it
- Authentication-store loading and the generic RPC summary are engine-owned boundaries. A consumer extension cannot safely repair their persisted data or recover discarded diagnostics.

### Expected merge conflict zones
- The credential summary parser and subscription branch of the legacy sign-out migration. Preserve named CLI accounts, unrelated API keys, and diagnostic redaction.

## 2026-11-11 — Claude test failures preserve provider diagnostics and credential ownership

### What changed
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/accounts.ts` adds optional check diagnostics and excludes migrated legacy default placeholders from stored subscription listings.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/errors.ts` exposes the existing provider-error text extraction.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/claude-cli-connection-test.ts` redacts and retains original errors and HTTP status, including readable timeout and missing-result explanations.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/claude-cli-login-slots.ts`, `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/oauth-login.ts`, and `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/claude-cli-account-test.ts` bind automatic and manual results to the tested CLI directory; login progress includes the redacted provider response.

### Why
- A classification such as `other` cannot explain a failure. A result for a previous credential must not overwrite a fresh sign-in. Login still awaits durable credential commit before testing.

### Why an extension could not handle it
- The built-in subscription lane owns SDK errors, credential-directory identity, and the login transaction. A UI extension cannot restore information after that lane discards it.

### Expected merge conflict zones
- Check metadata, the connection-test result/catch paths, and automatic/manual check updates. Preserve stable classification codes, secret redaction, and credential-directory comparisons.
