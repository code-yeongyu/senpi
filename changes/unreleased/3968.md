## 2026-11-25 - Opening a session keeps entry bodies on disk (senpi#3968)

### What changed

- `packages/coding-agent/src/core/session-file-pages.ts` (new): `SessionFilePages`, the content-free index of an opened file. While the file loads, every string of at least 1 KiB nested in an entry is replaced in place by a resident token naming the entry's line (id, byte offset, length) and the string's place in it; materializing the token reads that line back and checks it is still the same entry. A line that moved (the file was rewritten) makes it index the file again, once per change; a page it cannot find resolves as missing, so readers fall back to their JSONL recovery as for an evicted blob. Only current-version files are paged, and top-level fields stay resident.
- `packages/coding-agent/src/core/session-entry-file.ts`: `loadEntriesFromFile` / `loadEntriesFromFileAsync` take an optional `SessionEntryPager` that sees every parsed line with its byte range (`LineByteRanges`, from raw newline bytes), and record it in `loadedPages` beside the loaded entries.
- `packages/coding-agent/src/core/session-resident-store.ts`: `adoptPages`; `materialize` resolves page tokens through the adopted pager, transiently like a blob read; `clear()` drops it; `stats()` reports `pagedCount` when the load left strings on disk.
- `packages/coding-agent/src/core/agent-session.ts`: `releaseSettledSessionMemory` drops the materialized views when the store holds pages, as it already did after an eviction: views that read a paged string hold its only resident copy. Runtime messages are still tokenized only after an eviction.
- `packages/coding-agent/src/core/session-manager.ts`: every load of an opened file (`open`, `openAsync`, `setSessionFile`, `reloadFromDisk`) runs through a pager the resident store adopts. A trimming load keeps the history it parsed as `pagedHistory` (paged entries), which the first full-history read materializes into `historyView`; `holdsMaterializedHistory()` and `dropMaterializedCaches()` cover it like that view.

### Why

- senpi#3968: an opened session kept every entry with its body in the resident mirror for its lifetime, so a host's memory grew with the file's bytes (about 1.5x: +743 MiB retained for a 500 MB session). The mirror now grows with the entry count.

### Why an extension could not handle it

- The mirror, the resident store and the session file loader are SessionManager internals; no extension hook sees a load.

### Expected merge conflict zones

- LOW: the `pagedCount` check at the head of `releaseSettledSessionMemory` in `agent-session.ts`; the loader calls in `_setSessionFile`, `_setSessionFileAsync`, `reloadFromDisk`, `open` and `openAsync`; `_completeFileLoad`'s history view; the trimmed branch of `getEntries`, `_readWholeHistory`, `dropMaterializedCaches` and `holdsMaterializedHistory`.

### Fixed

- Opening a session no longer holds every entry's body in memory: long strings stay in the session file and are read back by byte range when needed, so a resumed session's memory grows with its entry count instead of its file size (#3968)
