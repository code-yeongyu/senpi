## 2026-11-12 - The process boot instant is read once (senpi#3152)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/process-identity.ts`: `processBootAtMs()` without an injected clock computes the boot instant once, from one `Date.now()`/`os.uptime()` pair, and reuses it; a call with an injected clock still computes.

### Why

- `os.uptime()` counts whole seconds, so two reads that straddled an uptime tick computed boot instants a second apart (senpi#3152, senpi#4301).

### Why an extension could not handle it

- The boot instant is read by the builtin terminal and schedule lease code itself.

### Expected merge conflict zones

- LOW: `processBootAtMs` in `process-identity.ts`.
