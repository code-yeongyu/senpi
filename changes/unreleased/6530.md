## 2026-11-12 - The process boot instant comes from the kernel's boot record (senpi#3152)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/process-identity.ts`: `processBootAtMs()` reads the kernel's recorded boot instant (`btime` in `/proc/stat` on Linux, `kern.boottime` from `/usr/sbin/sysctl`, by absolute path, on macOS) instead of rounding `now - os.uptime()`; elsewhere it still computes from uptime. That record cannot change while the machine is up, so it is read once per process and reused (the macOS read spawns a synchronous `sysctl`); a read that fails is not remembered, so the next call retries it, and the uptime fallback is never memoized. Callers keep their 120 s `sameBoot` tolerance.

### Why

- `os.uptime()` counts whole seconds, so two reads that straddled an uptime tick computed boot instants a second apart (senpi#3152, senpi#4301). Caching one read instead would break agreement between processes after a wall-clock step; the kernel's record moves for every reader alike.

### Why an extension could not handle it

- The boot instant is read by the builtin terminal and schedule lease code itself.

- LOW: `processBootAtMs` in `process-identity.ts`.
