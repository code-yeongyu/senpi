## 2026-11-22 - An idle path identity worker no longer keeps print mode alive (senpi#7230)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/permission-system/path-identity-transport.ts`: the worker is unref'd again after its message listener is attached, because attaching the listener refs the port again.
- `packages/coding-agent/src/core/extensions/builtin/permission-system/path-identity-host.ts`: a pending request's deadline timer keeps the process alive until its reply or deadline; an idle worker never does.

### Why

- With any path permission rule set, `omo -p` printed its answer and never exited (oh-my-openagent#12060): the idle worker held the event loop open.

### Why an extension could not handle it

- The permission system and its resolver worker are built into the engine; an extension cannot change the worker's ref state.

### Expected merge conflict zones

- LOW: the resolver's `send` promise body and the worker transport's `onMessage`.

### Fixed
- Print mode exits after its answer when a path permission rule is configured; the idle path identity worker no longer keeps the process alive ([#7230](https://github.com/code-yeongyu/senpi/pull/7230)).
