## 2026-11-05 - The Bun SQLite store is a published, source-only package (S21b b1a, senpi#5975)

### What changed

- `scripts/release-packages.mjs`: `WORKSPACE_PACKAGES` lists `packages/session-backends/sqlite-bun/package.json`, so the release's lockstep versioning moves it and the GitHub release notes include its CHANGELOG.
- `scripts/local-release.mjs`: the local release packs it, so isolated npm and Bun installs resolve senpi's dependency on it.
- `scripts/publish-command.mjs`: `requiresBuildOutput(sourceName)` decides whether a package must have a `dist/`; the source-only set is keyed by published name and a source name is looked up through the registry map first, so sqlite-bun (source name `@earendil-works/pi-storage-sqlite-bun`) needs none.
- `scripts/publish.mjs`: checks build output through `requiresBuildOutput`; `@code-yeongyu/senpi-storage-sqlite-bun` is source-only (it ships TypeScript source for Bun, like `@code-yeongyu/senpi-codemode`, so no `dist` is required). The package itself enters the registry set in `scripts/registry-packages.mjs` (after `senpi-agent-core`, its dependency) and the release changelog set in `scripts/release-changelog.mjs`.

### Why

Row S21b (senpi#5822): the default session store on Bun is the Bun SQLite durable store, so the published `@code-yeongyu/senpi` must be able to depend on it. Parent ruling: publish it like the other workspace packages through the normal release flow.

### Why an extension could not handle it

Release packaging is the repository's own publish tooling.

### Expected merge conflict zones

`requiresBuildOutput` in `scripts/publish-command.mjs`, the build-output check in `scripts/publish.mjs`, `WORKSPACE_PACKAGES` in `scripts/release-packages.mjs`, and the package list in `scripts/local-release.mjs`.
