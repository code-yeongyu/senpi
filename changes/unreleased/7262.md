## 2026-11-22 - Preserve queued input before a move manifest exists (#7262)

### What changed

- `packages/coding-agent/src/core/session-move/dropped-input-record.ts` stores the messages owed by a move. `packages/coding-agent/src/core/session-move/extension-state.ts` preserves that record across staging attempts.
- `packages/coding-agent/src/core/session-move/export.ts` uses the record for the manifest; `packages/coding-agent/src/core/session-move/finish.ts` requeues from it when reclaiming.

### Why

- Losing the release reply or failing to write a manifest previously left reclaim without the queued messages.

### Why an extension could not handle it

- The engine drains the queue and owns the move manifest, reclaim journal, and per-message replay IDs.

### Expected merge conflict zones

- Move staging cleanup, manifest construction, and reclaim journaling.

## 2026-11-22 - Re-answer a move release without repeating extension export (#7262)

### What changed

- `packages/coding-agent/src/modes/rpc/session-release.ts` records drained input before answering and reuses an existing seal for the same move ID.

### Why

- A caller that misses a reply can retry without dropping messages or triggering a second extension export.

### Why an extension could not handle it

- RPC release controls session admission, sealing, and the return of queued input.

### Expected merge conflict zones

- The final admission check, ownership fence, and release response.
