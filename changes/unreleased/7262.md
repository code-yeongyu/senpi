## 2026-11-22 - Preserve queued input before a move manifest exists (#7262)

### What changed

- `packages/coding-agent/src/core/session-move/dropped-input-record.ts` stores the messages a move release took, per session file and move, tagged with the session id and the release attempt. It counts only while that session's own seal names the attempt, so a release refused before its seal leaves no owed copy behind. `packages/coding-agent/src/core/session-move/extension-state.ts` exports the move-state root and the sealed-attempt lookup it uses.
- `packages/coding-agent/src/core/session-move/export.ts` uses the record for the manifest; `packages/coding-agent/src/core/session-move/finish.ts` requeues from it when reclaiming and removes only that session's record.

### Why

- Losing the release reply or failing to write a manifest previously left reclaim without the queued messages. The queued input must also have exactly one owner: a refusal hands it to the caller, so the move may not carry it as well, and two sessions in one folder must never share a record.

### Why an extension could not handle it

- The engine drains the queue and owns the move manifest, reclaim journal, and per-message replay IDs.

### Expected merge conflict zones

- Move staging cleanup, manifest construction, and reclaim journaling.

## 2026-11-22 - Re-answer a move release without repeating extension export (#7262)

### What changed

- `packages/coding-agent/src/modes/rpc/session-release-move.ts` holds the pre-seal move staging: extension export, the bundle-size check and the drained-input record, and reuses an existing seal for the same move ID. `packages/coding-agent/src/modes/rpc/session-release.ts` calls it, answers a successful release with everything the move owes, and hands back only this attempt's take in a refusal.

### Why

- A caller that misses a reply can retry without dropping messages or triggering a second extension export.

### Why an extension could not handle it

- RPC release controls session admission, sealing, and the return of queued input.

### Expected merge conflict zones

- The final admission check, ownership fence, and release response.
