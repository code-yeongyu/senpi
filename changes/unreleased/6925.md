## 2026-11-18 - show_html_page on a hand: the brain's page budget and prompt surface (senpi#6925)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/html-render/handed-pages.ts` (new): the session page-budget accounting (`reserveHandedPage`, `forgetHandedPages`) and the result text (`handedPageText`) move here from `tool.ts`, together with the per-page and per-session limits.
- `packages/coding-agent/src/core/extensions/builtin/html-render/hand-page-budget.ts` (new): `withHandPageBudget` wraps a brain's ToolHost for a hand. It applies the brain session's page budget to each page the hand hands back, and hands an over-budget page as written, consistently in its `tool_execution_end`, its message events and the returned message.
- `packages/coding-agent/src/core/extensions/builtin/html-render/tool.ts`: reads the prompt surface from `ctx.promptSurface` (on a hand, the brain session's), and uses `handed-pages.ts`.

### Why

- senpi#6921. A hand cannot see the brain's transcript, so its pages skipped the session budget. Its result text came from the hand's own environment, so a desktop session heard "not displayed" for a page it rendered.

### Why an extension could not handle it

- `show_html_page` is this builtin's own code, and builtins are never forwarded between brain and hand.

### Expected merge conflict zones

- LOW: `html-render/tool.ts` (`hostRendersPage`, the end of `execute`); the two new files.

## 2026-11-18 - ExtensionToolContext.promptSurface (senpi#6925)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ExtensionToolContext` gains the optional `promptSurface`: the prompt surface of the session the call belongs to. On a hand, that is the brain session's, sent with the call.
- `packages/coding-agent/src/core/extensions/runner.ts`: `createToolContext` serves `promptSurface`. On a session it comes from `getSystemPromptOptions().surface`; on a runtime without a session, from the new `bindSessionlessFacts({ promptSurfaceOf })`.

### Why

- senpi#6921 L2. A tool on a hand must report what the brain session's host does with its result.

### Why an extension could not handle it

- Only the runtime that runs a call knows the surface of the session the call belongs to.

### Expected merge conflict zones

- LOW: the end of `ExtensionToolContext` in `types.ts`; the tool-context fields and `bindSessionlessFacts` in `runner.ts`.

## 2026-11-18 - AgentSession.promptSurface (senpi#6925)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: a public `promptSurface` getter returns the surface the session's prompt is built for. The hand selection sends it with each call to a hand.

### Why

- senpi#6921 L2. A hand reports the brain session's surface, so the brain must be able to read it.

### Why an extension could not handle it

- The surface is session state that no extension API exposes outside a tool call.

### Expected merge conflict zones

- LOW: next to `setPromptSurface` in `agent-session.ts`.
