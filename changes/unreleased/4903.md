## 2026-10-29 - The EQ job can run the sandbox example for real (senpi#4829)

### What changed

- `.github/workflows/ci.yml`: the `fused-equivalence` job installs `bubblewrap`, `socat` and `ripgrep` through `scripts/install-ci-system-deps.sh`, pinned to the noble release pocket (`0.9.0-1build1`, `1.8.0.0-4build3`, `14.1.0-1`), and sets `kernel.apparmor_restrict_unprivileged_userns=0` when the runner has it at `1`.

### Why

- EQ case E28 runs `examples/extensions/sandbox` unmodified. On Linux, `@anthropic-ai/sandbox-runtime` refuses to start without `bwrap`, `socat` and `rg`, and `bwrap` needs capability-bearing unprivileged user namespaces, which Ubuntu 24.04 strips while that sysctl is `1` (the package README documents the same sysctl). Without them `/sandbox` reports "Sandbox is disabled" and the Linux B0 would pin the disabled path instead of the sandbox.
- The release-pocket versions never leave the archive, so the pins stay installable after later security updates.

### Why an extension could not handle it

- CI runner provisioning, not runtime behavior.

- LOW: the `fused-equivalence` job's steps in `.github/workflows/ci.yml`. Upstream pi-mono has no such job; keep both steps on a sync.
