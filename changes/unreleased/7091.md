## 2026-11-19 - An empty models.json declares no providers; parse errors name the position (oh-my-openagent#14414)

### What changed

- `packages/coding-agent/src/core/model-config.ts`: `ModelConfig.parse` treats an empty or whitespace-only (after comment stripping) models.json as declaring no providers, like a missing file, in both `load` and `loadSync`. A malformed file still fails, and its error now reads `Failed to parse models.json at line L, column C: ...`.

### Why

- `omo models discover` and every other reader turned an empty models.json into `JSON Parse error: Unexpected EOF`, although the file is the user's optional custom-provider list. Bun's `JSON.parse` errors carry no position, so a malformed file gave no hint where to look.

### Why an extension could not handle it

- models.json loading happens in core before any extension runs; no hook sees or replaces the parse.

### Expected merge conflict zones

- LOW: the head of `ModelConfig.parse` (the `JSON.parse` try/catch) in `model-config.ts`.

## 2026-11-19 - JSON syntax error position helper (oh-my-openagent#14414)

### What changed

- `packages/coding-agent/src/utils/json.ts`: adds `jsonSyntaxErrorPosition(text)`, a small strict-JSON scanner that returns the 1-based line and column of the first rejected character.

### Why

- Bun's `JSON.parse` errors have no offset, so models.json parse errors could not tell the user where the file is broken.

### Why an extension could not handle it

- The helper serves core config loaders (`model-config.ts`, `model-discovery-document.ts`), which run before extensions load.

### Expected merge conflict zones

- LOW: appended below `stripJsonComments` in `utils/json.ts`.
