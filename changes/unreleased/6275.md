## 2026-11-09 - A 403 that refuses one model no longer blocks the credential slot (senpi#3972)

### What changed

- `packages/coding-agent/src/core/credential-pool/classify.ts`: in the 403 branch, a refusal scoped to one model the plan does not include now fails the request instead of blocking the slot, matched by the new `MODEL_SCOPED_403_TEXT` patterns (the vendor naming the model and the entitlement gap in either direction). Account-level refusals that name no model still block the slot as `auth_error`.

### Why

- With the built-in z.ai provider, GLM-5.3 failed with "The provider rejected the credentials" / "No credential slots available" while GLM-5.2 worked with the same key: the refusal was model-level (the plan does not include GLM-5.3), but a 403 whose body mentions subscription, account or organization became `auth_error`, blocking the slot for every model on that provider until the re-probe (senpi#3972).

### Why an extension could not handle it

- Credential failure classification runs in the shared pool before any extension sees the error; no extension hook can un-block a slot the classifier already poisoned.

### Expected merge conflict zones

- LOW: the `MODEL_SCOPED_403_TEXT` patterns and the one added check in the 403 branch of `classify.ts`.
