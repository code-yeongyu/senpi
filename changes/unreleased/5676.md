## 2026-11-03 - The native-bypass decision is per session (senpi#5674)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/imagegen/state.ts`: the native bypass is recorded per session in a `WeakSet` keyed by the session's `sessionManager`; `setNativeBypass(session, enabled)` and `isNativeBypass(session)` replace the module-level flag.
- `packages/coding-agent/src/core/extensions/builtin/imagegen/tool.ts`: `generate_image` reads the bypass for its own `ctx.sessionManager`.

### Why

- senpi#5674: in a host running several sessions in one process, whichever session refreshed the arbitration last decided the bypass for every session, so a Claude session was told to call a native image tool it does not have.

### Why an extension could not handle it

- The bypass seam is this builtin's own state, shared with the openai-image-gen builtin.

### Expected merge conflict zones

- LOW: the `setNativeBypass`/`isNativeBypass` signatures in `state.ts` and their callers.

## 2026-11-03 - Arm the native bypass for the session that decided it (senpi#5674)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/openai-image-gen/index.ts`: `refresh` and `session_shutdown` set and clear the bypass for `ctx.sessionManager` instead of the whole process.

### Why

- senpi#5674: the arbitration `state` was already per session, but the bypass it published was process-global, so one session's model disabled `generate_image` for another.

### Why an extension could not handle it

- The arbitration and the bypass it publishes belong to this builtin.

### Expected merge conflict zones

- LOW: the two `setNativeBypass` calls.
