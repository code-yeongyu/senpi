## 2026-11-24 - Logout can compare the confirmed sign-in before removing it (senpi#7406)

### What changed

- `packages/ai/src/auth/types.ts`: `LogoutOptions.expectedLoginId`; optional `CredentialStore.deleteLogin(providerId, loginId)` removes the entry only while its `loginId` matches, under the same exclusion as `modify`/`delete`.
- `packages/ai/src/auth/credential-store.ts`: `InMemoryCredentialStore.deleteLogin`; `assertExpectedLogin` and `deleteStored` throw `ModelsError` `stale_login` on any difference; `revokeStoredOAuth` compares inside its `modify` callback before clearing or revoking anything.

### Why

- A sign-out the user confirmed for one sign-in removed whatever was stored, including a newer sign-in that replaced it between the read and the request (sisyphuslabs/dori-bot#253).

### Why an extension could not handle it

- The comparison must happen inside the credential store's write lock, which only the store and `Models.logout` own.

### Expected merge conflict zones

- LOW: `CredentialStore` interface tail and `revokeStoredOAuth`'s `modify` callback head.

## 2026-11-24 - Models.logout honours expectedLoginId (senpi#7406)

### What changed

- `packages/ai/src/models.ts`: `logout` routes the slot and whole-entry removals through the login comparison and rethrows `stale_login` unwrapped instead of as an `auth` store failure.

### Why

- Callers must tell "the sign-in changed, nothing happened" apart from a storage failure.

### Why an extension could not handle it

- `Models.logout` is the core removal path every surface uses.

### Expected merge conflict zones

- LOW: the `logout` body in `models.ts`.

## 2026-11-24 - Conditional logout through the runtime stores (senpi#7406)

### What changed

- `packages/coding-agent/src/core/auth-storage.ts`: `AuthStorage.deleteLogin` compares and removes under the auth.json file lock.
- `packages/coding-agent/src/core/runtime-credentials.ts`: forwards `deleteLogin`; a backing store without it refuses instead of removing unconditionally.
- `packages/coding-agent/src/core/model-runtime.ts`: `logoutProvider` checks `expectedLoginId` before the Claude CLI sign-out, so a stale request signs nothing out of the CLI.

### Why

- RPC `logout` `expectedLoginId` must reach the file lock; the Claude CLI sign-out is a side effect that must not run for a refused request.

### Why an extension could not handle it

- The auth store, its runtime overlay and the runtime's logout queue are core.

### Expected merge conflict zones

- LOW: after `AuthStorage.delete`, the end of `RuntimeCredentials`, the head of `logoutProvider`'s queued operation.
