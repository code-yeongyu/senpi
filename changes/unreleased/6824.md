## 2026-11-16 - Conditional named drains decide inside the child (senpi#6819)

### What changed

- The authenticated `drain_if_idle` host command checks instance ownership, engine handoff activity, pending prompts and questions, attachments, and requests and opens in flight. It closes router admission and holds automatic turns synchronously before starting the existing socket drain announcement.
- `--if-idle` uses this child command without a client census, signal, drain file, or fallback to an unconditional drain. Refusals have no drain side effects. Loaded worker isolates fail closed because their asynchronous snapshots cannot prove an atomic idle check.
- Host core construction and shared output helpers move out of the socket lifecycle module. Physical opens count before the first await, including retained-session reopens without a client. Conditional drain answers participate in the existing shutdown flush barrier. The method classification, inbound schema and delegated-connection policy register the host command.

### Why

- An updater must not park work or disconnect an attached client based on a stale census. Both the transport and router admission gates must be closed in the same child turn that proves the generation idle.

### Why an extension could not handle it

- Only the host child owns transport admission, registry activity, request accounting, and the drain lifecycle.

### Expected merge conflict zones

- MEDIUM: host core extraction, method schema registration, router open accounting, and the stop request/outcome types.

## 2026-11-16 - Parse the conditional named-drain flag (senpi#6819)

### What changed

- `host stop --drain --instance <id> --if-idle [--wait-ms <n>]` passes the conditional request to the host runner. Missing drain or instance arguments remain usage errors with exit 2.

### Why

- Updaters need a stable CLI contract that distinguishes a successful drain from a typed refusal and an older unsupported CLI.

### Why an extension could not handle it

- Host CLI argument parsing runs before extensions and is part of the process contract.

### Expected merge conflict zones

- LOW: host stop argument parsing, dispatch, and help text.

## 2026-11-16 - Document and prove conditional drain admission (senpi#6819)

### What changed

- RPC documentation specifies conditional drain JSON, exit codes, atomic admission, instance ownership, Windows authentication, positive exit evidence, and the fail-closed worker limitation.
- The inbound sample generator and its generated method fixture include the new connection-local command; the delegation corpus checks its host-admin refusal.
- Regression tests exercise real authenticated sockets, real session activity and bash, pending questions, in-flight requests and opens, attach and automatic-turn ordering, and the source CLI with its supervisor. CLI, generation, and shared test-quarantine sandboxes create their key directories with owner-only permissions on systems with a permissive umask.

### Why

- A successful conditional drain is irreversible. Refused work must remain admitted, and tests must distinguish feature failures from an unsafe fixture directory.

### Why an extension could not handle it

- These are host lifecycle and CLI process contracts, tested at their production boundaries.

### Expected merge conflict zones

- LOW: additive regression files, the CLI sandbox directory mode, and the named-drain documentation section.
