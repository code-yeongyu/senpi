## 2026-11-16 - A worker that keeps answering progress is not quarantined; a quarantined session is a retryable dead end (senpi#6452)

### What changed

- `packages/coding-agent/src/modes/rpc/session-worker-requests.ts`: `noteProgress()` restarts the no-progress deadline and re-arms pending non-command timers on any inbound worker message; the timeout value is unchanged.
- `packages/coding-agent/src/modes/rpc/session-worker-client.ts`: `receive()` calls `noteProgress()`, so a request that merely runs long under load is not a dead worker.
- `packages/coding-agent/src/modes/rpc/worker-session-open.ts`: an open naming a quarantined entry retires it and answers `session_closing` with `detail { reason: "session_quarantined", action: "retry" }`, so the retry reopens the session from its file.

### Why

- A slow-but-alive worker was quarantined by the fixed open budget, and the session then refused every attach with `session_closing` (senpi#6452: `rpc-worker-permission-preset` intermittently red on main, ~1 in 3 in a built environment and under load).

### Expected merge conflict zones

- LOW: the `receive()` entry in `session-worker-client.ts` and the open-path preamble in `worker-session-open.ts`.
