## 2026-11-22 - A typed check for recovery stream failures (senpi#5723)

### What changed

- `packages/ai/src/tool-call-middleware/recovery-stream-failure.ts`: new `isToolCallRecoveryStreamFailure(message)`, true when the message carries one of the three diagnostic types `terminateRecoveryStreamForFailure` attaches.
- `packages/ai/src/tool-call-middleware/index.ts`: re-exports it.

### Why

- The session needs to tell a recovery stream failure from a model failure without matching error text.

### Why an extension could not handle it

- The diagnostic types are private to the recovery middleware.

### Expected merge conflict zones

- LOW: the top of `recovery-stream-failure.ts`; the export list of `tool-call-middleware/index.ts`.

## 2026-11-22 - A recovery stream failure never switches models (senpi#5723)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_isHardErrorFallbackEligible` excludes `isToolCallRecoveryStreamFailure`, so the turn ends with the error on the same model.

### Why

- A tool-call recovery stream failure is a protocol problem in our recovery; hopping to the next fallback model could not fix it and repeated the cost.

### Why an extension could not handle it

- Fallback eligibility is decided inside the session.

### Expected merge conflict zones

- LOW: the condition list of `_isHardErrorFallbackEligible`; the `@earendil-works/pi-ai` import in `agent-session.ts`.
