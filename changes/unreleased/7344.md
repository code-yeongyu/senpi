## 2026-11-22 - Split terminal string sequences never reach the prompt as text (senpi#4352)

### What changed

- `packages/tui/src/stdin-buffer.ts`: `StdinBuffer` records the sequence its flush timer released. When the next read continues an APC/DCS/OSC string sequence (a released introducer with a body always continues; a bare introducer or lone ESC continues only on a multi-character read), the bytes up to ST or BEL are dropped, across further reads when needed. Dropping stops at an ESC that does not start ST or at any other control character. A lone ESC held past the escape window is not released as Escape when the read that follows continues a string sequence. 8-bit C1 introducers (U+0090, U+009D, U+009F) and ST (U+009C) are normalised to their 7-bit forms outside bracketed paste.
- `packages/tui/src/terminal-string-tail.ts` (new): C1 normalisation, the continuation rule, and the tail scanner.

### Why

- A Kitty graphics delete APC echoed back as input inside herdr reached the prompt as `Ga=d,d=I,i=...,q=2`: the timer released `ESC _` as Alt+_ before the body was read, and the body was framed as typed characters.

### Why an extension could not handle it

- Stdin framing happens inside `ProcessTerminal`'s `StdinBuffer`, before any extension or input listener sees the input. Once the body has been split into single characters, a listener cannot tell it from typing.

### Expected merge conflict zones

- MEDIUM: `StdinBuffer.process()` (the C1 normalisation after decoding, the string-tail block after the mouse-fragment discard, the stale-ESC condition) and the flush-timer callback; LOW: `clear()`.
