## 2026-11-07 - The trust-requiring resource scan answers asynchronously too (senpi#6185)

### What changed

- `packages/coding-agent/src/core/trust-requiring-resources.ts`: new. `hasTrustRequiringProjectResources` and `projectAgentsSkillDirs` move here from `trust-manager.ts` unchanged in behavior, written once as a probe generator with a synchronous driver (the existing exports) and an asynchronous one (`hasTrustRequiringProjectResourcesAsync`, `node:fs/promises`).
- `packages/coding-agent/src/core/trust-manager.ts`: the scan and its helpers leave; both exports are re-exported from the new module, so every importer is unchanged.

### Why

- The RPC workspace verbs (#6177) called the synchronous scan on the RPC session path, which `test/suite/no-sync-in-session-path.test.ts` forbids (its baseline never grows); main was red on it.

### Why an extension could not handle it

- The scan decides whether a session asks for a trust decision at all, before any project extension may load.

### Expected merge conflict zones

- MEDIUM: the removed block of `trust-manager.ts` (constants after the `TrustFile` type, `isHomeOrAboveDir` through `hasTrustRequiringProjectResources`); upstream edits to those helpers now land in `trust-requiring-resources.ts`.

## 2026-11-07 - The headless project_trust context lives apart from the startup UI (senpi#6185)

### What changed

- `packages/coding-agent/src/cli/project-trust-headless.ts`: new. `createHeadlessProjectTrustContext`: the `project_trust` handler context that never asks (no answer to select/confirm/input; notices to stderr outside the TUI), with no UI import.
- `packages/coding-agent/src/cli/project-trust.ts`: `createProjectTrustContext` builds on it and adds the startup selectors only for an interactive run with a UI; behavior is unchanged.

### Why

- `modes/rpc/project-workspace-commands.ts` (#6177) imported `createProjectTrustContext`, and through it `cli/startup-ui.ts`, `core/keybindings.ts` and `core/package-manager.ts`, putting their synchronous fs calls and `spawnSync` on the RPC session path.

### Why an extension could not handle it

- The context is what the core hands every `project_trust` handler; the import graph of the RPC session path is core.

### Expected merge conflict zones

- LOW: `createProjectTrustContext` in `cli/project-trust.ts`.

## 2026-11-07 - The RPC workspace verbs leave the synchronous trust path (senpi#6185)

### What changed

- `packages/coding-agent/src/modes/rpc/project-workspace-commands.ts`: uses `createHeadlessProjectTrustContext` and `hasTrustRequiringProjectResourcesAsync`; `readProjectTrust` is async.
- `packages/coding-agent/src/modes/rpc/connection-handler.ts`: awaits `readProjectTrust`.

### Why

- The RPC session path must not block the shared host (`test/suite/no-sync-in-session-path.test.ts`); #6177 had reached synchronous fs from these verbs.

### Why an extension could not handle it

- The verbs and the session path's import graph are core RPC.

### Expected merge conflict zones

- LOW: the `get_project_trust` case in `connection-handler.ts`.
