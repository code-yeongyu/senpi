## 2026-11-10 - An authorizing OAuth flow reuses only a registration that names its redirect URI (senpi#6327)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/mcp/auth/registered-redirect.ts` (new): `registrationNamesRedirect()` accepts a stored dynamic registration for a flow only if its `redirect_uris` contain the flow's redirect URI exactly (a registration without `redirect_uris` is kept); `withRegistration()` stores a new registration and, when it replaces another `client_id`, drops that client's refresh token.
- `packages/coding-agent/src/core/extensions/builtin/mcp/auth/oauth-provider.ts`: `McpOAuthProviderOptions.requireRegisteredRedirect`; `clientInformation()` hides a stored registration that does not name `redirectUrl` when it is set, so the SDK registers one that does; `saveClientInformation()` stores through `withRegistration()`.
- `packages/coding-agent/src/core/extensions/builtin/mcp/auth/context.ts`: `resolveServerAuth()` sets `requireRegisteredRedirect` exactly when the caller passes `redirectUrl` (`/mcp auth`, `auth-start`, `auth-complete`); background connects keep the stored registration.

### Why

- A dynamic registration is bound to its `redirect_uris`, and the provider handed the stored one to every flow. A background connect registers the placeholder `http://127.0.0.1:0/callback` and every `/mcp auth` binds a new loopback port, so the authorize request named a redirect URI the `client_id` never registered, and exact-matching authorization servers (django-oauth-toolkit, e.g. Readwise; Neon) answered `invalid_request: Mismatching Redirect URL` on every retry (code-yeongyu/oh-my-openagent#12963). The replaced client's refresh token is dropped because the SDK would otherwise present it under the new `client_id`.

### Why an extension could not handle it

- The dynamic registration and its reuse live in the MCP builtin's OAuth provider and token store, which the SDK reads directly during `auth()`; no extension hook sits between them.

### Expected merge conflict zones

- LOW: `clientInformation()` and `saveClientInformation()` in `auth/oauth-provider.ts`, and the `McpOAuthProvider` construction in `resolveServerAuth()` in `auth/context.ts`.

### Fixed
- MCP OAuth no longer fails with `Mismatching Redirect URL` on authorization servers that match `redirect_uri` exactly: `/mcp auth` and `/mcp auth-start` register a client for the redirect URI they send instead of reusing one registered for the background placeholder (`127.0.0.1:0`) or an earlier loopback port, and the replaced client's refresh token is not presented under the new client ([#6328](https://github.com/code-yeongyu/senpi/pull/6328))
