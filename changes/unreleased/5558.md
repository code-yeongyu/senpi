## 2026-11-02 - Responses sessions recover from reasoning issued to another caller (senpi#1836)

### What changed

- `packages/ai/src/api/openai-responses.ts`: the request is stripped of reasoning items this session already saw rejected on the route, and a 400 `reasoning encrypted_content was not issued to this caller` sends the request again without the reasoning items it replayed, around the existing `allowed_tools` fallback.
- `packages/ai/src/api/openai-responses-unissued-reasoning.ts` (new): `UnissuedReasoningReplay` detects the rejection, drops whole reasoning items, and remembers their ids per session, base URL and model until session teardown.

### Why

- senpi#1836: same-model replay resent caller-bound `encrypted_content` every turn, so a session served as another caller failed every next turn with the same 400. Removing `encrypted_content` alone still fails while the item `id` remains.

### Why an extension could not handle it

- The rejection happens inside the provider request; no extension hook sees the outgoing payload again after the provider answers, so only the adapter can resend it.

### Expected merge conflict zones

- LOW: the `createRequest` / tool-limit block of `stream()` in `openai-responses.ts`.
