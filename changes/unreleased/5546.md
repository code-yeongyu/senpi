## 2026-11-02 - Context estimates count CJK, kana and Hangul characters as one token each (senpi#3032)

### What changed

- `packages/ai/src/utils/estimate.ts`: a character from Hangul jamo/syllables, CJK radicals, punctuation, kana and ideographs (incl. extension A), compatibility ideographs or fullwidth forms (`isWideScriptCodeUnit`) weighs one full token (`weightedLength`); every other character keeps `CHARS_PER_TOKEN = 4`. Text, thinking, user/tool-result content blocks and serialized tool-call arguments use the weighted length.

### Why

- At four characters per token a CJK-heavy context was estimated at a quarter to a half of its real size, so the maxTokens clamp, compaction and emergency prune acted on a number far below the provider's and a long CJK session could fail permanently with a context-length 400 (senpi#3032).

### Why an extension could not handle it

- The estimate is the shared helper every provider path and the coding-agent compaction guards call.

### Expected merge conflict zones

- MEDIUM: `estimateTextTokens`, `estimateTextAndImageContentChars` and `estimateMessageTokens` in `estimate.ts`.
