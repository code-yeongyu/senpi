## 2026-11-23 - Preserve overlapping native tool calls during recovery (senpi#7393, closes #2203; from #2320 by @nahwan-kim)

### What changed

- `packages/ai/src/tool-call-middleware/recovery-content-lifecycle.ts` tracks active native tool calls by content index. Starts must be monotonic; completions can arrive in any order. Text and thinking content stay sequential.
- `packages/ai/src/tool-call-middleware/recovery-stream-wrapper.ts` passes the content kind into lifecycle admission.

### Why

- `recovery-content-lifecycle.ts` treated a second active native call as malformed. Valid Kimi Responses streams start several calls before closing any of them, so these streams ended in `Invalid native tool call event order` and every call was dropped. Leaked-text recovery stays on, and duplicate starts and post-end events are still rejected.
- `recovery-stream-wrapper.ts` has to tell native calls apart from content whose text parser needs sequential delivery.

### Why an extension could not handle it

- Both files reject the provider stream before the agent loop or any extension receives executable calls.

### Expected merge conflict zones

- `recovery-content-lifecycle.ts`: lifecycle admission and active-call tracking.
- `recovery-stream-wrapper.ts`: `canStart`.

### Fixed

- Tool-call recovery accepts overlapping native tool calls (monotonic starts, completions in any order), so Kimi and Claude Responses streams that start several calls before closing them no longer fail with `Invalid native tool call event order` and lose every call ([#7393](https://github.com/code-yeongyu/senpi/pull/7393), closes [#2203](https://github.com/code-yeongyu/senpi/issues/2203); from [#2320](https://github.com/code-yeongyu/senpi/pull/2320) by @nahwan-kim)
