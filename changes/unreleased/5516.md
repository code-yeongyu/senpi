## 2026-11-02 - Claude presets state the user's-language rule in their own text (senpi#4107)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/prompt-preset/claude-opus-5-5.ts`, `claude-opus-5.ts`, `claude-fable-5-1.ts` (and its alias `claude-fable-5-5`), `claude-fable-5.ts`, `claude-sonnet-5-5.ts`, `claude-haiku-5-5.ts`: `## Style` adds, after "match the user's tone, profanity included.", one sentence re-voicing the core rule (`dynamic-prompt/handoff.ts` `HANDOFF_LANGUAGE_RULE`; `gpt-6-astra.ts` "Reply in the user's language and register"): write in the user's language for every reply, note between tool calls and todo label, also after reading tool output, files or skills in another language. Copied per preset, not shared.
- `claude-opus-4-5.ts`, `claude-opus-4-6.ts`, `claude-opus-4-7.ts`, `claude-opus-4-8.ts`: the same sentence appended to each preset's own tuning text; `claude-opus-4-6.ts` gains a tuning block shaped like its siblings.
- `test/suite/prompt-presets-native-baseline.json`: the 66 rows of these 11 presets recaptured; +49 o200k tokens per preset on every surface.

### Why

The only language rule was `HANDOFF_LANGUAGE_RULE` inside the shared Handoff section, so a turn without a handoff block had none, the chat surface had none at all, and long English tool or skill output pulled Claude replies and todo labels into English (senpi#4107).

### Why an extension could not handle it

These are the presets' own core texts; the rule belongs in the system prompt each preset renders.

### Expected merge conflict zones

- LOW: the `## Style` tone sentence of each Claude 5.x preset, the tuning text of each `claude-opus-4-*` preset, and the `claude-*` rows of `prompt-presets-native-baseline.json`.

## 2026-11-02 - Todo phase and task fields name the user's language (senpi#4107)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/todotools/tools/todo.ts`: the `phase` description reads "Phase name, in the user's language" and the `items` task descriptions (init and append) read "Task content, in the user's language". The lookup fields `task` / `phase` are unchanged.

### Why

Todo labels are written before any handoff block restates the language rule, and a Claude run wrote them in English for a Korean user (senpi#4107); eval's `summary` field, which names the user's language next to the call, held in the same run.

### Why an extension could not handle it

The schema descriptions are this extension's own tool definition.

### Expected merge conflict zones

- LOW: `TodoPhaseInputSchema` and the `items` field of `TODO_PARAMS_SCHEMA`.
