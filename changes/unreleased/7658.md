## 2026-11-28 - The stdio RPC host answers a stream event its serializer rejects, then exits (senpi#7658)

### What changed

- `packages/coding-agent/src/modes/rpc/rpc-stdout-sink.ts` (new): `createRpcStdoutSink({ write, waitForBackpressure, shutdown })`, the stdio host's sink, moved out of `runRpcMode` unchanged except for the guard below.
- `packages/coding-agent/src/modes/rpc/rpc-mode.ts`: builds its sink with `createRpcStdoutSink` over the raw stdout writer and its own `shutdown`. The sink's per-line serializer catches an `Error` from the JSON projection (`toJsonEvent` rejects a `message_update` that carries a non-assistant message, or a `toolcall_start` whose content is not a tool call). It writes `{ type: "response", command: "prompt", success: false, errorCode: "invalid_stream_event", error, sessionId }` in place of the event and schedules `shutdown(1)` in a microtask. A value that is not an `Error` is rethrown unchanged.
- `packages/coding-agent/test/suite/rpc-invalid-stream-event.test.ts` (new): both malformed shapes produce that response and exactly one `shutdown(1)`; well-formed events pass through unchanged with no shutdown.

### Why

- The error used to escape the event flush, so the client saw neither a reply nor the cause. oh-my-openagent has been injecting exactly this guard into the installed `dist/modes/rpc/rpc-mode.js` by rewriting its source text (`bin/lib/rpc-stream-errors.js`). That patch has nothing to rewrite once senpi stops shipping its per-file `dist/` tree, so the behavior has to live here first.

### Why an extension could not handle it

- The stdout sink belongs to the RPC mode entry. Extensions never see a serialized line.

### Expected merge conflict zones

- LOW: the sink construction at the top of `runRpcMode` (upstream still builds the sink inline there).

### Fixed
- The stdio RPC host no longer lets a stream event its JSON projection rejects escape the event flush: it answers `{ "type": "response", "command": "prompt", "success": false, "errorCode": "invalid_stream_event" }` with the cause and exits with code 1 ([#7658](https://github.com/code-yeongyu/senpi/pull/7658))
