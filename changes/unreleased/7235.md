## 2026-11-22 - The presenter control start stays inside sun_path and never fails silently (senpi#5858)

### What changed

- `packages/coding-agent/src/modes/rpc/mcp-presenter-control-start.ts`: the POSIX control directory is created under the first temp root whose longest `mkdtemp` result still fits `MAX_SOCKET_PATH_BYTES`, reusing the existing `internalHostDirRoots()` roots (`host-lifecycle-scratch.ts`: the OS temp directory, then `/tmp`, the internal hop's roots since senpi#3487) instead of always using `tmpdir()`. When no root fits, or any later start step still fails, one typed `presenter_control_unavailable: <reason>` line with the socket path length and the limit goes to the host log before the unchanged fail-closed return; the swallow-everything catch is gone.

### Why

- A `TMPDIR` deep enough that `<TMPDIR>/senpi-presenter-XXXXXX/control.sock` exceeded `sun_path` made `listen()` reject inside the bare catch, so the host started with no control endpoint and no record — same-account enrollment was silently unavailable and the outcome was indistinguishable from "no control was requested" (senpi#5858).

### Why an extension could not handle it

- The presenter control endpoint is a host internal created before session extensions run; extensions never see its start, its socket path, or its failure.

### Expected merge conflict zones

- LOW: `mcp-presenter-control-start.ts` around the directory creation and the catch; the files are fork-only.
