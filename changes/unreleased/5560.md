## 2026-11-03 - Manual /compact asks a compaction owner when native preparation is empty (senpi#3354)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: when `prepareCompaction()` finds nothing to summarize, `compact()` emits `session_compact_requested` (via `_requestOwnerCompaction`) before refusing; a returned `compaction` runs through `_executeCompaction` as `precomputed`, otherwise the "Already compacted" / "Nothing to compact (session too small)" refusal is unchanged.

### Why

- `packages/coding-agent/src/core/agent-session.ts`: an extension that owns compaction was never asked to serve `/compact` after its own compaction entry or on a short session, because the native guard threw before any hook.

### Why an extension could not handle it

- `packages/coding-agent/src/core/agent-session.ts`: the refusal happens inside core `compact()` before any extension event fires.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/core/agent-session.ts` the `prepareCompaction` guard at the top of `compact()`, the `_executeCompaction` call in `compact()`, and the new `_requestOwnerCompaction` method before `applyCompaction`.

## 2026-11-03 - session_compact_requested extension event (senpi#3354)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: new `SessionCompactRequestedEvent` (`reason: "manual"`, `nativeOutcome: "already-compacted" | "too-small"`, `branchEntries`, `customInstructions`), `SessionCompactRequestedResult` (`compaction?`), the event in `ExtensionEvent`, and a `pi.on("session_compact_requested")` overload.
- `packages/coding-agent/src/core/extensions/runner.ts`: the event is placed `loop`; `emit` returns the first handler result that carries a `compaction`.
- `packages/coding-agent/src/core/extensions/index.ts`: exports the two new types.

### Why

- `packages/coding-agent/src/core/extensions/types.ts`: compaction owners need a hook for manual compaction when native preparation is empty. The event is additive, so `session_before_compact` and every existing handler are unchanged.

### Why an extension could not handle it

- `packages/coding-agent/src/core/extensions/types.ts`: the public event contract and its dispatch live in the extension runtime itself.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/core/extensions/types.ts` next to `SessionBeforeCompactEvent`, the `ExtensionEvent` union, `SessionBeforeCompactResult`, and the `session_compact` `on` overload; `packages/coding-agent/src/core/extensions/runner.ts` `EXTENSION_EVENT_PLACEMENT`, `RunnerEmitResult`, and the result capture in `dispatchEmit`; `packages/coding-agent/src/core/extensions/index.ts` type export list.
