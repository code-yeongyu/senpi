## 2026-11-13 - An export op refused while this host's own runtime is still stopping says so (senpi#6593)

### What changed

- `packages/coding-agent/src/modes/rpc/session-move-held-here.ts`: `stillStoppingHereDetail(op, cause)` answers the line a refused `finish` or `export` op is given when the only holder of the session is this host's own process, and `undefined` for every other refusal. The `export` line is new: the session has not finished stopping on this host, it was not exported, send export again once it has stopped. The `finish` line is unchanged and no longer exported by itself.
- `packages/coding-agent/src/modes/rpc/session-move-commands.ts`: the refusal of a failed move command takes its `detail` from that function, falling back to the error's own text.
- `packages/coding-agent/docs/rpc.md`: an `export` op sent while that runtime is still stopping is refused `session_held` with that line, and the wait has no bound.

### Why

- A release for a move answers at the host's close grace whether or not the session's runtime has stopped, and that runtime holds the session file until the last step of its dispose. An `export` op sent in that window was refused `session_held` with the text for a session open in another process ("Quit it there, then try again"), naming this host's own pid. There is no other process to quit. senpi#6454 gave the release's own export and a refused `finish` a true line; the two-request path kept the old one.

### Why an extension could not handle it

- The text of a `move_session` refusal is chosen in the RPC command handler; no extension sees the refusal.

### Expected merge conflict zones

- LOW: the `catch` of `moveSession` in `session-move-commands.ts`. `main` passes a fourth argument to `refusal` there (`landedWhenFenced`); keep both.
