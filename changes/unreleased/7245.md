## 2026-11-22 - Adopt a matching first-flush header (senpi#3904)

### What changed

- `packages/coding-agent/src/core/session-manager.ts`: the minting manager can append buffered setup and the first message to an existing file containing only its session header. An interrupted adoption preserves the header and retries the remaining setup.

### Why

- Opening the minted path from a second manager writes its header before the original manager flushes. Exclusive creation then refused the original manager's first message.

### Why an extension could not handle it

- The persistence layer owns the file descriptor, the unflushed setup, and recovery after a partial append.

### Expected merge conflict zones

- The unbound first-flush and append branches in `SessionManager._persist`.
