## 2026-11-22 - /login reports whether a saved API key was accepted (senpi#2725)

### What changed

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: after the API-key dialog saves a literal key, `reportApiKeyVerification` asks the provider once through `verifyApiKey` and shows the verdict.
- `packages/coding-agent/src/modes/interactive/login-outcome.ts`: `describeApiKeyVerification` turns the verdict into a rejected, accepted, or saved-without-verification notice.

### Why

- Any key was saved with only "Saved API key for X"; a refused key surfaced on a later request with no link back to the login.

### Why an extension could not handle it

- The built-in `/login` dialog owns the save and its status line; extensions cannot observe or annotate that step.

### Expected merge conflict zones

- LOW: `showApiKeyLoginDialog` and the new `reportApiKeyVerification` method in `interactive-mode.ts`; the login-outcome helpers.
