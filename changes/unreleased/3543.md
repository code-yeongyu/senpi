## 2026-11-26 - Reconcile OAuth refreshes by account identity (senpi#3407)

### What changed

- `packages/ai/src/auth/pool/slots.ts` and `packages/ai/src/auth/types.ts`: Match the flat OAuth credential to a unique slot by token or provider account identity. SIWC registrations use their issuer, subject and client ID. Carry refresh continuity metadata with the credential it describes.
- `packages/ai/src/auth/oauth-refresh.ts` and `packages/ai/src/auth/oauth-refresh-continuity.ts`: Bind a completed refresh to its input and output tokens so another store can adopt that rotation without trusting a reused slot name. An unknown or copied marker fails closed when it does not match. Preserve the rotated token if computing the marker fails.
- `packages/ai/src/auth/oauth-refresh.ts`: Refuse an ambiguous flat refresh before exchanging tokens; if a slot changes during the exchange, preserve both the replacement and the refreshed flat credential and report the ambiguity. A named refresh leaves a concurrently changed flat login untouched.
- `packages/ai/src/auth/resolve.ts`: Surface an ambiguous account as an actionable authentication error.

### Why

An external write can leave the flat credential and its account slot with different tokens. A slot name or entry-wide login ID alone cannot distinguish a refresh from a different sign-in. A token-bound receipt identifies one completed refresh; older writers and changes spanning more than one refresh may still require a retry.

### Why an extension could not handle it

Extensions can provide an account identity, but refresh locking, storage updates and error propagation are owned by the shared authentication runtime.

### Expected merge conflict zones

- `packages/ai/src/auth/pool/slots.ts` and `packages/ai/src/auth/types.ts`: flat-to-slot matching, credential metadata and refresh merges.
- `packages/ai/src/auth/oauth-refresh.ts`: refresh locking and compare-and-swap storage.
- `packages/ai/src/auth/resolve.ts`: refresh error classification.
