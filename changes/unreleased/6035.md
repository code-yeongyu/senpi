### Added
- `RemoteToolHost.openScope(scopeId, signal?)` opens a scope's epoch floor before its first tool call (senpi#5932), so a loop hook that runs first never reaches a floorless hand. It goes through the same gate as the first dispatch (`HandLink.openScope`), settles only on the hand's `floor_ack` at the session's epoch, answers the gate's refusal otherwise, and `aborted` when the signal ends first.

## 2026-11-05 - Open a scope's epoch floor before the first tool call (senpi#5932)

### What changed

- `packages/agent/src/execution/remote-link.ts`: `HandLink.openScope(lane, signal?)` opens the lane's floor through the existing epoch gate.
- `packages/agent/src/execution/remote-tool-host.ts`: `RemoteToolHost.openScope(scopeId, signal?)` and `OpenScopeResult`.
- `packages/agent/src/execution/testing/epoch-harness.ts`: the epoch rig gains `openScope` and `fence()`.

### Why

The floor opened lazily at the first tool dispatch, but loop hooks fire before it; on a fresh or just-moved session the hand had no floor when the first hook arrived, so an old owner's late call was admitted (senpi#5932).

### Why an extension could not handle it

The epoch gate and the frame receiver that routes `floor_ack` are private to the hand link.

### Expected merge conflict zones

`remote-link.ts` `HandLink` interface and returned object; `remote-tool-host.ts` return type.
