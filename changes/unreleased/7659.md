## 2026-11-28 - Every export loads the bundle; the per-file JavaScript and the inlined-only dependencies leave the package (senpi#7659)

### What changed

- `packages/coding-agent/package.json`: every `exports` module entry's `import` condition names the bundle's own entry for it (`./dist/bundle/<subpath>.js`, `.` as `index.js`), and `main` is `./dist/bundle/index.js`. Each entry keeps its `types` on the compiled declaration (`./rpc-entry`, `./cli`, `./valid-cwd`, `./private-fd-startup-release` and `./session-worker` gain one). `files` lists what ships positively: `dist/bundle`, `dist/**/*.d.ts`, and the assets the bundle reads from `dist/` at runtime (theme JSON, the interactive PNG, the HTML export's template and vendored scripts, the imagegen skill). The per-file JavaScript and `dist/senpi` are no longer shipped. The 17 dependencies the bundle inlines and nothing loads or declares at runtime move to `devDependencies`: `chalk`, `cross-spawn`, `diff`, `es-module-lexer`, `grok-mermaid`, `highlight.js`, `hosted-git-info`, `minimatch`, `re2js`, `semver`, `yaml`, `@mozilla/readability`, `linkedom`, `marked`, `picomatch`, `signal-exit`, `turndown`.
- `packages/coding-agent/test/package-distribution.test.ts`: each export's `import` must be its bundle entry, and its `types` a declaration compiled from a source file.

### Why

- Stage S2c of one payload copy per install. The bundle already served every subpath (senpi#7657). Shipping the per-file tree beside it duplicated the engine, and each inlined dependency was installed a second time for nothing.
- A dependency stays when the bundle keeps it external (`@earendil-works/chord`, `@silvia-odwyer/photon-node`, `@earendil-works/pi-pty`), when something loads it from disk (`jiti` through a variable-specifier import, `@anthropic-ai/claude-agent-sdk` by path, `@code-yeongyu/senpi-codemode` as a package), or when a shipped declaration imports it, so consumers' types still resolve (`pi-ai`, `pi-agent-core`, `pi-tui`, `typebox`, `zod`, `ajv`, `ignore`, `proper-lockfile`, `undici` (imported by `@anthropic-ai/sdk`'s shipped `internal/types.d.ts`), `@anthropic-ai/sdk`, `@modelcontextprotocol/sdk`, the vendored client, protocol and machine-ops). `@earendil-works/pi-realm-registry` stays a runtime dependency by repository rule.

### Why an extension could not handle it

- The package's export map, file list and dependency list are its distribution contract.

### Expected merge conflict zones

- MEDIUM: `exports`, `files` and `dependencies` in `package.json`.

## 2026-11-28 - The runtime snapshot copies a file two overlapping files entries select once (senpi#7659)

### What changed

- `packages/coding-agent/src/runtime-snapshot/package-files.ts`: `planPackageRoot()` plans each destination file once. `dist/bundle` and `dist/**/*.d.ts` (which plans its parent `dist`) used to plan every bundle file twice; the copy failed with `EEXIST`, `prepareRuntimeSnapshot` fell back to running in place, and launches lost their upgrade-safe snapshot (#2358).
- `packages/coding-agent/test/runtime-snapshot/shipped-files.test.ts`: overlapping entries still produce a snapshot that holds the bundle.

### Why

- npm accepts overlapping `files` entries, and the published layout of senpi#7659 uses them.

### Why an extension could not handle it

- The snapshot runs before any extension loads.

### Expected merge conflict zones

- None upstream: `runtime-snapshot/` is fork-only.

## 2026-11-28 - The bundle build reads each export's module from its declaration; the senpi pack ships one copy (senpi#7659)

### What changed

- `scripts/bundle-entry-points.mjs`: `compiledModuleOf()` maps an export to the compiled module it is built from (its `types` declaration's `.js` sibling), since `import` now names the bundle's output. `exportEntryPoints()` uses it.
- `scripts/check-entry-graphs.mjs`: an export served from the bundle is measured through the same declaration-to-module rule.
- `scripts/senpi-publish-pack-checks.mjs`: the senpi tarball must ship no compiled per-file JavaScript outside `dist/bundle/` (the HTML export's text assets excepted), and every file its `exports` map names.
- `scripts/coding-agent-consumer.mjs`: the install smoke runs the declared bin only; `dist/cli.js` is no longer shipped.
- `scripts/prepare-senpi-bundled-workspaces-pack.test.mjs`, `scripts/coding-agent-consumer.test.mjs`: fixtures without `dist/cli.js`, plus the two new pack rules.

### Why

- Without these, the build would read its own output as input, and a packed tarball could again carry the per-file tree or point an export at a missing file.

### Why an extension could not handle it

- Release and packaging tooling.

### Expected merge conflict zones

- LOW: `exportEntryPoints()`; the target lookup in `check-entry-graphs.mjs`; the top of `assertSenpiPackedWorkspaceFiles`.
