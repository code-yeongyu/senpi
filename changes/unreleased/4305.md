## 2026-10-26 - Fork files are built atomically and a header catch-up keeps its prefix (senpi#4295)

### What changed

- `packages/coding-agent/src/core/session-manager.ts`: `forkFrom` builds the fork through `replaceFileAtomically` (temp file, fsync, rename) instead of an exclusive header write followed by one `appendFileSync` per entry. The fresh timestamp and session id make collisions unlikely; the atomic rename replaces an existing target rather than rejecting it with `EEXIST`. When the post-close catch-up append of `_writeHeaderAsync` fails, the file is kept and cut back to the bytes known whole (`_keepCaughtUpPrefix`), and the missing entries are written, one line each, before the next append.
- `session-write-state.ts` makes buffering, an in-flight header writer, and a flushed file mutually exclusive states. Discard, reload, new-session, branch and full-rewrite transitions replace the entire state, so no stale append cursor or torn-tail cause survives a new file. The header writer owns its queue across compaction instead of relying on the resident array's identity. The flushed state's `tailFailure` carries the failure's `SessionRecoveryCause`; a torn final line found on open whose backup the disk refused rides the buffered state as `deferredTail` until the load completes, then is set aside before the first append.
- `session-write-recovery.ts`: `truncateToLastCompleteLine(path, cause, knownCompleteBytes?)` keeps the set-aside backup and recovery report for a torn tail, and accepts the exact durable byte boundary when a header catch-up's cut-back failed. Retrying cuts the whole failed batch, including any complete lines it landed, before replaying it; those bytes are written again from memory, so that cut keeps no backup and reports no recovery.
- The transcript journal counts the file as persisted only when no catch-up entries are still owed (`_fileHoldsMemory`).
- The atomic replacement helper removes its temporary file on a caught failure. A process crash before rename can still leave a hidden `.tmp` file; it is not a session and is not swept automatically, since another live writer may own it.

### Why

- A full disk part-way through `forkFrom` left a half-copied fork in the session list. A failed catch-up deleted the whole new file, including the header and entries already on disk. Independently tracked flush flags and pending entries could replay entries after discard/recreation, while compaction could strand a header-owned file behind repeated `EEXIST`.

### Why an extension could not handle it

- Both writes run inside `SessionManager`.

### Expected merge conflict zones

- MEDIUM: `packages/coding-agent/src/core/session-manager.ts`, `_writeHeaderAsync`, `_beginSessionFile` and the flushed append in `_persist`: the torn-tail cause and the deferred open-time tail live in `writeState`, not in separate fields.
- LOW: `forkFrom` file creation; `truncateToLastCompleteLine`'s known-boundary branch.
