## 2026-11-20 - Explicit local RPC watches only report their selected session

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/rpc-monitor-observer.ts` uses the subscription snapshot to identify the selected routing handles before delivering live records. `packages/coding-agent/src/core/extensions/builtin/terminal/rpc-monitor-targets.ts` preserves the selector type at this boundary.
- `packages/coding-agent/src/core/extensions/builtin/terminal/rpc-monitor-watch.ts` refuses an unresolved explicit session instead of scheduling a rescan. `packages/coding-agent/src/core/extensions/builtin/terminal/rpc-monitor-source.ts` cleans up refused watches and `packages/coding-agent/src/core/extensions/builtin/terminal/tools/monitor-rpc.ts` returns the refusal without binding a monitor ID.

### Why

- Lifecycle broadcasts can reach an observer even when the session does not match its subscription. They must not become monitor output.

### Why an extension could not handle it

- The built-in observer decodes records before extensions receive monitor notifications.

### Expected merge conflict zones

- Local subscription decoding and monitor registration. Host broadcast semantics are unchanged.
