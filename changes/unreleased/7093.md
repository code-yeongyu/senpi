## 2026-11-19 - OpenAI Responses tools get an object root schema (senpi#7092)

### What changed

- `packages/ai/src/api/openai-responses-shared.ts`: `convertResponsesTools` sends function parameters through `normalizeToolParametersForObjectRoot` before strict conversion. Strict sampling is still decided on the original schema.
- `packages/ai/src/api/bedrock-converse-stream.ts`: calls the renamed `normalizeToolParametersForObjectRoot` (formerly `normalizeToolParametersForBedrock`); behavior unchanged.

### Why

- OpenAI rejects a function whose root schema has `oneOf`/`anyOf`/`allOf` with `invalid_function_parameters`, so every prompt on the `openai` provider failed on the `eval` tool's root union (senpi#7092).

### Why an extension could not handle it

- Tool parameters are serialized inside the provider wire builder; no extension hook rewrites the Responses tool list before it is sent.

### Expected merge conflict zones

- LOW: the `convertResponsesTools` function-tool branch in `openai-responses-shared.ts` and the tool-schema-compat import block.

## 2026-11-19 - Root-combinator normalizer renamed for its second wire (senpi#7092)

### What changed

- `packages/ai/src/utils/tool-schema-compat.ts`: `normalizeToolParametersForBedrock` is now `normalizeToolParametersForObjectRoot`. The body is unchanged; the doc names both wires that need it (Bedrock #1947, OpenAI Responses #7092).

### Why

- The OpenAI Responses path needs the same root-union merge, including the #5150 branch-required hints, and a Bedrock-named helper on the OpenAI path would mislead readers.

### Why an extension could not handle it

- This is the shared wire normalizer used by provider builders inside `packages/ai`.

### Expected merge conflict zones

- LOW: open branches that import `normalizeToolParametersForBedrock` (for example #5539) need the new name.
