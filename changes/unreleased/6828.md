## 2026-11-16 - Agent shells never receive a declared credential (senpi#6828)

### What changed

- `packages/coding-agent/src/utils/shell.ts`: `getShellEnv()` passes the user shell environment through `withCredentialProxy()` before the kill guard's layer. Every variable named in the user's global `credentialProxy.credentials`, and any other variable carrying one of those values, is set to a fixed placeholder; a declared `baseUrlEnv` points at the credential's loopback proxy route. `getUserShellEnv()` (the user's own `!` commands) is unchanged.

### Why

- The bash tool, PTY bash, monitors and the tool child all spawn with `getShellEnv()`, which handed every engine credential to every agent command (senpi#6828). Step 1 of the agent vault design: a credential is used only through the injection proxy.

### Why an extension could not handle it

- The environment is built here before any extension sees a spawn; an extension cannot remove a value from it.

### Expected merge conflict zones

- LOW: `getShellEnv()` body and its import block.

## 2026-11-16 - Credential injection proxy and `credentialProxy` setting (senpi#6828)

### What changed

- `packages/coding-agent/src/core/credential-proxy/declarations.ts`: parses `credentialProxy.credentials[]` (`env`, `origin`, `header`, `scheme`, `baseUrlEnv`, `pathPrefixes`). `origin` must be https (plain http only for a loopback host) with no credentials, query or fragment; the header may not be a hop or framing header. Every `env` name found is withheld even when its entry is rejected.
- `packages/coding-agent/src/core/credential-proxy/proxy.ts`: a loopback HTTP proxy on `127.0.0.1:0` gated by a 32-byte random capability in the path. It forwards only to the declared origin (origin-form requests only), refuses dot segments and encoded separators, enforces `pathPrefixes`, replaces any client copy of the header, does not follow redirects, streams the response, and answers a failed upstream with a fixed text that never includes the value. It rejects when it cannot listen.
- `packages/coding-agent/src/core/credential-proxy/runtime.ts`: the process-wide holds (a realm registry, like the kill guard's runtime) and `withCredentialProxy()`. Withholding is set before the proxy starts and stays when it fails to start (fail closed).
- `packages/coding-agent/src/core/settings-manager.ts`: the `credentialProxy` settings field (read from global settings only).
- Review L3: a path segment starting with `..` or `.;` is refused (servers that strip path parameters normalise `..;x` to `..`).
- Not covered, stated in `docs/security.md`: the proxy runs in the engine process as the same OS user, so a same-user process can still read the engine's startup environment (`/proc/<pid>/environ`, `ps eww`) or memory (review L1).

### Why

- senpi#6820: values reach agent children only through a broker; a project's settings must not be able to send a user credential to a host of its choosing.

### Why an extension could not handle it

- `getShellEnv()` and the codemode kernels both need the same process-wide withholding, which lives with the shell environment in core.

### Expected merge conflict zones

- LOW: new fork-only directory; one field line in the `Settings` interface of `settings-manager.ts`.

## 2026-11-16 - `credential-proxy` builtin (senpi#6828)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/credential-proxy/index.ts`: activates the proxy at `session_start` from the global `credentialProxy` setting, reports problems as warnings and a start failure as an error (credentials stay withheld), and releases it at `session_shutdown`.
- `packages/coding-agent/src/core/extensions/builtin/index.ts`: registers it right after `kill-guard`, before any tool-registering builtin.
- `packages/coding-agent/src/core/extensions/builtin/hooks/command-runner.ts`: hook commands take their passthrough values from `withCredentialProxy(process.env)`, so a hook that passes a declared variable through gets the placeholder and can use its `baseUrlEnv` route (review L2). A hook that exits without reading its JSON input no longer raises an unhandled `EPIPE` from the stdin write; any other stdin write error is appended to the hook's stderr.

### Why

- senpi#6820.

### Why an extension could not handle it

- It is an extension; the registration line is the only edit to a shared file.

### Expected merge conflict zones

- LOW: one import and one array entry next to `kill-guard`.

## 2026-11-16 - Kernels never receive a declared credential (senpi#6828)

### What changed

- `packages/senpi-codemode/src/extension/runtime-factory.ts`: the kernel session environment includes the placeholder and proxy route for every declared credential (`withCredentialProxy(process.env)` entries that differ from `process.env`). The session environment overrides each kernel's inherited environment (py, rb, jl subprocesses, js worker and process kernels, `%npm`-style installs), so the value never reaches a kernel or its children.
- `packages/senpi-codemode/src/kernels/js/worker-shell-capture.js`: `Bun.spawn` pins the worker's environment view also when no cell is active, so a spawn from a timer or callback after its cell settled no longer inherits the OS environ that still holds the value (review M1).

### Why

- senpi#6820.

### Why an extension could not handle it

- The kernel environment is built in this extension.

### Expected merge conflict zones

- LOW: the `sessionEnv` line and one new function.
