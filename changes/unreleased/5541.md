## 2026-11-02 - A Windows resize outside a multiplexer repaints only the viewport (senpi#3405, PR #5541)

### What changed

- `packages/tui/src/tui.ts`: `doRender()` computes `preserveScrollbackOnResize = preserveMuxScrollback || process.platform === "win32"` and uses it in the width-change and height-change branches only, so a Windows resize outside a multiplexer takes the senpi#1704 viewport repaint (`renderMuxViewportRepaint`, absolute home for width changes) instead of `fullRender`. The focus-repaint and scrollback catch-up paths still key on `preserveMuxScrollback`.

### Why

- Since #1147 `fullRender` skips `ESC[3J` on `win32`, so a resize there wrote `ESC[2J ESC[H` (which Windows Terminal moves into its history) and re-emitted every transcript line: each width or height change appended one more full copy of the transcript to the scrollback.

### Why an extension could not handle it

- The resize branches are inside the renderer's own frame loop; no extension hook sees or replaces them.

### Expected merge conflict zones

- LOW: the width-change and height-change branches of `doRender()` in `tui.ts` (one new `const` above the width branch, two predicates swapped).

### Fixed
- Resizing a Windows terminal outside a multiplexer (fullscreen toggle, maximize, dragging the edge) no longer appends another copy of the whole transcript to the scrollback; the resize repaints only the visible viewport, as it already did inside tmux ([#5541](https://github.com/code-yeongyu/senpi/pull/5541))
