## 2026-11-24 - A pending idle handover is bounded (senpi#7427)

### What changed

- `packages/coding-agent/src/modes/rpc/host-idle-handover.ts`: `IDLE_HANDOVER_WAIT_LIMIT_MS` (10 minutes) and the `waitLimitMs` option bound how long an operation stays `handover_pending`. Past the limit it is abandoned as `handover_blocked` with a `reason` starting `idle_wait_expired:`, `admits()` admits new work again, and a new operation may begin. `stopTimer` clears the deadline together with the poll timer, so a switch that started is never cut.

### Why

- The pending wait had no deadline and no cancel verb. A host whose sessions never went idle (monitors waking them) stayed `handover_pending` forever and answered every prompt, steer, wake and peer delivery with `handover_pending:` (observed 2026-11-24).

### Why an extension could not handle it

- The admission gate and the operation state belong to the host core; no extension sees `begin_handover` or the gate.

### Expected merge conflict zones

- LOW: `HostIdleHandover.begin`, `stopTimer` and the module doc in `host-idle-handover.ts`.

## 2026-11-24 - omo dev builds are ordered by their build epoch (senpi#7428)

### What changed

- `packages/coding-agent/src/core/engine-build-identity.ts`: a pair where either side is an omo dev build (the version before `+` has the prerelease part `omob`) and both carry a build epoch is comparable, and `compareEngineOrdinal` orders it by that epoch alone. Release pairs keep the CalVer order, and a dev build without an epoch stays unordered.

### Why

- omo stamps its dev builds `0.0.0-omob.<omo>.<senpi>` by contract, so their version names no release position, and `olderEngineDetail` refused a later dev build as `older_engine` (running `2026.11.19-2-1-omob.6d05a3b.1975499+1795063675.1975499`, successor `0.0.0-omob.2a41028.6cbd012+1795530578.6cbd012`).

### Why an extension could not handle it

- The engine order decides the host handoff before any extension loads.

### Expected merge conflict zones

- LOW: `comparableEngines` and `compareEngineOrdinal` in `engine-build-identity.ts`.
