### Breaking Changes

- Host presentation tools now attach through the SDK. Standalone `show_html_page` retains its existing file output, schema, and lazy activation; a bare engine no longer registers it unconditionally.
- `show_html_page` leaves the engine catalog; SDK callers that do not supply `builtInExtensions` no longer receive it.

### Fixed

- Cancelled host-tool calls no longer run the standalone implementation after the host route becomes unavailable.

## 2026-10-30 - Attach presentation tools at the host SDK boundary (#5045)

### What changed

- `packages/coding-agent/src/extensions/index.ts` explicitly attaches the standalone HTML tool through `attachHostTools`.
- `packages/coding-agent/src/host-tools.ts` provides generic host registration; calls use a host route while one is announced and otherwise run the standalone implementation.
- `packages/coding-agent/src/host-tools.ts` clears an unavailable host route but throws `AbortError` instead of running the standalone fallback when the call's signal has been aborted.
- A host bridge must re-announce `senpi:host-tool-route` after an extension reload because the new registration starts without a route.
- `packages/coding-agent/src/index.ts` exports the attachment contract.
- The HTML implementation moved from engine builtins to `src/extensions/html-render/` without changing its schema, file preparation, result, or lazy exposure.
- The public SDK exposes writeHtmlPage and showHtmlPageTool. Both standalone execution and desktop host attachments use the same writer; its prepared bytes are compared against the pre-change output.

### Why

- A bare SDK engine must not acquire host presentation tools unconditionally. The CLI retains file output while desktop can supply the same callable through MCP.

### Why an extension could not handle it

- The implementation is an extension. Its default composition and public SDK export are owned by the host entry point.

### Expected merge conflict zones

- The `src/index.ts` public exports and `src/extensions/index.ts` host factories.

## 2026-10-30 - Host-supplied extension defaults retain settings control (#5045)

### What changed

- `packages/coding-agent/src/core/resource-loader.ts` composes explicitly supplied `host` factories with the session's default factories, outside the unconditional engine catalog.

### Why

- Moving a presentation tool to its host must preserve `enabledBuiltinExtensions`, `disabledBuiltinExtensions`, and explicit `builtin:<name>` loading.

### Why an extension could not handle it

- Default selection happens before extension factories run or settings are bound to the extension runtime.

### Expected merge conflict zones

- Factory classification in the `DefaultResourceLoader` constructor.

<!-- changes-log: packages/coding-agent/src/core/extensions/changes.md -->
## 2026-10-30 - Declare host-supplied default extensions (#5045)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts` adds `InlineExtension.host` so an SDK host can supply a default extension under existing per-name settings.

### Why

- Host tools must not live in the engine's unconditional catalog, and relocating them must not revive a tool the user disabled.

### Why an extension could not handle it

- The public factory contract tells the resource loader how to compose defaults before extension execution.

### Expected merge conflict zones

- The named `InlineExtension` variant in `packages/coding-agent/src/core/extensions/types.ts`.

## 2026-10-30 - Remove unconditional host HTML registration (#5045)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/index.ts` no longer imports or registers `html-render`.
- Its file-producing implementation now belongs to the standalone host's `src/extensions/html-render/`; the single-tool registration wrapper was removed.

### Why

- Host tools attach through the SDK rather than being unconditional engine builtins.

### Why an extension could not handle it

- Removing the unconditional catalog entry requires changing the builtin composition root.

### Expected merge conflict zones

- Import and registration entries in `packages/coding-agent/src/core/extensions/builtin/index.ts`.
