## 2026-11-10 - The Python sqlite guard reads only a private urllib.parse snapshot (senpi#6377)

### What changed

- `src/kernels/py/interpose.py`: `install()` builds one private copy of the `urllib.parse` namespace (`capture_module`), rebinds every function defined in that module to the copy, and takes `urlsplit`, `parse_qs` and `unquote` from it.

### Why

- Capturing only the entry points left their inner calls (`parse_qsl`, `unquote`, `unquote_plus`) on the live module globals. A cell could rebind them and steer `database_path`: on Python 3.11 that made the guard crash with a `TypeError`, and on 3.12 it could skip the permission check (#6376).

### Why an extension could not handle it

- The guard is the kernel's own permission interposition.

### Expected merge conflict zones

- LOW: the private dependency capture block at the top of `install()` in `interpose.py`.

### Fixed

- The Python sqlite permission guard no longer depends on `urllib.parse` attributes that cell code can rebind. Rebinding them could crash the guard on Python 3.11 or bypass a read-only check on 3.12 (#6376).
