## 2026-11-02 - A later login step keeps an open prompt (senpi#5425)

### What changed

- `packages/coding-agent/src/modes/interactive/components/login-dialog.ts`: `showPrompt` and `showManualInput` remember the rows they add above the input while the prompt waits for input; submit and cancel forget them. `showAuth`, `showDeviceCode` and `showDetails` replace the dialog content through `replaceContent`, which clears the dialog, adds the new step, then puts a prompt that is still waiting back below it with its input and its own hint (not a waiting or info hint shown after it). With no open prompt the dialog behaves as before.
- `packages/coding-agent/test/suite/regressions/5433-extension-oauth-prompt-input.test.ts`: a table case for an auth URL, a device code and setup details that arrive while a prompt is open, and a case where a waiting hint replaced the prompt hint before the auth step.

### Why

- In a Claude browser login, `claude auth login` prints its paste-code fallback URL (the paste-code prompt opens) before its `$BROWSER` helper reports the browser URL (`showAuth`). `showAuth` cleared the open prompt, so the user saw no place to paste the code. With the browser on another machine (SSH, WSL, a remote terminal) its localhost callback cannot reach the CLI, and the login could only time out.

### Why an extension could not handle it

- The order of the two URLs comes from the CLI's helper process and a file watch, so the extension cannot guarantee it; the dialog that discards the prompt is the interactive `LoginDialogComponent`, not an extension surface.

### Expected merge conflict zones

- LOW: `showAuth`, `showDeviceCode`, `showDetails`, `showManualInput` and `showPrompt` in `login-dialog.ts`.
