## 2026-11-12 - A move's export keeps the queued input from the moment the session is sealed (senpi#6542)

### What changed

- `packages/coding-agent/src/core/session-move/export.ts`: once the session is sealed for the move, and before anything else can fail, the export writes a manifest holding only the move and the queued input where the bundle will be (`keepQueuedInput`); the bundle takes its place when it is written. Nothing is written when there is no queued input or when a bundle is already there. A comment that said a session whose state folder is given as a function is never sealed is corrected.
- `packages/coding-agent/src/core/session-move/bundle-place.ts` (new): the place an export writes its bundle to. `queuedInputToCarry`: a call that sends no queued input, as a caller that restarted after a failed export does, carries what is kept at the place for this move; a call that sends a list carries that list. `putAtPlace`: when the place is taken, its other entries are removed and the staged ones moved in, and its manifest is replaced last by one rename over it, so the place always holds a manifest. `export.ts` uses both.

### Why

- The input a release takes out of a session was written only in the bundle's manifest. An export that failed after the seal and before the bundle left it in no file, so a `declined` finish took the session back without it.

- What is kept outlived the failed export but not the next one: a later export sent without the list replaced it with a bundle whose manifest listed nothing, and the bundle took its place by a removal then a rename, so a process that died between the two left no manifest there at all (senpi#6566's review).

### Why an extension could not handle it

- It is the session move's own export.

### Expected merge conflict zones

- LOW: `writeMoveBundle` in `export.ts`, between the seal and the read of the state folder, and its last two lines, which put the bundle at its place.
