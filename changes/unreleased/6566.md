## 2026-11-12 - A move's export keeps the queued input from the moment the session is sealed (senpi#6542)

### What changed

- `packages/coding-agent/src/core/session-move/export.ts`: once the session is sealed for the move, and before anything else can fail, the export writes a manifest holding only the move and the queued input where the bundle will be (`keepQueuedInput`); the bundle takes its place when it is written. Nothing is written when there is no queued input or when a bundle is already there. A comment that said a session whose state folder is given as a function is never sealed is corrected.

### Why

- The input a release takes out of a session was written only in the bundle's manifest. An export that failed after the seal and before the bundle left it in no file, so a `declined` finish took the session back without it.

### Why an extension could not handle it

- It is the session move's own export.

### Expected merge conflict zones

- LOW: `writeMoveBundle` in `export.ts`, between the seal and the read of the state folder.
