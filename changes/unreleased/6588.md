## 2026-11-13 - Read macOS process start times in UTC (senpi#6588)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/process-start-probe.ts` runs the darwin `ps -o lstart=` read with `TZ=UTC` and parses it with `lstartUtcMs`.
- `packages/coding-agent/src/core/extensions/builtin/terminal/orphan-reaper.ts` runs the darwin `ps -o lstart=,command=` read with `TZ=UTC` and parses its start with `lstartUtcMs`.

### Why

- `packages/coding-agent/src/core/extensions/builtin/terminal/process-start-probe.ts`: its start time is compared with the true start instant a lease holder records (`lease-file.ts`, `manifest-lease.ts`). A local-time lstart is ambiguous in the repeated fall-back hour, so a live holder started then read an hour off and was judged stale, letting a second writer in (senpi#6589).
- `packages/coding-agent/src/core/extensions/builtin/terminal/orphan-reaper.ts`: the same ambiguity put an orphan's start an hour off its recorded instant, so it was judged "unverifiable" and never reaped (senpi#6589).

### Why an extension could not handle it

- `packages/coding-agent/src/core/extensions/builtin/terminal/process-start-probe.ts` and `packages/coding-agent/src/core/extensions/builtin/terminal/orphan-reaper.ts` are the builtin terminal extension's own process-identity reads; there is no hook to replace how a builtin reads a pid's start time.

### Expected merge conflict zones

- `packages/coding-agent/src/core/extensions/builtin/terminal/process-start-probe.ts`: the darwin branch of `darwinProcessStartMs`. senpi#6562 carries the identical hunk.
- `packages/coding-agent/src/core/extensions/builtin/terminal/orphan-reaper.ts`: `execText` and `readDarwinEvidence`.

## 2026-11-13 - Parse a UTC ps lstart explicitly (senpi#6588)

### What changed

- `packages/coding-agent/src/utils/process-identity.ts` exports `lstartUtcMs`, which parses a `ps -o lstart=` value printed under `TZ=UTC LC_ALL=C` as UTC.

### Why

- `packages/coding-agent/src/utils/process-identity.ts`: `processStartTimeMs` parses an lstart in the process's local zone by design (legacy pidfiles keep local time). A read made under `TZ=UTC` needs a parse that does not depend on the reader's own zone or on the repeated fall-back hour (senpi#6589).

### Why an extension could not handle it

- `packages/coding-agent/src/utils/process-identity.ts` is a shared core utility used by builtin and RPC code; extensions cannot change how core parses a process start.

### Expected merge conflict zones

- `packages/coding-agent/src/utils/process-identity.ts`: the end of the file. senpi#6562 appends the identical `lstartUtcMs`.
