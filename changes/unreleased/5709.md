## 2026-11-03 - session_start handlers carry open-timing spans (senpi#5709, fixes #5707)

### What changed

- `packages/coding-agent/src/core/extensions/runner.ts`: with `SENPI_OPEN_TIMING=1`, `dispatchEmit` writes one `senpi open-timing` stderr line per `session_start` handler, naming the extension. With the flag unset, the timer is a no-op and no clock is read.

### Why

- A warm `open_session` idled 2.6 s on a macOS host inside the binding phase. Per-handler timing is what named the `openai-image-gen` handler as the one holding it.

### Why an extension could not handle it

- Handler dispatch is the runner's own loop. An extension cannot time the other extensions' handlers.

### Expected merge conflict zones

- LOW: `dispatchEmit` in `runner.ts` (one timer line before the handler loop, one mark after each handler).

## 2026-11-03 - Runtime creation carries open-timing spans (senpi#5709, fixes #5707)

### What changed

- `packages/coding-agent/src/main.ts`: with `SENPI_OPEN_TIMING=1`, `createCliRuntimeFactory` marks `project_trust` and `services` while building services, and `create_session` once the session exists. These marks join the host-open, worker-open, worker-commit, registry-open and rebind spans that `src/core/open-timing.ts` writes for each open phase.

### Why

- senpi#5707 asked for per-phase timing of the open path, behind a flag, so the await that idles a warm open can be named.

### Why an extension could not handle it

- Runtime creation runs before any extension loads.

### Expected merge conflict zones

- LOW: `createCliRuntimeFactory` in `main.ts` (two timers, three marks, one import).

### Fixed
- A warm `open_session` no longer runs `!command` key helpers to decide whether image generation is available. On a host where such a helper failed, every open waited about 1.3 s twice (the helper's retry backoff); availability is now read from configuration, and the helper runs only when `generate_image` sends a request ([#5709](https://github.com/code-yeongyu/senpi/pull/5709))

### Changed
- `generate_image` reports a configured source whose credential could not be resolved (for example a failing `!command` key helper) as `credential_unavailable`, naming the source, instead of `missing_config` ([#5709](https://github.com/code-yeongyu/senpi/pull/5709))

### Added
- `SENPI_OPEN_TIMING=1` writes one `senpi open-timing` stderr line per `open_session` phase, for finding what holds a slow open ([#5709](https://github.com/code-yeongyu/senpi/pull/5709))
