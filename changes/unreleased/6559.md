## 2026-11-12 - A move's `sealed_by.target` is documented as empty when the sealing release named no device (senpi#6539's review)

### What changed

- `packages/coding-agent/src/modes/rpc/session-move-wire.ts`: the comment on `RpcMoveSealedBy.target` says it is the empty string when the sealing release named no device, and what a caller shows for it. No behaviour changes.
- `packages/coding-agent/docs/rpc.md`: the same, where `sealed_by` is described.

### Why

- `release_session` takes `target` as optional and the ownership rule reads a release that named none as the empty string, so `sealed_by.target` can be empty; the docs and the type presented it as always naming a device.

### Why an extension could not handle it

- It is the host's own wire type and its reference.

### Expected merge conflict zones

- LOW: the `RpcMoveSealedBy` interface in `session-move-wire.ts`.
