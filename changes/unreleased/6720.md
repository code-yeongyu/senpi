## 2026-11-15 - Extensions register the session's device machine (senpi#6720)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`, `loader.ts`: `registerDeviceMachine(machine)`, one per session; a second registration throws `DeviceMachineConflictError` naming both extensions. `runtime/bootstrap.ts` and `tools/bash.ts`: bash reads the registered machine when a command runs, only with `OMO_TOOLS_VIA_DAEMON=bash`.
- `packages/coding-agent/src/index.ts`: the public entry exports what an extension needs to build one: `createToolMachine`, `ToolMachine`, `MachineOps`, `MachineExecRequest`, `MachineExecResult`, `OpContext`, `DeviceUnavailableError`, `DeviceMachineConflictError`.

### Why

- Q's order that tool calls go through the hands daemon: the omo-senpi plugin supplies the local daemon's machine, and senpi stays transport-free.

### Why an extension could not handle it

- The session builds the bash tool's options itself; without this API no extension can supply the device it runs on.

### Expected merge conflict zones

- LOW: `ExtensionAPI` near `registerFlag`; the runtime literal in `loader.ts`.

## 2026-11-15 - bash reads the session's device machine when a command runs (senpi#6720)

### What changed

- `packages/coding-agent/src/core/tools/bash.ts`: `deviceMachine` may be a resolver, read when the command runs, so a machine an extension registers after the tools are built is used. With `OMO_TOOLS_VIA_DAEMON=bash` and no machine, the existing `DeviceUnavailableError`.

### Why

- The device machine now comes from `registerDeviceMachine`, which an extension may call after the bash tool exists.

### Why an extension could not handle it

- The bash tool resolves its executor inside the built-in tool.

### Expected merge conflict zones

- LOW: the operations choice in `createShellToolDefinition`.

## 2026-11-15 - The public entry exports the device machine pieces (senpi#6720)

### What changed

- `packages/coding-agent/src/index.ts`: exports `createToolMachine`, `ToolMachine`, `ToolPathPolicy`, `MachineOps`, `MachineExecRequest`, `MachineExecResult`, `OpContext`, `DeviceUnavailableError` and `DeviceMachineConflictError`.

### Why

- An extension such as the omo-senpi plugin builds the device machine against the published package; `@code-yeongyu/senpi-machine-ops` is a private workspace package.

### Why an extension could not handle it

- Without the exports an extension cannot build a `ToolMachine` or match the typed errors with `instanceof`.

### Expected merge conflict zones

- LOW: the tools export block in `src/index.ts`.
