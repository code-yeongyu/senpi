## 2026-11-20 - A bash command starts only after its session-spawn record exists (#7128, senpi#7061)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/tools/spawn.ts`: a command attested to a session (linux, darwin) or launched behind the tool child's barrier starts behind the go-line shim (moved here from `terminal-jobs.ts`). `spawnCommandSession` writes the session-spawn record, lets the barrier admit the launch, and only then writes the go-line, a random `~senpi-go-<hex>` token.
- `packages/coding-agent/src/core/extensions/builtin/terminal/go-line-echo.ts` (new): `GoLineEchoFilter` drops the token's echo from the front of a gated command's output and passes everything else through.
- `packages/coding-agent/src/core/extensions/builtin/terminal/runtime-session.ts`: `TerminalRuntimeOptions.goLine`; the session runs its output through the filter and flushes it at exit.
- `packages/coding-agent/src/core/extensions/builtin/terminal/tools/context.ts`: `TerminalLaunchBarrier` is one method, `admit(session)`; it no longer wraps the launch or writes the go-line.

### Why

- senpi#7061 / senpi#7120: the record was written a few event-loop turns after the command started, so a command that proves its session as it starts (a seat gate run from bash) usually found none: 8 of 10 immediate self-checks on a Linux host.
- A native PTY echoes the go-line: 20 of 20 runs on macOS printed it ahead of the command's output, even with the old shim's `stty -echo`, which ran after the line arrived. The shim no longer touches the terminal's echo settings; the filter is what keeps the line out of the output.
- `runtime-session.ts` also ingests the decoder's final partial UTF-8 bytes at exit when no redactor is set; they were dropped before.

### Why an extension could not handle it

- This is the terminal builtin's own spawn path.

### Expected merge conflict zones

- MEDIUM: `spawnCommandSession` in `tools/spawn.ts`. LOW: the data callback and exit handler in `runtime-session.ts`; `TerminalLaunchBarrier` in `tools/context.ts`.

## 2026-11-20 - The tool child's terminal barrier only admits (#7128, senpi#7061)

### What changed

- `packages/coding-agent/src/modes/rpc/tool-child/terminal-jobs.ts`: `barrierFor` implements `admit` (record the launch with the server, wait for its ack, mark it invoked); the go-line shim and the go-line write moved to `spawnCommandSession`, which now sends a random token whose echo is dropped from the output.

### Why

- One gate for both runtimes: the in-process path now also gates on the session-spawn record (senpi#7061), and the old literal `go` line could be echoed into a native PTY's output.

### Why an extension could not handle it

- The tool child's job handlers are core RPC code.

### Expected merge conflict zones

- LOW: `barrierFor` in `terminal-jobs.ts`.
