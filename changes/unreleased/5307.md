## 2026-11-01 - sandbox-runtime and the MCP SDK resolve zod 4.6.7, clearing GHSA-mrhx-c7xc-m3w5 on zod 3 (senpi#5307, part of #4820)

### What changed

- `package.json`: a scoped override `{"@anthropic-ai/sandbox-runtime": {"zod": "4.6.7"}}`. npm then hoists zod 4.6.7 to the root, so the shipped `@modelcontextprotocol/sdk`, `zod-to-json-schema`, `openai` and `@anthropic-ai/sdk` (all declaring `^3.25 || ^4`) resolve it too; `package-lock.json`, `bun.lock` and `packages/coding-agent/install-lock` are regenerated with `refresh-lock`.
- `packages/coding-agent/examples/extensions/sandbox/index.ts`: declares the config fields it uses instead of extending sandbox-runtime's `SandboxRuntimeConfig`, whose published type is inferred from zod 3 declarations and is empty under zod 4. sandbox-runtime still validates the config at runtime with its own schema.

### Why

- `package.json`: GHSA-mrhx-c7xc-m3w5 (zod < 4.6.6) has no 3.x fix; 3.25.76 is the last 3.x release, and sandbox-runtime (through 0.0.81) still declares `zod ^3.25.0`. Its config schema parses identically under zod 4.6.7 and a real sandboxed command behaves the same.

### Why an extension could not handle it

- Dependency resolution happens at install, before any runtime extension loads.

### Expected merge conflict zones

- MEDIUM: `package.json` `overrides`, `package-lock.json`, `bun.lock`, `packages/coding-agent/install-lock/package-lock.json`: other dependency bumps regenerate the same lockfiles; re-run `bun run refresh-lock`.
