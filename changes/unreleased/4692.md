## 2026-10-29 - Recheck known interruption before start hooks (part of senpi#4692)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: skip start hooks and their final provider admission work when interruption is already known after the preceding admission awaits. Retain the existing post-hook interruption guard.

### Why

- `packages/coding-agent/src/core/agent-session.ts`: an automatic send whose run became interrupted during auth admission invoked `before_agent_start` before being held, then invoked it again on Resume.

### Why an extension could not handle it

- `packages/coding-agent/src/core/agent-session.ts`: core owns both the awaited admission ordering and the interrupted-run hold that decides whether hooks should begin.

### Expected merge conflict zones

- LOW: the `before_agent_start` block inside `_deliverCustomMessage` in `packages/coding-agent/src/core/agent-session.ts`.

### Fixed

- Automatic sends no longer invoke start hooks when interruption is already known before those hooks begin. Interruption arising during a callback still follows the existing extension admission contract.
