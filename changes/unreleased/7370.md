## 2026-11-22 - Interactive shutdown waits for queued settings writes (omo#9630)

### What changed

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: normal interactive shutdown awaits `SettingsManager.flush()` after session teardown and before `process.exit()`.

### Why

- A thinking-level change queues its per-model writes; when another writer held the state lock, the write retried asynchronously and a double Ctrl+C exited before it landed, so the next session started at the old level.

### Why an extension could not handle it

- The TUI owns the exit ordering; an extension cannot delay `process.exit()` on this path.

### Expected merge conflict zones

- LOW: `InteractiveMode.shutdown` in `interactive-mode.ts`.
