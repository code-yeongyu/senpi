## 2026-10-31 - gpt-6-astra reads a file wide once instead of re-reading it in small windows (senpi#5161)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/prompt-preset/gpt-6-astra.ts`: new `read-wide-once` rule (concern `tool-orchestration`), rendered once in `## Working the Task` right after "Read a file before claiming what it contains": read the whole region a question touches in one call (the whole file when it fits the read limit), work from that copy, and re-read a file only after it changed. The header gains the dated rationale.
- `packages/coding-agent/test/suite/prompt-presets-native-baseline.json`: the `gpt-6-astra:*` hashes are recaptured; every other preset's hash is unchanged.

### Why

- A session survey found this preset re-reading a path it had already read on several times the rate of the other presets on the same read tool, mostly as windows of 40 lines or fewer over a region an earlier call had returned. The preset had no file-reading rule, and the read tool's description invites offset/limit paging.

### Why an extension could not handle it

- The preset text is owned by this builtin extension.

### Expected merge conflict zones

- LOW: the `Gpt6AstraRuleId` union, the `GPT6_ASTRA_RULES` table and the "Read a file before claiming" sentence in `gpt-6-astra.ts`; the `gpt-6-astra:*` keys of the native baseline.
