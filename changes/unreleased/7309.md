## 2026-11-22 - A Windows generation-bound stop proves the target by the record's creation time and the answering instance (senpi#4071)

### What changed

- `packages/coding-agent/src/modes/rpc/host-stop-start-time.ts`: `startedBeforeRegistration` compares the live start time with the generation record's creation time (`birthtime`) instead of its mtime; a missing creation time is not proven.
- `packages/coding-agent/src/modes/rpc/host-stop.ts`: on the bound Windows path, an answering host without an `instanceId` refuses `unknown_owner`.
- `packages/coding-agent/src/modes/rpc/host-daemon-registration.ts`: comment stating that the record is rewritten at adoption, so its mtime is not a cutoff.

### Why

- The record is written at spawn and again after adoption (`host-successor.ts`), so its mtime can move past the real host's lifetime and let a reused pid pass; and `docs/rpc.md` requires an answering host to report the confirmed instance id.

### Why an extension could not handle it

- The proof runs inside the core host-stop path before any signal is sent.

### Expected merge conflict zones

- LOW: `recheckedTarget` in `host-stop.ts` and `startedBeforeRegistration` in `host-stop-start-time.ts`.
