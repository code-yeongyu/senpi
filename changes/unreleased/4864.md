## 2026-10-29 - Version-proven Windows private descriptor pairs (#4859, PR #4864)

### What changed

- `packages/coding-agent/src/private-fds.ts`: represents a private channel as a POSIX socket or an ordered Windows pipe pair; flattens table-wide descriptor aliases before adoption; inspects only pipe types and clears inheritance synchronously at receipt. `WINDOWS_PRIVATE_FD_PAIR_PROVEN` ships as `false`; when enabled it records the exact proven Bun version, so any runtime bump fails closed until the Windows proof and old-parser compatibility control re-run.
- `packages/coding-agent/src/private-fd-spawn.ts`: forwards both halves atomically on explicit hops, closes both owned copies after spawn, and carries consumed channels or shell spawns as null declarations.

### Why

- Windows private channels need separate read and write handles while preserving the existing declaration and one-shot ownership contract.

### Why an extension could not handle it

- Descriptor capture and inheritance clearing must finish during bootstrap, before extensions or unrelated children can start.

### Expected merge conflict zones

- Private descriptor parsing, ownership maps, and explicit-hop stdio construction.

## 2026-10-29 - Compose and protect inherited pipe pairs (#4859)

### What changed

- `packages/coding-agent/src/utils/inherited-duplex.ts`: reads the first descriptor and writes the second, retaining partial-write handling and backpressure; destroying the Duplex closes both.
- `packages/coding-agent/src/utils/private-fd-inherit.ts`: binds the Windows CRT descriptor-to-HANDLE conversion and `SetHandleInformation` synchronously through the existing Bun builtin boundary.

### Why

- The Windows pair has two owners to dispose and must not leak into ordinary children.

### Why an extension could not handle it

- These helpers run at process receipt and supply core transport ownership.

### Expected merge conflict zones

- Inherited duplex construction and destruction.
