## 2026-11-27 - Permission rules fail closed when a settings file does not load (senpi#6556, senpi#2624)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/permission-system/settings-load-guard.ts` (new): `assertPermissionSettingsLoaded` drains the load errors of the permission system's own `SettingsManager` and throws one error per failed file, naming the scope, `path:line:column` (for a syntax error), the cause, that the file's permission rules (deny rules included) cannot be applied, and how to fix it (fix or move the file aside, then `/reload` or restart).
- `packages/coding-agent/src/core/extensions/builtin/permission-system/index.ts`: `loadPermissionRules` calls the guard before deriving rules. The throw lands in the existing setup-error path (#2617), so every tool call in that session is refused with `Permission setup failed: ...` until the file loads. Carried from #2953 (MoerAI), extended with the position and the fix instruction.

### Why

- `SettingsManager` reads a file that fails to parse as `{}` and only records the error. The permission system never read that error, so one typo turned off every rule in the file, deny rules included, while the session still looked normal (the CLI printed only a generic settings warning). Owner decision for #6556: fail closed, never warn-only.

### Why an extension could not handle it

- The permission system is the builtin that owns rule loading and tool admission; an extension cannot add rules or block tool calls ahead of it once it has derived an allow-all ruleset.

### Expected merge conflict zones

- LOW: `permission-system/index.ts` imports and the `loadPermissionRules` line just before `loadPermissionSettings(...)`.

## 2026-11-27 - Settings syntax errors carry their line and column (senpi#6556)

### What changed

- `packages/coding-agent/src/core/settings-json-syntax-error.ts` (new): `SettingsJsonSyntaxError` (a `SyntaxError` with 1-based `line` and `column`) and `jsonSyntaxErrorOffset`, a strict-JSON scanner that finds where parsing stops.
- `packages/coding-agent/src/core/settings-json.ts`: `parseSettingsJson` rethrows a `JSON.parse` failure, and an unterminated block comment, as `SettingsJsonSyntaxError`. The message is unchanged; comment stripping keeps line breaks, so the position matches the file.

### Why

- The permission system must name `file:line` when it refuses to start (#6556). Bun's `JSON.parse` error carries no position, and V8's offset would refer to the comment-stripped text, so the position is computed here.

### Why an extension could not handle it

- `parseSettingsJson` is the core settings loader; the parse position is gone by the time any extension sees the recorded error.

### Expected merge conflict zones

- LOW: `settings-json.ts` block-comment branch and the final `JSON.parse` call.
