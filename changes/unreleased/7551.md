## 2026-11-27 - Diagnostic log writers redact resolved reference values (senpi#6337, senpi#7551)

### What changed

- `packages/coding-agent/src/core/sensitive-output.ts`: new `redactLogText(text)`, the one pass every diagnostic log writer runs on each string it writes: `redactSensitiveTokenValues` (resolved reference values, raw and encoded, then credential shapes) followed by the authorization-header / credential query-parameter rule the session and config-reload logs each kept a copy of. Everything is replaced with `[redacted]`.
- `packages/coding-agent/src/core/session-log.ts`: `safeText` calls `redactLogText` before truncating to 200 characters; the local `SENSITIVE_TEXT` pattern is gone. This covers the free-text `error`, `reason`, `cause` and `rejectionCause` fields in the file, the `sink` and the `SESSION_DEBUG` stderr mirror.

### Why

- A value a config reference (`$env`, `$file`, `$concat`) resolved to reached `session.log` as is whenever it sat in a free-text field, because the writer only matched header and query-string shapes. Redacting before truncating matters: a cut through a value would leave a prefix the registry no longer matches.

### Why an extension could not handle it

- The writers are core diagnostics that run before and outside any extension hook; their output reaches disk directly.

### Expected merge conflict zones

- LOW: the import block and `safeText` in `session-log.ts`; one function after `redactSensitiveTokenValues` in `sensitive-output.ts`.

## 2026-11-27 - moved-path-guard log redacts resolved reference values (senpi#6337, senpi#7551)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/moved-path-guard/guard-log.ts`: `logGuardEvent` runs every detail value through `redactLogText` before the JSON line is queued; the once-per-reason key is still computed from the details as given.

### Why

- The guard log wrote its JSON details (`file`, `reason`, ...) with no redaction at all, so a resolved reference value inside a path or reason reached `moved-path-guard.log`.

### Why an extension could not handle it

- The guard log is the builtin's own diagnostic sink; nothing else sees its lines before they are written.

### Expected merge conflict zones

- LOW: the import block and the line building `line` in `logGuardEvent`.

## 2026-11-27 - config-reload log redacts resolved reference values (senpi#6337, senpi#7551)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/config-reload/log.ts`: `safeText` calls `redactLogText` before truncating; the local `SENSITIVE_TEXT` copy is gone. `reason`, `message`, ids and paths in `config-reload.log` are covered.

### Why

- The writer matched only header and query-string shapes, so a resolved reference value echoed into a reload reason or a watcher error message was written as is.

### Why an extension could not handle it

- The log is the config-reload builtin's own sink, written synchronously from inside its watcher.

### Expected merge conflict zones

- LOW: the import block and `safeText`.
