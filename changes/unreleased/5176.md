## 2026-10-31 - Reworded idle replies pause the goal; the user grace parks on live wake sources (senpi#5160)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/goal/continuation.ts`: new deny reason `idle` after `GOAL_IDLE_REPLY_STREAK` (8) unattended replies in a row that make no progress, on the `immediate` and `userGrace` paths, whatever their wording.
- `packages/coding-agent/src/core/extensions/builtin/goal/monitor-continuation.ts`: the idle streak reuses the no-progress guard's progress signal (`toolEffectFingerprint`, todo change, human input); `#recordToolEffect` returns `{ progress, newEffect }` so the first-ever tool effect resets the idle streak while the no-progress guard keeps its seeding rule. A user turn that ends with a live wake source parks on `monitor` instead of arming the 10 s grace, and a grace timer that fires while a wake source is live re-parks.
- `packages/coding-agent/src/core/extensions/builtin/goal/lifecycle-helpers.ts`: an `idle` denial pauses the goal (`continuationStoppedAt`, no blocked reason) with the info notice `GOAL_IDLE_STOP_NOTICE`, the `goal-continuation-stopped` entry and an `engine-paused` entry.

### Why

- The repetition guard only tripped on identical reply hashes and the stale signature hashed the reply text, so a model rewording each "still waiting" reply re-fired the goal about every 10 s with no end. The grace timer also re-prompted while a monitor or background task was already going to wake the goal.

### Why an extension could not handle it

- Continuation admission and its timers are owned by this builtin; another extension cannot see the verdict inputs or the grace timer.

### Expected merge conflict zones

- MEDIUM: `evaluateGoalContinuation` and `isEligibleForGoalContinuation` in `continuation.ts`; `afterAgentEnd`, `#continueIfEligible` and `#recordToolEffect` in `monitor-continuation.ts`.
- LOW: `handleDeniedContinuation` in `lifecycle-helpers.ts`.

### Fixed
- An active goal no longer re-fires forever on reworded "still waiting" replies: 8 replies in a row with no progress pause it, resumable with any message, and a goal waiting on a live monitor or background task is not re-prompted after the 10 s user grace ([#5176](https://github.com/code-yeongyu/senpi/pull/5176))
