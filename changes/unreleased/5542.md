## 2026-11-02 - Top-level function declarations persist between JS cells (senpi#3127)

### What changed

- `packages/senpi-codemode/src/kernels/js/worker-indirect-eval.js`: `persistTopLevelDeclarations` collects top-level `function`, `function*` and `async function` names and `persistFunctionDeclarations` assigns each to its `persistTarget` right after the cell's directive prologue (`directivePrologueEnd`), on the first line. `isStatementOnly` treats `async function` as a statement, like `function`.

### Why

- Each cell runs in a fresh async wrapper and only `const`/`let`/`var` were persisted, so a helper declared with `function` was undefined in the next cell (senpi#3127).

### Why an extension could not handle it

- Cell wrapping and declaration persistence are internal to the JS kernel worker.

### Expected merge conflict zones

- LOW: `persistTopLevelDeclarations` and `isStatementOnly` in `worker-indirect-eval.js`.

### Fixed
- A top-level `function`, `async function` or generator declared in one JavaScript eval cell is now defined in the next cell, the way a `var` already was ([#5542](https://github.com/code-yeongyu/senpi/pull/5542))
