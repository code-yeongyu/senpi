## 2026-11-20 - Preserve prompts after boolean extension flags (#7116)

### What changed

- `args.ts` leaves the following positional argument untouched when the extension declares its option as boolean.

### Why

- The initial parse treated a positional prompt as the option's value and left the session with no first request.

### Why an extension could not handle it

- Extensions declare option types after the CLI first reads argv.

### Expected merge conflict zones

- The extension-option branch of `parseArgs`.

## 2026-11-20 - Use loaded flag declarations to identify positional messages (#7116)

### What changed

- `main.ts` recovers positional messages in their original order after loading an extension with a boolean flag used in the invocation.

### Why

- A string option consumes its following value; a boolean option must not consume the next message.

### Why an extension could not handle it

- The CLI owns the positional message list passed to the interactive session.

### Expected merge conflict zones

- Startup immediately after collecting extension flag declarations.

### Fixed
- A positional prompt after a boolean extension flag now reaches the session instead of being consumed as an option value ([#7116](https://github.com/code-yeongyu/senpi/pull/7116)).
