## 2026-11-02 - Opt out of claude.ai account connectors in the Claude Code child (senpi#5523)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/settings.ts`: parses `anthropicSubscriptionProvider.claudeAiConnectors` (boolean) and `SENPI_CLAUDE_SDK_OAUTH_CLAUDEAI_CONNECTORS` (`1`/`true`/`0`/`false`), env over project over global like the other provider keys.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/query-environment.ts`: `claudeCodeInlineSettings` builds the inline `--settings` object: `autoCompactEnabled` for the compaction owner, plus `disableClaudeAiConnectors: true` only when `claudeAiConnectors` is `false`.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/options.ts`: `buildAnthropicSubscriptionQueryOptions` takes `settings` from `claudeCodeInlineSettings`.

### Why

- The child runs with `--setting-sources=`, so a user's own Claude Code settings cannot turn the claude.ai account connectors off, and each attach adds their tool schemas (about 137K tokens measured by the reporter) to the context (oh-my-openagent#12166). Unset keeps the settings object identical, so existing fingerprints do not change; `configFingerprint` already hashes `options.settings`, so a flip restarts the resident process.

### Why an extension could not handle it

- The inline settings are built inside this builtin's query options; an extension cannot reach the Claude Code subprocess spawn.

### Expected merge conflict zones

- LOW: the `claudeCodeQueryEnvironment` import and `settings` line of `buildAnthropicSubscriptionQueryOptions` in `options.ts`; the top of `query-environment.ts`; the provider-settings interface and both parser return objects in `settings.ts`.
