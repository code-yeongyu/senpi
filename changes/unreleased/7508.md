## 2026-11-26 - One publisher per release tag; the draft cleanup keeps a draft another run published (senpi#7469)

### What changed

- `scripts/release.mjs`: after preparing a version, the closing line says the tag's Build Binaries run publishes it (it dispatches `publish-npm.yml` publish-only itself). It no longer prints a `gh workflow run publish-npm.yml ... -f publish-only=true` command for a person to run.
- `scripts/release-draft-cleanup.sh`: before deleting a draft GitHub Release because npm lacks the version, it lists the `publish-npm.yml` dispatch runs. It keeps the draft (exit 1, with the recovery steps) while any run titled with that version succeeded, and also when the runs cannot be listed.

### Why

- For 2026.11.25 the printed hand dispatch and the tag's Build Binaries dispatch both published. The hand run published every package. Build Binaries' run met the registry's lag on the main package and failed, and its finalize deleted the draft even though npm had the release.

### Why an extension could not handle it

- This is release tooling, which runs in GitHub Actions; no extension runs there.

### Expected merge conflict zones

- LOW: the closing log line of `scripts/release.mjs`; the end of `scripts/release-draft-cleanup.sh`, before its final delete.

## 2026-11-26 - A manual publish-only run is refused while Build Binaries publishes the tag (senpi#7469)

### What changed

- `.github/workflows/publish-npm.yml`: the release job of a manual publish-only run (`build_run_id` empty, not a dry run) first refuses while a Build Binaries run for `v<version>` is queued, running or has succeeded, naming that run. A manual run stays available for recovering a Build Binaries run that failed. The run title now carries the version (`run-name: Release <version>[ publish-only]`), which the draft cleanup reads.

### Why

- Two publish-only runs of one tag raced in 2026.11.25, and the second run's finalize deleted the draft GitHub Release.

### Why an extension could not handle it

- This is a release workflow; no extension runs in it.

### Expected merge conflict zones

- LOW: the top of `publish-npm.yml` (the `run-name` line) and the first step of its release job.
