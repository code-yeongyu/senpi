## 2026-10-26 - The senpi package ships the Windows socket-secret bridge (senpi#4312)

### What changed

- `packages/coding-agent/package.json`: `files` includes `native/socket-secret`, where the publish job stages `prebuilds/win32-x64/` and `prebuilds/win32-arm64/senpi_socket_secret.<host>.node`.

### Why

- sisyphuslabs/omo-desktop-app#4199: the Windows public socket secret is published and repaired through a native bridge with no fallback, so the installed package must carry it for both Windows architectures.

### Why an extension could not handle it

- Package contents are decided by the manifest, before any extension runs.

### Expected merge conflict zones

- LOW: the `files` array in `packages/coding-agent/package.json`.

## 2026-10-26 - publish.mjs requires the socket-secret bridge it is told to (senpi#4312)

### What changed

- `scripts/publish.mjs`: new `--require-socket-secret-bridge=win32-<arch>[,...]` flag, passed to `assertSenpiPackedWorkspaceFiles` for the senpi tarball.
- `scripts/senpi-publish-pack-checks.mjs`: `SOCKET_SECRET_BRIDGE_TARGETS`, `socketSecretBridgeFile(target)`, and an `options.requiredSocketSecretTargets` check that rejects a senpi tarball missing a named bridge.

### Why

- The bridge has no runtime fallback (sisyphuslabs/omo-desktop-app#4199), so unlike the PTY prebuild a missing target must block the publish, the best-effort arm64 build included.

### Why an extension could not handle it

- Publishing runs in the release tooling, outside the agent runtime.

### Expected merge conflict zones

- LOW: argument parsing at the top of `publish.mjs` and `validatePack`.

## 2026-10-26 - Native prebuilds and the npm publish carry the socket-secret bridge (senpi#4312)

### What changed

- `.github/workflows/native-prebuilds.yml`: Windows rows build `crates/senpi-socket-secret`, the win32-x64 row loads it and checks its ABI sentinel, and "Stage artifact" stages it at `native/socket-secret/prebuilds/<host>/` (three addons expected on Windows).
- `.github/workflows/publish-npm.yml`: a publish-only step stages both Windows bridges into `packages/coding-agent` and fails when one is missing; the publish passes `--require-socket-secret-bridge=win32-x64,win32-arm64`.

### Why

- sisyphuslabs/omo-desktop-app#4199 section 7: native packaging failure of the bridge is a release blocker.

### Why an extension could not handle it

- CI and release workflows run outside the agent runtime.

### Expected merge conflict zones

- MEDIUM: the "Stage artifact" step of `native-prebuilds.yml` and the publish command line in `publish-npm.yml`.
