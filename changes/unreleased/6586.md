## 2026-11-13 - The Claude model support check refuses an empty catalog instead of passing vacuously (senpi#6586)

### What changed

- `scripts/check-claude-code-model-support.mjs`: `catalogClaudeIds` now reads the model id from each catalog row's `id` field and keeps only chat rows (rows with `type: "chat"` or a `chat:` key prefix), and the catalog/binary paths are overridable via `SENPI_CHECK_CATALOG_PATH` / `SENPI_CHECK_BINARY_PATH` test hooks.
- `scripts/check-claude-code-model-support.mjs`: `checkCatalog()` prints a clear error and returns non-zero when `catalogClaudeIds` returns an empty list, so a future catalog key-format change fails loudly instead of printing "knows all 0 catalog Claude ids" and passing (senpi#6310 follow-up).
- `scripts/check-claude-code-model-support.test.mjs`: new test — an empty `anthropic-messages` catalog plus a binary containing the control id exits 1 and names the empty catalog, in both `--strict` and report mode.

### Why

- The check still passed vacuously when it found no Claude ids at all: with the fixture hooks, an empty `anthropic-messages` catalog plus a binary containing the control id printed "knows all 0 catalog Claude ids" and exited 0. A future change to the key format would fail silently again instead of failing loudly.

### Why an extension could not handle it

- `scripts/check-claude-code-model-support.mjs`: release workflow tooling run by `.github/workflows/releasability.yml`.

### Expected merge conflict zones

- LOW: the `checkCatalog()` guard after `catalogClaudeIds` in `scripts/check-claude-code-model-support.mjs`, and the new test case in `scripts/check-claude-code-model-support.test.mjs`.
