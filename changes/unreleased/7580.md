## 2026-11-27 - A session can be opened in memory only (senpi#7580, senpi#7567)

### What changed

- `packages/coding-agent/src/core/agent-session-runtime.ts`: `AgentSessionLaunchProfile.persistence` (`open_session.persistence`); `persistSession`, `switchSession` and `importFromJsonl` refuse a session whose profile chose `none` with `session_not_persisted`. `newSession` and `fork` already keep a non-persisted manager in memory.
- `packages/coding-agent/src/core/session-persistence.ts` (new): the `SessionPersistence` type, its wire validator and the typed refusal.

### Why

- A controller's own session (auth, model and provider calls) is not the user's conversation: it must leave no transcript and no record, the per-session `--no-session` (senpi#7567). A switch, an import or a park claim would give it a file after the fact.

### Why an extension could not handle it

- The session manager is chosen, and switch/import/persist run, in the runtime the host builds before any extension of the session loads.

### Expected merge conflict zones

- LOW: the `AgentSessionLaunchProfile` field list (one field after `persona`); the first line of `persistSession`, `switchSession` and `importFromJsonl`.

## 2026-11-27 - open_session persistence none and an enforced no-tools session (senpi#7580, senpi#7567)

### What changed

- `packages/coding-agent/src/modes/rpc/rpc-host-command-types.ts`, `method-classes-schema-host.ts`, `session-router-open-profile.ts`: `open_session.persistence: "file" | "none"`, validated at the open boundary (`invalid_launch_profile` for another value, and for `none` with a `sessionPath` or `retain_on_disconnect: true`) and held on the launch profile.
- `packages/coding-agent/src/modes/rpc/session-registry-open.ts`: a `none` session runs on `SessionManager.inMemory` and binds no recovery generation on disk.
- `packages/coding-agent/src/modes/rpc/session-worker.ts`, `session-worker-protocol.ts`, `session-worker-client.ts`, `worker-session-open.ts`: a worker isolate names no path for it (`prepared.sessionPath` optional) and the host side takes no path claim or reservation.
- `packages/coding-agent/src/modes/rpc/session-status-source.ts`, `session-registry-types.ts`: its `list_sessions` row carries `persistence: "none"`.
- `packages/coding-agent/src/modes/rpc/session-router-park.ts`: an open asking for `none` never claims a speculative park (a claim persists it).
- `packages/coding-agent/src/modes/rpc/session-router-occupancy.ts`, `rpc-session-event-types.ts`: a handoff drain closes it with the new `session_closed { reason: "not_persisted" }`.
- `packages/coding-agent/src/modes/rpc/session-tools-disabled.ts` (new), `connection-handler.ts`: `bash` on a session opened with `persona.tools: []` is refused with `errorCode: "tools_disabled"`.
- `packages/coding-agent/src/modes/rpc/custom-capability.ts`, `host-capabilities.ts`: capabilities `session_persistence_none` and `session_tools_none_enforced`.

### Why

- A host process that controls the engine over RPC needs a session of its own that is never written and can never run a command, even by mistake (senpi#7567). A client must be able to tell "nothing reopens this session" from a close and from a host stop, and must be able to refuse a host that lacks either guarantee.

### Why an extension could not handle it

- The session manager, the worker prepare, the park claim, the drain's close record and the RPC `bash` command are the host's own, decided before or outside any session extension.

### Expected merge conflict zones

- LOW: `openProperties` in `method-classes-schema-host.ts`, the claim miss list in `session-router-park.ts`, the capability list in `host-capabilities.ts`, the `bash` case of `connection-handler.ts`, the close call in `evictIdleSession`.
