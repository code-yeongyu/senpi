## 2026-11-05 - ToolHost.deviceFiles (senpi#5839)

### What changed

- `packages/agent/src/execution/tool-host.ts`: `ToolHost` gains an optional `deviceFiles(scope)` that returns the `DeviceFiles` of the device the host runs calls on.

### Why

Extensions on the loop side of a split session need the hand's file channel for the session's scope (senpi#5839).

### Why an extension could not handle it

The tool host is chosen by the embedder below the extension layer; an extension cannot reach it.

### Expected merge conflict zones

The `ToolHost` interface in `tool-host.ts`.

## 2026-11-05 - ctx.deviceFiles (senpi#5839)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ExtensionContext.deviceFiles` and `ExtensionContextActions.getDeviceFiles`.
- `packages/coding-agent/src/core/extensions/runner.ts`: the context getter, bound from `getDeviceFiles`; a runner with no session (a hand's runtime) defaults to `localDeviceFiles()`.

### Why

Memory, task and mode data must stay on the device when the loop runs elsewhere (senpi#5839, S40 file channel).

### Why an extension could not handle it

Which device a session's tools run on is known only to the session and its tool host.

### Expected merge conflict zones

The `sessionEnv` neighbourhood of `ExtensionContext` and `createContext`; the contextActions binding block in `runner.ts`.

## 2026-11-05 - The session binds its device files (senpi#5839)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `getDeviceFiles` returns the tool host's `deviceFiles` for the session's execution scope when the host serves one, otherwise `localDeviceFiles()`.

### Why

The loop side of a split session reaches the hand's files through the session's own tool host (senpi#5839).

### Why an extension could not handle it

The session's tool host and execution scope are not visible to extensions.

### Expected merge conflict zones

The `getSessionEnv` line of the contextActions block in `agent-session.ts`.
