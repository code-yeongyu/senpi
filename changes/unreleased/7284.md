## 2026-11-22 - Read skill MCP declarations asynchronously (#4048)

### What changed
- `packages/coding-agent/src/core/extensions/builtin/mcp/skills.ts` uses asynchronous stats and checked reads. `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`, `packages/coding-agent/src/core/extensions/builtin/mcp/skill-reveal.ts`, and `packages/coding-agent/src/core/extensions/builtin/mcp/project-skill-policy.ts` await declarations before using them.

### Why
- `packages/coding-agent/src/core/extensions/builtin/mcp/skills.ts` blocked the shared event loop even on cache hits. The callers in `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`, `packages/coding-agent/src/core/extensions/builtin/mcp/skill-reveal.ts`, and `packages/coding-agent/src/core/extensions/builtin/mcp/project-skill-policy.ts` require completed declarations, including revalidation after authorization decisions.

### Why an extension could not handle it
- The builtin owns discovery, reveal and policy rechecks in `packages/coding-agent/src/core/extensions/builtin/mcp/skills.ts`, `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`, `packages/coding-agent/src/core/extensions/builtin/mcp/skill-reveal.ts`, and `packages/coding-agent/src/core/extensions/builtin/mcp/project-skill-policy.ts`.

### Expected merge conflict zones
- The loader in `packages/coding-agent/src/core/extensions/builtin/mcp/skills.ts`, per-turn hook in `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`, scope state in `packages/coding-agent/src/core/extensions/builtin/mcp/skill-reveal.ts`, and authorization checks in `packages/coding-agent/src/core/extensions/builtin/mcp/project-skill-policy.ts`.

## 2026-11-22 - Reuse asynchronous path authorization for cached skill declarations

### What changed
- `packages/coding-agent/src/core/skill-access.ts` exposes the existing asynchronous file authorization check with the same optional provenance and allowed-root defaults as the checked reader.

### Why
- `packages/coding-agent/src/core/skill-access.ts` must revalidate cached project paths without synchronous filesystem access.

### Why an extension could not handle it
- `packages/coding-agent/src/core/skill-access.ts` owns the shared skill containment policy.

### Expected merge conflict zones
- `packages/coding-agent/src/core/skill-access.ts`: `authorizeSkillPathAsync` and its checked reader.
