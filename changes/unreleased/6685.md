## 2026-11-14 - A session cwd that is a file is refused (senpi#6685)

### What changed

- `packages/coding-agent/src/core/session-cwd.ts`: new `SessionCwdNotDirectoryError` (with `issue { sessionFile?, sessionCwd }`); `assertSessionCwdExists` also throws it when the session's cwd exists but is not a directory, so runtime creation never starts in a file.

### Why

- An `open_session` from another device whose `cwd` named a file (`/etc/hostname`) opened a session with that file as its working directory (oh-my-openagent#13400). Only `existsSync` was checked, and a file exists.

### Why an extension could not handle it

- The check runs before the session runtime exists; no extension is loaded yet.

### Expected merge conflict zones

- LOW: the end of `assertSessionCwdExists` in `session-cwd.ts`.

## 2026-11-14 - open_session refuses a cwd that is not a directory, typed (senpi#6685)

### What changed

- `packages/coding-agent/src/modes/rpc/session-router-open.ts`: after the open's folder is resolved (named or from the session file's header), a folder that exists but is not a directory answers `session_cwd_not_directory` with `errorData { cwd }`, before the registry opens or creates anything. A missing folder, or one the host cannot stat, keeps today's answer.
- `packages/coding-agent/docs/rpc.md`: the code in the open_session cwd section and the error list.

### Why

- A caller on another device cannot stat this host's paths, so only the host can refuse a file cwd; a typed code lets it say which argument to fix (oh-my-openagent#13400).

### Why an extension could not handle it

- The open's routing runs before any session, and so before any extension, exists.

### Expected merge conflict zones

- LOW: the lines after `openSessionFolder` in `open()`.
