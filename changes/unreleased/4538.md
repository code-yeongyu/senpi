## 2026-10-27 - repetitive-turns never cuts a reply off and ignores summaries separated by tool work (senpi#4537)

### What changed

- `repetitive-turns-lane.ts`: the lane compares each completed text-only reply with the previous one; a reply that calls a tool resets the comparison (`noteToolWork`, and `readPersistedAssistantTexts` restores only the text-only replies since the last tool call). The streaming arm path `observeTextDelta` is removed.
- `index.ts`: repetitive-turns no longer aborts the stream; it is judged at `message_end` and nudges after the complete reply. `queueRuleNudge` writes the nudge activation only when the nudge will be sent.
- `follow-up-limit.ts`: `ruleAlreadyCorrected` ends the one-correction episode at the next user message or when the agent calls a tool after the correction.

### Why

- In a long autonomous goal, a progress summary in the mandated status format was compared with the previous summary across hours of tool work, cut off mid-sentence on one near-duplicate pair, and the session was paused because one correction stayed spent until the next user message (senpi#4537, reported by jamestesting).

### Why an extension could not handle it

- The rule is a built-in extension; its lane, follow-up bound and nudge path are internal to it.

### Expected merge conflict zones

- LOW: `message_update` / `message_end` handlers in `ttsr/index.ts`.

## 2026-10-27 - The repetitive-turns activation no longer says output was interrupted (senpi#4537)

### What changed

- `rule-activation/renderer.ts`: a `nudge` activation owned by `repetitive-turns` reads "Reply repeated the previous one; a corrective nudge was queued." Other stream rules keep "Output interrupted; a corrective nudge was queued."

### Why

- repetitive-turns now judges a completed reply and never cuts it off, so "Output interrupted" would be false (senpi#4537).

### Why an extension could not handle it

- The renderer belongs to the built-in rule-activation extension.

### Expected merge conflict zones

- LOW: `summaryLine` in `rule-activation/renderer.ts`.
