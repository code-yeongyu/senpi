## 2026-11-22 - Revalidate compiled extension sources on NFS and FUSE (senpi#7298)

### What changed

- `packages/coding-agent/src/core/extensions/extension-module-cache.ts`: a stat-identity proof is reused only for sources on a filesystem whose attributes reflect writes; on NFS and FUSE mounts, and when the mount type cannot be read, a warm lookup re-hashes the source bytes.

### Why

- NFS and FUSE clients can serve cached attributes while an open returns newer bytes, so an edit made on another machine kept the old compiled extension generation until the attribute cache expired (senpi#6261).

### Why an extension could not handle it

- The compiled-module cache is core extension-loading machinery; an extension cannot change how its own source is validated before it loads.

### Expected merge conflict zones

- LOW: `stableIdentityOf` and `sourceUnchanged` in `extension-module-cache.ts`.
