## 2026-11-03 - An RPC host's supervisor hand-off stays out of the children it starts for agents (senpi#5635)

### What changed

- `packages/coding-agent/src/index.ts`: exports `childEnvironmentOf` (from `modes/rpc/host-identity-env.ts`) so `senpi-codemode` builds its kernel environments with the same helper through the public package API.

### Why

- An RPC host keeps its generation identity in its own `process.env`, and under Bun the OS environ still holds the key sentinel and watch binding it consumed. Every agent-facing child built from that env handed them on, so a senpi CLI started there adopted the parent host's identity or exited `internal_key_unavailable` (senpi#5635, senpi#5548).

### Why an extension could not handle it

- The child environments are built by the core shell helper, the tool child and the RPC client before any extension can intervene, and the hand-off names are owned by the RPC host.

### Expected merge conflict zones

- LOW: the touched lines only; upstream has no RPC host hand-off.
