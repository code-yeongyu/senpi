## 2026-10-26 - Gemini 3+ user turns end with their functionResponses and the final model turn replays unsigned calls as text (senpi#4337, fixes #3633)

### What changed

- `packages/ai/src/api/google-shared.ts`: `convertMessages` keeps every `functionResponse` part at the end of its user turn for Gemini 3+ models: text or inlineData merged after tool results (a follow-up prompt, a detached-tool `<system-reminder>`) now precedes the function responses instead of trailing them (`requiresFunctionResponseTrailingOrder`). Gemini 2 and earlier keep the previous part order byte-identically.
- `packages/ai/src/api/google-shared.ts`: the unsigned-toolCall text replay now also fires for the request's final model turn (`findFinalModelTurnStart`: the run of consecutive assistant steps immediately before the trailing user/tool-result run), not only for steps after the last user message carrying content. Earlier turns keep structured unsigned replay, and parallel calls whose first part carries a valid signature stay structured.

### Why

- Vertex's Gemini 3+ parser rejects a user turn shaped `[functionResponse, text]` with 400 "Requests ending with a model turn are not supported" (omo#9747, senpi#3633; measured against the live endpoint one variable per request: `[text, functionResponse]` and `[functionResponse]` return 200), and it strict-validates thought signatures on the request's final model turn even when a user message follows the tool results (400 "Function call is missing a thought_signature in functionCall parts", live-measured in senpi#3633). The current-turn boundary (last user message with content) misses that turn exactly when a steering note, recalled-memory notice or detached/cancelled-tool notification lands after tool results, which long-running sessions hit on nearly every detached eval. A mid-session switch to a Gemini 3+/4 model leaves the final model turn unsigned for the same reason.

### Why an extension could not handle it

- Both defects are in the outgoing wire shape built inside the provider adapter: no extension hook can reorder request parts or switch a step's replay encoding before the SDK serializes the request.

### Expected merge conflict zones

- LOW: `convertMessages`'s `replayUnsignedToolCallsAsText` computation and the trailing-order pass before `return contents;`.
- LOW: `requiresFunctionResponseTrailingOrder` beside `requiresThoughtSignatureReplay`, and `findFinalModelTurnStart` beside `findLastUserContentMessageIndex`.
