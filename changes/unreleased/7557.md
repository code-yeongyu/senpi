## 2026-11-27 - A stored session cwd under an unmounted automount is reported missing without probing it (senpi#4565, senpi#7557)

### What changed

- `packages/coding-agent/src/core/session-cwd.ts`: `getMissingSessionCwdIssue` asks `automountTriggerPathSync` before `existsSync`, so a stored cwd under an unmounted automount trigger (a Linux `/home/<user>/...` on a macOS host) is reported missing without a filesystem call.

### Why

- On macOS `/home` is an autofs trigger. A synchronous probe of a path below it can block the host thread in the kernel when the automounter does not answer, which stopped a host from accepting connections (senpi#4565).

### Why an extension could not handle it

- The session cwd check runs in the core session open path before any extension loads.

### Expected merge conflict zones

- LOW: `session-cwd.ts`, the `existsSync` condition in `getMissingSessionCwdIssue`.

## 2026-11-27 - Read path variants skip paths under an unmounted automount (senpi#4565, senpi#7557)

### What changed

- `packages/coding-agent/src/core/tools/path-utils.ts`: the synchronous `fileExists` behind `resolveReadPath` answers `false` for a path under an unmounted automount trigger (`automountTriggerPathSync`) instead of calling `accessSync` on it.

### Why

- `resolveReadPath` runs on the host thread while the permission system parses a `read` call. A synchronous access of a path under a macOS `/home` whose automounter does not answer never returns and stops the whole host (senpi#4565).

### Why an extension could not handle it

- The permission system and the read tool share this resolver; it is core tool code.

### Expected merge conflict zones

- LOW: `path-utils.ts`, the top of `fileExists`.

## 2026-11-27 - The open-free walk stops at an unmounted automount (senpi#4565, senpi#7557)

### What changed

- `packages/coding-agent/src/utils/paths.ts`: `realpathWithoutOpen` / `realpathWithoutOpenStrict` call `refuseUnmountedAutomountPath` before each component's `lstat`. A component under an unmounted automount trigger ends the walk like a missing one (`EAUTOMOUNT` joins `ENOENT`/`ENOTDIR` as a tolerated code): the rest of the path is kept verbatim.

### Why

- The walk avoids `open(2)` but still `lstat`s every component on the host thread; under a macOS `/home` whose automounter does not answer that call can block for good (senpi#4565).

### Why an extension could not handle it

- The walker is a shared utility used by the permission system and the monitor registration on the host thread.

### Expected merge conflict zones

- LOW: `paths.ts`, `resolveWithoutOpen`'s component loop and `MISSING_PATH_CODES`.

### Fixed
- A tool call (a `monitor` or `bash` command, a read, a session open) naming a path under an unmounted automount such as macOS `/home` no longer blocks the rpc host's main thread: the path is answered as not on this machine before any synchronous filesystem call, and automount resolver helpers are deduplicated, capped and not retried for five minutes after one misses its deadline ([#7557](https://github.com/code-yeongyu/senpi/pull/7557), refs [#4565](https://github.com/code-yeongyu/senpi/issues/4565))
