## 2026-11-12 - An experimental server works from a server directory too deep for its own socket (senpi#6522)

### What changed

- `packages/coding-agent/src/experimental/socket-path.ts` (new): `SocketPathTooLongError` (`code: "socket_path_too_long"`, `path`, `bytes`, `limit`) and `createServerEndpoint`, which keeps `<dir>/server-<id>-<nonce>.sock` when it fits `MAX_SOCKET_PATH_BYTES` (103) and otherwise binds `server.sock` in a fresh 0700 `senpi-xs-<8>` directory under the first guarded root (the OS temp directory, this user's `XDG_RUNTIME_DIR`, then `/tmp`), removed when the server closes; the directory records its server's pid and start time in `.owner`, and `reapOrphanedServerEndpoints` removes this user's `senpi-xs-*` directories whose recorded server is gone before a new one is created.
- The `.owner` start time is written and read through one bounded UTC probe (`readEndpointOwnerStartTime`, 5 s), so a server and a later sweep running under different `TZ` values read the same instant and a starved `ps` cannot hold either for long; before this, a sweep could prove a live server dead and remove its endpoint directory, unlinking `server.sock`.
- ONE rule decides the sweep: a record naming a pid holds its directory for as long as that process lives, proved by the recorded start time where there is one and by the pid alone where the probe could not read one (the writer retries it once, and records `null` rather than failing startup); only a directory with no record at all is held on age, for five minutes, while a server could still be writing one. A failure writing `.owner` removes the directory.
- The temp root must be one no other user can take an entry out of (`rootModeIsGuarded`, the bind alias's check), so a world-writable non-sticky `TMPDIR` is skipped.
- An unguarded OS temp directory falls back to `XDG_RUNTIME_DIR` before the shared `/tmp`.
- `packages/coding-agent/src/experimental/server.ts`: `startServer` refuses a public or control socket path over the limit with that error and takes its endpoint (the path it registers with the coordinator) from `createServerEndpoint`; `activateServer` checks both paths before starting a server.

### Why

- A server bound a long endpoint through its short bind-and-link, but connecting to a path over the limit fails with EINVAL, so the coordinator dropped every client and the auto-activated server retired with exit code 0; the client only said the server exited during startup.

### Why an extension could not handle it

- Socket placement is the experimental server's own startup path.

### Expected merge conflict zones

- LOW: the socket path setup in `startServer` and the head of `activateServer`.
