## 2026-11-15 - A relayed hand authority and the reference packet type for hand carriers (senpi#5924)

### What changed

- `packages/agent/src/execution/grant-verify.ts`: `HandAuthority` gains `{ kind: "relayed", peer }`. `authorize()` keeps the call's root for it, as for `self`.
- `packages/agent/src/execution/remote-executor.ts`: a relayed executor presents `peer` to the epoch fence, as a `peer` executor does. `close()` now settles only after every call it aborted has settled, then disposes the scopes.
- `packages/agent/src/index.ts`: exports the `ReferencePacket` type next to `createReliableTransport`, `EPOCH_FLOOR_PREFIX` next to `createHandEpochFence`, and `DurableStoreError` next to the durable store types.

### Why

- `packages/agent/src/execution/grant-verify.ts`: the R3 tool-relay mode (`hand_link`) reaches a hand through a relay that authenticates the sender and decides its execute grant for every batch. The hand must still fence by that sender. A `self` authority fences everyone as `self`, and a `peer` authority needs a grant snapshot the hand does not hold.
- `packages/agent/src/index.ts`: a carrier outside the package (the hand wire codec) decodes into the type the reference transport reads; a retired session's floors are deleted by their document key, so the prefix is not copied; a production embedder recognizes a store's refusal without loading the conformance kit.

### Why an extension could not handle it

- `packages/agent/src/execution/remote-executor.ts`: the sender each fence check sees is decided inside the executor, and only the executor knows when its running calls have settled; an embedder can supply neither from outside.

### Expected merge conflict zones

- LOW: `packages/agent/src/index.ts`, the reliable-transport and epoch-fence export lists.

## 2026-11-15 - The RPC host serves hand_link: a hosted brain's tool calls run on this machine's hand (senpi#5924)

### What changed

- `packages/coding-agent/src/main.ts`: a multi-session RPC host is built with `handLink: createHostHandLink(runtimeConfiguration)`, so it answers `hand_link`. The machine's hand (`createLooplessHand(..., { twoSidedHome: "hand" })`) opens on the first link.

### Why

- `packages/coding-agent/src/main.ts`: R3 tool-relay mode. A hosted brain's every tool and hook runs on the user's machine through the one daemon there (one process per machine), fed from relayed packet batches instead of `hand.sock`.

### Why an extension could not handle it

- `packages/coding-agent/src/main.ts`: the RPC host's options are built only here; an extension cannot add a host-level RPC method or a method class.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/main.ts`, the `hostOptions` object of the multi-session branch.

## 2026-11-15 - hand_link: tool-relay mode with the hand epoch fence (senpi#5924)

### What changed

- `packages/coding-agent/src/modes/rpc/hand-link-endpoint.ts` (new): one link per hosted session, running the same hand engine as `--hand` (`modes/hand/hand-endpoint.ts`). One epoch fence serves the host, and its owner is the delegated connection's principal.
  - **Generation:** `loop.generation` is the session's `RemoteFloor` epoch. A newer generation replaces and tears down the link; an older one is refused; a second sender or loop at the admitted generation is refused.
  - **Ending a link:** a malformed packet or a held scope ends the link, which reopens only at a higher generation.
  - **Answers:** each batch is answered at once, capped at one record; `more: true` says packets still wait.
  - **Link instance:** every answer names the session's link as `instance`, minted when this daemon opens that link. It stays the same within one daemon process and is new after a restart or a new generation, and when it changes the brain resets its hand transport.
  - **Durable state:** the epoch floors, each session's link record and the scope bindings persist, so a restarted daemon resumes a session at its generation.
  - **One admitting daemon:** every daemon under the agent dir shares the state. Every batch first reads the store's owner file, so a daemon another one has claimed the state from refuses it `hand_link_host_superseded`; its owner watch also ends its links between batches (aborting running calls), and its fence admits nothing once superseded. A daemon reopens a session at the generation it reached only when the daemon that opened it there ended it cleanly, after its calls settled; otherwise the brain moves to a higher generation.
  - **Bounded state:** a session holds at most 64 scopes (`hand_link_scope_limit`), and at most 256 sessions hold a live link (`hand_link_session_limit`). A record is compacted seven days after its last write, at the next daemon start: its holder, scopes and floors go, and a tombstone of its lowest generation and closed mark stays.
  - **`instance` in the request:** a batch names the last link instance its brain saw. A batch without one opens a link only where this daemon has none open; any other mismatch is `hand_link_instance_mismatch`.
  - **`close: true`** retires a session: its scope bindings and floors leave the state, and a tombstone refuses later batches `hand_link_session_closed`.
- `packages/coding-agent/src/modes/rpc/hand-link-session.ts` (new): one session's link (transport, packet reader, outbox).
- `packages/coding-agent/src/modes/rpc/hand-link-state.ts` (new): the durable state on one admission line with the fence: claim by this daemon's token, ownership check, fail-closed decoding, retirement.
- `packages/coding-agent/src/modes/rpc/locked-file-store.ts` (new, not hand-link specific): agent-core's memory store over a JSON file that several processes share. Every claim and commit is one read-check-write under `acquireOwnershipSafeLock`. Every write is an exclusive temp file, fsync, rename and directory fsync (`syncDirectory`), and is refused, leaving the file untouched, when the temp file cannot be created. Each claim writes the owner token to `<path>.owner` first; `owner()` reads that small file, retrying transient read errors, and `watchOwnership(token, onLost)` fires once when it names anyone else. `claimFor(token)` is idempotent for the current owner, a superseded owner's commit is refused `stale-epoch`, stale temp files are removed at claim, and a corrupt file fails closed.
- `packages/coding-agent/src/modes/rpc/hand-link-command.ts` (new): the router handler. It needs a delegated connection, and the sender is `principal.deviceId`.
- `packages/coding-agent/src/modes/rpc/method-classes.ts`: a new class `hand_link`, which no other class implies. `delegation-declaration.ts` accepts it in `granted`.
- `packages/coding-agent/src/modes/rpc/delegated-drive-origin.ts`: documents that `hand_link` is not an acting class, so it takes no cross-account ask.
- `packages/coding-agent/src/modes/rpc/rpc-host-command-types.ts`, `rpc-host-response-types.ts`, `method-classes-schema-host.ts`, `session-router-routing.ts`, `session-router-types.ts`, `multi-session-host.ts`, `session-router-close.ts`: the record, its answer and schema, the route, the host option, and the endpoint's close at host dispose.

### Why

- `packages/coding-agent/src/modes/rpc/hand-link-endpoint.ts`: R3 parity. The hosted loop's tools and hooks must run on device B's daemon, fenced by the brain's epoch (senpi#5924).
  - The batch reply never waits for a tool (review LOW-8).
  - Two daemons under one agent dir (a handover, or two endpoints) must never both admit batches, and neither may write over the other's state (review M1); a retried claim must not move the epoch twice (M2); a batch built for an earlier link must not reach a new one (L1).
  - Floors that live only as long as the process refused every session past generation 1 after a restart (`epoch_step_exceeded`: a floor moves one step from 0).
  - A managed peer is never stated same-account (review MEDIUM-5).

### Why an extension could not handle it

- `packages/coding-agent/src/modes/rpc/method-classes.ts`: the method-class table and host routing are the engine's own; a forwarder pins their digest.

### Expected merge conflict zones

- MEDIUM: `packages/coding-agent/src/modes/rpc/method-classes.ts` (the table and its digest), `session-router-routing.ts` (the host dispatch chain).
