## 2026-11-27 - A session's own persona narrows its runtime (senpi#7570, oh-my-openagent#13057)

### What changed

- `packages/coding-agent/src/core/agent-session-runtime.ts`: `AgentSessionLaunchProfile.persona` holds a session's own instructions and tool policy (`open_session.persona`); a session replace keeps it with the rest of the profile.
- `packages/coding-agent/src/core/resource-loader.ts`: `ResourceLoaderOptions.appendSystemPromptText` appends literal text after the resolved `appendSystemPrompt` sources; unlike them it is never read as a file path.

### Why

- A task daemon session needs the instructions and tool limits a per-process child gets from `--append-system-prompt` / `--tools` / `--exclude-tools`; without them an agent's denied tool was callable in a daemon-hosted child (oh-my-openagent#13057). The prompt text comes from a client over the wire, so it must stay text even when it names an existing file.

### Why an extension could not handle it

- The tool set and the appended system prompt are fixed when the runtime is built from the launch profile, before any extension of the session loads.

### Expected merge conflict zones

- LOW: the `AgentSessionLaunchProfile` field list (one field after `retryFallback`); the append-prompt resolution in `DefaultResourceLoader.reload` (one `.concat`).

## 2026-11-27 - The CLI runtime factory applies a session's persona (senpi#7570, oh-my-openagent#13057)

### What changed

- `packages/coding-agent/src/modes/headless/hand-selection.ts` and `headless-host.ts`: a persona session never runs on a hand. `select` to a device is refused with `persona_not_supported_on_hand`, and `restore` of a hand the file recorded installs the unreachable placeholder, because a hand builds its runtime from the scope root alone and its nested calls would run excluded tools.
- `packages/coding-agent/src/main.ts`: refuses `persona.tools` on a host that restricts its built-in tools by default without `--tools` (`persona_tools_unsupported`); the per-session `runtimeParsed` overlay narrows the host's tool flags with the launch profile's persona (`withSessionPersona`: allowlist intersection, denylist union, an empty allowlist means no tools), and the services get the persona's prompt as `appendSystemPromptText`.

### Why

- A multi-session host builds every session from its own argv; a session's persona is the only per-session tool policy, and it may only narrow what the host allows.

### Why an extension could not handle it

- The tool selection and the appended prompt are resolved in the runtime factory, before the session's extensions exist.

### Expected merge conflict zones

- LOW: the `runtimeParsed` spread and the `resourceLoaderOptions` block in `createCliRuntimeFactory`.

## 2026-11-27 - open_session.persona and the session_persona capability (senpi#7570, oh-my-openagent#13057)

### What changed

- `open_session.persona = { appendSystemPrompt?, tools?, excludeTools? }` is validated at the open boundary (`invalid_launch_profile` for a malformed one), held on the launch profile, recorded and replayed by a handover park, applied by the CLI and loopless runtime factories, and advertised as `session_persona`.
- An attach naming another persona is refused (`session_path_in_use`, `persona_mismatch`) in both registries, before the worker registry's binding checks; a `claim_session` naming a persona never takes a session parked without one.
- A persona session never runs on a hand: `select_hand` refuses it with `persona_not_supported_on_hand`, and a reopened file that recorded a hand gets the unreachable placeholder (a hand's runtime never receives the persona, and its nested calls would run excluded tools). A host restricting built-in tools by default refuses `persona.tools` with `persona_tools_unsupported`; padded tool names are refused.

### Why

- oh-my-openagent runs task children as daemon sessions; a child's agent tool policy and instructions must hold there exactly as on a per-child process, and a reused session (attach, claim, successor reopen) must never hand out a wider tool surface than the request asked for.

### Why an extension could not handle it

- The open profile, the attach and claim decisions and the park record are the host's own; no extension sees them before the session exists.

### Expected merge conflict zones

- LOW: `openProperties` in `method-classes-schema-host.ts`, the claim miss list in `session-router-park.ts`, the host capability list in `host-capabilities.ts`.
