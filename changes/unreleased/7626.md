## 2026-11-28 - A retirement read refuses only the identity it cannot settle, and names no host path (senpi#7622)

### What changed

- `packages/coding-agent/src/core/session-retirement.ts`: an id that is not a valid session id is refused with `RetirementFault("retirement_marker_unavailable", { action: "repair_session_header" })` before any marker path is built, instead of an untyped error. `RetirementFault.detail` names the store and marker relative to the agent dir (`retired-sessions`, `retired-sessions/<id>.json`); the absolute path is kept in the host-only `path` field. `recordRetirement` (lock, record, release) is shared by `retireSession` and the RPC close. `describeRetirementFailure` returns what a client may read of a failed retirement and the line the host log keeps. `lockRetirement` is no longer exported.

### Why

- One parked transcript with an invalid header id threw out of the handover restore loop and left every later session closed. Refusals also returned absolute host paths to RPC clients, some of which run on another machine.

### Why an extension could not handle it

- The retirement store is read by the host before any session or extension exists for the identity it decides.

### Expected merge conflict zones

- LOW: `RetirementFault` and `locations` in `session-retirement.ts`.

## 2026-11-28 - Handover restore keeps going past an unreadable identity; retirement refusals name no host path (senpi#7622)

### What changed

- `packages/coding-agent/src/modes/rpc/host-handover-reopen.ts`: a park whose retirement read is refused for that identity is skipped and kept, and the host log names it and the reason once per watch; the other parks are still reopened. A retirement store that cannot be read is logged when it stops the restore.
- `packages/coding-agent/src/modes/rpc/session-router-close.ts`: a `close_session` with `retire: true` whose retirement cannot be recorded answers `retirement_failed` with `errorData.detail` set to the fault code (plus its relative `store` or `marker`), or to `retirement_write_failed`, instead of raw error text. The full error goes to the host log.

### Why

- The restore stopped at the first transcript whose header id names no marker, and raw error text in `errorData` carried absolute host paths to RPC clients.

### Why an extension could not handle it

- Restore runs at host startup, before any session extension is loaded, and the close path builds the RPC answer itself.

### Expected merge conflict zones

- LOW: the per-park `catch` in `reopenHandoverParkedSessions` and the retirement block of `close()`.

### Fixed
- Handover and restart restore no longer stop at a parked transcript whose header id is not a valid session id: that session is kept parked and logged, and the others reopen ([#7626](https://github.com/code-yeongyu/senpi/pull/7626))
