### Added
- Add the session-owned managed-launch foundation for foreground services, with isolated call cancellation and session-end cleanup. On Windows the session and launch Job Objects permit no breakaway, so `CREATE_BREAKAWAY_FROM_JOB` is refused inside them. On macOS and Linux cleanup covers the launch's process group, every process that inherited its marker variable, and their descendants, so a process that starts its own session (`setsid`, Node `detached: true`) is ended too; on macOS a descendant whose environment the kernel hides (Apple platform and hardened-runtime binaries) is found only while one of its owned ancestors is still running. A cancel ends only the launches it finds, so a service restarts under the same key, and a finished launch with nothing left running releases its job and shim. Legacy raw process launches are not migrated ([#4236](https://github.com/code-yeongyu/senpi/pull/4236), part of [#4230](https://github.com/code-yeongyu/senpi/issues/4230); reported by 욜로개발조아 in the KakaoTalk OmO room).

### Fixed
- Cancel an unreleased managed bootstrap without waiting for it to initialize its control-pipe reader ([#4236](https://github.com/code-yeongyu/senpi/pull/4236)).

## 2026-10-25 - Session ownership for explicit managed launches (#4236)

### What changed

- `packages/coding-agent/src/modes/rpc/tool-child/session-launch-supervisor.ts`: keep a session Job Object and nested per-launch jobs on Windows, both without breakaway (`MANAGED_LAUNCH_JOB_LIMITS` in `packages/coding-agent/src/modes/rpc/tool-child/windows-job.ts`); on POSIX stop the launch's marked process tree, then its owned group; seal admission on session end, cancel only the starts and launches in progress for one owner key, reap finished launches with no running members, and let a failed stop or close be retried.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-tree.ts`: select a launch's POSIX processes from one process-table snapshot (leader group, inherited marker variable, ppid descendants) and signal them by exact pid, re-verified by start identity before escalation. The marker is read only from a process's environment: whole `/proc/<pid>/environ` entries on Linux, and on macOS the `ps -E` text after the same process's argv-only snapshot, so a process that merely names the marker in its arguments is never selected.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`, `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-role.ts`, and `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-wire.ts`: hold user execution behind a private control pipe and preserve tree and group cleanup after normal command completion or host loss.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`: actively terminate an unreleased inert bootstrap; after release, its owner stops containment before awaiting shim exit.

### Why

- `packages/coding-agent/src/modes/rpc/tool-child/session-launch-supervisor.ts`: managed foreground services need session ownership rather than a worker generation's cleanup lifetime; a job that permits breakaway lets a member leave it and every job above it.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-tree.ts`: a process group does not contain a descendant that starts its own session, and Playwright starts Chromium that way.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`, `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-role.ts`, and `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-wire.ts`: post-execution PID notification cannot provide before-execution containment admission.

### Why an extension could not handle it

- `packages/coding-agent/src/modes/rpc/tool-child/session-launch-supervisor.ts`: native job handles and process-group identity belong to the runtime owner.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`, `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-role.ts`, and `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-wire.ts`: the engine owns re-entry, the control pipe, and cleanup when the host disappears.

### Expected merge conflict zones

- The new managed-launch modules are fork-only. Existing raw cp/Bun/PTY launch families and the tool-child generation's breakaway flags are unchanged.
