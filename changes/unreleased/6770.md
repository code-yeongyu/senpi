## 2026-11-15 - A held Stop on a hand waits for proof of a running turn, not any call (senpi#5898)

### What changed

- `packages/coding-agent/src/modes/rpc/loopless-loop-hooks.ts`: `TURN_EVIDENCE` classifies every served event by what it proves about the session's turn, and its keys are the only events a hand serves, so a new served event cannot be dispatched until it is classified. `agent_end` is `"ended"`; a real (non-preview) `before_agent_start` and a model request sent mid-turn (`before_provider_request` with `idle: false`, the first a hand sees of a continuation turn) are `"running"`; `input` and `session_start` prove nothing.
- `packages/coding-agent/src/modes/rpc/loop-hook-call.ts`: `LoopHookCallBinding.turn` (`LoopTurnEvidence`) replaces `endsTurn`/`startsTurn`. An `"ended"` call takes its turn state when it starts, so a turn seen running while it still runs wins. Call facts gain `holdIdle` (internal): after the call, `isIdle` tracks the session only for work that holds it, and otherwise keeps the carried value. The `LATE_PER_SESSION` doc names the delay of late effects while the loop is idle (no hand-to-loop push yet, senpi#5778).
- `packages/coding-agent/src/modes/rpc/loop-hook-session-turns.ts` (new): keeps a session only while it can be read: its turn-ending call while it runs, and holds until released. A `"running"` event flips every turn end of the session and forgets it.

### Why

- #6751 review L2 and #6770 review M1: idleness after a turn ended on any call, or only on `before_agent_start`, while continuation turns start with no `before_agent_start`. #6770 review L2: the state was taken after the call, so a turn that started during a slow `agent_end` was lost. #6751 review L3 and #6770 review L1: the per-session state outlived every finished session.

### Why an extension could not handle it

- The loop-hook call and its per-session state belong to the loopless runtime.

### Expected merge conflict zones

- MEDIUM: `TURN_EVIDENCE` and the event branches of `extensionLoopHooks`. Slice 4 (#6766) forwards `agent_start` and `turn_start`; whichever PR lands second must classify both as `"running"` (the typed table refuses them until then).

## 2026-11-15 - An internal idle hold for work that outlives a hand's turn-ending call (senpi#5898)

### What changed

- `packages/coding-agent/src/core/extensions/loop-hook-idle-hold.ts` (new, internal, not extension API): `bindIdleHold` and `holdIdle`, keyed by the context object. Work that outlives an `agent_end` handler on a hand (a Stop held for background work) holds the call's view of whether the loop session is still idle after the turn, and releases it once it settles. Nothing is added to `ExtensionContext`.
- `packages/coding-agent/src/core/extensions/runner.ts`: `LoopHookCallFacts.holdIdle`, registered for a loop-hook call's context with `bindIdleHold`.

### Why

- A hand forgets a session's turn state as soon as nothing can read it (#6770 review L1), and only the work that holds the state knows when it is done. The hold is internal plumbing between the runner and the hooks builtin, so no third-party extension sees or depends on it.

### Why an extension could not handle it

- The context's facts are bound by the runner; an extension cannot reach another extension's call state.

### Expected merge conflict zones

- LOW: the loop-hook call branch of `createContext`.

## 2026-11-15 - A held Stop holds the hand's turn state until it settles (senpi#5898)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/hooks/stop-lifecycle.ts`: an `agent_end` that holds its Stop for background work takes the call's idle hold (`holdIdle(ctx)` from `loop-hook-idle-hold.ts`) and releases it when the held Stop settles: after it ran, or when it is dropped (`agent_start`, `session_shutdown`, or a newer held Stop replacing it). A local session's contexts have no hold, so nothing changes there.

### Why

- #6770 review L1: a hand keeps a finished session's turn state only while a held Stop can still read it.

### Why an extension could not handle it

- The Stop lifecycle is the hooks builtin's own state.

### Expected merge conflict zones

- LOW: `dropPending`, `dispatchPendingIfQuiet` and the held branch of the `agent_end` handler.
