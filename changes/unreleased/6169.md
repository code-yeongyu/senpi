## 2026-11-07 - Session-less MCP status reads get no peer data; server snapshots gain optional session scoping (senpi#3001)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/mcp/service.ts`: `getWireStatusSnapshot()` and `refreshWireStatusSnapshot()` return `{ servers: [] }` to a caller that passes no session id while more than one session is live, instead of the most recently attached session's status; with a single live session the stored snapshot is that session's own, so the id-less read keeps working. `getServerSnapshots(sessionId?)` returns only the servers the named session declares, and `[]` for an unknown id; the no-arg call still lists the merged config of all live sessions.
- `packages/coding-agent/test/suite/regressions/2514-mcp-session-binding.test.ts`: three regression tests for senpi#3001 — the per-owner catalog fence (item 1), no connection created when the service is disposed mid re-sync (item 2), and the no-id peer-data fence plus session-scoped server snapshots (item 3).

### Why

- senpi#3001: `#latestWireStatus` held whichever session captured last, so a caller passing no session id could receive a peer's status, and `getServerSnapshots()` listed the merged config of all live sessions. The per-session status already resolved through the calling session's binding; the id-less reads did not.

### Why an extension could not handle it

- The wire-status snapshot and the server snapshots are produced inside the builtin MCP service's session binding and credential resolution; no extension hook sits between the capture and the caller.

### Expected merge conflict zones

- LOW: the id-less fences in `getWireStatusSnapshot()` / `refreshWireStatusSnapshot()`, the optional `sessionId` parameter on `getServerSnapshots()`, and the three regression tests.
