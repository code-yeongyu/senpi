## 2026-11-02 - Images inside returned or printed eval values are attached, not serialized (omo#12185, PR #5552)

### What changed

- `packages/senpi-codemode/src/kernels/js/value-images.js` (new): `projectValueImages` replaces each image payload inside a plain object or array with `[<mimeType> <size> KB -> attached]` and returns the payloads.
- `packages/senpi-codemode/src/kernels/js/worker-core.js`: a cell's returned value is projected before `valueRepr`, and each payload is emitted as a `display` image frame.
- `packages/senpi-codemode/src/kernels/js/worker-runtime.js`: `print`, `console.log`, `console.error` and the JSON `display` fallback project their values the same way.
- `packages/senpi-codemode/src/kernels/py/prelude.py`: `_project_value_images` does the same for the cell value, for `print` (`_cell_print` in the user namespace) and for the JSON `display` fallback.

### Why

- A `tool.computer()` or `tool.read()` reply returned or printed from a cell was serialized whole, so a screenshot reached the model as ~400 KB of base64 text instead of an image block.

### Why an extension could not handle it

- The serializers live in the codemode kernels themselves.

### Expected merge conflict zones

- LOW: `runCell` in `worker-core.js`, the console wiring in `worker-runtime.js`, `run_cell` and the `USER_NS` helper table in `prelude.py`.
