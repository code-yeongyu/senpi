## 2026-11-05 - snapshot format: links, buttons and fields in document order (senpi#5941)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/webfetch/webfetch/content.ts`: `htmlToSnapshot` lists landmarks, headings, links, buttons and form fields one per line.
- `packages/coding-agent/src/core/extensions/builtin/webfetch/webfetch/content.lazy.ts`: lazy export of `htmlToSnapshot`.
- `packages/coding-agent/src/core/extensions/builtin/webfetch/webfetch/fetcher.ts`: `snapshot` joins `WebfetchFormat` and asks for HTML.
- `packages/coding-agent/src/core/extensions/builtin/webfetch/webfetch/tool.ts`: the `format` enum gains `snapshot` and its description one sentence.

### Why

- Reader-mode markdown drops navigation, buttons and fields, so an agent could not see where a page leads (senpi#5941). Measured with o200k_base on the omowright#33 pages: Hacker News 3,100 tokens vs 5,084 for markdown.

### Why an extension could not handle it

- The format is a parameter of the builtin webfetch tool.

### Expected merge conflict zones

- LOW: the `format` enum and description in `tool.ts`; the fused-equivalence goldens that embed that schema.
