## 2026-11-02 - Clipboard OSC 52 reaches the terminal through the stdout guard and tmux (senpi#3052)

### What changed

- `packages/coding-agent/src/utils/clipboard.ts`: `emitOsc52()` writes through pi-tui's `writeTerminalSequence` instead of `process.stdout.write`. Inside tmux it probes `#{allow-passthrough}|#{set-clipboard}|#{client_termfeatures}` for the current pane through the async clipboard command runner (250 ms budget). With `set-clipboard on` it keeps the raw sequence and appends the `wrapTmuxPassthrough` DCS envelope only when passthrough is allowed and the client lacks the clipboard feature. With `set-clipboard` off or external it sends only the envelope when passthrough is allowed. Disabled passthrough and a failed probe keep raw OSC 52.

### Why

- `packages/coding-agent/src/utils/clipboard.ts`: interactive senpi's `ProcessTerminal` diverts external stdout to the debug log, so `/copy`, selection copy and the todo copy command reported success without reaching the terminal. Inside tmux, raw OSC 52 reaches the outer terminal only with `set-clipboard on` and a clipboard-capable client, while the DCS envelope skips tmux's paste buffer, so the envelope is added only where tmux would not forward the copy itself.

### Why an extension could not handle it

- `packages/coding-agent/src/utils/clipboard.ts`: clipboard transport is a shared host utility used by interactive selection and core commands. Extensions get no hook between the copied text and the terminal write.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/utils/clipboard.ts`: the `@earendil-works/pi-tui` import, `routeOsc52ThroughTmux()`, and the async `emitOsc52()` awaited at both `copyToClipboard` call sites.

## 2026-11-02 - Terminal control sequences bypass the external stdout guard (senpi#3052)

### What changed

- `packages/tui/src/terminal.ts`: new exported `writeTerminalSequence(data)`. While a started `ProcessTerminal` hides external stdout it writes through that terminal's raw stdout writer, otherwise through the current `process.stdout.write`. `installExternalStdoutGuard()` publishes the raw writer and `removeExternalStdoutGuard()` clears it only if it is still that terminal's, so stop, restart and a replacement terminal each route to the current stdout. One guarded terminal at a time is assumed.
- `packages/tui/src/index.ts`: re-exports `writeTerminalSequence`.

### Why

- `packages/tui/src/terminal.ts`: the guard diverted every external `process.stdout.write` to `onExternalStdoutWrite`, including intentional control sequences such as senpi's clipboard OSC 52 write.
- `packages/tui/src/index.ts`: coding-agent reaches the writer through the package barrel.

### Why an extension could not handle it

- `packages/tui/src/terminal.ts`: the guard and its raw writer are private to `ProcessTerminal`.
- `packages/tui/src/index.ts`: package exports cannot be changed by an extension.

### Expected merge conflict zones

- LOW: `packages/tui/src/terminal.ts`: `installExternalStdoutGuard()` / `removeExternalStdoutGuard()` and the new function above `ProcessTerminal`.
- LOW: `packages/tui/src/index.ts`: the terminal export block.
