## 2026-10-27 - Record and predeclare each role's presence object at its resolved local root (desktop#4199)

### What changed

- `crates/senpi-socket-secret`: add `presenceRootOpen`, `presenceObjectCreate` and `localAppDataPath`. A root is created with the owner-only DACL. Its canonical path, volume serial, file ID and locality come from one handle that follows reparse points. An object is created with `FILE_CREATE` relative to a root handle whose recorded identity and `local` classification were checked. It has no delete sharing; its header is written and flushed, then the directory is flushed. An existing name is `exists`, never replaced.
- `packages/coding-agent/src/modes/rpc/socket-secret-native.ts`: `loadPresencePlacement` returns the placement natives on Windows. Otherwise it returns a typed reason (`unsupported_platform`, `native_unavailable`, `native_abi_mismatch`).
- `packages/coding-agent/src/modes/rpc/presence-placement.ts`: resolves the presence root once, predeclares a role's presence object in the recorded root, and verifies the recorded root for issuers and claimants.
- `packages/coding-agent/src/modes/rpc/endpoint-reservation-store.ts`: moves to schema 3. A reservation records its presence root and the owner's kernel session. Each role records its predeclared object. An offer whose object is outside the recorded root is refused with `presence_not_predeclared`. A row whose placement names a placed root or a predeclared object but lacks a column, or names a placement or unavailable reason the schema does not write, is refused with `row_malformed` (review fold): it is unreadable evidence, never a row that recorded no presence.
- `packages/coding-agent/src/modes/rpc/host-launch-reservation.ts`: the supervisor offer and the host offer each predeclare their object before committing. A claimant verifies the recorded root before it claims.
- `packages/coding-agent/src/modes/rpc/host-ensure-start.ts`: resolves the root beside the endpoint lock target before the supervisor offer and spawn.
- `packages/coding-agent/src/modes/rpc/host-lifecycle.ts`: offers the host role through the presence-predeclaring helper.

### Why

- Design 4.2a, "Lifetime object and binding": an offer predeclares its role's presence object before any wrapper spawn, created and flushed before the offer commits.
- Design 4.2a, "Placement.": the reserving owner resolves the root once and records its canonical path, physical identity, classification and its own kernel-session identity. Issuers, participants and probers never re-resolve the root. A participant that reaches a different physical directory fails its claim with a typed error. Without a local root the row records `presence_unavailable`, and startup is not refused for that reason alone.

### Why an extension could not handle it

- Reservation, placement and claim run before extensions load and own native handles, process identity and child launch.

### Expected merge conflict zones

- `packages/coding-agent/src/modes/rpc/endpoint-reservation-store.ts`: schema SQL, `reserve`/`offer` signatures and row mapping.
- `packages/coding-agent/src/modes/rpc/host-launch-reservation.ts`: offer and claim helpers.
- `packages/coding-agent/src/modes/rpc/host-ensure-start.ts`: `reserveSupervisorLaunch`.
- `packages/coding-agent/src/modes/rpc/host-lifecycle.ts`: `offerReservedHost`.
- `packages/coding-agent/src/modes/rpc/socket-secret-native.ts` and `crates/senpi-socket-secret`: native exports and the loader.
