## 2026-11-17 - show_html_page: images are read only from loading contexts, and only model-issued calls hold page budget (senpi#6917)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/html-render/image-references.ts` (new): `findLocalImages` moved here from `images.ts` and now tokenizes the page the way HTML does. `<!-->` and `<!--->` end a comment at once. A quote starts an attribute value only right after `=`. A tag the page never closes is dropped. A path counts as loaded only in `src`, `srcset`, `poster`, `href`/`xlink:href`, `data` and `background` attributes, in `url()` inside a `style` attribute or a `<style>` body, and as a quoted path in a `<script>` body or an `on*` handler. Other attributes, `<xmp>`/`<noscript>`/`<iframe>`/`<noembed>`/`<noframes>` bodies and CDATA sections only show a path.
- `packages/coding-agent/src/core/extensions/builtin/html-render/images.ts`: imports `findLocalImages` and `IMAGE_MIME_TYPES` from `image-references.ts` and keeps the reading and inlining.
- `packages/coding-agent/src/core/extensions/builtin/html-render/tool.ts`: the session's page budget is reserved and counted only when `ctx.issuedByModel` is true. That covers agent-loop calls and Cursor exec-frame calls. Calls from `ctx.executeTool()` and `pi.executeTool()` (`codemode-<uuid>`) no longer keep a reservation.
- `image-references.ts` also reads only the first of a tag's repeated attribute names, as a browser does.

### Why

- senpi#6915 (review LOWs L4-L7 of senpi#6912), and the queue review of senpi#6917 (M1, L1, L2). A Cursor exec-frame call runs while its issuing message is still streaming, so a lookup in saved messages missed it, and the page skipped the session budget although its result joins the transcript. An empty comment hid the next image. An apostrophe in an unquoted value swallowed the rest of the page. A path only shown in `alt`, `title`, `<xmp>`, `<noscript>` or CDATA refused the whole page. Calls from `pi.executeTool()` held budget until the session shut down.

### Why an extension could not handle it

- `show_html_page` and its image inliner are this builtin's own code.

### Expected merge conflict zones

- LOW: `html-render/image-references.ts` (new), the imports of `html-render/images.ts`, and `issuedByModel`/`execute` in `html-render/tool.ts`.

## 2026-11-17 - ExtensionToolContext.issuedByModel (senpi#6917)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ExtensionToolContext` gains `readonly issuedByModel: boolean`. It is true when the model issued the running call, through the agent loop or a provider's exec channel (Cursor). `ExtensionContextActions` gains the optional `isModelIssuedToolCall(toolCallId)` that backs it.
- `packages/coding-agent/src/core/extensions/runner.ts`: `createToolContext` sets `issuedByModel` from the bound `isModelIssuedToolCall`, and is false when no host binds one.

### Why

- senpi#6915 / senpi#6917 review M1. show_html_page must know whether its result joins the transcript, so the page counts against the session's page budget. Only the session knows a call's origin. Looking the id up in saved messages missed Cursor exec-frame calls, which run before their issuing message is saved.

### Why an extension could not handle it

- A tool sees only its call id; the origin of the call is known only to the session that ran it.

### Expected merge conflict zones

- LOW: the end of `ExtensionToolContext` and `ExtensionContextActions` in `types.ts`; the tool-context fields in `runner.ts` (`createToolContext`, the bound-action fields and their assignment).

## 2026-11-17 - The session reports which tool calls the model issued (senpi#6917)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: the session binds `isModelIssuedToolCall` for the extension runner. It is true for an agent-loop call while its issuer is recorded (`_toolCallIssuers`). It is also true for a Cursor exec-frame call from its preflight, which the bridge now calls with `{ execBridge: true }`, to its result (`emitExecBridgeToolResult`) or its block (`_execBridgeToolCalls`).
- `packages/coding-agent/src/core/cursor-exec-bridge-session.ts`: passes `{ execBridge: true }` to the session preflight.

### Why

- senpi#6917 review M1. A Cursor exec-frame call is issued by the model, and its result joins the transcript, but it runs while the issuing message is still streaming. A tool needs the session to tell it so.

### Why an extension could not handle it

- The call's origin is session state; no extension hook sees it.

### Expected merge conflict zones

- LOW: `preflightToolCall`'s options and the head of its body, `emitExecBridgeToolResult`, the `_execBridgeToolCalls` field, and the extension context actions in `agent-session.ts`.
