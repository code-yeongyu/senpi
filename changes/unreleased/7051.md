## 2026-11-19 - Use protocol-aware MCP health checks (senpi#6617)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/mcp/health-probe.ts`: select the health request from the recorded protocol version and validate modern discovery.
- `packages/coding-agent/src/core/extensions/builtin/mcp/health.ts`: use the probe for pre-call validation.
- `packages/coding-agent/src/core/extensions/builtin/mcp/idle.ts`: use the probe for ordinary keep-alive.
- `packages/coding-agent/src/core/extensions/builtin/mcp/shared-connection.ts`: use the probe for shared keep-alive and guard against stale failures and reconnects after authentication becomes required.
- `packages/coding-agent/src/core/extensions/builtin/mcp/modern/request.ts`: expose the recorded modern protocol version.
- `packages/coding-agent/src/core/extensions/builtin/mcp/modern/era.ts`: share the existing discovery result schema with the health probe.

### Why

- MCP `2026-07-28` removed `ping`; treating its method-not-found response as a dead connection caused unnecessary reconnects. Legacy connections still need ping, and unknown future versions must not inherit an assumed probe.

### Why an extension could not handle it

- The builtin MCP client owns protocol negotiation, pre-call validation, and both connection-lifecycle timers; an external extension cannot replace those internal checks.

### Expected merge conflict zones

- MEDIUM: MCP health and lifecycle logic in `health.ts`, `health-probe.ts`, `idle.ts`, and `shared-connection.ts`.
- LOW: protocol-state access in `modern/request.ts` and schema visibility in `modern/era.ts`.
