## 2026-11-22 - Leaving GPT after a reload restores the edit tools (senpi#3838)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/gpt-apply-patch/extension.ts` records which edit tools a GPT swap removed in the session. On a non-GPT model, it removes `apply_patch` and restores only the recorded tools that are still registered.
- `packages/coding-agent/src/core/extensions/builtin/gpt-apply-patch/types.ts` lets the extension use the existing session-entry API.

### Why

- A new extension instance needs to recover which tools the GPT swap removed. An active `apply_patch` alone cannot tell it: lazy activation can add `apply_patch` without replacing any tools.

### Why an extension could not handle it

- The fix is inside the builtin extension that owns the swap.

### Expected merge conflict zones

- LOW: toolset synchronization and session startup in `extension.ts`, and the extension API type in `types.ts`.

### Fixed
- Switching away from GPT restores only the `edit` and `write` tools GPT replaced, even after a reload or resume. Lazy activation of `apply_patch` does not enable those tools when switching models ([#7356](https://github.com/code-yeongyu/senpi/pull/7356)).
