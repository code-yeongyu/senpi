## 2026-11-04 - A session opened over a delegated connection outlives that connection (senpi#5808)

### What changed

- `packages/coding-agent/src/modes/rpc/multi-session-host.ts`: `createHostCore` treats an `open_session` without `retain_on_disconnect` on a delegated connection (`writer.delegations.isDelegated`) as retained, the default a machine-owned host already applies. An explicit `false` is honored, and a connection that never declares is unchanged.

### Why

- Since senpi#5651 a forwarder opens one delegated connection per viewer, and that connection ends when the viewer leaves. The ordinary drop rule (`releaseConnection` -> `releaseDisconnectAttachment`) then closed the session the viewer opened, so the next viewer could not attach (`session_closing`; senpi#5808). The forwarder keeps serving the session, so ending its per-viewer connection now detaches.

### Why an extension could not handle it

- Connection lifetime and `open_session` dispatch belong to the RPC host's per-line handler, which no extension reaches.

### Expected merge conflict zones

- LOW: two lines in `createHostCore`'s `handle`, next to the `machineOwned` default.

### Fixed
