## 2026-10-25 - Shared clipboard transport survives redirection and tmux (senpi#4263)

### What changed

- `packages/tui/src/clipboard.ts`: encode OSC 52 once, wrap for `TMUX`, prefer a per-call controlling tty handle with finally-close, and retain the caller output route when unavailable or on Windows.
- `packages/tui/src/index.ts`: export the shared clipboard transport.
- `packages/tui/src/tui-alt-screen.ts`: use the shared transport for standalone selection copy, preserving the injected clipboard and terminal fallback routes.

### Why

- `packages/tui/src/clipboard.ts`: clipboard escapes must reach the terminal rather than a redirected stdout log.
- `packages/tui/src/index.ts`: the coding-agent and standalone TUI need one transport implementation.
- `packages/tui/src/tui-alt-screen.ts`: the fallback needs the same tmux DCS envelope and tty delivery as the coding-agent.

### Why an extension could not handle it

- `packages/tui/src/clipboard.ts`: terminal I/O and descriptor ownership belong to the TUI package.
- `packages/tui/src/index.ts`: package exports cannot be changed by an extension.
- `packages/tui/src/tui-alt-screen.ts`: the standalone fallback runs without a host-injected clipboard implementation.

### Expected merge conflict zones

- LOW: `packages/tui/src/clipboard.ts`: new clipboard transport.
- LOW: `packages/tui/src/index.ts`: clipboard export.
- LOW: `packages/tui/src/tui-alt-screen.ts`: clipboard import and fallback write.
