## 2026-11-09 - A fresh process's failed cooling probe names the blocked pooled accounts (senpi#5963)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: when an assistant turn fails with an account-scoped usage limit on a pooled provider where no account can serve, the session reads the same pool health the turn-boundary refusal uses and the client projection of that failed message (`message_end`, `agent_end`) appends the accounts sentence. The engine message keeps the provider text.
- `packages/coding-agent/src/core/retry-fallback/usage-limit.ts`: `withAccountsOut` is the one formatter for `No account can serve: ...`; `AccountUsageLimitError` builds its text through it, so the turn-boundary refusal is byte-identical.

### Why

- A fresh process keeps its single cooling probe (senpi#3771). When that probe hit the weekly limit again, the user saw a generic account-limit message naming no account, while a later turn in the same process named every blocked account.

### Why an extension could not handle it

- The surfaced error is the session's own projection of the failed turn's message, and pool health is read inside `AgentSession`; no extension hook rewrites that projection.

### Expected merge conflict zones

- LOW: `agent-session.ts` `_processAgentEvent` just before the `_emit` call, and the assistant projection in `_emit`.
