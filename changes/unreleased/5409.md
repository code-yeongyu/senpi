## 2026-11-02 - Refuse a zero-padded or non-canonical explicit release version (senpi#5406, #5409)

### What changed

- `scripts/calver.mjs`: `assertCanonicalCalVer(version)` returns a canonical CalVer version (`YYYY.M.D` or `YYYY.M.D-N`, kept byte for byte by semver's parser) and otherwise throws `CalVerInputError` with code `CALVER_ZERO_PADDED` or `CALVER_NOT_CANONICAL`, naming the input and the form npm would publish (`2026.11.02-1 -> use 2026.11.2-1`). The CLI exposes it as `--check <version>`, and `computeToday` is exported.
- `scripts/release.mjs`: `--version` is validated while the arguments are parsed, before the pinned `--sha` checkout or any git command. The old explicit-version regex check is gone; auto-compute is unchanged.
- `.github/workflows/publish-npm.yml`: the `require-version` job runs in every mode and refuses a non-canonical explicit version with the dispatch ref's validator, and the `release` job needs it. The input description no longer gives a padded example.

### Why

- npm strips leading zeros, so the input `2026.11.02-1` was published as `2026.11.2-1` while the tag and manifests said `2026.11.02-1`, and consumers that compare versions as strings broke.

### Why an extension could not handle it

- The release script and workflow are repository tooling outside the extension runtime.

### Expected merge conflict zones

- LOW: `parseArgs()` and `resolveVersion()` in `scripts/release.mjs`; the `require-version` job and the `release` job's `needs` in `publish-npm.yml`.
