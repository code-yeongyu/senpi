## 2026-11-17 - getAllTools() marks the session's eval-only tools (senpi#6886)

### What changed

- `packages/coding-agent/src/core/tool-info.ts`: `toolInfosOf(definitions, evalOnly)` replaces the per-entry `toolInfoOf` export; a tool in the given set is projected with `evalOnly: true`.
- `packages/coding-agent/src/core/runtime/active-tools.ts`: `registeredEvalOnlyToolNames(armed, toolRegistry)`, the registered tools the armed eval-only routing withholds (empty while unarmed).
- `packages/coding-agent/src/core/agent-session.ts`: `getAllTools()` projects through `toolInfosOf` with that set, so extensions see which tools a cell alone can reach.

### Why

- tool_search and the eval description need the session's actual eval-only routing (declared `exposure: "eval"`, the fixed by-name set, or an SDK override); only the session knows it.

### Why an extension could not handle it

- The armed eval-only set is session state; extensions read tools only through `pi.getAllTools()`.

### Expected merge conflict zones

- LOW: `getAllTools()` in `agent-session.ts`; the import of `tool-info.ts`.

## 2026-11-17 - ToolInfo.evalOnly (senpi#6886)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ToolInfo.evalOnly?: true`, present while the session routes the tool through eval only.

### Why

- A model that searches for a tool a prompt names must be told it exists and is reachable as `tool.<name>(...)` in a cell.

### Why an extension could not handle it

- `ToolInfo` is the public projection `pi.getAllTools()` returns.

### Expected merge conflict zones

- LOW: the end of the `ToolInfo` type.

## 2026-11-17 - tool_search lists matching eval-only tools (senpi#6886)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/tool-search/service.ts`: `searchEvalOnly(query, limit, options)` ranks the tools `getAllTools()` marks `evalOnly` in an index of their own, so catalog ranking is unchanged and no feeder can activate them.
- `packages/coding-agent/src/core/extensions/builtin/tool-search/extension-document.ts` (new): `extensionDocument`, moved out of `service.ts` so both indexes build the same document.
- `packages/coding-agent/src/core/extensions/builtin/tool-search/tool.ts`: matching eval-only tools get their own section with parameters and `call: tool.<name>({ ... }) inside eval`, and `details.evalOnly`; a tool the query names exactly keeps its redirect hint instead (senpi#1682). The description says eval-only matches are listed separately.

### Why

- tool_search never returned eval-only tools, so a model that could not see a tool a prompt named concluded it was not registered.

### Why an extension could not handle it

- tool_search is this builtin's tool.

### Expected merge conflict zones

- LOW: `execute` and `buildToolSearchResultText` in `tool.ts`; `search` in `service.ts`.

## 2026-11-17 - The eval description names the eval-only tools (senpi#6886)

### What changed

- `packages/senpi-codemode/src/extension/reachable-tools.ts`: `evalOnlyToolNames(pi)` reads `ToolInfo.evalOnly`.
- `packages/senpi-codemode/src/prompt/eval-prompt.ts`, `src/prompt/eval-prompt-template.ts`, `src/tool/eval-tool.ts`, `src/tool/eval-tool-options.ts`: `evalOnlyTools` adds `Eval-only tools (absent from your direct tool list, reachable only here): ...` under the `tool.<name>(args)` prelude entry; the `tool_schema(name?)` entry states the no-name result `{ tools: [every tool name] }`.
- `packages/senpi-codemode/src/index.ts`, `src/extension/kernel-preludes.ts`: `evalDescriptionKey` covers the prelude docs and the eval-only names, so eval re-registers at turn start when either changes.
- `packages/senpi-codemode/src/bridges/schema-bridge.ts`: `EvalSchemaToolInfo.evalOnly`.

### Why

- A host may replace the whole system prompt and drop the session's eval-only paragraph; the eval description is always read. The tool_schema() doc said "list tool names" while the call returns `{ tools: [...] }`, and a caller that took the keys saw only `tools`.

### Why an extension could not handle it

- This is the codemode extension's own description.

### Expected merge conflict zones

- LOW: the `tool.<name>` and `tool_schema` prelude lines of the template; `registerEvalForRuntime` and the `turn_start` handler in `index.ts`.
