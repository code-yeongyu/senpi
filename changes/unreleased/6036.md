### Changed
- On Node.js, senpi no longer opens or creates session state: where a session would open (the CLI after its Bun re-exec attempt, including a multi-session RPC host before it starts, or the SDK's `createAgentSession`), it prints one message that recommends the senpi binary, or Bun 1.4 or newer, and exits non-zero. `--version`, `--help`, `--no-session` and other commands that touch no session keep working on Node. Developers can set `SENPI_SESSION_STORE=jsonl` on Node to keep the legacy JSONL session store ([#6036](https://github.com/code-yeongyu/senpi/pull/6036)).

### Fixed
- Under Bun, the RPC host watchdog now fires when its supervisor's pipe closes; before, it never noticed ([#6036](https://github.com/code-yeongyu/senpi/pull/6036)).

## 2026-11-05 - A Node process gets one steering message where it would open session state (S21b b2, senpi#6036)

### What changed

- `packages/coding-agent/src/main.ts`: `createSessionManager` refuses to open session state on Node (one message, exit 1) unless the `SENPI_SESSION_STORE=jsonl` developer hatch is set. It runs after the Bun re-exec attempt in `cli.ts`, and after the `--no-session`/`--help`/`--list-models` early return.
- `packages/coding-agent/src/main.ts`: the `--mode rpc --multi-session` branch refuses the same way before the host starts, since every session it serves opens session state.

### Why

Plan row S21b (senpi#5822), K9.a: the durable session store exists only on Bun, so a process still on Node must not silently run on a store that does not exist there.

### Why an extension could not handle it

Session state opens before extensions load.

### Expected merge conflict zones

The start of `createSessionManager` and of the multi-session branch in `src/main.ts`.

## 2026-11-05 - The host watchdog reads its inherited pipe under Bun (S21b b2, senpi#6036)

### What changed

- `host-watchdog.ts`: under Bun, `net.Socket({ fd })` never reads the fd, so the watchdog never saw its supervisor's pipe close. It now reads the fd the way `watchHostLifetime` does, with EBADF treated as inactive.

### Why

The RPC host lifecycle tests run under Bun now (S21b, senpi#5822), and Bun is the default runtime. The same pattern in `SupervisorOwner` is senpi#6010.

### Why an extension could not handle it

The RPC host's own lifecycle code.

### Expected merge conflict zones

The fd read in `host-watchdog.ts`.

## 2026-11-05 - The moved-path guard follows a runtime $HOME change on Bun (senpi#5822)

### What changed

- `packages/coding-agent/src/utils/user-home.ts` (new): `userHomeDir()` answers like Node's `os.homedir()` on every call: `$HOME` (`USERPROFILE` on Windows) when set and non-empty, else the account's home.
- `packages/coding-agent/src/core/extensions/builtin/moved-path-guard/{walk,known-moves,resolve,resolve-async,command-paths}.ts`: the guard's home spellings, legacy roots, `~` expansion and walk stop read `userHomeDir()` instead of `os.homedir()`.

### Why

- Bun's `os.homedir()` keeps the home it read at startup and ignores a later `process.env.HOME` change; Node's re-reads the variable (measured on Linux, Bun 1.4.4 vs Node 26). The guard documents that its home follows `$HOME`, so under Bun a host that changes the variable (an embedding host, the test harness) had its breadcrumb ignored as "movedTo is outside the user's home", moved sessions were not found by `--continue` or the picker, and schedule delivery failed with "working directory no longer exists".

### Why an extension could not handle it

- The guard is a builtin extension; its home resolution is internal to it.

### Expected merge conflict zones

- LOW: the `userHomeDir` imports and call sites in the five guard files.

## 2026-11-05 - The SDK default-store open refuses Node unless the JSONL hatch is set; session rows tie-break by path on every runtime (S21b b2, senpi#6036)

### What changed

- New `session-store/node-guard.ts`: the steering message, the `SENPI_SESSION_STORE` hatch (read on Node only) and `exitUnlessSessionStateAvailable()`, the CLI's one refusal exit.
- `session-store/default-binding.ts`: on Node, binding a persisted session throws the steering message unless the hatch is set (then the legacy JSONL store is used).
- `packages/coding-agent/src/core/session-discovery.ts`: new `newestActivityFirst` comparator, used by `sortSessionInfos`: newest activity first, and rows with the same activity time ordered by path.
- `packages/coding-agent/src/core/moved-sessions.ts`: the moved-here, moved and merged listings sort with the same `newestActivityFirst` instead of a local comparator without a tie-break.

### Why

Plan row S21b (senpi#5822), K9.a: the SDK path must refuse Node the same way the CLI does.
- Sessions written back to back share a millisecond almost always (measured 192/200 under Bun, 196/200 under Node), so the activity time ties and the stable sort kept the directory's listing order. Node's `readdir` returns names sorted (libuv sorts its scandir result) while Bun's returns the filesystem's own order (on ext4 `own,moved` 200/200 under Bun vs `moved,own` 200/200 under Node), so the picker listed the same sessions in a different order on Bun. Ordering ties by path gives Node's order on both runtimes.

### Why an extension could not handle it

The binding runs inside `createAgentSession`, before extensions load.
- Session listing and its order are core session-manager behavior that the picker, `--resume` and RPC read before any extension can intervene.

### Expected merge conflict zones

`bindDefaultSessionStore` in `session-store/default-binding.ts`.
- LOW: `sortSessionInfos` and the new `newestActivityFirst` in `session-discovery.ts`; the sort calls in `moved-sessions.ts`.

## 2026-11-05 - A coding-agent CI job runs the Bun-hosted test files under Bun (S21b b2, senpi#6036)

### What changed

- `.github/workflows/ci.yml`: new job `test-coding-agent-bun` ("Test (coding-agent on Bun)") runs `bun --bun vitest run` in `packages/coding-agent`, which runs exactly the files in `test/bun-hosted-tests.ts`; the `check-and-test` fan-in requires it.

### Why

Plan row S21b (senpi#5822): files that open persisted session state or start the CLI as a child need the durable store, which exists only on Bun, so they run under Bun and the Node shards leave them out.

### Why an extension could not handle it

CI workflow configuration.

### Expected merge conflict zones

The job list and the `check-and-test` needs list in `ci.yml`.
