## 2026-11-10 - The attachment gate refuses unattached session commands by default (senpi#6245)

### What changed

- `packages/coding-agent/src/modes/rpc/session-attachment-gate.ts`: `attachmentGate` answers every non-exempt session command from a connection that holds no attachment with the typed `session_not_attached` refusal (`errorData.reason` + `errorData.action`). The one-release grace that served the command and wrote one stderr line is gone, and `SENPI_RPC_REQUIRE_ATTACH` is no longer read, so no value re-opens the path. The exempt list, the existing carve-outs (`close_session`, `set_session_context`, `release_attachment`, RULING-96 recovery-page authority), session-less commands and the connection-less single-session handler are unchanged.

### Why

- A same-uid process that could open a host's socket could prompt, steer, abort or release any session it listed without attaching, with a `clientMessageId` it chose. Cross-device reply routing carries its route in `clientMessageId`, so a forged id became a forged reply route (senpi#6245, the follow-up to senpi#3795). Every known caller already attaches before a session mutation, so the deprecation that shipped with senpi#3814 can end.

### Why an extension could not handle it

- The gate runs in the RPC router before lifecycle routing and worker dispatch; an extension sees a command only after the router has admitted it.

### Expected merge conflict zones

- LOW: the tail of `attachmentGate` (the grace branch it replaces) and the removed `logSafe` helper above it.

## 2026-11-10 - Tests and RPC docs follow the enforced attachment gate (senpi#6245)

### What changed

- `packages/coding-agent/docs/rpc.md`: the attach sections drop the "this release serves and logs" wording and name `session_not_attached` as the answer to every unattached session command.
- `packages/coding-agent/test/suite/regressions/6245-unattached-prompt-refused.test.ts` (new): an unattached `prompt` (plain and steer), `steer` and `follow_up` with a crafted `clientMessageId` are refused with no switch and with `SENPI_RPC_REQUIRE_ATTACH=0`, and no record carries the forged id.
- Tests that pinned grace assert the refusal instead, and tests whose callers sent from an unattached connection now attach first so each still proves its own refusal (`secret_answer_refused`, `hold_input_requires_interactive_client`, `session_busy`, `feature_disabled`, dialog origin, `extension_ui_progress` reply).

### Why

- The suites encoded the grace behavior; with enforcement on by default they must exercise attached callers, as every production caller already is.

### Why an extension could not handle it

- These are the core RPC host's own tests and protocol docs.

### Expected merge conflict zones

- LOW: the touched test setup lines and the attach paragraphs of `docs/rpc.md`.

### Breaking Changes
- The RPC host refuses every session command (`prompt`, `steer`, `follow_up`, `abort`, `resume_session`, ...) from a connection that is not attached to that session with `session_not_attached`; attach first with `attach_session` or `open_session { sessionPath }`. `SENPI_RPC_REQUIRE_ATTACH` is removed: the grace that served and logged these commands has ended ([#6311](https://github.com/code-yeongyu/senpi/pull/6311))
