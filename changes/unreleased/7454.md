## 2026-11-25 - A host restart does not re-run a run that ended on a provider error (senpi#7449)

### What changed

- `packages/coding-agent/src/core/host-restart-continuation.ts`: `restartVerdict` reads the stop reason of the newest model response in the engine-started run. When that response ended with `stopReason: "error"` (a provider 429 `rate_limit_error`, for example), the run is not continued: the interrupted-run hold stays, and `restartHoldData()` names it with the new `RestartHoldReason` `ended_on_provider_error`. A run the restart cut (aborted, or mid-tool) still continues under the senpi#7020 / senpi#7079 rules, including `RESTART_CONTINUATION_LIMIT`.

### Why

- An RPC host stopped itself on idle, and the next host start continued every session whose last engine-started run was unfinished. Thirty-one of those turns had already ended on their own with a provider 429, so within about 2 s each one sent another request into the same limit. The restart had not cut those runs, so it has nothing to continue.

### Why an extension could not handle it

- The restart decision runs inside `AgentSession` while a reopened session binds, before any extension can see a turn.

### Expected merge conflict zones

- LOW: the backward walk in `restartVerdict` and the `RestartHoldReason` union in `host-restart-continuation.ts`.

### Fixed
- A host restart no longer re-runs sessions whose last turn ended on a provider error such as a 429 rate limit; those sessions stay paused with the reason `ended_on_provider_error` until resumed ([#7454](https://github.com/code-yeongyu/senpi/pull/7454)).
