## 2026-10-28 - A gateway upstream's billing hold no longer blocks the whole provider, and a served response releases it (senpi#4577)

### What changed

- `packages/coding-agent/src/core/retry-fallback/upstream.ts` (new, fork-only): `modelUpstream` and `failureUpstream` name the vendor behind a model id and the one vendor a failure text names.
- `packages/coding-agent/src/core/retry-fallback/unusable.ts`: an account-scoped failure naming the failing model's vendor, on a provider that also serves another vendor's models, is held as `upstream:<provider>:<vendor>`; other account-scoped failures keep the `account:<provider>` hold. New `isSpent(model)`, `spentError(model)`, `scope(model, errorMessage)` and `noteServed(model)`, which releases the provider's account hold, the served model's upstream hold and its exhaustion mark. The constructor takes the candidate registry.
- `packages/coding-agent/src/core/retry-fallback/controller.ts`: `noteServed` feeds the reconciliation; the walk reports an upstream hold as `limit: "model"`; `isSpent` / `spentError` replace `accountError`.
- `packages/coding-agent/src/core/retry-fallback/candidates.ts`: the `isProviderSpent(provider)` filter becomes the model-aware `isSpent(selector)`.
- `packages/coding-agent/src/core/agent-session.ts`: `_resolveCompactionModel` and the prompt turn-boundary spent check read `isSpent(model)` / `spentError(model)`.

### Why

- A billing error from one upstream behind a gateway held every route of that gateway, skipped its same-provider fallback rung, and kept refusing compaction after the same provider served the session again (senpi#4577, code-yeongyu/oh-my-openagent#11569).

### Why an extension could not handle it

- The holds live in the core retry-fallback controller, which compaction model selection and the fallback ladder consult before any extension runs.

### Expected merge conflict zones

- LOW: `UnusableEntries` in `retry-fallback/unusable.ts` and `noteServed` / `walkFallback` / `nextCandidate` in `retry-fallback/controller.ts` (fork-only files).
- LOW: the `usable` predicate and the spent-account throw in `_resolveCompactionModel`, and the turn-boundary spent check in `_prompt`, in `agent-session.ts`.

### Fixed
- A billing or usage-limit error from one upstream behind a gateway provider no longer marks the whole provider spent: the gateway's other routes stay available as fallbacks, and once the provider serves the session again compaction and fallback recover ([#4584](https://github.com/code-yeongyu/senpi/pull/4584))
