## 2026-11-01 - Kill guard judge exported for the codemode bridge and workers (senpi#5349, PR #5354)

### What changed

- `packages/coding-agent/src/index.ts`: exports `decideKillGuardRequest`, `KILL_GUARD_TAG`, `KILL_GUARD_MODULE_URL`, `killGuardProtectedPids`, `readKillGuardSetting` and the `KillGuardRequest`, `KillGuardVerdict`, `KillGuardSetting` types from the new `core/kill-guard/` module.

### Why

- The codemode extension decides Python kernels' kill-guard checks on the host, exports the protected pids to its kernels, reads the user switch, and hands its JS workers the judge module's URL; all of it comes from the coding agent so there is one judge.

### Why an extension could not handle it

- The bundled codemode extension reaches the coding agent only through the package root (`@code-yeongyu/senpi`); the judge must live in the coding agent because its own `tool_call` guard and durable-monitor restore use it too.

### Expected merge conflict zones

- LOW: the export list next to `createEventBus` in `src/index.ts`.

## 2026-11-01 - Kill guard judge embedded in the compiled binary (senpi#5349, PR #5354)

### What changed

- `packages/coding-agent/package.json`: `build:binary` adds `./src/core/kill-guard/index.ts` as an explicit `bun build --compile` entry.

### Why

- Codemode workers import the kill guard's judge by URL; in the compiled binary that module has to be an embedded entry under its source path.

### Why an extension could not handle it

- The compile entry list is the package's own build script.

### Expected merge conflict zones

- LOW: the `bun build --compile` entry list in `build:binary`.

## 2026-11-01 - Kill guard judge shipped as its own module in every layout (senpi#5349, PR #5354)

### What changed

- `scripts/build-coding-agent-bundle.mjs`: the build fails when the judge (`kill-guard.js`, emitted by a new `kill-guard` lazy entry in `scripts/bundle-entry-points.mjs`) and the chunk `core/kill-guard/host.js` lands in are in different directories.
- `scripts/build-binaries.sh`: both release `bun build --compile` commands embed `./src/core/kill-guard/index.ts`.
- `scripts/create-source-archive.sh`: the source archive requires `packages/coding-agent/src/core/kill-guard/index.ts`.

### Why

- A codemode worker cannot resolve the `@code-yeongyu/senpi` peer specifier in every layout, so the host hands it a URL to the judge's own file, which must exist in the npm bundle, the compiled binary and the source archive.

### Why an extension could not handle it

- These are the release build scripts themselves.

### Expected merge conflict zones

- LOW: `lazyEntryPoints` in `scripts/bundle-entry-points.mjs`, the path-identity directory check in `buildBundle`, the two compile lines and the required-path list.

### Added
- Kill guard: an agent command, `monitor`, `bash_input` text once a line of it is submitted (Enter, a line break in the text, or a later `enter` key), read as the shell's line editor builds it across calls and reloads (cursor keys, ctrl+u/ctrl+k/ctrl+w and ctrl+y yanks; a line sent with any byte other than printable text and backspace, or with a named key other than enter, is refused when its bytes, plus the text killed earlier in the session when the line yanks, hold the letters of `kill` in any order or a tab followed a kill-family prefix; ctrl+c drops the line's record; a line ending in a backslash is judged together with the line that completes it; a line recalled from history or that bash would history-expand (`!` events, a leading `^`, `fc`) is refused unjudged, and so is a line edited with any other key the guard does not model (vi-mode keys, unmodelled meta keys, unknown escapes; tab keeps the kill-prefix rule), a line that changes key bindings, history or aliases (`bind`, `set -o vi`/`emacs`, `set -H`, an assignment to `histchars` or `HISTFILE`, `shopt` with a `hist*` option, `history -r`/`-n`/`-s`/`-a`, an `alias` definition, `fc` in any spelling), a line whose command word comes from an expansion or ANSI-C quoting, and an unparsable line naming one of those commands or a kill-family one), `tool.bash` call or restored durable monitor that would signal every process (`kill -1`, a `pkill` pattern such as `a||b`, `.*` or a single letter), a protected process (pid 1, the agent, its ancestors, the user's service manager) or a process group holding one, including behind `busybox` and `env -S`/`--split-string`, is refused before it runs, with a `[senpi:kill-guard]` message naming the rule and a narrow alternative; `terminal.killGuard: "off"` in user settings turns it off ([#5354](https://github.com/code-yeongyu/senpi/pull/5354))
