## 2026-10-28 - Tools added during a compaction no longer cancel it (senpi#4706)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_claimCompactionController()` records the active tool names when a compaction claim is taken (`compaction-tool-baseline.ts`). While that claim is live, `setActiveToolsByName()` calls `abortCompaction()` and `_incrementMessageRevision()` only when the change revokes a tool from that baseline; a change that only adds tools, or adds and then drops a tool the compaction did not start with, leaves the compaction and the context revision alone. With no live claim every active-tool change still aborts and bumps the revision, and binding-time changes stay exempt as before.

### Why

- MCP servers finish connecting after startup, outside the extension-binding window, and every server's tool registration changed the active set. A manual compaction sent right after startup was cancelled once per server that connected while it ran (`aborted`, `aborted`, `committed` on the third try) (#4706).
- A summary is prepared against the active tool set, so it goes stale only when a tool that set held is revoked. A tool added mid-compaction is absent from the history being summarized.

### Why an extension could not handle it

- The abort and the revision bump happen inside core `setActiveToolsByName()`, which every tool-registration path (MCP connect, `tool_search` promotion, `pi.setActiveTools()`) reaches; an extension cannot tell core that a change is additive.

### Expected merge conflict zones

- LOW: the `activeToolNamesChanged` block in `setActiveToolsByName()` and the tail of `_claimCompactionController()` in `agent-session.ts`.

### Fixed
