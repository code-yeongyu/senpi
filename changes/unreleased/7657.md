## 2026-11-28 - Extensions get the host's own instance of every library subpath (senpi#7657)

### What changed

- `packages/coding-agent/src/core/extensions/senpi-subpath-modules.ts` (new): `SENPI_SUBPATH_MODULES`, the host's namespace for every `@code-yeongyu/senpi/<subpath>` library export (`engine`, `engine-trust`, `mcp-env-grants`, `pending-input`, `presenter-authority`, `private-fds`, `prompt-presets`, `session-worker-data`, `subscription-egress`, `tools-core`). The programs `rpc-entry`, `program-resume-startup` and `bun-runtime`, and the unpublished `client`, are not listed.
- `packages/coding-agent/src/core/extensions/loader.ts`: `VIRTUAL_MODULES` spreads `SENPI_SUBPATH_MODULES` in place of its single `session-worker-data` entry.

### Why

- Inside a bundled or compiled senpi, an extension importing any other subpath resolved the package's per-file `dist/` copy. On an installed 2026.11.28-1, an extension importing the library subpaths made the bundled Node CLI read 2070 per-file modules, a second engine graph with its own module state and classes beside the bundle's.

### Why an extension could not handle it

- Which module instance an extension import resolves to is decided by the loader's virtual-module table.

### Expected merge conflict zones

- LOW: the end of the `VIRTUAL_MODULES` table and the import block of `loader.ts`.

## 2026-11-28 - The release bundle emits an entry for every exports subpath (senpi#7657)

### What changed

- `scripts/bundle-entry-points.mjs`: `exportEntryPoints()` reads the coding-agent manifest's `exports` and returns one entry per subpath, named for it (`.` is `index`), built from the compiled file its `import` condition names. `bundleRequiredInputs()` lists them in place of the hand-written `index`, `rpc-entry` and `client` inputs.
- `scripts/build-coding-agent-bundle.mjs`: the main split build takes `cli` plus every export entry, so each subpath shares the CLI's module instances. The plugin that empties `bun/runtime-modules` for Node no longer applies to that module's own entry, so `dist/bundle/bun-runtime.js` keeps its real contents.
- `scripts/node-bundle-smoke.test.ts`: under Node and Bun, an extension importing every library subpath gets, export for export, the running bundle's own entry for it.

### Why

- First stage (S2a) of shipping one copy of the code: the bundle must serve every subpath before `exports` can point at it. `exports` and the per-file tree stay unchanged in this stage.

### Why an extension could not handle it

- The bundle layout is release build tooling.

### Expected merge conflict zones

- LOW: the main `build()` call's `entryPoints` and `bunRuntimeModulesPlugin` in `build-coding-agent-bundle.mjs`; `bundleRequiredInputs()`.
