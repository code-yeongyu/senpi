## 2026-11-22 - A bash run with no output hands eval callers empty text (senpi#7209)

### What changed

- `packages/senpi-codemode/src/tool/tool-result-marshal.ts`: `marshalToolResult` leaves `audience: "model"` text parts out of `.text`, as `render-result.ts` already does.

### Why

- `tool.bash({ command: "true" }).text` was the literal `"(no output)"`, so eval code could not tell empty output from that text and `if (out)` guards misfired.

### Why an extension could not handle it

- The marshal is this extension's own boundary between a host tool result and the value a cell receives.

### Expected merge conflict zones

- LOW: the text-part filter at the top of `marshalToolResult`.

## 2026-11-22 - The bash empty-output placeholder is model-only (senpi#7209)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/tools/bash.ts` and `packages/coding-agent/src/core/tools/shell-output.ts`: a run with no output returns `(no output)` as a `modelOnlyText` part instead of visible text.

### Why

- The placeholder exists because providers need a non-empty block; it is not output, and programmatic callers (eval's `tool.bash`) must see empty text.

### Why an extension could not handle it

- Both bash tools build their own result content; the audience of a part is set where it is created.

### Expected merge conflict zones

- LOW: the success return of the PTY bash foreground run and `formatOutput` in shell-output.
