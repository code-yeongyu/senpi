## 2026-11-12 - The bundle's stale zod allowance is placed on the Claude SDK's exact chunk (senpi#6514 follow-up)

### What changed

- `scripts/bundle-zod-core-guard.mjs`: `sdkSourceOutputs` names the bundle outputs whose esbuild metafile inputs include the vendored `@anthropic-ai/claude-agent-sdk` `sdk.mjs`, and `assertBundleZodCores(bundleDir, sdkOutputs)` counts the allowed stale copies per exact file instead of summing them across every file a name pattern matches. Each allowed name (`chunks/sdk-*.js`, `chunks/session-worker.js`) must match exactly one SDK output and every SDK output must match one; any stale copy in another file, including another `chunks/sdk-*.js`, fails.
- `scripts/build-coding-agent-bundle.mjs`: passes the outputs derived from its own metafiles to the scan; the main graph's options move into the exported `mainBuildOptions()`.
- `scripts/bundle-zod-core-guard.test.mjs`, `scripts/build-coding-agent-bundle.test.mjs`: the SDK's copies moved into the unrelated `sdk-*` chunk now fail; the real-bundle test rebuilds the graph in memory and checks the report names the SDK's exact chunk.

### Why

- The real build emits an unrelated `chunks/sdk-*.js` beside the SDK's chunk, so the pattern matched both and the count was summed: a stale copy could move from the SDK's chunk into the other one without failing the scan.

### Why an extension could not handle it

- The release build scripts are core.

### Expected merge conflict zones

- LOW: `assertBundleZodCores` and the guard call in `buildBundle`.
