## 2026-11-22 - A 408 or a reset connection retries on the same model (senpi#3251)

### What changed

- `packages/ai/src/utils/retry.ts` and `packages/ai/src/utils/retry-profile/classifiers.ts`: retry classification prefers the structured HTTP status for 408. For legacy Mistral errors, it reads only the anchored `Mistral API error (NNN):` prefix for the 408 signal. Other legacy errors retain their existing status and reason-phrase rules. `ECONNRESET` remains retryable.

### Why

- An empty-body gateway 408 and a reset socket can recover on the same model. An HTTP 400 that merely mentions 408 should still take the hard-error fallback path without spending a same-model retry.

### Why an extension could not handle it

- Retry classification lives in pi-ai.

### Expected merge conflict zones

- LOW: provider error classification in `retry.ts` and the default retry profile's call to it.

## 2026-11-22 - Preserve Mistral HTTP status in provider diagnostics (senpi#3251)

### What changed

- `packages/ai/src/api/mistral-conversations.ts`: attaches the response status to the HTTP error with the shared diagnostic carrier and copies it to the terminal assistant message without changing the displayed error.

### Why

- The response status distinguishes an actual 408 from a 400 whose body quotes one.

### Why an extension could not handle it

- The adapter sees the HTTP response before turning the failure into an assistant message.

### Expected merge conflict zones

- LOW: the non-OK response and stream catch in `packages/ai/src/api/mistral-conversations.ts`.

## 2026-11-22 - Document structured status in retry decisions (senpi#3251)

### What changed

- `packages/ai/src/provider-diagnostic.ts`: the contract now states that a structured 408 makes an otherwise non-terminal failure eligible for same-model retry. The SDK guide documents the same behavior.

### Why

- The diagnostic preserves the status used by the existing retry policy; it no longer serves only as descriptive metadata.

### Why an extension could not handle it

- The contract belongs with the shared `ProviderDiagnostic` type in `packages/ai/src/provider-diagnostic.ts`.

### Expected merge conflict zones

- LOW: the type documentation in `packages/ai/src/provider-diagnostic.ts`.
