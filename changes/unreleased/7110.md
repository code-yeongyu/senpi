## 2026-11-20 - gpt-6.2 core, second edition: goal first, plan after reading, the core owns the todo rules (#7110, senpi#7101)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/prompt-preset/gpt-6.2-rules.ts` (new): the rule table moves out of `gpt-6.2.ts` and is rewritten. 37 rules in nine sections: Intent Gate, Goal and plan, Understand first, Keep going, When to involve the user, Code, Done means verified, Reporting, Limits.
- What the core says now that it did not: work out the situation behind a request before acting (what it points at, memory, the instruction files, the conversation); open with what the user wants and what it is for, once per request, after the first look when the meaning sits in what the request points at (the "I read this as" line on the terminal, plain sentences on the app surface, none in chat); that understanding is the goal, and a registered goal is written from it; work larger than a few tool calls is planned in the todo tool one action per item, and the list is kept true (the tool keeps one item in progress, so the rule describes a cursor); what the user names is read in full by the session, and a subagent takes a side task only when asked for or when the session can state it because it has looked; reports are tied to events (an item closes, a finding, a decision of the session's own, an obstacle) and an update never ends the turn; the user's instruction files count as standing authorization for commits and the other gated actions.
- Asking and choosing no longer overlap: the session asks when the outcome itself is unclear and the candidates call for materially different work, and chooses, as this user would, when the outcome is clear and only the way to it is open. A continuation prompt, reminder or notification the harness injects is not a new request.
- `packages/coding-agent/src/core/extensions/builtin/prompt-preset/gpt-6.2.ts`: renders the table and carries the design note.
- `packages/coding-agent/src/core/extensions/builtin/prompt-preset/contract.ts`: `presetFirstTurnPlanDefault` (`off` for every GPT preset, `force` otherwise) and `presetOwnsTodoRules` (`gpt-6.2`).
- `test/suite/prompt-presets-contract.test.ts`, `test/suite/prompt-presets-gpt-6-2.test.ts`: the default per preset; the rule-table checks import the new module. `test/suite/prompt-presets-native-baseline.json`: the six `gpt-6.2` rows are recaptured. No other hash changes.
- `.agents/skills/senpi-qa/scripts/scenarios/first-turn-plan-preset-qa.mjs` (new): drives the real CLI in RPC mode against the fake model server and asserts the first request per preset (forced `tool_choice`, the hidden reminder, `Task_Management`, the 6.2 sections and opener per surface).

Token count of the rendered core (`o200k_base`; section headings plus every rule the surface renders with every tool present, no tool guidelines):

| Surface | before | after |
|---|---|---|
| terminal | 1,558 | 2,117 |
| app | 1,613 | 2,192 |
| chat | 1,597 | 2,092 |

A GPT-6.2 session no longer receives the first-turn reminder (108 tokens) or `Task_Management` (76 tokens).

### Why

- senpi#7101: nine GPT-6.2 sessions from one day wrote a todo list, and often registered a goal, before reading what the request pointed at; lists went stale for more than a hundred tool calls; 12 to 20 percent of turns carried text for the user; "read it all" was done through filtered slices. The first 6.2 core left the goal, the todo list and delegation to tool descriptions and shared blocks that disagree with each other.

### Why an extension could not handle it

- Preset resolution and the cores are this builtin's own code.

### Expected merge conflict zones

- Fork-only files. The rule table moved to a new file, so an open change to the rules in `gpt-6.2.ts` conflicts as a whole.

## 2026-11-20 - The first-turn plan default follows the prompt preset (#7110, senpi#7101)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/todotools/index.ts`: an unset `todo.firstTurnPlan` resolves through `presetFirstTurnPlanDefault` of the active preset (`off` under a GPT preset, `force` elsewhere); a value the user set still wins. `Task_Management` is not appended after a preset listed in `presetOwnsTodoRules` (`gpt-6.2`).
- `packages/coding-agent/test/suite/todo-first-turn.test.ts`, `todo-first-turn-harness.ts`: the opener per model id and setting, and the system prompt after each preset.

### Why

- The opener made GPT sessions write a list before they had read anything: the first tool call was `todo` `init` in 9 of 9 measured sessions (senpi#7101). The 6.2 core now states the todo rules itself, so a second copy after it would be a second home for the same rule.

### Why an extension could not handle it

- The opener and the appended block live inside the todotools builtin.

### Expected merge conflict zones

- LOW: the `before_agent_start` handler in `index.ts`.

## 2026-11-20 - `getTodoFirstTurnPlan` takes the preset's default (#7110, senpi#7101)

### What changed

- `packages/coding-agent/src/core/settings-manager.ts`: `getTodoFirstTurnPlan(fallback = "force")` returns the configured `force`, `remind` or `off`, and `fallback` when the setting is absent or invalid.
- `packages/coding-agent/src/core/settings-shapes.ts`: the `firstTurnPlan` comment names the per-preset default.

### Why

- The default now depends on the active prompt preset, which the settings manager does not know; the caller passes it.

### Why an extension could not handle it

- The settings accessor is core code that the builtin calls.

### Expected merge conflict zones

- LOW: one accessor in `settings-manager.ts`.

### Changed
- GPT models no longer open a session with a forced todo list: `todo.firstTurnPlan` defaults to `off` under a GPT prompt preset, and a value you set still wins ([#7110](https://github.com/code-yeongyu/senpi/pull/7110))
