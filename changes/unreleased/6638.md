## 2026-11-13 - A release refuses a publish-set package the npm registry does not know (senpi#6636)

### What changed

- `scripts/npm-registry.mjs`: `assertRegistryPackagesKnown(names, lookup)` asks the registry about every value of `registryPackageNames` (`npm view <name> name` by default) and throws one error that lists every unknown name and the two manual first-publish steps. A registry failure other than a 404 propagates from the lookup, so it is never read as known or unknown. Run directly (`node scripts/npm-registry.mjs`), the module performs that check and exits 1 on an unknown name.
- `scripts/release.mjs`: calls it first, before the pinned build, the catalog regeneration, the forced suite and any commit, tag or push; `--dry-run` runs it too.
- `scripts/publish.mjs`: calls it right after the publish arguments are resolved, before any package is staged, packed or published.

### Why

- npm trusted publishing cannot do a package's first publish. A release that reached `npm publish` with an unknown name published part of the set and stopped there, after the tag was pushed (senpi#6636, senpi#5784).

### Why an extension could not handle it

- Release and publish tooling is not an extension surface.

### Expected merge conflict zones

- LOW: the first lines of `main()` in `release.mjs`, the line after `publishArgs` in `publish.mjs`, and the end of `npm-registry.mjs`.

## 2026-11-13 - CI checks the publish set against the npm registry (senpi#6636)

### What changed

- `.github/workflows/registry-packages-published.yml` (new): on a PR that changes `scripts/registry-packages.mjs`, `scripts/npm-registry.mjs` or the workflow, and on main, runs `node scripts/npm-registry.mjs` and fails while a publish-set name is unknown to the npm registry.

### Why

- A PR that adds a package to the publish set should see the missing first publish at review time, not at the next release's publish step (senpi#6636).

### Why an extension could not handle it

- CI configuration is not an extension surface.

### Expected merge conflict zones

- None: the workflow is new.
