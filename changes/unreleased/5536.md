## 2026-11-02 - The ambient lane never hands Claude Code the host API key (senpi#1195)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/auth-environment.ts`: `stripAmbientApiKey` drops `ANTHROPIC_API_KEY` and every `SENPI_*` variable and keeps the rest of the host environment.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/auth-lane.ts`: the ambient branch of `queryWithAuthLane` builds the SDK child environment with `stripAmbientApiKey`; `options.env` still layers last.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/availability.ts`: `probeAmbientClaudeAuthStatus` spawns `claude auth status` with the same environment (injectable `env`; `spawnProbe` receives it).

### Why

- Claude Code prefers `ANTHROPIC_API_KEY` over the claude.ai login, so a stale key in the host environment (one captured by a long-lived multi-session RPC host) billed an API key for every subscription turn on the ambient lane and failed only with a credit or usage-limit message. The managed lanes already strip it. The probe follows so availability agrees with the turn lane.

### Why an extension could not handle it

- The child environment is assembled inside this builtin provider immediately before each SDK spawn; no hook sees it.

### Expected merge conflict zones

- LOW: the ambient branch at the top of `queryWithAuthLane` in `auth-lane.ts`, `auth-environment.ts` beside `stripManagedAuthEnvironment`, and the spawn in `probeAmbientClaudeAuthStatus`.
