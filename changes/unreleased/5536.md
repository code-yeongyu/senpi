## 2026-11-02 - The ambient lane never hands Claude Code a host API key that would shadow the subscription (senpi#1195)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/auth-environment.ts`: `stripAmbientApiKey(parent, policy)` is the one ambient child-environment helper. It drops every `SENPI_*` variable and drops `ANTHROPIC_API_KEY` unless `keepsAmbientApiKey` keeps it: policy `inherit`, or an x-api-key gateway (`ANTHROPIC_BASE_URL` non-empty and not on Anthropic's own origin `https://api.anthropic.com`, any path or trailing slash; an unparsable value counts as a gateway; `ANTHROPIC_AUTH_TOKEN` empty or unset). The rule reads the host environment only: a models.json `baseUrl` layered later by `claudeCodeQueryEnvironment` (#4765) never keeps the key. `ignoredAmbientApiKey` names a dropped key.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/settings.ts`: new `ambientApiKey` (`"strip"` | `"inherit"`) in `anthropicSubscriptionProvider`, env override `SENPI_CLAUDE_SDK_OAUTH_AMBIENT_API_KEY`, same precedence and invalid-value handling as `compactionOwner`. `resolveAmbientApiKey` holds the one default: unset means `"strip"`.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/auth-lane.ts`: the ambient branch of `queryWithAuthLane` builds the SDK child environment with `stripAmbientApiKey` and the resolved policy; `options.env` from `buildOptions` (the `options.ts` overlay) still layers last and never carries an API key.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/availability.ts`: `probeAmbientClaudeAuthStatus` spawns `claude auth status` with the same helper (injectable `env` and `ambientApiKey`); `readAmbientClaudeAuthStatus(signal, policy)` keeps one memo per policy.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/oauth-login.ts`, `guidance.ts`, `index.ts`: `configuredFor` passes the policy to the probe. When the probe finds no login and the lane dropped a host key, it emits one `ambientApiKeyIgnoredDiagnostic` (kind `ambient_api_key_ignored`, `ignoredKey: "ANTHROPIC_API_KEY"`, guidance naming `ambientApiKey: "inherit"` and the `anthropic` provider; it says the login probe did not report a login, since the probe also reads false when it could not run) to the session log as `claude_sdk_oauth_ambient_api_key_ignored`; the key's value is never included.
- `packages/coding-agent/docs/providers.md`, `packages/coding-agent/docs/settings.md`: the ambient lane no longer promises to inherit `ANTHROPIC_API_KEY`; the new setting and env override are documented.

| Ambient setup | Before | After |
|---|---|---|
| claude.ai login, no key | OAuth | unchanged |
| claude.ai login + stale `ANTHROPIC_API_KEY` (this issue) | key billed | OAuth |
| `CLAUDE_CODE_OAUTH_TOKEN` | token | unchanged |
| `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` (bearer gateway) | gateway; a stale key could hijack it | gateway via bearer, key dropped |
| `ANTHROPIC_BASE_URL` + `ANTHROPIC_API_KEY`, no `AUTH_TOKEN` (x-api-key gateway) | gateway via key | unchanged, key kept |
| `ANTHROPIC_BASE_URL=https://api.anthropic.com` (any path) + stale key + claude.ai login | key billed | OAuth, key dropped (not a gateway) |
| host key + claude.ai login + models.json `baseUrl` (#4765) | key shadowed the login | key dropped, OAuth to the models.json URL |
| `ANTHROPIC_API_KEY` only, no login | configured, key billed | not configured, diagnostic names the ignored key; `ambientApiKey: "inherit"` restores the old behavior |
| any setup with `ambientApiKey: "inherit"` | n/a | key passed through as before the fix |
| Bedrock/Vertex/Foundry switches, managed lanes, `anthropic` provider | unchanged | unchanged |

### Why

- Claude Code prefers `ANTHROPIC_API_KEY` over the claude.ai login, so a stale key in the host environment (one captured by a long-lived multi-session RPC host) billed an API key for every subscription turn on the ambient lane and failed only with a credit or usage-limit message. The managed lanes already strip it. An x-api-key gateway's key is its credential, not a billing hazard: dropping it would leave the gateway with none, or send the claude.ai bearer to it. The probe and the turn lane share one helper so availability and the turn cannot disagree.

### Why an extension could not handle it

- The child environment is assembled inside this builtin provider immediately before each SDK spawn; no hook sees it.

### Expected merge conflict zones

- LOW: the ambient branch at the top of `queryWithAuthLane` in `auth-lane.ts`, `auth-environment.ts` beside `stripManagedAuthEnvironment`, the probe spawn and reader export in `availability.ts`, the ambient branch of `configuredFor` in `oauth-login.ts`, and the parse lists in `settings.ts`.

### Fixed
- The Claude subscription provider's ambient lane no longer passes a host `ANTHROPIC_API_KEY` to Claude Code unless it is an x-api-key gateway's credential, so a stale key cannot bill an API key instead of the subscription; `anthropicSubscriptionProvider.ambientApiKey: "inherit"` keeps the old pass-through ([#1195](https://github.com/code-yeongyu/senpi/issues/1195))
