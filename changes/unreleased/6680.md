## 2026-11-14 - An interrupt stops the turn's background jobs at once

### What changed

- `packages/coding-agent/src/core/run-background-jobs.ts`: `RunBackgroundJobs.stop(turnId)` stops every job of the turn at once (`Promise.allSettled`) instead of one after another; `stopped` and `failed` still list the jobs in start order.

### Why

- A job that ignores TERM holds its stop for the whole TERM-then-KILL grace, so the `interrupt { background: "stop" }` answer waited one grace period per such job; now it waits one in total.

### Why an extension could not handle it

- `RunBackgroundJobs` is the session's own record of each turn's jobs; the RPC `interrupt` awaits it.

### Expected merge conflict zones

- LOW: `RunBackgroundJobs.stop` in `run-background-jobs.ts`.

## 2026-11-14 - An interrupt's stop names a session the manager no longer holds

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/session-bundle.ts`: `stopForInterrupt` fails with `the terminal manager has no session <id> to stop` when `manager.stop` found no registry entry, and keeps `<id> was still running after the stop (TERM, then KILL)` for a session the stop did not end, as the auto-reap reports them.

### Why

- Both cases were reported as still running after a TERM and a KILL that were never sent for the first one.

### Why an extension could not handle it

- This is the terminal builtin; the change is inside it.

### Expected merge conflict zones

- LOW: `stopForInterrupt` in `session-bundle.ts`.

## 2026-11-14 - One check for `interrupt`'s `background` field

### What changed

- `packages/coding-agent/src/modes/rpc/pause-command-validation.ts`: `interruptBackgroundError(background)` holds the `background must be "stop".` check; `validatePauseCommand` uses it, and so does the terminal control endpoint.

### Why

- The terminal control endpoint passed the field through unchecked while the RPC host refused any value but `"stop"`.

### Why an extension could not handle it

- `interrupt` is an RPC host command.

### Expected merge conflict zones

- LOW: the `interrupt` check in `validatePauseCommand`.

## 2026-11-14 - The terminal control endpoint refuses an `interrupt` `background` other than `"stop"`

### What changed

- `packages/coding-agent/src/modes/interactive/session-control-session-commands.ts`: the control endpoint's `interrupt` refuses a `background` other than `"stop"` with the RPC host's reason, before it touches the turn.

### Why

- The endpoint passed any value through, so an invalid one interrupted the turn as a plain interrupt where the RPC host refused it.

### Why an extension could not handle it

- The control endpoint is interactive-mode code.

### Expected merge conflict zones

- LOW: the `interrupt` case of `runSessionControlCommand`.
