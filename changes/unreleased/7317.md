## 2026-11-22 - MCP prompt commands follow the live prompt catalog (senpi#7249)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/mcp/prompts.ts`: `createMcpPromptCommandSync` registers prompt commands now and after every `onMcpRegistrationChanged`; a handler resolves its server and prompt by name from the live catalog when invoked, and reports a prompt the server no longer offers instead of calling it.
- `packages/coding-agent/src/core/extensions/builtin/mcp/index.ts`: attach registers through that helper; `session_shutdown` and removal of the MCP extension dispose it.

### Why

- Prompt commands were registered once at attach. A prompt from a later catalog generation (startup race, `prompts/list_changed`) never became a command, and a registered command kept the arguments it was registered with.

### Why an extension could not handle it

- The MCP builtin owns both the prompt catalog and the command registration; no other extension sees the catalog generations.

### Expected merge conflict zones

- LOW: the attach block and the two shutdown handlers in `mcp/index.ts`; `registerMcpPromptCommands` in `mcp/prompts.ts`.
