## 2026-10-31 - Merged root unions keep branch-only required fields as a hint (senpi#5138)

### What changed

- `packages/ai/src/utils/tool-schema-compat.ts`: `mergeRootObjectUnion` appends one `REQUIRED for <branch>: <fields>.` sentence per anyOf/oneOf branch to the merged root's `description`, listing that branch's required names that the merged `required` (branch-common names only) dropped. A branch is named by its first literal-valued property (`action=run`, `action=peek|stop`), else `option <n>`. allOf merges are unchanged, since they already require every branch's names.

### Why

- senpi#5138: object-only OpenAI-compatible routes saw the eval tool with no required fields at all, so a weaker tool-calling model had no wire signal that a run needs `language`, `code` and `summary`.

### Why an extension could not handle it

- The root-union merge is the shared provider wire adaptation every OpenAI-compatible, Moonshot and Bedrock request goes through.

### Expected merge conflict zones

- LOW: the return block of `mergeRootObjectUnion` and the two helpers added after it.

## 2026-10-31 - eval validates a run call's missing fields first (senpi#5138)

### What changed

- `packages/senpi-codemode/src/tool/eval-argument-validator.ts` (new): `registerEvalArgumentValidator` registers the eval schema's argument validator. A run call (`action` omitted or `"run"`) missing `language`, `code` or `summary` (absent, null, or a blank summary) fails with one `required` error per missing field, in that order, carrying the eval teaching text (`language` names the enabled languages). Every other call goes through the generic `validateToolArguments` path and its coercion unchanged.
- `packages/senpi-codemode/src/tool/eval-request.ts`: `evalRunFieldRequiredMessage` is the single source of the three run-field teaching errors, shared by validation and `parseEvalRequest`.
- `packages/senpi-codemode/src/tool/eval-tool.ts`: `createEvalTool` registers the validator for its schema.

### Why

- senpi#5138: a run call missing `language` got the generic anyOf dump (every branch's failure), and the eval-specific error in `parseEvalRequest` was never reached because validation failed first.

### Expected merge conflict zones

- LOW: one import and one call in `createEvalTool`.
