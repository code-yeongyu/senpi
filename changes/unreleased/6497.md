## 2026-11-12 - The bundle resolves the MCP SDK's zod imports to one pinned zod, whatever the install layout (senpi#6497)

### What changed

- `scripts/build-coding-agent-bundle.mjs`: `zodSingleCopyPlugin` redirects every `zod`, `zod/v4`, `zod/v4-mini` and `zod/v3` import made from `@modelcontextprotocol/sdk` to the zod that `packages/coding-agent` depends on (4.6.7).
- `scripts/build-coding-agent-bundle.test.mjs`: a fixture build with an npm-style hoisted 4.0.0 `zod/v4`, and a scan of the built bundle for zod versions older than 4.6.6.

### Why

- Release builds install with npm, whose lockfile hoists zod 3.25.76 to the root; the MCP SDK's `zod/v4` then bundled a zod 4.0.0 copy that parses remote MCP server responses. bun installs hid it.
- The Claude agent SDK embeds its own minified zod (4.6.2) inside `sdk.mjs`; that copy is not an import and cannot be redirected.

### Why an extension could not handle it

- The bundle build is core.

### Expected merge conflict zones

- LOW: `commonBuildOptions` plugin list in `scripts/build-coding-agent-bundle.mjs`.
