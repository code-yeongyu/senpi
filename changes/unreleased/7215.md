## 2026-11-22 - Match custom gateway models to catalog compatibility flags (senpi#6286)

### What changed

- `packages/ai/src/providers/all.ts` looks up compatibility flags by exact model ID and API. A matching provider wins; otherwise, only fields shared by all matching routes are returned.

### Why

- Gateways need known model quirks without inheriting flags specific to another route.

### Why an extension could not handle it

- The built-in catalog owns the route data used to resolve ambiguous matches.

### Expected merge conflict zones

- Built-in model lookup and normalization in `all.ts`.

## 2026-11-22 - Preserve catalog defaults under models.json overrides (senpi#6286)

### What changed

- `packages/coding-agent/src/core/provider-composer.ts` applies catalog compatibility flags before provider and model settings, preserving explicit overrides field by field.

### Why

- Without `mixedStrictTools: false`, a gateway can reject a request that mixes strict and non-strict tools.

### Why an extension could not handle it

- Core composes models declared in `models.json` even when no extension is installed.

### Expected merge conflict zones

- Custom model construction and compatibility merging in `provider-composer.ts`.
