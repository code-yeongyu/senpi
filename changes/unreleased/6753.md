## 2026-11-15 - A forwarded session_before_* event returns its result on a hand (senpi#5898)

### What changed

- `packages/coding-agent/src/core/extensions/runner.ts`: `emitForwardedLoopEvent` is generic over the event and returns its result. A forwarded `session_before_*` event (on a hand, `session_before_compact`) returns what a session's `emit` returns: the last handler result, and the first `cancel` ends the walk. `dispatchLifecycle` collects that result and halts on `cancel`. Every other event still returns `undefined`.

### Why

- A hosted loop's PreCompact hooks and its users' compaction extensions run on the hand. Their `cancel` or custom `compaction` must go back to the loop that compacts.

### Why an extension could not handle it

- The runner owns how handler results combine. An extension cannot read another extension's result.

### Expected merge conflict zones

- LOW: `emitForwardedLoopEvent` and `dispatchLifecycle` in `runner.ts`.

## 2026-11-15 - A hand serves a hosted loop's compaction and shutdown events (senpi#5898)

### What changed

- `packages/coding-agent/src/modes/rpc/loopless-loop-hooks.ts`: `extensionLoopHooks` serves `session_before_compact` (its reply carries the combined `SessionBeforeCompactResult`), `session_compact`, `session_compact_failed` and `session_shutdown`. `session_before_compact` gets a local `signal` that aborts when the call's signal aborts.
- `packages/coding-agent/src/modes/rpc/loop-hook-payloads.ts`: new. It is the hand's boundary parse of every forwarded loop event's payload, moved out of `loopless-loop-hooks.ts`. A compaction `preparation` carries `fileOps` as string arrays, which become Sets on the hand.
- `packages/coding-agent/src/modes/rpc/loop-hook-call.ts`: `LoopHookCall.run` passes the call's own signal to `dispatch`.

### Why

- senpi#5898 (K8, K9): the brain emits every loop event and the hand runs the hooks. The user's PreCompact and PostCompact shell hooks, and their extensions' compaction and shutdown handlers, never ran for a hosted loop.

### Why an extension could not handle it

- The loop-hook lane and the call's facts belong to the loopless runtime.

### Expected merge conflict zones

- MEDIUM: `extensionLoopHooks` event branches (other #5898 slices add events there) and the parsers in `loop-hook-payloads.ts`.
