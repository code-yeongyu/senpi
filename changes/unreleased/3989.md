## 2026-11-22 - Eval kernels run Git Bash for a bare bash on Windows (Fixes oh-my-openagent#10894)

### What changed

- `packages/senpi-codemode/src/extension/kernel-path-env.ts`: new `kernelShellEnv`, the shell environment every kernel child gets through the session environment. It keeps the bundled `bun` directory (omo#9362). On win32 it resolves the same bash the bash tool uses, `getShellConfig(shellPath)`: the `shellPath` setting, then `SENPI_GIT_BASH_PATH`, then the Git for Windows install. It puts that bash's directory first, once, only when the directory is a Git-style `bin` that holds `bash.exe` and `sh.exe` and no `find.exe`/`sort.exe`/`timeout.exe` that would shadow System32 for every kernel child. On win32 it also names that bash to the Python kernel (`SENPI_KERNEL_BASH`), even when its directory does not qualify for PATH. A missing bash or the `System32`/`Sysnative` WSL launcher changes nothing, and other platforms are unchanged. `sessionShellPath(ctx)` reads `shellPath` the way the session's bash tool does: from this session's agent dir, and from project settings only when the project is trusted.
- `packages/senpi-codemode/src/extension/runtime-factory.ts`: the session environment uses `kernelShellEnv({ shellPath: sessionShellPath(ctx) })` in place of the local `bundledBunPathEntry`.
- `packages/senpi-codemode/src/kernels/py/prelude.py`: at startup the kernel reads and removes `SENPI_KERNEL_BASH`, so cells and their children never see it. On Windows a bare `bash`/`sh` in `subprocess.Popen` and `asyncio.windows_utils.Popen` (used by `asyncio.create_subprocess_exec`) argv or command lines runs exactly that bash, and `%%bash`/`%%sh` run it with `-c`, the bash tool's launch, instead of going through cmd.exe. Without a named bash nothing is patched; POSIX is unchanged.
- `packages/senpi-codemode/test/kernel-path-env.test.ts`, `test/py-prelude-windows-bare-shell.test.ts`: Windows lookup is simulated with temp-dir PATHs and fake `bash.exe`/`sh.exe` files, including a configured `shellPath` and a usr\bin-like directory with coreutils; `sessionShellPath` runs against temp agent and project settings, trusted and untrusted. The prelude loads as a module and its helpers, `%%bash` launch and environment removal run with a host-named fake bash.
- `packages/senpi-codemode/.gitignore`: ignore `__pycache__/` and `*.pyc` so a compiled prelude never gets committed.

### Why

- A default Git for Windows install puts only `Git\cmd` on PATH, so a bare `bash` in a cell resolved to `C:\Windows\System32\bash.exe`, the WSL launcher, and booted the WSL VM. The bash tool never did that because it resolves through `getShellConfig`. In Python, CreateProcess searches System32 before PATH, so the PATH entry alone does not reach list-form `subprocess` calls.

### Why an extension could not handle it

- The kernel environment and the embedded Python prelude are built inside this package before any cell runs.

### Expected merge conflict zones

- The `sessionEnv` line in `runtime-factory.ts`, the `%%bash` branch of `_magic_cell`, and `_shell` plus `main` in `prelude.py`.

### Fixed
- On Windows, a bare `bash` or `sh` started from an `eval` cell (`Bun.$`, `Bun.spawn`, Python `subprocess`, `%%bash`) now runs the same Git Bash the bash tool uses, instead of `System32\bash.exe`, which booted the WSL VM. Its Git `bin` directory goes first on the kernels' PATH only when it holds `bash.exe` and `sh.exe` and no coreutils that would shadow Windows' `find`/`sort`/`timeout`. Without a Git Bash nothing changes; macOS and Linux are unaffected. Reported by @JunesuChoi. ([oh-my-openagent#10894](https://github.com/code-yeongyu/oh-my-openagent/issues/10894))
