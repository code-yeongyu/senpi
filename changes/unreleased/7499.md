## 2026-11-26 - Host state files are replaced by rename (senpi#3305)

### What changed

- `packages/coding-agent/src/modes/rpc/host-daemon-state.ts`: `writeStateFile` writes a temporary file beside its target and renames it over the target (`writeJsonAtomic`), instead of writing the target in place.
- `packages/coding-agent/src/modes/rpc/host-daemon-registration.ts`: `writeHostRegistration` writes the pointer through `writeStateFile`; its own temporary file and rename are gone.
- `packages/coding-agent/src/modes/rpc/host-state-json.ts`: `writeJsonAtomic` retries a rename Windows refuses for a moment, with the transient-replace retry that `core/credential-pool/state-file.ts` had, now defined once in `utils/paths.ts` and imported by both writers.

### Why

- A handoff rewrites its successor's `generations/<id>/host.pid` once the successor answers, and `host status`, the prune and the pointer election read that file without a lock. A write in place truncates first, so a read between the truncate and the write, or any read after a writer that ended there, found no record and left the generation serving the socket out of `generations`. A caller waiting for that row asked the successor again and was refused `stale_generation` (the release failure of `test/rpc-host-handoff-clientless.test.ts`).

### Why an extension could not handle it

- The daemon directory is written by the RPC host and its clients before any extension loads, and extensions have no part in host registration.

### Expected merge conflict zones

- LOW: `writeStateFile` in `host-daemon-state.ts` and the pointer write in `host-daemon-registration.ts`; both are fork-only files.
