## 2026-10-30 - Validate SIWC ID tokens before returning credentials (senpi#5012)

### What changed

- `auth/oauth/openai-chatgpt.ts` verifies the code exchange's ID token before returning a credential, carrying the attempt nonce and issued client ID into validation. Fetch and the clock are injectable. Refresh preserves the sign-in's validated identity and retained ID token.
- `auth/oauth/openai-id-token.ts` verifies RS256 signatures with WebCrypto, discovers and caches OpenAI's JWKS, reloads unfamiliar keys, and requires issuer, audience, expiry, nonce, and subject. Validation failures have a typed error.
- `auth/types.ts` declares optional subject, display-only email, issuer, clientId, idToken, and scopes fields. Provider registration and the missing-scope rejection remain unchanged.

### Why

- OpenAI's SIWC sign-in section 4 requires signature and claim validation before trusting an account identity. The vendored flow previously checked only that an ID token was present.

### Why an extension could not handle it

- Code exchange and credential construction are internal to the bundled OAuth flow; an extension cannot validate its pending nonce before the flow returns credentials.

### Expected merge conflict zones

- `auth/oauth/openai-chatgpt.ts` code exchange, login arguments, and refresh credential construction; `auth/types.ts` OAuthCredential fields.
