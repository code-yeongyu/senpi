## 2026-11-10 - A rule that is one field lookup is published as data (senpi#6318)

### What changed

- `packages/coding-agent/src/modes/rpc/method-class-rule-data.ts` (new): rule-data language version 1, `{ version, field, map, default }`. `fieldRule()` declares a versioned rule as that data and builds its `classify` from the same data. `ruleDataOf()` reads the data form of a table entry.
- `packages/coding-agent/src/modes/rpc/method-classes.ts`: `set_model@1` and `set_thinking_level@1` are declared with `fieldRule` (scope `session` / `turn` is `drive`, anything else `device_admin`; same outputs, same versions, digest unchanged). `describeRpcMethodClasses()` adds `rule_data` for each such type.
- `packages/coding-agent/src/modes/rpc/delegation-classify.ts`: `classify_record` adds `rule_data` next to `static: false, rule: N` when the rule has a data form. Every existing field is unchanged.
- `packages/coding-agent/src/modes/rpc/rpc-protocol-info-types.ts`: doc comment for `method_classes.rule_data`.

### Why

A forwarder that classifies records on a delegated connection could cache only static answers. For a dynamic method such as `set_model` it asked `classify_record` for every record, one engine round trip between receipt and dispatch, unless it kept a hand-written copy of the rule. Publishing the engine's own rule as data removes both: the forwarder evaluates exactly what the engine runs.

### Why an extension could not handle it

The method-class table, `classify_record` and `get_protocol_info.method_classes` are engine-owned RPC surfaces.

### Expected merge conflict zones

- LOW: the `set_model` / `set_thinking_level` entries of `RPC_METHOD_CLASS` and `describeRpcMethodClasses()` in `method-classes.ts`; the static/rule spread in `delegation-classify.ts`.

### Added
- RPC: `classify_record` and `get_protocol_info.method_classes` carry `rule_data`, the engine's own rule as data, for each method-class rule that is one field lookup (`set_model@1`, `set_thinking_level@1`), so a client can classify those records without a round trip per record ([#6319](https://github.com/code-yeongyu/senpi/pull/6319))
