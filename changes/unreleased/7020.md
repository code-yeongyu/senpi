## 2026-11-19 - A session that was live when its host ended resumes by itself on the next host (senpi#7020)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `holdAutomaticTurns()` adds its unattended hold under its own key `host-drain` (`HOST_DRAIN_HOLD_KEY`) instead of the generic `unattended`. After `bindExtensions` finishes restoring the lifecycle, a session whose `session_start` says `continued` releases the holds the restart caused, once (`_continueAfterHostRestart`, decision in the new `core/host-restart-continuation.ts`): when only those holds are left it resumes through the ordinary Resume path (`_resumeOnce`), so wakes held during a handoff drain are delivered, a goal resumes, and an engine-started run the restart cut continues with the interrupted-run directive; when another hold stays (a person's Stop, an unattended hold the session already had) it drops only `host-drain`. `abortForHostShutdown` records the run it cuts as interrupted.
- `packages/coding-agent/src/core/session-lifecycle.ts`: `cutByHostShutdown()` writes the cut run as interrupted; `continueAfterRestart()` lets the restart's continuation of an engine-started run through the interrupted-run gate until that run starts.
- `packages/coding-agent/src/core/host-restart-continuation.ts` (new): `engineStartedLastRun` (the newest run's start on the branch is an `engine-turn-start`, not a user message or a user-directed custom message such as a Resume directive) and `restartRelease`.

### Why

- A host restart or handoff left every retained session silent: the reopen forced it unattended, the drain's hold was replayed as a real unattended hold, and a run the restart cut stayed held for a person. Orchestrator lanes stopped after every deploy of the host.

### Why an extension could not handle it

- The hold ledger, the interrupted-run gate and the resume path are `AgentSession` internals; the reopen is the RPC host's.

### Expected merge conflict zones

- LOW: `holdAutomaticTurns`, one private method and one field near it, one call at the end of `bindExtensions`, three lines in `abortForHostShutdown`.

## 2026-11-19 - session_start says when a host restart continued the session (senpi#7020)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `SessionStartEvent.continued?: boolean`, `true` when a host reopened the session because it was live when the previous host ended.

### Why

- A handler that suppresses work on a cold reopen (the goal extension's continuation-flood guard) must not suppress a session the restart merely interrupted.

### Why an extension could not handle it

- The event is emitted by the host's open; only the host knows why it reopened the session.

### Expected merge conflict zones

- LOW: one optional field on `SessionStartEvent`.

## 2026-11-19 - A continued session keeps its goal streak (senpi#7020)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/goal/index.ts`: the load-time suppression of a goal ending on `GOAL_CONTINUATION_CAP` trailing continuations skips a `session_start` with `continued`.

### Why

- A long-running goal that a host restart interrupted stayed parked until a person wrote, although nothing about it was cold.

### Why an extension could not handle it

- This is the builtin goal extension's own session-start policy.

### Expected merge conflict zones

- LOW: one condition in the `session_start` handler.

## 2026-11-19 - The park record says whether the session was live (senpi#7020)

### What changed

- `packages/coding-agent/src/modes/rpc/host-handover-parked.ts`: `HandoverParkedEntry.live?: true`, validated by `isEntry` (older readers ignore it).
- `packages/coding-agent/src/modes/rpc/session-router-residency.ts`: `recordRetainedSession` takes `live` (default: `resident`); every resident stamp is live.
- `packages/coding-agent/src/modes/rpc/session-router-occupancy.ts`, `session-router-close.ts`: a handoff drain park and a clean-stop park are live; an idle-sweep park is not; an unload rewrites the entry without it.
- `packages/coding-agent/src/modes/rpc/session-router-open.ts`, `session-registry-types.ts`, `session-registry-opening.ts`: `reopenParked` opens a live entry with the host-internal launch-profile flag `continued` (never read from the wire), which reaches `session_start` as `continued`, instead of `attended: false`; an entry without `live` reopens unattended as before.

### Why

- The successor could not tell a session that was working when its host went away from one that had been idle-parked, so it held all of them.

### Why an extension could not handle it

- The park record and the successor's reopen are the RPC host's.

### Expected merge conflict zones

- LOW: one field and one validation line in the park record; one parameter in `recordRetainedSession`; the `reopenParked` body.
