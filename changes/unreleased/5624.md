## 2026-11-03 - Consumed deliveries leave lifecycle waits; lifecycle records carry only background changes (senpi#5612)

### What changed

- `packages/coding-agent/src/core/lifecycle-background-waits.ts` (new): `waitingCustody(active)` drops `consumed` custody from what the session waits on; `boundBackground(background, alreadyOmitted)` keeps the first 32 background sources of a snapshot and counts the rest in `backgroundOmitted`; `readBackgroundSource` is the one parser of a background source.
- `packages/coding-agent/src/core/lifecycle-background-changes.ts` (new): `backgroundChanges(durable, live)` computes what a record must carry (`set`: sources added or changed, `removed`: names that left); `replayBackground(records)` rebuilds the set from records in `seq` order, where a record without `backgroundChanges` replaces the set with its whole list.
- `packages/coding-agent/src/core/lifecycle-ledger.ts`: the constructor replays every record of the session into the durable background set; `update()` takes the full `backgroundSources` and writes when they change; `write()` stores `backgroundChanges` against the last written record, names no source in `waitingOn.background`, and counts every open source in `waitingOn.backgroundOmitted`. The durable set advances only when the append succeeds.
- `packages/coding-agent/src/core/lifecycle-record.ts`: `LifecycleRecord.backgroundChanges?`.
- `packages/coding-agent/src/core/session-lifecycle.ts`: `evaluate()` projects `children`, `childSources`, `background` and the wake-source dedupe from `waitingCustody(active)`, publishes `waits` through `boundBackground`, and hands the full list to the ledger. The terminal-publication guard still reads every open custody record.
- `packages/coding-agent/src/core/session-lifecycle-types.ts`: `LifecycleWaits.backgroundOmitted?: number`.
- `packages/coding-agent/src/core/lifecycle-children.ts`: `readWaits()` parses sources through `readBackgroundSource`, reads `backgroundOmitted`, and bounds a reported list the same way.

### Why

- `packages/coding-agent/src/core/session-lifecycle.ts`: a steered delivery is consumed inside the run that is still running, and `consumed` custody counts as open until `settleRun()` at `idle()` or the next `startRun()`. Every consumed delivery of one long run stayed in `waitingOn.background`, and the ledger appended the whole snapshot on each change, so lifecycle bytes grew with the square of the deliveries (one transcript reached 3.67 GB). A consumed delivery's message is already in the conversation, so nothing waits on it; its custody record stays `consumed` for crash recovery (senpi#4848).
- `packages/coding-agent/src/core/lifecycle-ledger.ts`, `packages/coding-agent/src/core/lifecycle-background-changes.ts`, `packages/coding-agent/src/core/lifecycle-record.ts`: genuinely open sources (for example many queued followUps) must not make each record grow either. A record now carries only what changed, so its size follows the change, and the ledger constructor already reads every record, so replay costs nothing new. Old transcripts keep loading: their full-list records reset the replayed set, and the first record after load removes stale names once.
- `packages/coding-agent/src/core/lifecycle-background-waits.ts`, `packages/coding-agent/src/core/lifecycle-children.ts`, `packages/coding-agent/src/core/session-lifecycle-types.ts`: the in-memory and RPC snapshot stays bounded at 32 named sources plus an exact count, like `childReports`.

### Why an extension could not handle it

- The wait projection and the durable lifecycle record are owned by the core lifecycle controller and ledger; no extension writes or shapes them.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/core/lifecycle-ledger.ts` the constructor's record scan, the start of `update()` after the restoring guard, and the record literal in `write()`.
- LOW: `packages/coding-agent/src/core/session-lifecycle.ts` the projection lines at the top of `evaluate()`, the `waits` literal and the `ledger.update` call.
- LOW: `packages/coding-agent/src/core/lifecycle-children.ts` the background loop and return of `readWaits()`.

### Fixed
- A session that keeps receiving wakes inside one long run no longer grows its transcript quadratically: a consumed delivery leaves `waitingOn.background` at once, and each lifecycle record stores only the background sources that changed, with `backgroundOmitted` counting every open source ([#5612](https://github.com/code-yeongyu/senpi/issues/5612))
