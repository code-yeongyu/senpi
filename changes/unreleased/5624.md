## 2026-11-03 - Consumed deliveries leave lifecycle waits; a record names at most 32 background sources (senpi#5612)

### What changed

- `packages/coding-agent/src/core/lifecycle-background-waits.ts` (new): `waitingCustody(active)` drops `consumed` custody from what the session waits on; `boundBackground(background, alreadyOmitted)` keeps the first 32 background sources and counts the rest in `backgroundOmitted`.
- `packages/coding-agent/src/core/session-lifecycle.ts`: `evaluate()` projects `children`, `childSources`, `background` and the wake-source dedupe from `waitingCustody(active)`, and publishes `waits` through `boundBackground`. The terminal-publication guard still reads every open custody record.
- `packages/coding-agent/src/core/session-lifecycle-types.ts`: `LifecycleWaits.backgroundOmitted?: number`.
- `packages/coding-agent/src/core/lifecycle-children.ts`: `readWaits()` reads `backgroundOmitted` and applies the same bound to a restored record.

### Why

- `packages/coding-agent/src/core/session-lifecycle.ts`: a steered delivery is consumed inside the run that is still running, and `consumed` custody counts as open until `settleRun()` at `idle()` or the next `startRun()`. Every consumed delivery of one long run stayed in `waitingOn.background`, and `lifecycle-ledger.ts` appends the whole snapshot on each change, so lifecycle bytes grew with the square of the deliveries (one transcript reached 3.67 GB). A consumed delivery's message is already in the conversation, so nothing waits on it; its custody record stays `consumed` for crash recovery (senpi#4848).
- `packages/coding-agent/src/core/lifecycle-background-waits.ts`, `packages/coding-agent/src/core/lifecycle-children.ts`, `packages/coding-agent/src/core/session-lifecycle-types.ts`: genuinely open sources (for example many queued followUps) must not make each record grow either; a capped list plus a count keeps every record bounded and the total exact, and restoring an older record with every source named keeps the same bound so a load does not re-amplify.

### Why an extension could not handle it

- The wait projection and the durable lifecycle record are owned by the core lifecycle controller and ledger; no extension writes or shapes them.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/core/session-lifecycle.ts` the projection lines at the top of `evaluate()` and the `waits` literal.
- LOW: `packages/coding-agent/src/core/lifecycle-children.ts` the return of `readWaits()`.

### Fixed
- A session that keeps receiving steered wakes inside one long run no longer grows its transcript quadratically: a consumed delivery leaves `waitingOn.background` at once, and each lifecycle record names at most 32 background sources with `backgroundOmitted` counting the rest ([#5612](https://github.com/code-yeongyu/senpi/issues/5612))
