## 2026-11-12 - A synchronous caller can see the pending block-log appends inside a directory (senpi#6488)

### What changed

- `packages/coding-agent/src/core/credential-pool/block-log.ts`: `pendingCredentialBlockLogsWithin(directory)` lists the block logs inside `directory` with an append still pending (added in #6502 beside `settledCredentialBlockLogsWithin`). The coding-agent test removal guard uses it to make `rmSync` refuse with `PendingBlockLogRemovalError` while one is pending, and the suite harness teardown now awaits the guarded `fs.promises.rm` instead of calling `rmSync`.

### Why

- A synchronous removal cannot wait, and an append already running on the thread pool can create the log while its walk is under way (senpi#6488).

### Why an extension could not handle it

- The append chain is private to the block-log module; only it knows which writes are still pending.

### Expected merge conflict zones

- None upstream: `core/credential-pool/` is fork-only.
