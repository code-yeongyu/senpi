## 2026-10-26 - Generalize Responses tool-call ID serialization for all extension providers (senpi#4395)

### What changed

- `packages/ai/src/api/openai-responses-shared.ts`: Normalize tool call IDs for Responses-compatible providers and synthesize missing item IDs. Preserve valid same-model IDs; on model switches, omit the old ID for native OpenAI and Codex or replace it for compatible gateways. Replay native reasoning only for its originating model while retaining readable reasoning across switches.

### Why

The serializer previously gated foreign tool call ID normalization on a static set of built-in provider names. Some custom Responses-compatible gateways reject calls without an item ID. Same-provider model switches have a separate replay constraint: an original item ID may be paired with reasoning that is no longer replayed.

### Why an extension could not handle it

`packages/ai/src/api/openai-responses-shared.ts` owns wire serialization for Responses endpoints; extensions register model capabilities but cannot alter the internal transcript translation logic.

### Expected merge conflict zones

- LOW: `normalizeToolCallId` provider check and `function_call` object creation in `openai-responses-shared.ts`.
