## 2026-10-26 - Generalize Responses tool-call ID serialization for all extension providers (senpi#4395)

### What changed

- `packages/ai/src/api/openai-responses-shared.ts`: In `convertResponsesMessages`, allow any model targeting `api: "openai-responses"` (`model.api === "openai-responses"`) to translate foreign tool call IDs into normalized compound tokens rather than gating on a static provider name allowlist; ensure `function_call` input items always carry an `id` attribute starting with `fc_` (defensively synthesizing `fc_${shortHash(callId)}` when an item ID is missing or unprefixed); and only replay `reasoning` items when `isSameModel` is true, preventing foreign model reasoning dumps from corrupting cross-model thread history.

### Why

The Responses message serializer previously gated tool call ID normalization on a static set of built-in provider names (`allowedToolCallProviders.has(model.provider)`). Any custom extension provider (e.g. `commandcode` or third-party gateways) using the `openai-responses` wire API had their tool call IDs stripped, emitting `function_call` items without the required `id` field and causing strict Responses API gateways to reject payloads with HTTP 400 `invalid_request_error: param "input"`.

### Why an extension could not handle it

`packages/ai/src/api/openai-responses-shared.ts` owns wire serialization for Responses endpoints; extensions register model capabilities but cannot alter the internal transcript translation logic.

### Expected merge conflict zones

- LOW: `normalizeToolCallId` provider check and `function_call` object creation in `openai-responses-shared.ts`.

### Fixed
- In OpenAI Responses message serialization, foreign tool call IDs are now translated for any target model using `api: "openai-responses"` rather than gating on a static provider allowlist; `function_call` wire items defensively fall back to an `fc_<hash>` item ID when an un-prefixed ID is present; and foreign `reasoning` items are dropped across mid-session model switches instead of leaking into alien provider payloads ([#4395](https://github.com/code-yeongyu/senpi/issues/4395)).
