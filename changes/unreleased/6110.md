## 2026-11-06 - A model-not-in-plan 403 no longer blocks the credential slot (senpi#3972)

### What changed

- `packages/coding-agent/src/core/credential-pool/classify.ts`: in the 403 branch of `classifyCredentialFailure`, a refusal that names one model the account's plan does not cover (new `MODEL_NOT_IN_PLAN_TEXT` / `MODEL_UNAVAILABLE_TEXT`) now returns `fail_request` instead of failing over with an `auth_error` block, so the slot stays selectable for other models on the same provider.
- `packages/coding-agent/test/credential-error-taxonomy.test.ts`: four new model-refusal cases (subscription/plan wording, model-not-available, model-not-found on a 403) plus a guard case proving a subscription suspension still blocks the slot as `auth_error`.

### Why

- A 403 reading "Your subscription does not include access to model-a" matched the account-scoped 403 text (`subscription`) and persisted an `auth_error` block, so every model on the provider went dark until re-probe while another model on the same key worked fine. The refusal is a verdict on that model, not on the credential.

### Why an extension could not handle it

- Credential classification is core pool behaviour below every extension hook; no extension sees the refusal before the pool decides whether to block the slot.

### Expected merge conflict zones

- LOW: the 403 branch of `classifyCredentialFailure` and the taxonomy test table are touched by credential-pool work only.
