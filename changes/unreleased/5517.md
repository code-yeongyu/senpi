## 2026-11-02 - Trust-state reads skip the lock when the state file is absent (senpi#5096)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/hooks/trust-storage.ts`: `FileHookStateStorage.read()` returns the empty trust state without taking the `proper-lockfile` lock when `hooks-state.json` does not exist. The lock-and-re-read path is unchanged for a file that exists but is unparsable, so the ABA revalidation for legacy in-place writers (truncated-then-published snapshots) is preserved.

### Why

- In a normal session with no trusted hooks, every read created and removed a `hooks-state.json.lock` directory in the agent directory and in `<cwd>/.senpi`, even though there was nothing to revalidate. That lock churn was the hottest filesystem-event source in the 20-session soak (#4999). Writers publish atomically by rename, so an absent file needs no exclusion and a concurrent publish is picked up by the next read, matching the async `readAsync` path which never locked.

### Why an extension could not handle it

- Hook trust storage is the builtin `hooks` extension's own persistence layer, wired directly into the session's trust checks; no extension hook interposes on its read path.

### Expected merge conflict zones

- LOW: the `read()` method of `FileHookStateStorage` is also touched by neighbouring trust-storage work, but those change the lock/re-read branches for present-but-malformed snapshots, not the absent-file early return added here.

### Fixed
- Reading hook trust state no longer creates and removes a lock directory on every read when `hooks-state.json` is absent, so sessions with no trusted hooks stop flooding filesystem watchers with lock events ([#5096](https://github.com/code-yeongyu/senpi/issues/5096))
