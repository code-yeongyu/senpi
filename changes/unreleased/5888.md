## 2026-11-05 - a Windows pipe's identity is read with stat again (senpi#5888, #5404 regression)

### What changed

- `packages/coding-agent/src/modes/rpc/socket-ownership.ts`: on win32 `statSocketIdentity` reads with `stat`, as it did before #5404. Every POSIX platform keeps `lstat`.

### Why

- #5404 switched the read to `lstat` so a symlink planted at a POSIX socket path reads as another entry. On Windows the public endpoint is a named pipe with no filesystem entry. After #5404, main's `RPC named pipes (Windows)` job failed: the supervisor's post-publish identity read broke, and `rpc-host-lifecycle` hosts never reached `public_verified`. A pipe name cannot be a planted link, so `lstat` adds nothing there.

### Why an extension could not handle it

- The identity read runs inside the lifecycle supervisor before any session or extension exists.

### Expected merge conflict zones

- LOW: `statSocketIdentity` in `socket-ownership.ts`.
