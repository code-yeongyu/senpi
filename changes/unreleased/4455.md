## 2026-10-27 - Anthropic sends the cross-session stable system prefix as its own cached block (senpi#4447)

### What changed

- `packages/ai/src/api/anthropic-messages.ts`: `buildParams` builds `params.system` through `anthropicSystemTextBlocks`, passing the leading system message's `stablePrefixLength`.
- `packages/ai/src/api/anthropic-system-blocks.ts`: new. With a stable prefix the prompt goes out as two text blocks whose concatenation is the prompt; the stable block carries the system `cache_control`, the tail none, so the breakpoint count is unchanged.

### Why

- One system block with one breakpoint missed whenever any byte of a volatile tail (memory, MCP instructions) differed between sessions, so a new session read only the tools prefix and re-wrote the ~20k-token stable prompt.

### Why an extension could not handle it

- System block construction and breakpoint placement happen inside `packages/ai/src/api/anthropic-messages.ts` after every extension hook.

### Expected merge conflict zones

- LOW: the `params.system` assignment in `buildParams` in `packages/ai/src/api/anthropic-messages.ts`.

## 2026-10-27 - before_agent_start results say whether their prompt change is stable or volatile (senpi#4447)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `BeforeAgentStartEventResult.systemPromptCache` (`"stable" | "volatile"`; builtins default to stable, other extensions to volatile).
- `packages/coding-agent/src/core/extensions/runner.ts`: `emitBeforeAgentStart` tracks the stable prefix (the prompt up to the first volatile change, shrunk when a later handler rewrites it) and returns it as `systemPromptStablePrefix`.

### Why

- Only the extension knows whether its addition changes between sessions; the runner is where the composed prompt is known.

### Why an extension could not handle it

- The composition loop lives in `packages/coding-agent/src/core/extensions/runner.ts`.

### Expected merge conflict zones

- LOW: `BeforeAgentStartEventResult` in `packages/coding-agent/src/core/extensions/types.ts` and the `systemPrompt` branch of the `dispatch:` loop in `packages/coding-agent/src/core/extensions/runner.ts`.

## 2026-10-27 - Real turns and the prewarm prefix carry the stable system prefix (senpi#4447)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_applyBeforeAgentStartResult` stores the runner's `systemPromptStablePrefix` on the agent state.
- `packages/coding-agent/src/core/prompt-cache-prefix-request.ts`: the preview composition passes the prefix into `buildProviderContext`, and `toPrefixContext` returns it on the prefix `Context`.

- The real request, the prewarm and the keep-alive ping must split the system prompt the same way to share one cache entry.
