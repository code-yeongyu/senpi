## 2026-10-27 - Anthropic sends the cross-session stable system prefix as its own cached block (senpi#4447)

### What changed

- `packages/ai/src/api/anthropic-messages.ts`: `buildParams` builds `params.system` through `anthropicSystemTextBlocks`, passing the leading system message's `stablePrefix`.
- `packages/ai/src/api/anthropic-system-blocks.ts`: new. When the rendered prompt still starts with the recorded stable prefix it goes out as two text blocks whose concatenation is the prompt; the stable block carries the system `cache_control`, the tail none, so the breakpoint count is unchanged. A prompt that no longer starts with it (a later `context_with_system` rewrite) goes out as one block.

### Why

- One system block with one breakpoint missed whenever any byte of a volatile tail (memory, MCP instructions) differed between sessions, so a new session read only the tools prefix and re-wrote the ~20k-token stable prompt.

### Why an extension could not handle it

- System block construction and breakpoint placement happen inside `packages/ai/src/api/anthropic-messages.ts` after every extension hook.

### Expected merge conflict zones

- LOW: the `params.system` assignment in `buildParams` in `packages/ai/src/api/anthropic-messages.ts`.

## 2026-10-27 - Context and the leading system message carry the stable system prefix (senpi#4447)

### What changed

- `packages/ai/src/types.ts`: `Context.systemPromptStablePrefix` and request-time `SystemMessage.stablePrefix` (the prefix text, so a rewritten prompt that no longer starts with it is detected). The prefix is shared across sessions in the same working directory: the base prompt names the cwd.

- Providers with block-level prompt caching need to know where the cross-session stable part of the system prompt ends.

### Why an extension could not handle it

- `Context` and `SystemMessage` are the provider-facing contract defined in `packages/ai/src/types.ts`.

### Expected merge conflict zones

- LOW: the `Context` and `SystemMessage` interfaces in `packages/ai/src/types.ts`.

## 2026-10-27 - before_agent_start results say whether their prompt change is stable or volatile (senpi#4447)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `BeforeAgentStartEventResult.systemPromptCache` (`"stable" | "volatile"`; builtins default to stable, other extensions to volatile) and `ExtensionContext.getSystemPromptStablePrefix()` / `ExtensionContextActions.getSystemPromptStablePrefix`, so an extension that builds its own request from `getSystemPrompt()` splits it like the turn.
- `packages/coding-agent/src/core/extensions/builtin/hooks/index.ts`: per-prompt UserPromptSubmit system messages are `systemPromptCache: "volatile"`.
- `packages/coding-agent/src/core/extensions/runner.ts`: `emitBeforeAgentStart` tracks the stable prefix (the prompt up to the first volatile change, shrunk when a later handler rewrites it) and returns it as `systemPromptStablePrefix`; the extension context exposes the session's current prefix through `getSystemPromptStablePrefix`.

### Why

- Only the extension knows whether its addition changes between sessions; the runner is where the composed prompt is known.

### Why an extension could not handle it

- The composition loop lives in `packages/coding-agent/src/core/extensions/runner.ts`.

### Expected merge conflict zones

- LOW: `BeforeAgentStartEventResult` in `packages/coding-agent/src/core/extensions/types.ts` and the `systemPrompt` branch of the `dispatch:` loop in `packages/coding-agent/src/core/extensions/runner.ts`.

## 2026-10-27 - Real turns and the prewarm prefix carry the stable system prefix (senpi#4447)

### What changed
