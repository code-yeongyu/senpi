## 2026-11-22 - Replacement events identify both sessions (senpi#6505)

### What changed

- `packages/coding-agent/src/modes/rpc/connection-handler.ts` includes the previous durable ID and file when announcing a replacement. `packages/coding-agent/src/modes/rpc/rpc-session-event-types.ts` keeps both fields optional for readers of older host events. `packages/coding-agent/src/modes/rpc/host-capabilities.ts` advertises `session_replaced_origin`.

### Why

- An attached client can distinguish a replacement of its bound session from a stale notification about another session behind the handle.

### Why an extension could not handle it

- Only the RPC host knows both bindings at the moment it publishes the replacement.

### Expected merge conflict zones

- The session-rebind announcement, host capability list and event type.
