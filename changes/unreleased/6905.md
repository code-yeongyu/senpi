### Fixed

- A hold added while a session is already paused (a second Stop, or a released Stop re-armed when the turn the user's message started is stopped) now announces its `pauseSeq` with `session_paused`. A client quoting the last seq it saw in `resume_session { expectedSeq }` is no longer refused as `stale` for a hold it never saw. `session_resumed` still fires once per pause, and a run fence alone emits nothing ([#6900](https://github.com/code-yeongyu/senpi/issues/6900)).
