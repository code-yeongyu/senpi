## 2026-10-28 - A refused account pool ends the turn with a provider diagnostic (#4676)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/provider-diagnostic.ts` (new): `anthropicSubscriptionDiagnostic(error)`. `AllAccountsBlockedError` maps to category `auth` with code `account_pool_auth_blocked` when every account is auth-blocked, otherwise `rate_limit` with code `account_pool_blocked` and `resetsAt` = the soonest retry. A pin (account fallback off) to an account that is no longer configured sets no diagnostic: that is a configuration error, not a limit, and a `rate_limit` would make a goal back off and retry something that cannot succeed. A classified SDK failure maps by kind: `auth_error` -> `auth` (`authentication_error`), `rate_limit` -> `rate_limit` (`rate_limit_error`), `overloaded` -> `provider_unavailable` (`overloaded_error`), `billing` -> `unknown` (`billing_error`), `org_not_allowed` -> `unknown` (`permission_error`); other kinds set nothing. The result is revalidated with `sanitizeProviderDiagnostic`.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/stream.ts`: the catch block sets `output.providerDiagnostic` from it for an `error` stop (never for an abort).

### Why

- A pool refused locally ended the turn as "The provider returned an error that could not be classified (anthropic-subscription, no code)", because the stream set only `errorMessage` and `provider-failure.ts` then reports `unknown` (code-yeongyu/oh-my-openagent#11683). Same class as the chatgpt-subscription fix (#3771).

### Why an extension could not handle it

- This is the anthropic-subscription extension's own stream adapter.

### Expected merge conflict zones

- LOW: the catch block of `streamAnthropicSubscription` in `stream.ts`.

## 2026-10-28 - Account-pool refusal tokens in the provider diagnostic vocabulary (#4676)

### What changed

- `packages/ai/src/utils/provider-diagnostic-vocabulary.ts`: `categoryForProviderCode` accepts `account_pool_auth_blocked` (`auth`) and `account_pool_blocked` (`rate_limit`). Neither is compatible with any HTTP status, since the refusal is local.

### Why

- A subscription extension that refuses a request from its own account pool needs a code that survives `sanitizeProviderDiagnostic`; an opaque code may only name an `unknown` failure, and one code maps to one category, hence two tokens (#4676).

### Why an extension could not handle it

- The vocabulary is the closed allowlist every diagnostic is revalidated against.

### Expected merge conflict zones

- LOW: the `auth` and `rate_limit` arms of `categoryForProviderCode`.
