## 2026-11-05 - Session entries on the store's append-only record log (S21b-a, senpi#5950)

### What changed

- `packages/agent/src/durable/session-store.ts`: a session's entries are records in the store's append-only log, one kind per session (`session/<id>`). A record is an append (one entry) or a rewrite (the full header and entries, replacing everything before it). `readSessionState` reads the last rewrite plus every later append in seq order (a key seen twice keeps its first record). The manifest document holds only the header a new session starts with, and its divergence. `sessionManifestKey`, `sessionRecordKind`, `manifestWrite`, `appendRecordWrites` and `rewriteRecordWrite` are the one layout both writers use. A handle still refuses a duplicate key against the entries it holds.
- `packages/agent/src/index.ts`: exports that layout (and `SessionState`) from the main entry for the S07 importer.

### Why

Measured: two processes bound to one session, each appending, kept only one writer's entries. Each handle held the entry list in memory and wrote the whole manifest per append, so the last writer won. Row S21b (senpi#5822) needs co-bound Bun processes to keep writing. The store contract (DurableStore/SyncCommitStore) does not change.

### Why an extension could not handle it

The session store's own storage layout.

### Expected merge conflict zones

`session-store.ts` (layout functions, readSessionState, planAppend/planRewrite, the open handles); the durable-store export block in `packages/agent/src/index.ts`.

## 2026-11-05 - The S07 importer writes the shared record-log layout (S21b-a, senpi#5950)

### What changed

- `packages/coding-agent/src/core/session-import/jsonl-import.ts`: it reads sessions through `readSessionState` and writes through the shared layout. A file that only adds entries after the held ones (same header and divergence) is appended as records; any other change rewrites the session from the file, with S07's outcomes, divergence and ledger as before. A stored divergence is parsed into its typed shape.

### Why

The importer wrote the same manifest layout directly and raced a co-bound appender the same way (an extending import dropped an entry appended meanwhile).

### Why an extension could not handle it

The importer is the durable store's own JSONL writer.

### Expected merge conflict zones

`importFile`'s write planning and `getSession`/`recordProjection` in `jsonl-import.ts`.
