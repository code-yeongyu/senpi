## 2026-11-15 - Extensions load by placement and read it as `pi.placement` (senpi#6756)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: new `ExtensionPlacement` (`"fused" | "hand" | "hosted-hand"`). `ExtensionSessionProfile.side?` is replaced by a required `placement`, and `DEFAULT_EXTENSION_SESSION_PROFILE` carries `placement: "fused"`. `ExtensionAPI` gains the read-only `placement`. The `HandlerRegistrationOptions.runs` doc names which placement registers what.
- `packages/coding-agent/src/core/extensions/loader.ts`: `ExtensionSessionOptions.side?` is replaced by `placement?` (absent: `"fused"`). `sessionProfile()` fills it, `createExtensionAPI` puts it on `pi`, and `pi.on` registers a handler declared `runs` only when `registersSide(placement, runs)` holds. `loadExtensions` takes its options through a generic that types every key it does not name as `never`, so a stray key (the removed `side` included, also from a spread) fails to compile instead of being ignored.
- `packages/coding-agent/src/core/extensions/placement.ts` (new): `registersSide`, exhaustive over the placements. `"hand"` (a split-local hand) does not register `runs: "brain"`; `"fused"` and `"hosted-hand"` register both sides.

### Why

- No caller set a side, so the `runs` filter was inert, and nothing told an extension where it ran. A hosted hand loaded with a hand side would have dropped every `runs: "brain"` loop hook, although the hosted loop forwards those events to it (the hand is the extensions' home). One placement value, set by the host that builds the runtime, now drives both the filter and what the extension reads.

### Why an extension could not handle it

- The registration filter and the `pi` object are the loader's; an extension cannot learn its own placement or keep the loader from dropping its handlers.

### Expected merge conflict zones

- LOW: `ExtensionSessionProfile`, `DEFAULT_EXTENSION_SESSION_PROFILE`, the Session Context block at the head of `ExtensionAPI` and the `HandlerRegistrationOptions.runs` doc in `types.ts`.
- LOW: the type import list, `ExtensionSessionOptions`/`sessionProfile()`, the head of the `api` object in `createExtensionAPI`, the `runs` check in `pi.on`, and the `loadExtensions` signature in `loader.ts`.

## 2026-11-15 - The resource loader carries the extensions' placement (senpi#6756)

### What changed

- `packages/coding-agent/src/core/resource-loader.ts`: `DefaultResourceLoaderOptions.placement?` (an `ExtensionPlacement`, default `"fused"`) joins `sessionKind`/`sessionContext` in the extension session profile every load uses.

### Why

- The host that builds a runtime knows where its extensions run; this option carries that to the loader, which sets `pi.placement` and filters `runs` by it.

### Why an extension could not handle it

- The extension session profile is built by the resource loader before any extension loads.

### Expected merge conflict zones

- LOW: the extension type import list, `DefaultResourceLoaderOptions`, and the `extensionSession` assignment in the `DefaultResourceLoader` constructor.

## 2026-11-15 - A loopless hand loads its extensions as a hand or a hosted hand (senpi#6756)

### What changed

- `packages/coding-agent/src/modes/rpc/runtime-factory-loopless.ts`: the resource loader gets `placement: "hosted-hand"` when the runtime is its extensions' home (`twoSidedHome: "hand"`, which `runHand` passes for `senpi --hand` since #6747), otherwise `"hand"`.
- `packages/coding-agent/test/suite/regressions/6756-hand-keeps-brain-handlers.test.ts` (new): a spawned `senpi --hand` runs a user extension's `runs: "brain"` `input` handler for a forwarded `input` loop hook, and the extension reads `"hosted-hand"`.

### Why

- A hosted hand runs its extensions' loop hooks for the hosted loop, so it must keep their `runs: "brain"` handlers; a split-local hand leaves them to its loop.

### Why an extension could not handle it

- The runtime factory is the only place that knows which kind of hand it builds.

### Expected merge conflict zones

- LOW: the `resourceLoaderOptions` object in `createLooplessRuntimeFactory`.

### Added

- Extensions can read where they run as `pi.placement`: `"fused"`, `"hand"` (the tool side of a split-local session) or `"hosted-hand"` (the tool side of a hosted session, the extensions' home). `senpi --hand` loads its extensions as `"hosted-hand"` and keeps their handlers declared `runs: "brain"`, so the hosted loop's `input` and `before_agent_start` hooks reach them; a split-local hand does not register them ([#6765](https://github.com/code-yeongyu/senpi/pull/6765))

### Changed

- The `loadExtensions` option `side` is replaced by `placement`, and `ExtensionSessionProfile.side` by `placement`. `loadExtensions` now rejects an option key it does not know at compile time ([#6765](https://github.com/code-yeongyu/senpi/pull/6765))
