## 2026-11-22 - Claude pool account names are display-only for fallback (senpi#4712)

### What changed

- `packages/coding-agent/src/core/retry-fallback/classification-text.ts` keeps the fixed pool refusal heading, optional model-limit prelude, and trailing retry marker in the classifier input.
- `packages/coding-agent/src/core/retry-fallback/billing.ts`, `packages/coding-agent/src/core/retry-fallback/usage-limit.ts`, and `packages/coding-agent/src/core/retry-fallback/circuit-probes.ts` classify that input, including when the session formats exhausted rungs.
- `packages/coding-agent/src/core/retry-fallback/circuit.ts`, `packages/coding-agent/src/core/retry-fallback/cooldown.ts`, `packages/coding-agent/src/core/retry-fallback/limit-reset.ts`, and `packages/coding-agent/src/core/retry-fallback/transient-network.ts` use the same input for circuit, cooldown, reset, and network-blip decisions.
- `packages/coding-agent/src/core/turn-retry-eligibility.ts` and `packages/coding-agent/src/core/agent-session.ts` exclude the account list from turn retry and delay checks. The held-pool account summary is still appended only when displaying the already classified account limit.

### Why

- An account named `billing-team` or `Opus weekly limit` could turn an authentication error into a billing or usage-limit fallback.

### Why an extension could not handle it

- The core fallback engine classifies failures and formats exhausted rungs, including errors already stored as text.

### Expected merge conflict zones

- LOW: fallback classifier entry points and the session's turn retry checks.

## 2026-11-22 - Share Claude pool refusal headings with fallback (senpi#4712)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/guidance.ts` and `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/stream-guidance.ts` share the fixed refusal heading and model-limit lead with the classifier. Rendered guidance is unchanged.

### Why

- The fallback engine needs the pool's summary and retry hint without interpreting account names as error codes.

### Why an extension could not handle it

- This builtin renders the guidance, but the core engine owns retry classification.

### Expected merge conflict zones

- LOW: the all-account refusal heading and model-limit lead.
