## 2026-11-05 - A session's ownership is readable before a write (senpi#5889)

### What changed

- `packages/coding-agent/src/core/session-manager.ts`: new `getOwnership()` answers who may write the file now, from the
  write guard's own fold over `fileEntries` (the one every persisted write is checked against).
- `packages/coding-agent/src/core/session-move/write-guard.ts`: the incremental fold is public as `ownership(entries)`;
  `assertWritable`, `assertRewritable` and `isWritable` read it unchanged.

### Why

- RPC admission must refuse input into a sealed file before a `prompt` is accepted. The guard refused it only when the
  turn persisted the user message, after the client had already been told the prompt started.

### Why an extension could not handle it

- The ownership fold lives inside the session manager's write path; extensions see neither the guard nor `fileEntries`.

### Expected merge conflict zones

- LOW: the `getSessionFile` / `getOwnership` accessors in `session-manager.ts` and its import block.

## 2026-11-05 - A write into a sealed session is refused with session_moved_away (senpi#5889)

### What changed

- `packages/coding-agent/src/modes/rpc/client-input-handler.ts`: a new admission of `prompt`, `steer` or `follow_up` checks
  `sessionManager.getOwnership()` first and throws `SessionMovedAwayError` for a session that is moving or moved. The
  refusal carries `errorCode: "session_moved_away"` and `errorData: { state }`. A replay of an already admitted id is
  answered as before.
- `packages/coding-agent/docs/rpc.md`: the "Sealed session" refusal.

### Why

- Clients branch on a refusal's code, never its text. The refusal had no code, and a `prompt` was accepted before its
  turn failed to write, so a client could not show a read-only session with a copy action (omo-desktop-app#4049).

### Why an extension could not handle it

- Admission and its refusal records are the RPC host's; no extension hook runs before a prompt is accepted.

### Expected merge conflict zones

- LOW: the top of the `admissions.admit` callback and the refusal spread at the end of `handleClientInput`.
