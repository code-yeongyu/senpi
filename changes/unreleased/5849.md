## 2026-11-05 - pi.executeTool() runs on the prepared ToolHost (senpi#5849)

### What changed

- `packages/coding-agent/src/core/execute-tool-on-host.ts` is new: `runExecuteToolOnHost()` runs one `executeTool()` call as a one-call sequential batch on `createPreparedToolHost`, with the agent's batch store, execution scope and `onExecutionPipeline` witness sink. The caller's signal and `onUpdate` reach the tool body unchanged, a thrown body keeps today's `{ details: { isError: true } }` result, the session's `tool_call` and `tool_result` chains run in the host's preflight and finalize steps, and a block or a hook failure is returned to the caller as before.
- `packages/coding-agent/src/core/agent-session.ts`: `executeTool()` keeps its tool lookup and `invalid_params` check, then runs the call through `runExecuteToolOnHost()` instead of calling `tool.execute()` itself. Its preflight waits on the event queue as it stood when the call was made, as before.

### Why

Plan row S19a (senpi#5826): every tool body runs on the ToolHost, so no `executeTool()` call reaches a tool without the prepared executor's prepare, freeze and release.

### Why an extension could not handle it

`executeTool()` is the session's own extension API method; an extension cannot change how the session runs it.

### Expected merge conflict zones

`agent-session.ts` in `executeTool()` and its imports.
