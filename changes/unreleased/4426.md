## 2026-10-27 - Never exchange a managed account-pool sentinel (senpi#3924)

### What changed

- `packages/ai/src/auth/resolve.ts`: `resolveStoredOAuth` refuses a stale credential whose `access` and `refresh` are the provider's managed-sentinel material (`managedSentinelMaterials`) with a `ModelsError("auth")` instead of calling `refreshOAuthCredential`, so the placeholder never reaches a provider's token endpoint.

### Why

- A pooled provider's flat entry is not an account. For a provider-managed pool it is the `<provider>-managed` sentinel with `expires: 0`, so a request that resolved it without a slot sent the sentinel to the token endpoint: every compaction on a pooled `chatgpt-subscription` failed with a 401 while the session's own turns, leased on the pinned slot, kept working.

### Why an extension could not handle it

- Staleness and the refresh call live inside `resolveStoredOAuth`, below every extension hook.

### Expected merge conflict zones

- LOW: the staleness block at the top of `resolveStoredOAuth` in `auth/resolve.ts`.

## 2026-10-27 - Session-scoped auth for auxiliary requests (senpi#3924)

### What changed

- `packages/coding-agent/src/core/model-registry.ts`: `getApiKeyAndHeaders(model, { sessionId })`; with a session id it resolves through `ModelRuntime.getSessionAuth`, without one it is unchanged.
- `packages/coding-agent/src/core/model-runtime.ts`: `getSessionAuth(model, sessionId)` resolves the slot the rotation stream would pick for that session (same policy gates: runtime key, `credentials.rotation: false`, `ownsAccountSelection`), and falls back to `getAuth(model)` when the provider holds no pool.

### Why

- A pooled provider's flat entry is not an account. For a provider-managed pool it is the `<provider>-managed` sentinel with `expires: 0`, so a request that resolved it without a slot sent the sentinel to the token endpoint: every compaction on a pooled `chatgpt-subscription` failed with a 401 while the session's own turns, leased on the pinned slot, kept working. Approach adapted from #2049 by @youngminsw.

### Why an extension could not handle it

- Auth resolution for a direct provider call is `ModelRegistry`/`ModelRuntime` state; an extension cannot read the credential pool's slot health or the stream's pick.

### Expected merge conflict zones

- LOW: `getApiKeyAndHeaders` in `model-registry.ts`; the new `getSessionAuth`/`sessionSlotAuth` beside `getAuth` in `model-runtime.ts`.

## 2026-10-27 - One slot pick for the stream and auxiliary callers (senpi#3924)

### What changed

- `packages/coding-agent/src/core/credential-pool/session-slot.ts` (new): `pickRotationSlot` (pin, else affinity order with the user's account order) and `selectSessionSlot` (that pick over unblocked accounts, else over all, so a blocked session account is reported rather than swapped).
- `packages/coding-agent/src/core/credential-pool/rotation-stream.ts`: `streamWithCredentialRotation`'s `select` calls `pickRotationSlot`; re-exports `selectSessionSlot`.
- `packages/coding-agent/src/core/credential-pool/failover.ts`: `isAvailable` is exported.

### Why

- Auxiliary requests must authenticate as the account the session's turns use; sharing the pick keeps the two from drifting.

### Why an extension could not handle it

- Slot selection is internal to the credential pool.

### Expected merge conflict zones

- LOW: the `select` callback in `rotation-stream.ts`; the `isAvailable` export in `failover.ts`.

## 2026-10-27 - Compaction authenticates as the session's account (senpi#3924)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/compaction/speculative.ts`, `compaction/openai-remote.ts`, `compaction/index.ts`: `getApiKeyAndHeaders` receives `{ sessionId: sessionManager.getSessionId() }`; the remote-compaction context type accepts the option.

### Why

- A pooled provider's flat entry is not an account. For a provider-managed pool it is the `<provider>-managed` sentinel with `expires: 0`, so a request that resolved it without a slot sent the sentinel to the token endpoint: every compaction on a pooled `chatgpt-subscription` failed with a 401 while the session's own turns, leased on the pinned slot, kept working.

### Why an extension could not handle it

- The builtin is the caller; the fix is passing its session to the registry.
