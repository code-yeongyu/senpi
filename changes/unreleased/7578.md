## 2026-11-27 - `senpi trash` routes before argument parsing (omo#11072, senpi#7578)

### What changed

- `packages/coding-agent/src/main.ts`: `dispatchTrashCommand(args)` runs right after the `schedule` route, BEFORE `parseArgs`, and exits with the code it returns, so `senpi trash list|restore|empty` never falls through into argument parsing or a session. The implementation is `src/cli/trash-command.ts` behind an `await import(...)` in `src/cli/deferred-commands.ts`; the trash core, the `deletePolicy` setting and the `trash` tool live in the new builtin `core/extensions/builtin/delete-policy/`.

### Why

- omo#11072: an agent permanently deleted worktrees despite a "use trash, never rm" rule. The approved design ships a trash core, a `trash` tool and a user-side `trash` CLI first (PR a of 3); the user needs `list`, `restore` and `empty` from a terminal, including on headless Linux where no file manager exists.

### Why an extension could not handle it

- Extensions register tools, commands and flags inside a session; a top-level subcommand that must run without starting a session or parsing session arguments has to be routed in `main.ts`, exactly like `host` and `schedule`.

### Expected merge conflict zones

- LOW: the import list from `./cli/deferred-commands.ts` and the block of exit-code dispatches (`host`, `schedule`, `trash`) just before `parseArgs(args)` in `main()`.

### Added
- Deletes can go to the trash instead of being permanent (omo#11072, part 1 of 3). The new `trash` tool moves files and directories to a restorable trash: the freedesktop trash (`~/.local/share/Trash`) on Linux and, by default, on macOS too, as a same-volume rename that takes milliseconds; `deletePolicy.macosTrash: "os"` uses the Finder Trash through `/usr/bin/trash` instead, which cost 35-38 s per call from a background session. It always stays on the item's own volume and refuses rather than copying across devices. `senpi trash list|restore <id>|empty [--older-than <n>d|--all]` manages the trash from a terminal. The new `deletePolicy` setting (`trash` by default, `trash-only`, or `log-only`, the default when `CI=true`) bounds that trash with `retentionDays` and `maxTrashBytes`. Every permanent delete is appended to `audit/deletes.jsonl` in the agent directory ([#7578](https://github.com/code-yeongyu/senpi/pull/7578)).
