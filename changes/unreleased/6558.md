## 2026-11-12 - Project verbs refuse user-global files by real path, from the loader's own root list (senpi#6547)

### What changed

- `packages/coding-agent/src/core/skills.ts`: `userGlobalSkillRoots()` is the one list of user-global skill roots (the agent dir's skills root, `~/.agents/skills`, user-selected roots); `loadSkills` builds its skill allowlist from it.
- `packages/coding-agent/src/core/resource-loader.ts`: `ResourceLoader.getUserSkillRoots()` exposes the exact list `updateSkillsFromPaths` passes to `loadSkills` (package-resolved user selections plus global `skills` settings paths), so there is no second assembly.

### Why

- The senpi#6547 security review (CLEAR, 2 LOWs): a session opened in `$HOME` could read and rewrite `~/.agents/skills/<x>/SKILL.md` through `read_project_skill_file` / `write_project_skill_file` (the refusal covered only the agent dir), and `read_project_file` / `write_project_file` never refused at all, reaching `.pi/agent/AGENTS.md`, the global context file. A project verb must reach only the project folder's own files, never user-global configuration.

### Why an extension could not handle it

- The refusal is a containment decision inside the RPC verbs' path resolution, and the root list is the loader's own allowlist source; both are core runtime code no extension can replace or observe early enough.

### Expected merge conflict zones

- LOW: the `userGlobalSkillRoots` extraction and the allowlist call in `skills.ts`; the `getUserSkillRoots` member on `ResourceLoader` / `DefaultResourceLoader` and the `userSkillRoots` argument in `updateSkillsFromPaths`; the refusal call sites in `modes/rpc/project-file-commands.ts`, `project-skill-commands.ts` and `project-mcp-commands.ts`, and the shared helper in `modes/rpc/project-file-path.ts`.

### Fixed
- RPC: `read_project_file` / `write_project_file`, `read_project_skill_file` / `write_project_skill_file` and `get_project_mcp_servers` / `set_project_mcp_servers` refuse a file whose real path lies in the agent dir or in any user-global skill root the engine loads (`~/.agents/skills`, a selected skill root), so a session opened in `$HOME` can no longer read or edit global skills, the global context file or the global MCP file through the project verbs; the root list is derived from the loader's own skill allowlist (senpi#6547 review)
