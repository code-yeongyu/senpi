## 2026-11-13 - Native external wake preserves message provenance and current admission

### What changed

- `packages/coding-agent/src/core/external-wake.ts` adds source-bound, opaque wake permits and idempotent results. `packages/coding-agent/src/core/session-control-actions.ts` retires sources with their extension generation. `packages/coding-agent/src/core/external-admission.ts` exposes its current closure and admission generation to the native wake path.
- `packages/coding-agent/src/core/agent-session.ts` starts native inspection with a run-scoped system instruction, validates admission after asynchronous preparation, preserves cancellation through retry, and removes the instruction before a queued ordinary prompt. Existing non-consuming preview preparation preserves configured system policy; message-oriented preparation remains for ordinary prompts.
- `packages/coding-agent/src/core/messages.ts` excludes the UI-only wake marker from model input. `packages/coding-agent/src/core/provider-composer.ts` selects one actual transport for both streaming and capability checks. `packages/coding-agent/src/core/model-runtime.ts` enforces the request constraint after auth and semaphore waits.

### Why

- `packages/coding-agent/src/core/external-wake.ts`, `packages/coding-agent/src/core/external-admission.ts`, and `packages/coding-agent/src/core/session-control-actions.ts`: Stop, draft changes, cancellation, expiry, session replacement and reload must prevent a late wake, while duplicate requests must not create another run.
- `packages/coding-agent/src/core/agent-session.ts` and `packages/coding-agent/src/core/messages.ts`: a local signal to inspect external data must not become a user message or consume pending user context. The data itself remains a genuine read-tool result.
- `packages/coding-agent/src/core/provider-composer.ts` and `packages/coding-agent/src/core/model-runtime.ts`: a familiar API name cannot establish the properties of an overridden or auth-selected transport.

### Why an extension could not handle it

- `packages/coding-agent/src/core/external-wake.ts`, `packages/coding-agent/src/core/external-admission.ts`, `packages/coding-agent/src/core/session-control-actions.ts`, and `packages/coding-agent/src/core/agent-session.ts` own atomic native admission, current editor/Stop state, run settlement and generation retirement. An extension cannot reproduce those guarantees with queued messages.
- `packages/coding-agent/src/core/messages.ts`, `packages/coding-agent/src/core/provider-composer.ts`, and `packages/coding-agent/src/core/model-runtime.ts` own conversion and final provider dispatch, after extension-level checks have already completed.

### Expected merge conflict zones

- MEDIUM: `packages/coding-agent/src/core/agent-session.ts` request projection, prompt claim and settlement; `packages/coding-agent/src/core/model-runtime.ts` token-recovery dispatch.
- LOW: `packages/coding-agent/src/core/external-admission.ts` state accessors; `packages/coding-agent/src/core/session-control-actions.ts` generation retirement; `packages/coding-agent/src/core/messages.ts` custom conversion; `packages/coding-agent/src/core/provider-composer.ts` transport selection. `packages/coding-agent/src/core/external-wake.ts` is new.

## 2026-11-13 - Transport-declared non-user continuation

### What changed

- `packages/ai/src/types.ts` defines the optional transport capability and request constraint. `packages/ai/src/models.ts` inspects the actual model's transport. `packages/ai/src/api-registry.ts` and `packages/ai/src/compat.ts` preserve the declaration through scoped and compatibility registration.

### Why

- `packages/ai/src/types.ts`, `packages/ai/src/models.ts`, `packages/ai/src/api-registry.ts`, and `packages/ai/src/compat.ts`: a provider can override an existing API or select another transport for a model. Undeclared support must remain false on that actual path.

### Why an extension could not handle it

- `packages/ai/src/types.ts`, `packages/ai/src/models.ts`, `packages/ai/src/api-registry.ts`, and `packages/ai/src/compat.ts` own transport contracts, resolution and registration below extension admission.

### Expected merge conflict zones

## 2026-11-13 - Bound lint batches by command-line length on Windows

### What changed

- `scripts/lint-ratchet.mjs` bounds batches by executable/argument size as well as file count and reports the operating system's spawn error. Its CLI regression runs the real linter against a corpus larger than the Windows command limit and verifies every diagnostic.
- `scripts/realm-census.json` classifies the external wake reducer as immutable methods whose mutable map is allocated per session history.

### Why

- `scripts/lint-ratchet.mjs` previously sent 107,438 characters for a 2,000-file batch, exceeding Windows CreateProcess's 32,767-character limit. The mandatory check stopped with an uninformative null status before assessing the code.
- `scripts/realm-census.json` records that duplicate suppression does not share mutable delivery state across sessions or module copies.

### Why an extension could not handle it

- `scripts/lint-ratchet.mjs` is repository validation tooling; extensions do not control its subprocess arguments.
- `scripts/realm-census.json` is the repository's module-state audit, outside the extension runtime.

### Expected merge conflict zones

- LOW: `scripts/lint-ratchet.mjs` subprocess helper and tracked-file batching loop.
- LOW: `scripts/realm-census.json` additive reducer classification.
