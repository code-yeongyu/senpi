## 2026-11-27 - A startup phase that keeps reporting progress is extended, not cut at its allowance (senpi#7545)

### What changed

- `packages/coding-agent/src/modes/rpc/host-startup-wire.ts`: `StartupMilestone` gains `progress`, a record that completes nothing; `STARTUP_PROGRESS_INTERVAL_MS` (2 s) is how often a coordinated producer sends it.
- `packages/coding-agent/src/modes/rpc/host-startup-beacon.ts`: `reportStartupProgress(report, budgetMs)` sends `progress` from the producer's own event loop every interval until the attempt's decision budget has passed; the supervisor and the host child (through the existing relay) both run it while coordinated. Neither timer keeps the process alive.
- `packages/coding-agent/src/modes/rpc/host-startup-events.ts`: a `progress` record extends the current phase only when it comes from the producer that owns that phase; from the other producer it is `ignored`, not a protocol failure. Progress records keep the strict per-producer sequence and have their own cap (256) apart from the 32-milestone cap.
- `packages/coding-agent/src/modes/rpc/host-startup-policy.ts`: `StartupController.progress()` moves the phase deadline to `STARTUP_PROGRESS_STALL_MS` (15 s) after the report when that is later, still clipped to `STARTUP_DECISION_BUDGET_MS` (180 s, unchanged). A phase that reported progress and then went quiet for the stall bound times out with `limit: "stall"`; the phase allowance is the first window only.

### Why

- On a loaded machine (agents-newyork-1, load average ~35 on 14 cores) ensure SIGTERMed shard supervisors that were slow but working: one logged `senpi rpc host ready on …/p-3999df8d9c179431.sock` and was stopped with `readiness_timeout` after 18.4 s, and others failed with `phase=public_published; limit=phase; phase_budget_ms=15000; elapsed_ms=16808`. A fixed per-phase allowance cannot tell a slow host from a stuck one; a progress report from the host's own event loop can.

### Why an extension could not handle it

- The startup controller, the startup pipe and the supervisor's beacon run before any extension loads, in the launcher and the supervisor, which run no extensions.

### Expected merge conflict zones

- LOW: `host-startup-policy.ts` `startStartupController` (`enter`/`expire` and the returned controller).
- LOW: `host-startup-events.ts` `startupEventIngress`, the record dispatch after the sequence checks.

### Fixed
- An RPC host that starts slowly on a loaded machine is no longer stopped while it is still making progress: each startup phase is extended while the host keeps reporting progress, and fails only after 15 s without a report (the 180 s overall startup budget is unchanged) ([#7545](https://github.com/code-yeongyu/senpi/pull/7545))
