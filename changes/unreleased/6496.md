## 2026-11-12 - The no-follow lock open comments claim only what holds (senpi#6496)

### What changed

- `packages/coding-agent/src/modes/rpc/sqlite-file-identity.ts`, `packages/coding-agent/src/modes/rpc/ownership-safe-lock.ts`: comments only. SQLITE_OPEN_NOFOLLOW is checked while SQLite resolves the path; the open after it applies O_NOFOLLOW to the last component only, so a directory swapped for a symbolic link in between is still followed (same-user attacker only). A file on a user-mounted FUSE filesystem can also make an open block.

### Why

- Review of senpi#6493 at df07ba75f8, LOW 1: the comments said no link is ever followed and that a blocking device needs `mknod` privilege.

### Why an extension could not handle it

- The publish lock is an RPC host internal that runs before extension loading.
