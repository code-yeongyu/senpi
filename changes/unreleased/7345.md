## 2026-11-22 - show_html_page reports an inline display from the client's inline_html capability (senpi#6346)

### What changed

- `packages/agent/src/execution/remote-protocol.ts`
- `packages/agent/src/execution/remote-tool-host.ts`
- `packages/agent/src/execution/remote-executor.ts`: a `RemoteInvoke` carries the optional boolean `inlineHtml` (validated on decode), the remote tool host reads it per batch from its new `inlineHtml` option, and the executor hands it to the hand's `HandCall`.

### Why

- show_html_page read the `app` prompt surface as "this host renders the page inline", but the prompt surface only says how replies are formatted, so a client that opens with `app` and renders no pages got a result claiming the reader saw the page (senpi#6346).

### Why an extension could not handle it

- The tool's result depends on what the connected RPC client declared in the handshake, and only the RPC connection handler, the extension runner's tool context and the brain/hand call wire carry that to the tool.

### Expected merge conflict zones

- LOW: the touched spots are fork-only additions next to the senpi#6921 `promptSurface` plumbing.
