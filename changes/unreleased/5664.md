### Added
- Two-sided extensions on a split session: an extension that registers loop events and `tool_call`/`tool_result` without `runs` declarations keeps one state. On the hand, its tool events are forwarded to the loop that owns the call (the call's nested `extension-events` plane), and the reply is applied as a local handler's result would be. The forward fails closed when the loop's process lacks that extension's handlers. Builtins and fused/headless sessions are unchanged ([#5664](https://github.com/code-yeongyu/senpi/pull/5664)).

## 2026-11-03 - Two-sided extension event forwarding (senpi#5664)

### What changed

- `packages/coding-agent/src/core/extensions/two-sided-forwarding.ts` is new: the two-sided classification (builtins excluded), the hand's forwarder, and the loop's `extension-events` plane handler (fail-closed).
- `packages/coding-agent/src/core/extensions/runner.ts`: `emitToolCall`/`emitToolResult` take `{ forward, only }`. A forwarded extension is replaced at its registration position. Adds `extensionHandles()` and `twoSidedExtensionPaths()`.

### Why

Brain/hand split S29 (decision C7(c)): an unmodified extension whose loop and tool hooks share in-memory state must see one state on a split session.

### Why an extension could not handle it

The dispatch of every extension's tool events is the runner's.

### Expected merge conflict zones

`runner.ts` `emitToolCall` and `emitToolResult` loop heads, and the accessor block near `getExtensionPaths`.

## 2026-11-03 - Nested requester for loopless tool handlers (senpi#5664)

### What changed

- `packages/coding-agent/src/modes/rpc/loopless-tool-call.ts`, `loopless-tool-handlers.ts`, `runtime-factory-loopless.ts`, `remote-executor-scope.ts`: the hand call's `nested` requester reaches the `tool_call`/`tool_result` handlers, which forward a two-sided extension's events through it.

### Why

Brain/hand split S29: forwarding rides the call's own nested plane (S31).

### Why an extension could not handle it

The loopless runtime's execute path is core.

### Expected merge conflict zones

`runtime-factory-loopless.ts` `execute` wiring; `loopless-tool-call.ts` handler event shapes.
