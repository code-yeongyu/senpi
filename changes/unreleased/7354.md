## 2026-11-22 - An accepted socket is released on the peer's FIN (senpi#7354)

### What changed

- `packages/coding-agent/src/modes/rpc/internal-record-stream.ts`: the host side of the sealed internal hop is built with `allowHalfOpen: false`. After the peer's FIN it ends its own side once queued writes are out, then closes. The supervisor side keeps `allowHalfOpen: true`.
- `packages/coding-agent/src/modes/rpc/rpc-public-auth.ts`: after the socket's `end` and the reader's last line, `PublicRpcConnection` ends the socket and destroys it once the end is flushed.
- `packages/coding-agent/src/modes/rpc/host-handoff-announcement.ts`: `deliverLate` reads the stream to the peer's FIN after it writes the `host_superseded` record.
- `packages/coding-agent/src/modes/rpc/multi-session-host.ts`: a listener `close` outside shutdown logs `senpi rpc socket listener closed: <address> accepts no connection`.
- `packages/coding-agent/src/modes/rpc/host-lifecycle-proxy.ts`: when the host child refuses the proxy's hop, the supervisor logs `host child refused a client connection on <socket> (<reason>); resetting public connections until it accepts again`, once per outage. It logs `host child accepts connections again after refusing <n>` when the child accepts again.
- `packages/coding-agent/test/suite/rpc-accepted-socket-release.test.ts` (new), `packages/coding-agent/test/suite/rpc-host-socket-churn.test.ts` (new).

### Why

- oh-my-openagent#14725: a socket host on macOS under Bun held about 10,000 accepted unix sockets whose peers had gone, until it reached the process fd limit and stopped accepting. Every connection is served through a wrapper stream that stayed half-open after the peer's FIN, so the socket was released only when the runtime turned the FIN into a close. Node and Bun on Linux do; those macOS hosts did not.
- A host whose listener closed went on running its sessions with no log line, and its supervisor reset every public connection without saying why.

### Why an extension could not handle it

- The accepted-socket lifecycle, the internal hop and the public key filter belong to the RPC host's transport. No extension API reaches them.

### Expected merge conflict zones

- NONE upstream: these RPC host files are fork-only.
