## 2026-11-23 - A host answers a peer's last requests, then ends the connection on its FIN (senpi#7354)

### What changed

- `packages/coding-agent/src/modes/rpc/host-peer-end.ts` (new): `PendingReplies` tracks the replies one connection still owes; `endAfterPeerFin` waits after the peer's FIN for them to settle and for the connection's queue to flush, then closes, within `PEER_END_REPLY_GRACE_MS` (30 s).
- `packages/coding-agent/src/modes/rpc/multi-session-host.ts`: the socket listener is `allowHalfOpen: true`. `serve()` tracks every dispatched line (and the oversized-line answer) and arms `endAfterPeerFin` after the line reader; the close is the socket sink's half-close, destroyed after `SOCKET_CUT_GRACE_MS`. A listener `close` outside shutdown logs `senpi rpc socket listener closed: <address> accepts no connection`.
- `packages/coding-agent/src/modes/rpc/predecessor-endpoint.ts`: the successor route listener is `allowHalfOpen: true`; its connections go through `serve()` too.
- `packages/coding-agent/src/modes/rpc/rpc-public-auth.ts`: the peer's FIN ends the filter's released input (after its last line), no longer the socket. The router view ends its readable side on that end and is destroyed only once the socket is gone.
- `packages/coding-agent/src/modes/rpc/host-handoff-announcement.ts`: a connection delivered its `host_superseded` record during a drain is read to the peer's FIN, so it closes.
- `packages/coding-agent/src/modes/rpc/host-lifecycle-proxy.ts`: the public proxy listener is `allowHalfOpen: true`. An unsealed hop (Windows) is awaited to its connection outcome like the sealed one, so a refusal of either logs `host child refused a client connection on <socket> (<reason>); resetting public connections until it accepts again`, once per outage, and the recovery logs `host child accepts connections again after refusing <n>`.
- `packages/coding-agent/src/modes/rpc/host-admission-proxy.ts`: the request reader iterates with `destroyOnReturn: false`, so the client's FIN no longer destroys the client; after the FIN the client is ended when the host side ends, or cut at `PROXY_CLIENT_END_GRACE_MS` (35 s, longer than the host's own 30 s, and kept in this module because the supervisor's module graph is budgeted); with no hop (a stopping supervisor) it is ended once its replies are out.
- Tests: `test/suite/rpc-host-peer-fin.test.ts`, `test/suite/rpc-host-peer-end.test.ts`, `test/suite/rpc-public-proxy-hop.test.ts`, `test/suite/rpc-host-socket-churn.test.ts`, `test/helpers/rpc-host-socket-count.ts` (new); `test/fixtures/rpc-lifecycle-clock.ts` takes `createServer`'s options form, which the proxy now uses.

### Why

- oh-my-openagent#14725: socket hosts on macOS under Bun held about 10,000 accepted unix sockets whose peers had gone. Nothing in the host ended a connection on the peer's FIN; whether the socket closed depended on the runtime. Where the runtime ended it at once (Node), the replies still owed were lost: a peer that sent its last request and half-closed got EOF instead of the answer, on the bare and the supervised path alike.
- A host whose listener closed kept running its sessions with no log line, and a supervisor whose host child refused its hop reset every public connection without saying so; on Windows the refusal never reached the logging path at all.

### Why an extension could not handle it

- The accepted-socket lifecycle, the public key filter and the supervisor proxy belong to the RPC host's transport. No extension API reaches them.

### Expected merge conflict zones

- NONE upstream: these RPC host files are fork-only.

### Fixed
- A socket host answers the requests a peer sent before its FIN and then ends the connection, within 30 s, whatever the runtime does with the FIN; a long-running host no longer keeps connections whose peers are gone, and a peer that half-closes after its last request gets the answer ([#7354](https://github.com/code-yeongyu/senpi/pull/7354))
- A host whose listener closes outside shutdown logs it, and the supervisor logs once when its host child refuses the connections it proxies, on every platform ([#7354](https://github.com/code-yeongyu/senpi/pull/7354))
