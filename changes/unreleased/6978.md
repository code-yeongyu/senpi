### Added

- Eval kernels attest the processes they run for a session: a python, ruby or julia kernel, or a process-isolated JavaScript kernel, is recorded for its session, so every command it starts (a `Bun.$` command included) resolves to that session; a worker-thread JavaScript kernel attests the `Bun.spawn` children it reports. A `Bun.$` command of a worker-thread kernel is not attested ([#6978](https://github.com/code-yeongyu/senpi/pull/6978))

## 2026-11-18 - Answer `session-of-pid` before the engine loads (#6978)

### What changed

- `packages/coding-agent/src/index.ts` exports `attestSessionSpawn`, `resolvePidSession`, `sessionSpawnsDir` and their types, so the codemode extension attests the kernel processes it spawns for a session.
- `packages/coding-agent/src/cli.ts`, `packages/coding-agent/src/bun/cli.ts` and `packages/coding-agent/src/cli-main.ts` call `dispatchSessionOfPidCommand()` (new `src/cli/session-of-pid-command.ts`) right after the agent-directory command. `session-of-pid <pid> --json` prints one version-1 JSON record from `resolvePidSession` and exits 0 when the pid is attested, 1 when it is not, 2 on invalid arguments.

### Why

- A gate in a shared rpc host must learn which session called it (senpi#6972). The caller's `PI_SESSION_ID` is whatever its last `exec` set; the engine's spawn records plus the kernel ancestry are not.

### Why an extension could not handle it

- The command is a metadata query of every CLI entry, answered before providers, migrations or hosts load, like `config agent-dir`.

### Expected merge conflict zones

- LOW: the metadata-command dispatch lines at the top of `src/cli.ts`, `src/bun/cli.ts` and `src/cli-main.ts`, and the export list in `src/index.ts`.

## 2026-11-18 - The local shell attests its spawned shell to the calling session (#6978)

### What changed

- `packages/coding-agent/src/core/tools/shell-operations.ts`: `BashOperations.exec` options take an optional `sessionId`, and `ShellExecHost` an optional `attestSessionSpawn(sessionId, pid)`. When both are present, the spawned shell's pid is attested on spawn and released on exit, alongside the host's own `onSpawn`/`onExit`.
- `packages/coding-agent/src/core/tools/bash-core.ts` passes the session id whenever it exposes the session environment.
- `packages/coding-agent/src/core/tools/bash.ts` (`createLocalShellOperations`) supplies `attestSessionSpawn` from `core/session-spawn-attestation.ts`; the worker-safe core imports nothing new.

### Why

- senpi#6972: a process a tool call started must be provable as that session's, not as whichever session its environment names.

### Why an extension could not handle it

- The pid exists only inside the core shell path's spawn callback.

### Expected merge conflict zones

- LOW: the `exec` option list in `shell-operations.ts` and the `createLocalShellOperations` host object in `bash.ts`.
