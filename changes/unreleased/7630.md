## 2026-11-28 - A generated default-extension shim is only a file: re-export (senpi#7625)

### What changed

- `packages/coding-agent/src/core/generated-shim-banner.ts`: `generatedShimTarget` returns a target only when the re-export after the generated banner is a `file:` URL, the only form the seed step writes. Any other specifier (a relative `./x.js`, a bare name) makes the file the user's own extension, so the default-extension loader, the seed step and the config-reload change filter all leave it alone.

### Why

- A non-`file:` target was checked with `existsSync` against the process working directory, not the shim's own directory, so the same file was kept in one session, deleted in another, and overwritten by the seed step when the engine's builtins are on disk.

### Why an extension could not handle it

- The seed step and the default-extension loader decide what a file in the agent's `extensions` directory is before any extension runs.

### Expected merge conflict zones

- LOW: the return line of `generatedShimTarget`.
