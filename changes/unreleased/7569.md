## 2026-11-27 - gc collects identity-less endpoint directories, and nothing produces them (senpi#7564)

### What changed

- `packages/coding-agent/src/modes/rpc/host-generation-paths.ts`: `makeEndpointSubdirectory` (non-recursive, `EEXIST` accepted, a missing parent rejects with `ENOENT`) and `makeGenerationDirectory` (`generations/`, then `<id>`); `createGenerationDirectory` builds on both, so it never creates the endpoint directory itself.
- `packages/coding-agent/src/modes/rpc/host-reservations.ts`: a session-path claim publish creates `reservations/` only inside an existing endpoint directory; against a collected endpoint the claim fails and its caller reports it.
- `packages/coding-agent/src/modes/rpc/host-lifecycle.ts`: a direct-launch supervisor registers its endpoint (`createDaemonDirectories`) before its generation; every supervisor makes its generation directory inside a registered endpoint and fails startup instead of recreating a collected one.
- `packages/coding-agent/src/modes/rpc/host-gc-husk.ts` (new): `reapHusk` removes a directory nothing names only when nothing in it names a socket, its whole tree is older than `HUSK_HORIZON_MS` (14 days), and every process record in it names a process that is not running (an unreadable record counts as running); removal is rename-to-`.reap-<name>-<pid>`, re-read, delete, with a rename back when the tree no longer qualifies. `sweepReapLeftovers` finishes or undoes a dead reaper's leftover.
- `packages/coding-agent/src/modes/rpc/host-gc.ts`: a `socket: null` endpoint goes through `reapHusk` and is reported as removed with `identity_unknown_expired` (`HostGcRemovedReason`), kept as `unknown_identity`, or `failed`; new `husk` option injects the clock and pid probe.
- `packages/coding-agent/src/modes/rpc/host-gc-pass.ts`: the budgeted pass judges identity-less directories with the same rule and sweeps reap leftovers and dead writers' staged markers.
- `packages/coding-agent/src/modes/rpc/host-gc-pass-marker.ts`: the writer unlinks its staged `gc-last-run.json.<pid>.tmp` on exit; `sweepStagedMarkers` removes staged markers whose writer is not running.

### Why

- A directory with no `endpoint.json` or naming `settings.json` cannot be locked (the ensure lock hashes the socket, not the directory name), so gc kept every such directory forever as `unknown_identity`; recursive `mkdir` calls in writers other than the identity writer kept producing them. One long-lived machine held 66 of them out of 78 endpoint rows, plus about 130 leaked staged markers from short-lived processes exiting mid-pass.

### Why an extension could not handle it

- Endpoint directory layout, the gc evidence rules and the supervisor's startup are engine internals under `src/modes/rpc/`; no extension surface writes or judges them.

### Expected merge conflict zones

- LOW: `host-gc.ts` and `host-gc-pass.ts` (the per-endpoint loop), `host-lifecycle.ts` (the generation directory at supervisor start), `host-reservations.ts` (`publish`). All are fork-only RPC host files.

### Fixed
- `host gc` and the budgeted gc pass collect endpoint directories that nothing names once nothing in them has changed for 14 days and no process they record is running, host writers no longer create such directories, and staged gc markers no longer leak ([#7569](https://github.com/code-yeongyu/senpi/pull/7569))
