## 2026-11-26 - unload_session names the child sessions it detached (senpi#7480)

### What changed

- `packages/coding-agent/src/modes/rpc/session-unload.ts`: the `unloaded` answer carries `detached`, read in the step that claims the close; the port's `openChildSessions` returns ids.
- `packages/coding-agent/src/modes/rpc/session-router-routing.ts`: `openChildSessions` returns the session ids of the host's child rows instead of their count.
- `packages/coding-agent/src/modes/rpc/rpc-effect-answer-types.ts`: `RpcUnloadAnswer` gains optional `detached`.
- `packages/coding-agent/src/modes/rpc/effect-record.ts`, `packages/coding-agent/src/modes/rpc/effect-ledger.ts`: the unload receipt keeps `detached`.

### Why

- A caller could only list the children before an unload, a read a child can start or end around.

### Why an extension could not handle it

- The set is the host registry's at the moment of the close claim, which only the RPC host sees.

### Expected merge conflict zones

- LOW: `claimAndUnload` in `session-unload.ts` and the `openChildSessions` binding in `session-router-routing.ts`.
