## 2026-11-17 - getAllTools() carries a tool's own row renderers (senpi#6903)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ToolInfo` picks `renderCall` and `renderResult` from the definition, beside `permissionParser`.

### Why

- A host that draws a tool's calls somewhere other than the tool's own row (codemode's nested `tool.<name>()` rows in an eval cell) had no way to reach the renderers, so those calls drew as raw fields (oh-my-openagent#12994).

### Why an extension could not handle it

- `ToolInfo` is the public shape `pi.getAllTools()` returns; codemode is an extension and reads tools only through it.

### Expected merge conflict zones

- LOW: the `ToolInfo` `Pick` list in `types.ts`.

## 2026-11-17 - The tool projection carries a tool's row renderers (senpi#6903)

### What changed

- `packages/coding-agent/src/core/tool-info.ts`: `toolInfoOf` projects `renderCall` and `renderResult` when the definition has them; a tool without them projects neither key.

### Why

- So `getAllTools()` hands them to hosts that draw the tool's calls elsewhere (oh-my-openagent#12994).

### Why an extension could not handle it

- The projection is core's; extensions only read its output.

### Expected merge conflict zones

- LOW: the object literal in `toolInfoOf`.

## 2026-11-17 - A nested call of a tool with its own renderers is drawn by them (senpi#6903)

### What changed

- `packages/senpi-codemode/src/tool/tool-widgets.ts`: `renderToolCallWidget` takes a `renderers` lookup; for a non-core tool it draws the call with the tool's `renderCall` and the result with its `renderResult` (bounded: call 5 lines, result 5 collapsed / 40 expanded), and keeps the generic row when there are none, the args were truncated, no details were kept, or the renderer throws.
- `packages/senpi-codemode/src/tool/call-capture.ts`, `nested-tool-call.ts`, `cell-handler.ts`: a nested call of a tool with `renderResult` keeps a JSON copy of its result details (at most 16 KiB) on its summary.
- `packages/senpi-codemode/src/tool/render-detail.ts`, `render-result.ts`, `src/index.ts`, `src/bridges/schema-bridge.ts`: the lookup (`pi.getAllTools()`) is passed from the eval tool's result renderer to the widget.

### Why

- Every non-core `tool.<name>()` call drew as `tool.<name>(<JSON args>)` plus the raw result preview, so eval-only tools that bring a readable row (omo's thread tools) showed raw fields in a cell (oh-my-openagent#12994).

### Why an extension could not handle it

- The nested rows are codemode's own rendering.

### Expected merge conflict zones

- MEDIUM: `renderToolCallWidget` and the context helpers in `tool-widgets.ts`.
- LOW: `recordToolCall`'s parameter list, `runNestedTool`'s signature, the `renderers` object in `index.ts`.
