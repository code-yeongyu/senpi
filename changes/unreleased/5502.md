## 2026-11-02 - AuthResult says when the provider client authenticates at request time (senpi#3840)

### What changed

- `packages/ai/src/auth/types.ts`: `AuthResult` gains optional `requestTimeAuth: true`, documented as "the provider's client authenticates the request itself at send time", independent of `ambient`.

### Why

- senpi#3840: compaction's credential pre-check could tell a configured keyless provider (a Bedrock profile saved by `/login`, a bearer token env) from an unconfigured one only through `ambient`, which also ranks startup models (#2327) and must not mark a provider the user configured.

### Why an extension could not handle it

- The resolver result type is the contract between built-in providers and every consumer; an extension cannot add a field to it.

### Expected merge conflict zones

- LOW: the `AuthResult` interface body.

## 2026-11-02 - Keyless cloud resolutions carry requestTimeAuth (senpi#3840)

### What changed

- `packages/ai/src/providers/amazon-bedrock.ts`: every `{ auth: {} }` resolution (bearer token env, stored profile, and the ambient credential-chain branches) sets `requestTimeAuth: true`; `ambient` is unchanged.
- `packages/ai/src/providers/google-vertex.ts`: both ADC resolutions (stored choice and ambient) set `requestTimeAuth: true`.
- `packages/ai/src/providers/anthropic.ts`: the workload identity federation resolution sets `requestTimeAuth: true`.

### Why

- senpi#3840: these resolutions carry no key or credential header because the SDK authenticates at send time, so compaction refused the stored-profile and bearer-token Bedrock branches although normal turns worked.

### Why an extension could not handle it

- The built-in provider resolvers produce these results; only they know which branch authenticates at request time.

### Expected merge conflict zones

- LOW: the `resolve` return literals in each provider's api-key auth.

## 2026-11-02 - The model registry forwards requestTimeAuth (senpi#3840)

### What changed

- `packages/coding-agent/src/core/model-registry.ts`: `ResolvedRequestAuth` gains `requestTimeAuth?: true`, copied from the provider resolution beside `ambient`.

### Why

- senpi#3840: compaction reads request auth through `getApiKeyAndHeaders` and needs the marker to accept a Bedrock profile saved by `/login`.

### Why an extension could not handle it

- `ModelRegistry.getApiKeyAndHeaders` is the extension-facing facade itself; the field must exist on its result.

### Expected merge conflict zones

- LOW: the `ResolvedRequestAuth` union and the success return in `getApiKeyAndHeaders`.
