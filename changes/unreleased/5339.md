## 2026-11-01 - Job widgets: specs are written only by designated models (senpi#5339)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/job-widgets/model-author.ts`: `jobWidgetModelResolver` resolves the explicit `jobWidgets.model` setting, then the host route, and nothing else; the `session` source is removed from `JobWidgetModelSources`.
- `packages/coding-agent/src/core/extensions/builtin/job-widgets/session-author.ts`: the session's current model is no longer passed as a source, so a session with no designated model sends no spec request.
- `packages/coding-agent/src/core/extensions/builtin/job-widgets/request-controller.ts`: the `unavailable` outcome carries the typed reason `no_designated_model`; its 30 s backoff and the request/hourly-slot refund are unchanged.
- `packages/coding-agent/src/core/extensions/builtin/job-widgets/session-host.ts`: the `setJobWidgetAuthorResolver` contract says a route that answers no model means no spec, never the session's model.

### Why

- A model consumer runs only on the models designated for it, never on the parent/session model, even when the designated route answers nothing or fails (senpi#5338; same rule as code-yeongyu/oh-my-openagent#12010 for delegated children).

### Why an extension could not handle it

- It is the job-widgets builtin's own resolution order; a host route can add a model but cannot remove the builtin's session fallback.

### Expected merge conflict zones

- LOW: the job-widgets author files only.
