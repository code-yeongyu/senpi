## 2026-11-25 - Session telemetry is decided per caller on a shared host (senpi#7446)

### What changed

- `packages/coding-agent/src/core/telemetry-consent.ts` (new): the one rule. Effective permission = the host's own setting permits AND every caller of the session granted. `SessionTelemetryCallers` holds a session's standing answer and each attached caller's live answer and answers a `TelemetryCallersVerdict` per use: `events` needs every caller's grant, `attribution` is removed only by a decline. `openingCallersVerdict` gives a new session its opener's verdict.
- `packages/coding-agent/src/core/agent-session.ts`: `AgentSession.setTelemetryCallers`, `telemetryPermitted()` (events) and `attributionPermitted()` (headers), read at each use; the extension context reads it through `getTelemetryPermitted`.
- `packages/coding-agent/src/core/agent-session-runtime.ts`: `AgentSessionLaunchProfile.telemetryConsent` (the wire opener's answer); the runtime applies the callers' permit to its session and to every replacement, and takes live changes through `setTelemetryCallers`.
- `packages/coding-agent/src/core/provider-attribution.ts`, `packages/coding-agent/src/core/sdk.ts`: provider attribution headers (app identity only) read `AgentSession.attributionPermitted()` per request: the host's install-telemetry setting still decides for an unanswered caller, and any caller's decline or revoke removes them.

### Why

- A host process is shared: Desktop and CLI callers attach to the same engine. With policy taken from the host process alone, Desktop could neither grant telemetry on a host it started disabled nor keep its own requests out of an enabled CLI host, and a process-wide switch would change independent CLI sessions.

### Why an extension could not handle it

- The callers of a session are known only to the host's router, and provider attribution is applied inside the session's stream function; an extension sees neither.

### Expected merge conflict zones

- LOW: `agent-session.ts` around `setBrowserEngine` and the extension context actions; `sdk.ts` at `mergeProviderAttributionHeaders`; `agent-session-runtime.ts` constructor and `apply`.

## 2026-11-25 - `ctx.telemetryPermitted` (senpi#7446)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: `ExtensionContext.telemetryPermitted` and `ExtensionContextActions.getTelemetryPermitted`.
- `packages/coding-agent/src/core/extensions/runner.ts`: the getter, `false` on a runner with no session.

### Why

- An exporter has to apply the session's decision when it collects an event and again before it delivers a buffered one, so a revocation also drops what was buffered.

### Why an extension could not handle it

- The decision combines the host's setting with every caller's live answer, which only the host holds.

### Expected merge conflict zones

- LOW: `types.ts` next to `sessionEnv` and `getSessionEnv`; `runner.ts` next to `getSessionEnvFn`.

## 2026-11-25 - `telemetry_consent`: each caller's live telemetry answer (senpi#7446)

### What changed

- `packages/coding-agent/src/modes/rpc/session-router-telemetry.ts` (new): records each attached connection's answer on the session entry and hands the session (in-process runtime or worker) the callers' verdict.
- `packages/coding-agent/src/modes/rpc/rpc-host-command-types.ts`, `attachment-types.ts`, `rpc-host-response-types.ts`: `open_session.telemetry`, `attach_session.telemetry`, and the `set_telemetry_consent` command.
- `packages/coding-agent/src/modes/rpc/session-router-open-profile.ts`: validates the answer and records it on the launch profile; an open without it answers `unanswered`.
- `packages/coding-agent/src/modes/rpc/session-router-open.ts`, `session-router-park.ts`, `session-attachment-commands.ts`, `session-router-relocation.ts`, `session-router-routing.ts`: open, claim and attach declare the caller; a connection that leaves takes its live answer with it; the new command is routed.
- `packages/coding-agent/src/modes/rpc/session-worker-protocol.ts`, `session-worker-client.ts`, `session-worker.ts`: `telemetry_callers` carries the verdict to a worker session.
- `packages/coding-agent/src/modes/rpc/host-handover-parked.ts`, `host-handover-parked-open.ts`: a parked session keeps its standing answer across a handover.
- `packages/coding-agent/src/modes/rpc/custom-capability.ts`, `host-capabilities.ts`: the `telemetry_consent` capability.
- `packages/coding-agent/src/modes/rpc/rpc-input-validation.ts`, `method-classes.ts`, `method-classes-schema.ts`, `method-classes-schema-host.ts`, `method-classes-schema-fields.ts`: boundary validation and the `thread` method class.
- `packages/coding-agent/src/modes/rpc/session-registry-types.ts`: `RpcSessionEntry.telemetry` (callers and the verdict the session confirmed); registry error `telemetry_update_unconfirmed`.
- `packages/coding-agent/src/modes/rpc/session-router-context.ts`, `session-router-types.ts`: `onTelemetryContainmentLost`, defaulting to `exitForTelemetryContainment` (exit code 79).
- `packages/coding-agent/src/modes/rpc/rpc-host-lifecycle-types.ts`, `session-event-writer.ts`: the `host_telemetry_containment` host record.
- `packages/coding-agent/src/modes/rpc/session-worker-client.ts`: `failClosed`, which ends a worker that did not confirm a stricter verdict.
- `packages/coding-agent/src/modes/rpc/rpc-client.ts`: `RpcClient.setTelemetryConsent`.

### Why

- Unanswered, declined or revoked consent of one caller must not export, a caller grant must never override a host opt-out, and two callers sharing a host process must not decide for each other's sessions.

### Why an extension could not handle it

- Callers, attachments and their lifetimes live in the host router.

### Expected merge conflict zones

- MEDIUM: `session-attachment-commands.ts` `attach`; `session-router-open.ts` after `ownOpen`; the method-class tables.

## 2026-11-25 - The attached terminal answers for its own telemetry (senpi#7446)

### What changed

- `packages/coding-agent/src/modes/interactive/attach.ts`, `run-attached-tui.ts`: `--attach` sends the terminal user's own install-telemetry setting as its `attach_session.telemetry` answer.

### Why

- An attach without an answer is `unanswered`, which would turn a session's telemetry off for as long as its own user looks at it.

### Why an extension could not handle it

- The attach request is built by the attached terminal client before any extension runs.

### Expected merge conflict zones

- LOW: the `attach_session` request in `attach.ts`.

### Added
- A shared host decides each session's telemetry from the host's own setting AND every caller of that session: `open_session.telemetry`, `attach_session.telemetry` and `set_telemetry_consent` carry each caller's live answer, extensions read `ctx.telemetryPermitted`, an older peer that sends no answer never grants telemetry events, and provider attribution headers are removed by any caller's decline ([#7465](https://github.com/code-yeongyu/senpi/pull/7465))
- A worker session that does not confirm a revoked telemetry answer within 2 s is ended. If it is not seen to exit within a further 2 s, the host sends `host_telemetry_containment` to every connection and exits with code 79; embedders may observe that exit code ([#7465](https://github.com/code-yeongyu/senpi/pull/7465))
