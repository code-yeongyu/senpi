## 2026-10-28 - Bounded recovery manifest and immutable catalog nodes (S09, part of senpi#4272)

### What changed

- `packages/coding-agent/src/modes/rpc/compact-recovery-ids.ts` (new): the one identifier grammar of the recovery protocol (S09-Q2 A, RULING-57 Q2). A bounded id is 1..128 bytes of `[A-Za-z0-9][A-Za-z0-9:_-]*`, checked as empty / overlong / forbidden character before any use as a key, a path element or a log field; a SHA-256 digest is exactly 64 lowercase hex characters; a content ref is a 16-digit catalog counter root (`c-0000000000000001`) with at most `CATALOG_REF_MAX_STEPS` (8) three-digit child steps (`:000`..`:127`), a deeper one refused as `too_deep`, never a storage number or a path. A ref is cut-scoped (RULING-58 (3)): minted for one token, resolvable only under it, never a stable identifier outside the process; a ref from one cut is refused against another as `range`. Branded `BoundedId`, `ContentDigest`, `ContentRef`; S15's admission identifiers reuse this module (conformance test recorded on #4272).
- `packages/coding-agent/src/modes/rpc/compact-catalog-codec.ts` (new): the one frozen-reference codec (RULING-46 item 2) for S09-Q1 A. Digest = SHA-256 over `u8 tagLength || tag || u64be byteLength || bytes` with tag `senpi-recovery-catalog/1/utf16le/<leaf|node|root>` (the stored encoding is part of the domain, RULING-58 (1): a store writing another encoding gets its own tag and never collides) and bytes the exact stored bytes (the UTF-16LE code units of the store leaf text, a lone surrogate at a leaf boundary included), never a reconstructed or transcoded value; a format bump changes `CATALOG_VERSION` and therefore every tag, and a retired prefix is never reused. A catalog node is one JSON text with a fixed field order (`format`, `version`, `entries[{kind,id,length,digest}]`), canonical decimal integers and entries in child order, so its encoding is deterministic by construction; `CatalogNodeWriter` refuses, without retaining, the entry that would pass 128 entries or the 32,768-code-unit leaf bound (64 KiB stored, under D and F); `decodeCatalogNode` is a strict schema parse of bytes the caller has already verified.
- `packages/coding-agent/src/modes/rpc/compact-recovery-catalog.ts` (new): the immutable catalog tree (R4.B1). Components stream in and nodes are packed bottom-up, so at most one open node per level is resident (`peakBuffered` <= 128 x depth) and no collection of every component exists; each node is one store leaf plus a private pointer leaf (storage ids, never hashed or sent) and one owner that shares the pinned content it describes, so releasing the root owner releases the tree and no second checkpoint copy is made. A failed build (released child, storage failure, retired cut) releases every construction owner and reports no root or digest. Reads walk the ref's path and verify the stored bytes of every node against its parent's digest (the root against the manifest's) before decoding; a changed byte, or a private pointer leaf that is not a pointer list, is `CompactReadError("integrity")` (the pointer leaf needs no digest of its own: every child it points at is verified against its parent's digest before use), an unknown, malformed or foreign-cut ref `range`.
- `packages/coding-agent/src/modes/rpc/compact-catalog-families.ts` (new): the S09 family adapter over a frozen root: the persistent root leaf of `lifecycle`, `dialogs`, `active`, `calls` and `settled`, an absent collection as an explicit empty component. S10 extends this adapter to every member and index (R4.B2).
- `packages/coding-agent/src/modes/rpc/compact-recovery-manifest.ts` (new): the compact-v1 manifest, bounded scalar identity only: socket epoch, admission id, route kind, session, session epoch, generation, cut sequence, history version, token, leaf, active message, turn, checkpoint digest (the root node under the `root` domain), catalog root ref and length. A string that is a bounded protocol id is inline; any other (a user-chosen session id, a transcript id) becomes the first catalog components (`manifest`/`<field>`) and the manifest carries its ref, exact length and digest, so the original value reads back exactly and never enters the store as an identifier. One manifest and catalog per token, built once and released with the token; a build that fails after its catalog tree exists (a refused read, a broken layout) releases the tree before it reports, and the oversized fields are asserted to be the leftmost leaf's first entries in field order (a typed `ownership` refusal otherwise).
- `packages/coding-agent/src/modes/rpc/compact-recovery-state.ts`: `catalog(token, caller)` (the manifest, built under the token's and the cut's leases) and `readCatalog(token, caller, ref)` (one verified node or component; the raw ref is validated first); a reclaimed token releases its catalog before its root. `compact-read-lease.ts`: the `integrity` read reason. `compact-recovery-types.ts`: `storage_unavailable` carries a closed `StorageUnavailableReason` (RULING-58 (2): `integrity` the corruption signal, `range`, the store's and the transcript component's reasons), never a free string, and `RecoveryCounters.unavailable` counts those refusals by detail (`integrity` apart from `range`) beside `refused`; a refusal carries its kind and detail only, no stored bytes and no partial decode. `compact-session-state.ts`, `compact-lane-current.ts`, `session-acceptance-lane.ts`: `cutStorage(root, use)`, the cut's store under its lease.
- Behind `SENPI_ENGINE_SOCKET_COMPACT_UPDATES` (off by default): no transport, no selection (S17), no S10 family coverage and no S11 page route; the manifest is reachable only through the internal recovery owner.

### Why

- R4.B1 (senpi#4272, X03/X04): the manifest names a frozen checkpoint and its catalog root and never lists every component; each catalog node obeys F/D and 128 entries; huge ids and user strings become refs; digests are deterministic across runs and hosts (no host path, timestamp, storage id or map order in hashed bytes). RULING-57 fixed the digest domain separation, the verify-before-decode rule and the allow-list identifier grammar.

### Why an extension could not handle it

- The frozen roots, their store leaves and the token leases are host-internal; no extension event sees a cut, its storage or a token lookup.
