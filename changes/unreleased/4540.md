## 2026-10-27 - The reply language survives compaction and long tool output (omo#11527)

### What changed

- `packages/coding-agent/src/core/user-prose.ts`: new. The parts of a user message the user wrote themselves: `withoutTaggedBlocks` drops `<name>...</name>` blocks (`<environment_context>`, reminders) in one linear pass. An unclosed `<` (TypeScript generics) no longer triggers the quadratic backtracking of a tag regex, which took 345-1137 ms on a 100 KB paste. An optional `ProseScan` counts the characters the pass visits. Fenced code is dropped by splitting on the fences, inline code and links by bounded regexes. `ownLines` also drops quoted spans of every style (`"..."`, curly quotes, `「」`, `『』`, `«»`, with a length bound), `>` lines and lines that read as pasted log or error output.
- `packages/coding-agent/src/core/reply-language-reading.ts`: new. `readReplyLanguage` reads the language a user message is written in from `ownLines`. The first line with two or more words decides; otherwise all remaining prose does. A non-Latin script with at least 30% of the words names the language. Latin-dominant text is not named. A script shared by several languages is named by its script (`Cyrillic script`).
- `packages/coding-agent/src/core/reply-language-request.ts`: new. `readReplyLanguageRequest` finds a request only in a message that, after fenced code and tagged blocks are removed, is ONE non-empty line of at most 120 characters. The line must hold the directive as a whole sentence ("영어로 답해줘", "앞으로 답변은 영어로 해줘", "please reply in Korean from now on"), optionally after a few lead words. It must have no mark of reported speech: a quotation mark, a speaker prefix, an em/en-dash or `--` attribution, a forwarded or mail header, or an attribution verb ("said", "mentioned", "라고", "말씀하셨", "요청하셨", "그러시", "하래"). Any multi-line message has no request: a wrong request is sticky (it outranks the user's language and survives compaction), and reported content across lines cannot be told apart reliably, so a directive inside a longer message is ignored by design. Negations and other tasks (translate, write) do not match.
- `packages/coding-agent/src/core/user-language.ts`: new. `insertReplyLanguageNotes` adds one user-role note after a tool-result run that is followed by the next assistant message (or the end of the context). It is added once 4000 characters of tool results, custom messages, bash output and branch summaries have built up since the user's last message. The note names the reply language the user explicitly asked for; otherwise the non-Latin language they write in. A run that carries words the user typed into a tool's answer gets no note, since those words already follow it as a user message (senpi#2920, senpi#2118). A note can only name one of the fixed language names, so no user text is ever copied into it. A note already in the context (converted output converted again) keeps its language. Each message's reading is cached in a `WeakMap` keyed by the message, its content object and a 32-bit FNV-1a hash of its text parts, so repeated `convertToLlm` calls do not re-read history and any in-place edit, even one that keeps every length, is read again. `replyLanguageOf` computes the same state over a message list.
- `packages/coding-agent/src/core/messages.ts`: `convertToLlm` runs `insertReplyLanguageNotes` first. A compaction summary with a `userLanguage` renders the same note after `</summary>` inside its own text block, so no new user message is added. `CompactionSummaryMessage` gains the optional `userLanguage` and `userLanguageRequested`.
- `packages/coding-agent/src/core/session-manager.ts`: `projectSession` sets `userLanguage`/`userLanguageRequested` on the newest compaction summary from the user messages before that compaction entry (`annotateCompactionUserLanguage`). It is derived at projection time, so sessions compacted before this change get it too, an explicit request survives the compaction, and the session file format is unchanged.
- `packages/coding-agent/src/core/tool-result-user-words.ts`: the private `wordMessage` is exported as `followerMessage` and takes any `Message` source, so the reply-language note reuses its provenance rule.

### Why

- omo#11527: a Korean-speaking user got English replies after compactions and tool-heavy turns. After a compaction the context held no Korean user turn and nothing that named the user's language. The summary prompt (`extensions/builtin/compaction/prompts.ts`) has no language field and its English template produces English prose. Long English tool output then sat between the last Korean message and every reply. The only language rule was one sentence in the Handoff section of the system prompt.
- The note is derived only from the messages, at fixed positions, so each request extends the previous one byte for byte and the provider's cache prefix stays valid.

### Why an extension could not handle it

- The note must be part of every provider request and of compaction-summary rendering, which `convertToLlm` and the session projection own. A `context` hook would not reach the summarization and transport paths that call `convertToLlm` directly.

### Expected merge conflict zones

- LOW: the `convertToLlm` head in `messages.ts` and the compaction-summary case; the tail of `projectSession` in `session-manager.ts`.

## 2026-10-27 - Compaction summaries can carry the user's reply language (omo#11527)

### What changed

- `packages/agent/src/harness/messages.ts`: `CompactionSummaryMessage` gains the optional `userLanguage` and `userLanguageRequested`, set by the coding agent's session projection.

### Why

- The `AgentMessage` union takes `compactionSummary` from this interface, so the coding agent's reply-language note needs the fields here (omo#11527).

### Why an extension could not handle it

- A type in the shared message union.

### Expected merge conflict zones

- LOW: the `CompactionSummaryMessage` interface.

### Fixed
- Replies stay in the user's language after a compaction and after long English tool output. The context now names the reply language after the compaction summary and after long tool-output stretches: the language the user explicitly asked for, otherwise the non-Latin language (such as Korean) they write in.
