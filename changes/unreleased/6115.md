## 2026-11-06 - Hand rig steps wait for a quiet event loop (senpi#6115)

### What changed

- `packages/agent/src/execution/testing/hand-harness.ts`: `drain`, the wait every rig step takes between manual-clock advances, now loops `setImmediate` turns until a probe (two immediates with a sentinel between them) sees the host loop quiet, bounded at 64 turns; before it took exactly one `setImmediate` turn. Where the host has no `setImmediate` a single timer turn is the step, as before.

### Why

- senpi#6114: `test/execution/hand-conformance-async-store.test.ts` FAULT-HAND-01..05 failed `every call settled: not reached within 600000 ms of transport time` on main. The async store confirms each write only after three `setTimeout(0)` hops, the rig delivers carrier messages on the manual clock, and one `setImmediate` per 5 ms tick let a write land one hop per tick while the fault profile's own timers kept re-arming ahead of it, so `settle` spent its whole transport budget. Deterministic locally from #6051's own commit (which added the test); the previous main runs were green only by runner timing.
- The probe is immediates, not `setTimeout(0)`: node clamps `setTimeout(0)` to about 1 ms, and a 600 s transport budget is 120,000 ticks, so a timer-based quiet check costs about 150 s per case against vitest's 30 s wall limit. `setImmediate` costs microseconds, and each loop iteration still runs the timers phase, so pending `setTimeout(0)` hops land between two immediates.

### Why an extension could not handle it

- The harness is the conformance rig every hand case runs on; its step semantics are not reachable from an extension.

### Expected merge conflict zones

- LOW: the `drain`/`ioTurn` block near the top of `hand-harness.ts`.
