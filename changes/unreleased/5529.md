## 2026-11-02 - Entitlement and account-state refusals are not retried (senpi#3350)

### What changed

- `packages/ai/src/utils/retry.ts`: a new `ENTITLEMENT_REFUSAL_PATTERNS` list (OpenCode Go "an active ... subscription is required", Kimi "subscription does not have access", Antigravity "user location is not supported" and "verify your account to continue", Z.ai 1313 "request frequency has been limited due to abnormal usage") joins the non-quota non-retryable patterns, so it outranks the `server.?error` and `429` retryable tokens their wrappers carry. `isEntitlementRefusalMessage()` is exported for the fallback layer.

### Why

- The OpenCode Go 403 and the Z.ai 1313 lock were retried with backoff before any fallback, although waiting cannot lift either one.

### Why an extension could not handle it

- Retry classification is a core choke point in `packages/ai/src/utils/retry.ts`; no extension hook reorders the non-retryable-before-retryable pattern test.

### Expected merge conflict zones

- LOW: the non-retryable pattern lists; senpi#5512 edits the retryable list in the same file, on different lines.

## 2026-11-02 - Entitlement refusals bind a usage-limit scope (senpi#3350)

### What changed

- `packages/coding-agent/src/core/retry-fallback/usage-limit.ts`: `usageLimitScope()` counts an entitlement refusal (`isEntitlementRefusalMessage()`) as a usage limit, so the existing model/account scope rule binds it.

### Why

- With no scope the refused provider only got the default selector cooldown and the chain picked it again.

### Why an extension could not handle it

- Usage-limit scoping lives in the core retry-fallback modules wired directly into `agent-session.ts`; no extension hook overrides it.

### Expected merge conflict zones

- LOW: the `limited` disjunction in `usageLimitScope()`.
