## 2026-11-06 - Cancel sealed input when local input rejects (senpi#6062)

### What changed

- `packages/coding-agent/src/modes/interactive/terminal-sealed-secrets.ts`: the local input and sealed latch share a cancellation signal. A local rejection cancels that request immediately and emits the existing typed `cancelled` outcome.

### Why

- `packages/coding-agent/src/modes/interactive/terminal-sealed-secrets.ts`: an unhandled local rejection previously left the sealed request open until its deadline.

### Why an extension could not handle it

- `packages/coding-agent/src/modes/interactive/terminal-sealed-secrets.ts`: the terminal adapter owns the local promise and sealed latch race.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/modes/interactive/terminal-sealed-secrets.ts`, `raceTerminalSecretInput`.

## 2026-11-06 - Settle only offered sealed secret requests (senpi#6062)

### What changed

- `packages/coding-agent/src/modes/rpc/secret-sealed-holders.ts`: settled frames are limited to the request's offered holders. Requests ending before key generation completes emit no unmatched holder frame.
- Deterministic key-failure and settle-before-key tests cover the asynchronous request latch.

### Why

- `packages/coding-agent/src/modes/rpc/secret-sealed-holders.ts`: a holder snapshot alone does not prove a request was offered.

### Why an extension could not handle it

- `packages/coding-agent/src/modes/rpc/secret-sealed-holders.ts`: the holder source owns request delivery and settlement.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/modes/rpc/secret-sealed-holders.ts`, `SealedSecretHolders.settle`.
