## 2026-10-13 - edit, write and read refuse a non-regular target instead of blocking on it (senpi#2888)

### What changed

- `packages/coding-agent/src/core/tools/file-tool-host.ts`: `refuseSpecialFile` stats the target on the tool machine and throws `Could not <verb> file: <path>. It is a special file, not a regular file.` when `files.stat` reports it as `other`: neither a regular file, a directory nor a symlink, such as a FIFO, a device or a socket. A target the machine cannot stat passes, so the tool's own access check or open still reports it as before.
- `packages/coding-agent/src/core/tools/edit-core.ts`: with the machine's operations, the edit core refuses a special-file target after its access check and before it reads the file.
- `packages/coding-agent/src/core/tools/write-core.ts`: with the machine's operations, the write core refuses a special-file target before it reads the diff baseline and before it writes.
- `packages/coding-agent/src/core/tools/read-core.ts`: with the machine's operations, the read core refuses a special-file target after its access check and before the image probe and the read.
- The check runs on the tool's machine, so a configured remote machine classifies its own targets without consulting this host's filesystem. Explicit custom operations are unchanged: they own their filesystem.

### Why

- Opening a FIFO with no peer blocks until one appears, and a device can be read forever. The edit and write tools waited on that open and, because they deliberately keep the mutation queue locked until the in-flight call settles, never settled on abort either, so a model that named a pipe or a terminal device froze the turn (senpi#2888). This matches the upstream counterpart in oh-my-pi (`b84cfa9`).

### Why an extension could not handle it

- The blocking open happens inside the core tools' machine operations. A `tool_call` hook could stat the path first, but every other caller of the tools (SDK, RPC, hosts of the tools-core entry, other extensions) would still hang, so the refusal belongs where the file is opened.

### Expected merge conflict zones

- `edit-core.ts`: the lines between the access check and `ops.readFile`.
- `write-core.ts`: the lines between the filesystem policy check and the baseline read.
- `read-core.ts`: the lines between `ops.access` and the image probe.
- `file-tool-host.ts`: `refuseSpecialFile` after `lexicalCanonicalPath`, and its type imports.
