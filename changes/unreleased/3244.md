## 2026-10-13 - edit, write and read refuse a non-regular target instead of blocking on it (senpi#2888)

### What changed

- `packages/coding-agent/src/core/tools/path-utils.ts`: `assertNotSpecialFile` stats an existing target and throws `Could not <verb> file: <path>. It is a <kind>, not a regular file.` for a FIFO, socket, character device or block device. A regular file, a directory and a target that cannot be stat'ed pass, so the tool's own access check or open still reports those as before.
- `packages/coding-agent/src/core/tools/edit.ts`: with the default local operations, the edit tool runs the check after its access check and before reading the file.
- `packages/coding-agent/src/core/tools/write.ts`: with the default local operations, the write tool runs the check before it reads the baseline for the diff and before it writes.
- `packages/coding-agent/src/core/tools/read.ts`: with the default local operations, the read tool runs the check after its access check and before the image probe and the read.
- Custom operations (for example a remote filesystem) are unchanged; the check stats the local filesystem only.

### Why

- Opening a FIFO with no peer blocks until one appears, and a device can be read forever. The edit and write tools waited on that open and, because they deliberately keep the mutation queue locked until the in-flight call settles, never settled on abort either, so a model that named a pipe or a terminal device froze the turn (senpi#2888). This matches the upstream counterpart in oh-my-pi (`b84cfa9`).

### Why an extension could not handle it

- The blocking open happens inside the core tools' default filesystem operations. A `tool_call` hook could stat the path first, but every other caller of the tools (SDK, RPC, other extensions) would still hang, so the refusal belongs where the file is opened.

### Expected merge conflict zones

- `edit.ts`: the lines between the access check and `ops.readFile`.
- `write.ts`: the lines before the baseline read.
- `read.ts`: the lines after `ops.access` and before `detectImageMimeType`.
- `path-utils.ts`: the new export after `pathExists`.
