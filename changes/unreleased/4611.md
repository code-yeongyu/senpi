## 2026-10-28 - A silent SSE body is a typed transport stall within 90 s (senpi#4608)

### What changed

- `packages/ai/src/api/anthropic-messages.ts`: `iterateSseMessages` reads the body through `readWithSseLiveness`; the bound comes from the `streamLivenessTimeoutMs` stream option (`undefined` takes the default, `0` disables). A liveness failure ends the turn as an error carrying the typed stall wording.
- `packages/ai/src/api/simple-options.ts`: passes `streamLivenessTimeoutMs` through.

### Why

- senpi#4608: an SSE response whose headers arrived and whose body then delivered nothing was bounded only by the agent loop's stream-start bound (300 s, 600 s when raised for slow thinking models) or idle bound, both sized for a slow model, so a dead transport hung the turn for minutes. The new bound sits below the event level: a slow model whose connection still sends pings is never cut off, and the start bound is unchanged. Anthropic documents ping events without an interval, hence the 90 s default.

### Why an extension could not handle it

- The response body is read inside the provider adapter; extensions see only parsed events, which a silent body never produces.

### Expected merge conflict zones

- LOW: the `iterateSseMessages` / `iterateAnthropicEvents` signatures and the event loop head in `anthropic-messages.ts`.

## 2026-10-28 - A silent SSE body is a typed transport stall within 90 s (senpi#4608)

### What changed

- `packages/ai/src/utils/sse-liveness.ts` (new): `readWithSseLiveness` bounds each body read by a no-bytes deadline (`DEFAULT_SSE_LIVENESS_TIMEOUT_MS`, 90 s). Every chunk, `event: ping` and `:` comment keepalives included, re-arms it. On expiry it cancels the body with `SseTransportLivenessError` ("SSE transport liveness timeout after <n>ms (no bytes received)"), which releases the connection, and throws that error.
- `packages/ai/src/utils/retry.ts`: the liveness wording is a provider stream stall (`isProviderStreamStallError`) with its own row in `describeProviderStallForUser`, so it takes the bounded same-model retry and fallback path like the WebSocket liveness verdict.

The new bound sits below the event level: a slow model whose connection still sends pings is never cut off, and the start bound is unchanged. Anthropic documents ping events without an interval, hence the 90 s default.
