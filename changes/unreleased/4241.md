### Added
- Add `session_service` to run foreground daemons with session-owned leases, reuse existing external daemons without adopting them, and release only the calling session's lease on stop. Two sessions share a daemon only when the OS user, key, command, arguments and environment (its home included) all match; the caller passes its own client settings through `client_env` ([#4241](https://github.com/code-yeongyu/senpi/pull/4241), part of [#4230](https://github.com/code-yeongyu/senpi/issues/4230); reported by 욜로개발조아 in the KakaoTalk OmO room).

## 2026-10-25 - Register foreground session services (#4241)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/terminal/extension.ts`: register the session service tool beside the existing terminal tools.
- `packages/coding-agent/src/core/extensions/builtin/terminal/service-extension.ts`: expose ensure/list/stop, preserve service ownership across reloads, seal ended sessions, and apply a caller-supplied `client_env` to the service and probe and return it; the generic tool sets no product-specific variables.
- `packages/coding-agent/src/core/extensions/builtin/terminal/service-probe.ts`: run probes through managed call containment; only the documented absence marker permits startup, while native refusal and timeout remain errors.

### Why

- `packages/coding-agent/src/core/extensions/builtin/terminal/extension.ts`: agents need a discoverable foreground service path instead of an independent-daemon escape.
- `packages/coding-agent/src/core/extensions/builtin/terminal/service-extension.ts`: a service belongs to its session leases rather than the tool call or disposable worker that first requested it.
- `packages/coding-agent/src/core/extensions/builtin/terminal/service-probe.ts`: a permission or protocol failure is not evidence that a daemon is absent.

### Why an extension could not handle it

- These are the built-in terminal extension's service bindings. User extensions do not own the runtime's native containment handles or host-wide lease registry.

### Expected merge conflict zones

- `packages/coding-agent/src/core/extensions/builtin/terminal/extension.ts`: additive tool registration; the service implementation lives in new fork-only modules.

## 2026-10-25 - Lease foreground services across host-local sessions (#4241)

### What changed

- `packages/coding-agent/src/modes/rpc/tool-child/session-services.ts`: share host-owned foreground services until the final lease is released; key each daemon by OS user, service key, command, arguments and environment, so sessions with different homes or users never share one; borrow external daemons without native enrollment, recheck borrowed availability, and require a positive identity probe when a second workspace differs only in its working directory.

### Why

- `packages/coding-agent/src/modes/rpc/tool-child/session-services.ts`: cancelling a client call or ending one borrowing session must not kill a sibling session's service, and ending any session must never kill an external daemon; a probe run with one home's settings proves nothing about another home's registered daemon.

### Why an extension could not handle it

- `packages/coding-agent/src/modes/rpc/tool-child/session-services.ts`: lease release coordinates the session-owned native launch supervisor outside disposable tool-child generations.

### Expected merge conflict zones

- The service registry is a new fork-only module; raw cp/Bun/PTY launch migration remains separate.
