## 2026-11-28 - A session opened on a shared model runtime reads the current models.json (senpi#7645)

### What changed

- `packages/coding-agent/src/core/model-config.ts`: a `ModelConfig` keeps the models.json text it was loaded from, and `readsSameFileAs(other)` compares two loads.
- `packages/coding-agent/src/core/model-runtime.ts`: `refreshIfConfigChanged(options)` reads models.json once and runs the full `refresh` only when the text differs from the loaded config. It answers whether it rebuilt.
- `packages/coding-agent/src/core/agent-session-services.ts`: a session opened on a shared runtime calls `refreshIfConfigChanged` before the #1844 scoped refresh of its own registrations, which still runs when the file is unchanged.

### Why

- The in-process multi-session host builds its `ModelRuntime` once. A provider added to models.json while the host had no open session (so no config-reload watcher was running) was never composed: every later session failed its first turn with `No API key found`, and thread deliveries read `started` with no turn.

### Why an extension could not handle it

- The shared runtime and the session-open refresh are host internals; an extension loads after the open and cannot change which models.json the runtime composed.

### Expected merge conflict zones

- LOW: the shared-runtime refresh branch in `createAgentSessionServices`; `reloadConfig` / `refresh` neighbours in `ModelRuntime`; the `ModelConfig` constructor and its `parse` / `parseAndMigrate` returns.
