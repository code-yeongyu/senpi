## 2026-11-22 - An extension abort keeps queued input delivering (senpi#5239)

### What changed

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: the extension abort handler bound in `bindCurrentSessionExtensions` calls the new `abortKeepingQueuedDelivery()`. It aborts the run, waits for the session to be idle, moves whatever is still queued into the TUI-held queue (`compactionQueuedMessages`, still shown as pending) and sends it through `flushCompactionQueue({ willRetry: false })`. It never writes the queue into the editor. `restoreQueuedMessagesToEditor` loses its `abort` option. Explicit dequeue, tree navigation while streaming, user Stop (`abortAndFireQueuedMessages`) and terminal compaction failure still hand queued input back to the editor.

### Why

- senpi#5239: `ctx.abort()` drained the person's submitted queued messages into the editor as unsent drafts. An unattended session never pressed Enter again, so the message stayed undelivered and the session stalled. An extension abort stops the turn, not the person's input. RPC and print mode already kept the queue on this path.

### Why an extension could not handle it

- The handler is the TUI's own binding of `ExtensionContext.abort`, and the editor and held queue it touches are private to interactive mode. An extension calling `ctx.abort()` cannot change what the host does with the queue.

### Expected merge conflict zones

- LOW: the `abortHandler` entry in `bindCurrentSessionExtensions`, `restoreQueuedMessagesToEditor` and the new `abortKeepingQueuedDelivery` right below it.

### Fixed
- An extension abort in the TUI no longer turns queued messages into unsent editor drafts. They stay queued and are sent once the aborted run settles, so unattended sessions keep going ([#7346](https://github.com/code-yeongyu/senpi/pull/7346))
